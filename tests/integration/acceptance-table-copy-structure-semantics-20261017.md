# 同库空表复制的自增语义实测

本记录是实现复制表结构之前的数据库语义验证，不是 DBArk 产品、图形界面或安装包验收。执行者为 Root，员工只读采集原始结果；未据此接纳其它版本、平台、非默认步长/偏移或 Navicat 行为。

## 实际范围与结果

每批先核 `server-200` 实际主机、地址及账号，随后绑定既有隔离 13384 的 UUID、MySQL 8.4.11、Linux、大小写模式 0；自增步长与偏移均为 1。认证仅留内存。操作只针对本轮随机隔离库，无 Docker、GUI、系统剪贴板或用户权限修改。

三类合成源表分别覆盖有数据且计数已增长、空表且计数超过 JavaScript 安全整数、空表默认计数。每例只发送一次 `CREATE TABLE … LIKE`，不补发调整计数的 DDL。

- 新表均为空，目录报告下一自增值为准确字符串 `1`；各新表首次独立插入的编号也为字符串 `1`。
- 自增列属性保留；列目录一致，完整 DDL 仅表名和顶层自增计数不同。默认值和表注释中刻意嵌入的 `AUTO_INCREMENT` 文本保持原文，不能用全局替换清除计数。
- 新表具有不同的原生物理表编号；复制前后已落盘的源定义、目录、行与原生编号一致。
- 新表插入后源不变由执行脚本断言、已确认查询及结果标志支持；最终源快照没有另外落盘，独立采集不把这个标志冒充第二份原始快照。

[MySQL 官方 CREATE TABLE LIKE 说明](https://dev.mysql.com/doc/refman/8.4/en/create-table-like.html)支持空表、列属性和索引的语义，也明确外键等不会保留；该页没有明确本次下一自增计数规则。计数结论来自上述实测，不能只凭文档推断。
