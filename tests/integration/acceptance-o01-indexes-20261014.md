# O01 索引差异验收：2026-10-14

阶段：0.9 源码与安装验收中，未公开。用户全功能目标仍进行，O01 保持部分。本记录区分自主原生 SQL 研究、生产 API、真实 Electron、实际安装及公开下载；存在测试文件或单元通过不代替下一层验证。

## 研究与实现

五基线自主原生研究为 115 个单次 ALTER 变体，69 接受、46 真实拒绝、零采集错误；230 份前后 SHOW CREATE 原字节与 UTF-8 往返一致，原数据未丢失。另有 30 个 FK / 60 表 / 10 随机库的目录名称与 POS 研究。全部本轮库、线程已清理；无 Docker、全局配置或业务数据操作。脱敏夹具保留自主 SHOW CREATE、白名单 STATISTICS 和来源摘要，不含行值、服务器身份、随机库或凭据。

MySQL 5.7 接受 DESC 语法但丢弃方向，Maria 某些普通 TEXT/超长键会自动前缀/截短；产品据此在投递前限制，不能把 SQL 成功当语义保真。My8 外键目录保留逻辑原名，而 5.7/Maria 使用文件名映射；不能拆约束 ID 或把任意 Unicode 简单编码。My8 POS 从 1 起，SYS 目录从 0 起。原研究中错误的统一 POS 假设原样保留，正确排序后 30/30 与 KCU 元组一致。

生产实现使用字段/索引共用短会话、取消状态机、可信修订、实际有界缓存及用途隔离。目录读取有数量和 JSON 字节预算，权限不足降为 partial；取消/断线不伪装成空目录。FK 稳定语义引用包含双方身份、有序列组及 TYPE，合法候选键增加不改变引用；外部 FK 动作或映射变化能够使原计划失效。主键选择、自动外键键、分区、生成与隐藏属性按可信证据保护。

## 首轮失败及修正

1. My8.4 原 12 项首轮为 10 通过、2 断言失败：目录 SUB_PART 采用 BIGINT 字符串，查询结果使用不重复内部列键；修正测试取值后 12/12。产品实现没有因测试而改用浮点或丢失精度。
2. Maria 两版首轮各 8 通过、4 失败：实际 `version_compile_os` 是 `debian-linux-gnu`，初版仅认 `Linux`，造成完整目录不可用。仅为两个已实证精确版本增加该值，未知版本与伪造 linux 子串仍 partial，随后各 13/13 适用通过。
3. Windows UI 首轮 6 通过、1 测试选择器失败：全局 alert 同时匹配 Monaco 辅助节点；原草稿保护实际已触发。将断言定位到实际 toast，整轮 7/7。
4. SSH 15 项首轮总 153.876 秒，单个包含四次 get/preview/apply 的用例超过默认 30 秒；其余 14 项通过且清理完成。用例总限改为 120 秒，复验总 159.199 秒、15/15，其中连续四操作 31.641 秒。没有延长生产连接、取消或严格关闭时限。

每轮证据独立保存在 `.cache/o09-product-validation/runNN-*`，研究在 `.cache/o09-index-native-evidence`，失败自主结构在 `.cache/o09-index-product-evidence`；原件不进入源码归档。后续最终清单需核对实际输入/dist 哈希，测试过程中发生过共享目录查询 LIMIT 收紧，不将较早构建外推为最终安装产物。
