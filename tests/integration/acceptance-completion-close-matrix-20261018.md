## 实际路径与清理依据

Root 先核 SSH 宿主、地址和用户；每条只读 Docker 操作前再核宿主及本机 Unix socket 上下文，获取六端口各唯一的容器／hostname 映射，没有更改容器。数据库首次写入前核准确版本、容器 hostname、服务端口及实例信息；MySQL 另核 UUID，MariaDB 使用已匹配的实例元组。后续身份读取必须与本次原元组相同。

每个目标独立建立随机库及三列空表，原表标记、完整定义摘要、库字符集和排序规则均固定。仅调用一次真实 `engine.handle('metadata.completion', …)`，结果准确三列且 `incomplete=false`。旁观始终返回原生 driver／Query，不替换请求、结果或关闭实现；原命令逐一收到 Query-end，无命令／连接错误。Engine 返回后核每个原始流自身的 close 事件或 closed 状态，再由独立控制连接按原 threadId 确认服务器线程消失。

严格 TLS 目标在握手完成且流仍可读时核 `encrypted`、`authorized`、无授权错误、非空 cipher 及目标 IP 的证书身份校验。原始 TCP 和 TLS 两个对象分别登记、分别核关闭，不能用 TLS 对象的 close 代替另一个对象。CA 采用已有授权材料，启用 `rejectUnauthorized` 和 `verifyIdentity`，本轮没有生成或修改证书。

只在原任务成功、全部双端终态成立后，调用原 Engine 的 `closeAll`，再核同实例、原表完整定义与零行、整个库仅含本例表，且无例程、触发器或事件。恢复自己安装的创建旁观后精确删除本例随机库并核不存在，最后严格关闭原控制流。六目标全部完成上述路径，不新增数据库用户、授权或业务数据，系统剪贴板操作为 0。
