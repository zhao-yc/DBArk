# Q03 第三检查点：查询历史、保存与重连默认库

本批是 0.16 开发源码的查询上下文修复，接续[补全会话检查点](acceptance-q01-session-context-20261015.md)。0.16 尚未创建标签或公开安装资产，Q01 和 Q03 均保持部分。

## 行为与实现

- 历史的默认库在引擎取得会话互斥后、发送用户 SQL 前固定，通过可信任务事件交给主进程。脚本在 B 库开始、正文再 `USE A` 时，历史仍记 B；不能完成后才读取最终 A，也不能从渲染进程注入。普通、参数与完整导出任务都使用该链路。准备阶段取消、失效会话等没有执行快照的失败记录保留未知。
- 保存查询采用点击时的正文和当前会话协议缓存。布局与保存记录区分已知库、确认无库和未知；后两者不会回退标签的初始库或连接配置默认库。没有打开会话的旧草稿仍兼容原初始库行为。
- 查询发送到协议终态之间，恢复草稿先持久化为未知，并等待实际写盘成功后才发送用户 SQL，不能把 400 毫秒防抖当作崩溃安全。保存失败不发送本次 SQL；建连和落盘期间的取消意图在投递前再次检查，迟到完成不继续执行。终态仅异步读取内存缓存，不附加 `SELECT DATABASE()`，不污染 `ROW_COUNT()`、警告、事务或临时表。读回竞态和关闭的标签不会覆盖新执行或复活标签。
- 断线后不重放 SQL；未知库的下次建连先显示“确认重连数据库”。确认只改变下次建连目标，留空表示无默认库；仍需用户再次明确执行。原事务、临时表和 SQL 模式不会被重建成原会话。
- 显式 `sessions.open.database=null` 覆盖连接配置默认库。历史和保存面板带出新上下文，旧记录标注“旧记录的初始库”，不把历史上无法确认的库追认成真实会话库。

主要入口：`src/shared/queryContext.ts`、`src/engine/index.ts`、`src/main/index.ts`、`QueryTab.tsx`、`ActivityDialog.tsx`。文案在 `queryContext.zh-CN.ts`。

## 配置迁移

SQLite 版本由 4 升至 5，表结构和已有 JSON 记录不重写。新增上下文仍存在原 JSON 中；升级提高版本是为了让旧客户端拒读，避免忽略“无库/未知”而套用旧默认库。单元测试核对 schema4 原始查询行、加密凭据、空库/未知上下文和工作区草稿跨重启保存。既有 schema1/2/3 的无损迁移与失败回退断言相应更新。

使用真实用户配置前先退出所有实例、备份完整用户目录。回退应使用升级前的完整备份，另行保留新版目录；不得改 `user_version` 欺骗旧客户端。

## 保留的失败与平台限制

- 初次在受限 Windows 沙箱运行五个单元文件，SQLite 原子重命名被 `EPERM` 拒绝；改用正常 Windows 临时目录的授权执行环境。没有因此放宽原子保存或修改存储逻辑。
- run57 完整单元为 2002 过、6 失败：既有 VM 测试夹具未提供新增的 `pendingQueryHistory`，导致生产分派中的引用错误及准备任务断言连带失败。补齐夹具状态，新增真实生产分派的并发历史用例后，run59 为 2012 全过；再增加未知草稿补全断言，run63 为 2013 全过。原始输出均保留。
- 发送前落盘复核后 run72 为 2017 全过，但 run73 类型检查指出新测试 spy 被推断为零参数元组；显式补上命令/输入参数类型，run74 类型及 run75 单元通过。再补普通工具栏取消完整导出的投递前场景后，最终 run76 为 2019 全过、run77 类型通过。没有为通过测试放宽发送互斥、落盘失败或取消行为。
- 上一固定提交 `a3275ae` 的 [CI 38668320925](https://github.com/zhao-yc/DBArk/actions/runs/38668320925) 总体失败。类型/2003 单元通过；Windows x64 和 macOS arm64 的源码及真实安装各 23 离线通过、110 私网跳过；macOS x64 源码 22 过、1 失败、110 跳过，未执行后续安装验收。失败是离线 CTE 补全没有出现建议，错误上下文显示限额/超时状态，不能仅凭此确定冷启动原因。日志、完整测试 ZIP 和错误上下文已下载归档，须继续定位，不能将该提交宣称三平台通过。
