# Q01 第四检查点：Worker 就绪与分期超时

0.16 仍开发中，Q01 保持部分。本批接续[查询上下文检查点](acceptance-q03-query-context-20261015.md)，尚未创建发行标签或公开安装资产。

## 问题证据与边界

`a3275ae` 的 macOS x64 源码离线 CTE 用例曾失败；错误上下文为未出现建议及限额/超时提示。后续 `478daea` 使用相同 Worker 字节（SHA `b6d24e944f6947e85db8acaf8b60fd584113b9a2c13b7a6b888ce36585ed45d2`）的三平台源码与真实安装离线用例通过。原始失败没有稳定复现，不能仅凭后来通过宣称根因已定位或把旧失败改成通过。

源码核实原客户端的 2 秒期限同时包含模块加载与文本解析。Windows Node 24 独立线程执行当时真实 bundle 的合成 64 字符 CTE，模块加载约 133 ms、首次解析约 264 ms、复用解析约 5 ms；研究原件为 `run81-worker-start-timing.json`。这仅证明本机存在明显首次开销，不能代替 macOS Electron 证据。

## 实现

- 本地 Worker 完成模块加载和监听器注册后报告版本 1 就绪消息。客户端等待有效就绪后才传递有界 SQL 快照；等待期间固定引号模式，不受调用方随后修改影响。
- 启动期限 8 秒；就绪后解析单独限时 2 秒。每个期限绑定请求和阶段，旧计时回调、旧线程消息及重复就绪不能提前结束新请求、延长解析或重复发送正文。
- 替换、取消、超时和卸载仍终止整个线程，清理待发正文、计时器和监听器。成功后复用空闲已就绪线程；不自动重试解析或用户 SQL。
- 界面区分“补全启动超时”和“补全分析超时”，用户可继续编辑、执行或手动重新触发。预算、目录、会话模式及数据库未知的原有边界保留；补全不执行数据库 SQL、不上传正文。

入口为 `completionWorkerClient.ts`、`completion.worker.ts`、`SqlEditor.tsx` 和集中中文文案。未改变依赖版本、数据库服务、配置版本或凭据策略。

run86 执行期间仅补入一行说明断言期限的注释。移除此行恢复的被测脚本与起始 SHA 完全相等，原件保存在 `run86-tested-sql-completion.spec.ts`；没有变更执行逻辑。run87 使用包含该注释的当前脚本完整通过，用时 804756 ms；`.cache/o16-worker-ready-full-final-proof.json` 核对 199 个源/测试/包文件与开始输入一致、百万行真实用例通过，以及终态资源。

Worker 为 **2068157 字节、gzip 366115 字节**，SHA `a80a01a05555b38969d2bedfeb2efb6b3d2d4b0aa7098dd23b42f999fe9f6cab`。三份依赖许可证仍逐字节等于安装依赖原文。当前不把构建成功视为安装验收。

固定新源码原生 CI 同时验证 2025 单元，以及 Windows x64、macOS arm64/x64 的源码和实际 NSIS/DMG 安装。每轮离线用例均执行三个独立编辑器首次加载，共 18 个冷编辑器；它们不是失败重试。三份运行/任务元数据与四个 job 日志共七份原件已归档，`.cache/o16-worker-ready-ci-attestation.json` 核对摘要与数量。私网跳过项不能记为三平台实库通过；本机新安装包的完整实库及公开下载资产仍待后续发布验收。
