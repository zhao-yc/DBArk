## 原失败及修正

1. VM首轮Engine在CSV已提交502行、原字段值及DDL比较通过后，独立HEX投影比较失败，原进程退出1。查询的 `CAST(id AS CHAR) AS id` 与 `ORDER BY id` 使排序取文本别名；另行只读比较证明按BigInt重排原502行后，与明确原列排序的结果逐字段一致。修订只针对验收SQL，保留数值预期、120秒及零重试。原catch缺失的首差异不能事后补造；后续增加有界原差异与失败位置。
2. 首轮窗口误把 Windows shell 启动器PID当作Electron主PID，进入连接配置前即失败。沿用项目原生适配器的严格父子关系检查，保留原句柄／清单及平台门，未改成接受任意不同PID。
3. 次轮窗口未悬停数据库行便寻找隐藏操作按钮，原30秒定位超时。补上真实滚动和悬停，不强制点击、不延长超时，原失败及现场另存。
4. 两次成功窗口的封存控制器仍退出1：用户名子串扫描误匹配JSON结构键 `config.rootDir`。Root核原报告只命中该结构键，密码原文及解码附件无命中；另写核对记录，原控制器退出码及报告保持。原Playwright的两例通过和退出0单独记录，不宣称控制器本身成功。
5. 剩余实例首次只读准备误把5.7的server_id固定为1，并要求TLS握手后仍是裸TCP流，准备脚本退出1，未创建测试库。另轮固定已观测的server_id=0，分别绑定原TCP及握手取得的可信TLSSocket，完整核身份／证书／原流结束后通过。仅修订私有准备脚本，产品、正式套件、数值预期及期限均未更改，不重分类首轮失败。
