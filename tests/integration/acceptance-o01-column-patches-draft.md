## 执行边界与五库矩阵

必须明确设置 `DBARK_INTEGRATION_ENABLED=1`。仅允许服务器 `192.168.31.200` 的 `13357/13380/13384/13310/13311`，用 `DBARK_COLUMN_PATCH_TEST_PORT` 逐实例选择，默认 `13384`。复用 `.cache/dbark-test.env`，禁止输出秘密、禁止本机 Docker。每例随机 `dbark_e2e_*` 库；finally 先退出应用释放会话，再 DROP 精确本例库并查询零残留。

真实运行应记录源码/安装包哈希、实例版本、开始结束时间、用例结果、失败截图和残留库检查。原定义模式归一化、实际 nullable overlay、MariaDB 表达式/引导字面值只读、generated/on-update/分区等未改片段保留还需后端五库集成证据；本 UI 首批用例不替代完整兼容矩阵。

DDL 可能隐式提交且不可事务回滚。取消不是回滚；没有可信 not-sent 或 completed 结构化进度时按未知状态核对实际定义。失败再次执行必须重新读取和明确生成新预览，不能以文件重试、网络重试或错误字符串自动重放。

## 首轮真实运行记录（保留失败）

主智能体统一执行 `.cache/o01-product-validation/run01-windows-ui`，7 项首轮为 4 通过、3 失败。通过项为两个入口与单次 apply、外部定义改变拒绝、DDL 等待取消、快照释放与退出确认。原日志、error-context 和截图保持原样。

3 项失败发生在新增测试定位阶段，尚未覆盖各自完整后半段，不能据此记为产品通过：

- 批量默认：同一 stamp 行存在字段类型和默认表达式两组“小数秒精度”，宽泛 locator 触发严格模式；截图显示类型组禁用、默认组可编辑。修为“修改 默认值”所在属性组内定位，仍保留填 6 再清空及实库结果断言。
- 数据草稿保护：全页 role=alert 同时包含真实错误 toast 与两个 Monaco 空提示，宽泛断言严格模式失败；截图已展示正确 dataDirty，源草稿仍在。修为真实 `.toast[role=alert]`，仍要求两个入口拒绝且后续跨表草稿/事务保持。
- 忙任务：侧栏按钮由 `.row-actions{display:none}` 隐藏，仅对象行 hover/focus 才显示；点击工具栏刷新后未悬停对象行，locator 等待超时。修为真实对象行 hover 后点击，不 force、不绕过忙任务断言；草稿保护用例的第二入口同样显式 hover。

修订仅涉及新 spec，运行源码不变。修订后只执行 TypeScript 与用例发现检查；重跑真实 GUI 由主智能体另行安排。

随后主智能体从首轮截图指出原默认值摘要直接显示内部对象。按授权新增 `formatReadColumnDefault` 纯中文展示，区分无 DEFAULT、SQL NULL、空文本、文字 NULL、精确数值、HEX、位串与只读表达式；无法解析明确要求核对原片段，原 SQL 不变且不求值。新增两项语义展示单元，相关 UI 单元共 17 项通过；该必要运行源码修订须由主智能体重新 build02 后再验，原 build01 结果不覆盖。
