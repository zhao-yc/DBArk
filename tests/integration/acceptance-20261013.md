## 实测推动的修复

1. mysql2 的 DDL/DML 状态包会发出 `fields(undefined)`，CALL 最后状态包可能没有结果编号；引擎正确跳过空列并独立分配状态结果，连接致命错误也能结束任务。
2. 无参数控制语句首次选择文本协议，含参数语句保留预处理。失败后不自动切换协议重试，避免写操作重复。
3. JSON 显式用 UTF-8 解码；启用 mysql2 静态解析器，数组结果支持合法原型同名字段。
4. 文本旧值比较为 `BINARY CONVERT(列 USING utf8mb4) <=> BINARY CONVERT(? USING utf8mb4)`，兼容 latin1，同时识别宽松排序规则掩盖的文本变化。数字、日期和二进制类型保持原生比较。
5. 锁定 mysql2 3.24.5 并通过 pnpm 补丁给 TLS options 补传真实 `host`，IP 证书不再被错误地按 localhost 验证。CA 与身份校验始终在认证前完成，没有关闭严格校验。

引擎单元测试 60 项通过，TypeScript 检查通过；`pnpm install --frozen-lockfile --ignore-scripts` 成功复现包含驱动补丁的依赖。

## 连接配置变更保护补验

在上述五版本各 12 项基线完成后，追加了连接配置保存保护，避免地址、认证信息变更后仍静默使用旧会话。名称、分组、颜色和记住密码策略可正常保存；未重填的秘密保持原值，空串明确清除。

主进程保存敏感配置期间阻止同连接的新请求，引擎检查现存会话、运行任务以及首个 `await connect` 前已登记的建连操作。有活动时拒绝保存且不取消任务；无活动时清掉旧配置缓存，再保存本地配置，下次 `connections.open` 使用新值。磁盘失败恢复旧配置，旧系统密文无法解密时仍能显式重填密码修复。

补验结果：

- 全项目 12 个单元测试文件、121 项通过；其中 `engine-*.test.ts` 四个文件共 66 项通过。
- MySQL 8.4.11：13 项核心测试和 3 项权限/断线/SQL 恢复边界测试通过，共 16 项；本次未重复百万行、SSH/TLS 和其余四版本，保留前述历史验收结果。
