# 未发行草案：DBArk 0.17.0 — 搜索、工作台与数据工具

本文件是发行说明草案，不代表已创建标签、发布安装包或完成发行验收。记录范围为0.16之后、统筹分支 `task/parallel-integration-20261015` 已推送的固定检查点 [`c712f6c2fa488f5c4f922da5b88b8bce5c427dec`](https://github.com/zhao-yc/DBArk/commit/c712f6c2fa488f5c4f922da5b88b8bce5c427dec)。后续修复与新候选的实际证据由统筹核对后更新；旧0.16的安装、CI及公开下载验收不作为本版结果。

## 本批新增与改进

### 全库搜索与本地查询检索

工作台“全库搜索”提供结构名称、定义正文和表/视图数据搜索。按明确连接、数据库、对象及字段选择范围，支持文字、大小写和相应正则模式；目录与命中按需分页，失败范围单独显示，取消等待读取与连接收尾。结构名称覆盖十类对象，定义正文读取完整SHOW CREATE，搜索不会执行这些定义。

数据搜索支持跨页字段选择、宽表分块投影、完整值匹配及有限命中预览，区分NULL、JSON与HEX。所选字段可读但定位键无权时，允许给出明确的只读命中，不能据此冒充可编辑记录。命中记录定位会重新核验对象身份、定义、模式和可靠键；当前稳定身份方案仍限已明示的Linux、ASCII名称、非分区InnoDB及相应目录权限。搜索结果和当前定义均为只读导航，没有搜索后直接修改数据或同步结构的入口，见[搜索说明](../database-search.md)。

“历史与查询”中的保存查询浏览、执行历史改为有界概要分页，可分别筛选来源、名称/完整SQL，以及执行成功/失败或错误正文。全文正文在明确打开时按摘要重新读取；陈旧记录不覆盖后来保存的内容。另有无需数据库连接的“搜索保存查询”，在独立本地Worker中完成文字或可终止正则检索，打开后定位首处SQL命中。打开均建立新标签，不自动执行SQL；来源失效必须明确换源，换源后的默认库为未知。界面分页不代表整个本地SQLite文件按磁盘流式装载。详见[保存查询分页](../development/saved-query-pages.md)、[执行历史分页](../development/history-pages.md)和[本地全文搜索](../development/saved-query-search.md)。

### 当前页查找替换

表页“当前页查找替换”及Ctrl/Cmd+F、Ctrl/Cmd+H增加格内逐处导航、仅替换当前一处和可取消正则；同格多个命中、Unicode和零宽位置分别处理。替换先形成当前页草稿，再通过原“预览并提交”流程明确写库，翻页或上下文变化使旧计划失效。只读表仍可查找，NULL、DEFAULT与二进制保持独立；替换文字中的 `$1`、`$&` 等按字面保留，不提供捕获组展开。范围是当前页完整原值，不能当成全表批量更新，见[实现及限制](../development/d06-page-find-replace-20261015.md)。

### 保存查询来源绑定与执行计划

查询标签新增明确的“保存到原查询”和“另存为新查询”。来源绑定保留所见摘要、连接身份及默认库类别，源被修改、删除或上下文变化时拒绝陈旧覆盖；用户可明确另存。保存、另存不执行正文、不替换同源其他标签的物理会话、临时表、结果或事务，见[来源绑定](../q03-query-binding.md)。

“执行计划”增加原会话JSON计划树、服务器节点关系、估算指标及原始JSON查看；只有明确的格式能力错误允许文本回退，普通SQL错误不自动重发。保存、更新来源、另存及摘要冲突处理期间保留既有计划节点、折叠和选择状态；真正新执行仍更新结果和计划。此入口不执行EXPLAIN ANALYZE，估算成本不等于真实耗时。实现与分层验收见[首批集成](../../tests/integration/acceptance-parallel-integration-20261016.md)、[计划状态说明](../q07-plan-state-20261016.md)和[第三批验收](../../tests/integration/acceptance-parallel-third-20261016.md)。

### 普通窗口与LATERAL补全

补全增加普通SELECT内联窗口、独立命名WINDOW的PARTITION BY/ORDER BY字段作用域，避免外层输出别名穿入窗口或UNION末分支泄漏。窗口继承、窗口名编辑和帧边界等未支持位置保守停止建议；字段建议不保证目标版本能执行窗口SQL，见[窗口边界](../development/sql-completion-window-scope.md)。

LATERAL派生关系可引用合法的前置来源，保留遮蔽、分支隔离和本查询块星号规则。能力只按已识别的MySQL8.0.14及以后受支持版本范围启用；MySQL5.7、当前MariaDB与未知版本关闭，复杂连接及其他未覆盖语法仍不支持。新草稿复用已有建连返回的非秘密版本事实，物理会话优先使用自身事实，不为判断能力额外发送SQL。第三批已将语义切片接入真实编辑器并完成分版本验证；作者早期“未接线”说明不能代表此检查点状态，见[第三批验收](../../tests/integration/acceptance-parallel-third-20261016.md)。完整SQL语义、例程局部名及其他驱动仍未完成。

### JSON对象成员移动

在既有JSON节点和结构编辑上，非空对象及嵌套对象菜单新增成员顺序移动，按原成员与移动后的最终序号定位。移动保留完整键值token、重复成员、数字词法和对象外原文，不使用JSON解析后重新序列化来重建整段内容。通过原字段缓冲形成草稿，再集中预览提交；这是同一对象内的成员移动，不能当成跨对象搬移或任意JSON重构。产品菜单接线及三个真实界面用例已纳入[第四批验收](../../tests/integration/acceptance-parallel-fourth-20261016.md)，D04完整工作包仍为部分。

### 二进制查看、Hex暂存与结果类型

表页“单元格”、记录表单字段展开，以及双击/Enter提供Hex、编码文本和图片查看。按实际字节包装识别二进制；TEXT/LONGTEXT即使协议报告BLOB仍是普通文本，SQL NULL与空字节不同，重复列名按唯一内部键取值并显示对应列名。

**任意SQL查询结果始终只读**，不能从结果查看器暂存或回写表。只有满足原表页编辑条件的完整值，才可经Hex缓冲、草稿、SQL预览和明确确认提交；编码文本仅查看，不做文本编码写回。Hex每页4096字节，完整Hex编辑最多131071字节并受原始262144字符预算约束；超限输入整体拒绝，不能把截取前缀或显示片段当完整值暂存。恢复二进制网格实际粘贴派发的同时，F2/普通文字入口仍受专门限制。

完整字节解码最多2MiB，文本查看最多256KiB。图片限PNG、JPEG、静态WebP，受完整值、结构及像素预算限制；不支持SVG、HTML、GIF、APNG、动画WebP，也不从外部路径或URL加载。Web/BFile及完整图像编辑不在本批交付范围。格式和预算见[二进制说明](../development/d07-binary-cell-viewer-20261015.md)、[Hex预算](../development/d07-hex-budget-20261016.md)；当前实际结果类型与粘贴证据以[第三批](../../tests/integration/acceptance-parallel-third-20261016.md)、[第四批验收](../../tests/integration/acceptance-parallel-fourth-20261016.md)为准。下述新Delete守卫修复尚未计入已验范围。

### 收藏、虚拟分组与新查询导航

工作台新增收藏与虚拟分组、对象树星标、专注模式，以及应用内复制/粘贴对象链接。打开时按明确连接和对象身份核验，表/视图进入数据页，其他定义只读查看；没有注册操作系统协议，也不执行链接中的SQL。新建查询意图会撤销迟到的表页、定义和旧错误导航，最新有效请求仍沿原入口处理。功能说明见[工作台](../w02-workbench.md)，六个受控回包流程与真实双连接流程的证据分别见[第四批验收](../../tests/integration/acceptance-parallel-fourth-20261016.md)，不能把受控回包当成真实数据库导航。

### 两表结构比较：仅审查稿

工作台“结构比较”可明确配对两张已有基本表，按源→目标比较字段、主键/索引及出向外键，展开原片段和未覆盖项；支持受限差异选择、生成并保存SQL审查稿。**该入口不能执行结构同步**，不推断重命名，不提供整库或多表同步。任一所选项不可靠时撤回整批审查SQL，不能用前面的删除部分代替完整方案。

默认FULLTEXT的识别不代表允许生成特殊索引ADD审查稿；外键支撑仍须完整受控BTREE，目标外键命名空间未证明时拒绝危险组合。表选项、分区、CHECK、触发器及入向外键等未覆盖范围需另核对；“已覆盖范围相同”不等于整表或数据库相同。见[比较入口及限制](../development/schema-compare-connected-preview.md)和[第四批验收](../../tests/integration/acceptance-parallel-fourth-20261016.md)。

### XLSX导入导出与文件精度

表页“导入/导出”增加Excel工作簿（XLSX）、工作表/表头选择、字段映射，以及样本和完整流式导出；旧二进制XLS不支持，不承诺公式重算或完整Excel工作流。BIGINT、DECIMAL、微秒、NULL/空串、二进制及BIT64沿用精度政策；定标浮点和未知声明保守拒绝有损输入，不以服务器无警告证明无损。实际导入警告停止并回滚失败批次，此前已提交批次仍然存在。入口见[XLSX说明](../development/excel-first-slice.md)，1201行界面往返及六组合XLSX/CSV/JSON精度、真实警告批次回滚证据见[第二批验收](../../tests/integration/acceptance-parallel-second-20261016.md)。前序检查点的专项证据不替代新候选安装验收。

### 全文与空间索引

表页及对象树“索引与主键差异”新增受控InnoDB FULLTEXT/SPATIAL的查看、预览、新增和明确删除。全文只使用已证明的完整文本字段及一致字符集/排序规则；空间使用一个已为NOT NULL的空间字段，MySQL8还要求源显式SRID与独立目录一致，不自动改列或坐标系。

已有特殊索引不开放改名、重建或与BTREE互换；解析器、表达式、前缀、生成/隐藏属性等无法保真的定义保持只读。单次ALTER最多新增一个全文索引，并提示可能的重建与内部辅助结构保留。仍有DDL隐式提交、外部结构并发窗口及一次性令牌约束，失败或取消不自动重放。该索引面板的明确DDL操作与上面的只读比较审查稿是两个独立入口，详见[特殊索引说明](../development/o01-special-indexes-20261016.md)。

### 同次新执行的多CSV归档

查询“新执行并完整导出”新增“CSV ZIP：全部行集与执行状态清单”。明确确认后，在当前标签的同一物理会话重新执行一次捕获SQL；按原协议顺序把每个行集写为CSV，清单保留非行集状态、语句/结果位置、重复列名映射和警告。空行集仍保留标题；没有行集时也可生成仅含清单的有效归档。不为取得后续行集重新执行SQL。

使用不压缩的ZIP64、逐行背压和目标同目录原子替换，最多200个含状态结果、最终文件10GiB，预算包含全部容器字节。失败或取消时保留原目标并清理本任务未提交文件；已执行或已提交的数据库操作不会因此撤销，也不自动重连或重放。操作系统强杀可能留下partial，不提供自动续跑。详见[归档格式与边界](../development/query-multi-csv-archive.md)。
