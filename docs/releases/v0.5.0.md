# DBArk 0.5.0 开发预览

新增“执行 SQL 并完整导出”，当前支持 MySQL/MariaDB。源码及本机安装已验，三平台主分支原生验收通过；标签发布和公开下载另行验收，不与本机包混用。全 Navicat 功能目标继续推进。

## 新增与修复

- 捕获查询选区或全文，在当前标签会话明确进行一次新执行，保留临时表、变量和事务。配置参数、选择文件不执行模板；失败和再次执行需要重新确认，不自动重放已提交写入。
- JSON 顺序保存多种列结构、零行集和状态包的版本封装；CSV 指定本次第 N 个行结果，状态包不占 N，其它结果和后续语句仍执行一次。不存在目标结果保留原文件，不能撤销 SQL。
- 完整文件有界流式写入，预览每结果最多 200 行、合计 16 MiB；BIGINT/DECIMAL、日期微秒、NULL、空串、二进制与重复/原型同名列按位置保留。支持 UTF-8、UTF-16LE、GB18030 及九类型参数。
- 默认文本严格模式遇 FLOAT/DOUBLE 明确停止，避免合并相邻值；显式二进制模式保留 IEEE 数值并提示首次准备对警告诊断的影响。诊断/控制发送前选文本，不进行失败准备后的透明回退。
- 共用原子文件 IO、64 KiB 编码缓冲、无损编码检查、短写消费和同目标互斥，只有实际 rename 成功才标记文件提交。晚到取消不会把已保存文件误报取消，文件提交与数据库事务分别显示。
- 修复确认按钮双击误触取消，执行按钮运行时保留原位置并禁用；实际取消有独立按钮。修复准备期引擎退出后的迟到任务投递，以及清理失败后仍使用错误前事务状态；任务及历史错误继续脱敏。
- 修复 SSH 真实断线只发连接结束事件时的等待挂起。取消/磁盘错误和断线都等待本代命令及控制连接收尾，拒绝断线会话复用，不以重新连接掩盖失败。

## 范围和升级

文件最多 200 个含状态的结果、1024 列，原始/序列化字段各 8 MiB、单行 16 MiB、文件 10 GiB；Base64、JSON 转义和编码可更早达到预算，超限拒绝而非静默截断。CSV 多结果容器、JSON 全结果封装恢复、断点续写、已完成查询游标续读及更宽预处理兼容继续保留，封装 JSON 不能直接当表 JSON 数组导入。

沿用 schema 2，升级或回退前退出并备份完整用户目录。支持手动更新；Windows 未发行签名，macOS 仅 ad-hoc 签名、未公证。实体 Mac Gatekeeper 及完整导出 macOS 内网 UI 未验证，不把原生离线安装外推实库。其它驱动、数据视图、结构设计、同步、备份和建模继续按 [完整清单](https://github.com/zhao-yc/DBArk/blob/main/docs/navicat-coverage.md) 推进。
