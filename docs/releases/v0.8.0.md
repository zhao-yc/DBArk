# DBArk 0.8.0 开发预览

本批新增既有表的字段差异编辑，改善日常字段、默认值与注释修改。修复后的源码已通过 604 项单元、五版本及 SSH/TLS 共 102 项核心适用用例、14 项最小权限和五版本 Windows 新增桌面 35/35。原失败记录保留；完整旧功能回归、实际安装与公开发布仍在进行，本文件尚不是公开文件通过证明。

## 当前实施范围

- 结构化新增、删除、重命名、类型、可空、默认值、注释与位次补丁，只生成本次改动的一条 ALTER，不从简化表模型重建未改字段、索引、外键和表选项。
- 显式区分不修改默认值、无 DEFAULT、SQL NULL、空字符串、文本 NULL、精确数字及受控时间表达式；SQL 预览只读，最后确认一次执行。
- 有界原定义解析与补丁预算，未改片段保留，未知或可能改变语义的目标列操作按属性显示只读原因。MariaDB 表中存在不能证明内部重述等价的默认值时，整表字段 ALTER 都受保护；不能因为只改旁列或使用原生改名而绕过。
- 短独立结构会话、有界快照和单次令牌，执行前重核目标、配置、模式及原定义；不占用查询标签的事务，不自动重放 DDL。明确外部结构变更的剩余窗口和维护时段要求。
- 结构操作提交、完成、核验及释放分别记录；取消、断线或核验失败不能被误报为已经撤销变更。

## 研究证据与边界

五基线独立定义取证中，170 条原始 DDL 有 142 条成功、28 条被真实服务器拒绝，取得 164 份 SHOW CREATE。两版 MariaDB 均证实：一个 Unicode 默认表达式在原样重建、旁列 ALTER 和原生改名后，后续省略列 INSERT 的实际默认值会改变，旧行保持。产品首轮也重现此问题，修复后按整表保护；只有单批默认值修改完整覆盖全部可控风险默认值，才允许生成计划，无法可靠解析的默认属性仍只读。

同一证据也说明该类 MariaDB 定义不能直接用于含结构 SQL 导出。0.8 增加拒绝保护，原目标文件保留，纯数据 SQL、CSV 和 JSON 导出继续独立执行；0.7 及更早版本的这一结构导出边界仍需明确，旧发布文件不会被替换。兼容 SQL 模式隐藏表属性时也拒绝含结构导出。

MySQL 5.7 与两版 MariaDB 的二进制文字默认值也存在实证丢字节，且 `information_schema` 不能恢复原字节。首批禁止自动重述这些列和含结构导出；旁列可改，显式受控 SET/DROP 默认值可执行，但服务器仍以不可靠文字形式返回时，仅报告已完成、未核验，不自动重放。原值摘要标为不可可靠解析，旧整表设计器也受保护。普通明确 HEX/BIT 默认值与无 DEFAULT/NULL 按实际能力处理。

另有五版本 48 例原生时间默认值、HEX 与 BIT 探针：38 例实际插入读值成功，10 例语法拒绝。MySQL 5.7 使用完整原列 MODIFY 设置时间默认值，MySQL 8 使用 SET DEFAULT 的受控括号形式，MariaDB 使用已验证语法。上述原生研究与产品 API、桌面、安装包证据分别记录，不互相替代。

MySQL 8 的 TEXT/BLOB 非 NULL 默认值在字段修改中预先使用 MODIFY DEFAULT 表达式，不能从 CREATE 支持推导 ALTER COLUMN setter 也支持。MariaDB UCA1400 完整排序规则别名通过实际目录能力精确解析，不能从名称前缀猜字符集；默认规则及显式别名分别验收，受限账户无需新增权限。
