# D04 JSON 树节点值编辑

0.14已公开，源码、本机及公开NSIS、主分支及固定标签三平台分别验收，范围见实际记录。0.13标签和下载资产保持不变。本批在记录树中增加“编辑此节点值”，只替换选中标量、对象或数组的完整JSON值。成员新增、删除、改名、数组插入删除移动及其它D04子能力继续独立推进，不能把值替换当作完整树编辑。

## 原文及定位

复用既有有序词法树，用精确列名、成员序号和数组下标定位。重复成员分别选择，点号、斜线、Unicode和原型同名字段没有路径表达式语义。仅替换目标token范围；其它原文、空白、数字指数、负零及成员顺序保留，根token外的空白也保留。服务器已规范化或丢弃的原始内容无法恢复。

字符串输入须带JSON双引号；JSON null暂存为字段中的JSON原文，与SQL NULL独立。整字段SQL NULL、DEFAULT、HEX仍由既有字段或整行编辑承担。替换值和合并后的完整字段均校验，限制仍为262144个UTF-16代码单元、262144字节UTF-8、64层、8192节点、单容器2048条目，不放宽原读取和解析边界。失败保留原输入及所有页面草稿，不生成部分树。

## 身份和草稿

入口同时捕获目标、连接修订、加载代次、元数据签名、UUID、行对象、data/original引用、当前树缓存文档和精确节点。暂存重新核对身份和完整原文；同内容的新对象也不能冒充同一快照。每次打开有独立输入会话，旧会话的迟到改字事件不能覆盖重开的同一个节点。

节点、字段Map及整行输入为三个互斥variant。非法原文同样进入现有dirty和离开三选守卫；切行、关闭、模式切换、隐藏标签、原生退出及刷新继续使用原保护。暂存只生成原字段JSON模式输入，再一次进入同一DraftRow[]，保留已有草稿和original；最终写入仍需原SQL预览和一次性确认。没有新增IPC、引擎写路径、会话或持久schema。

视图、无可靠键、非InnoDB、生成列、待删除、过期及忙碌均使用原能力门。无输入时行对象变化撤下节点输入，有dirty时保留原文但最终身份门拒绝覆盖竞争快照。普通字段的只读展开和删除行为保持，避免重演0.13完整回归中发现的问题。

## 界面及验收

树默认查看，点击节点按钮才打开输入；支持Ctrl+Enter、macOS的Cmd+Enter暂存到本页。节点路径和详细限制可展开查看，独立滚动区域保留底部操作按钮。树的查看、展开和打开输入不自动查询、提交或保存持久状态。

候选74项和类型检查不计入正式0.13。实际接入正式1697项单元及类型检查通过，首次类型检查发现旧静态组件测试缺少新增回调，补齐后完整检查通过。首轮8项Windows实库界面为7过1失败：根token替换保留了原空格和换行，而新用例误期望去掉空白。改为精确匹配保留的原文，不使用trim放松断言。实际截图另外发现节点输入挤出底部操作，修正布局并补按钮在面板和窗口内的断言，原始报告及截图保留。

修正版原8项已在MySQL 5.7/8.0/8.4、MariaDB 10.11/11.4共40次通过。MariaDB 10.11首轮曾在进入该项节点操作前发生原5秒分页加载超时，7过1失败；保留报告且未更改等待、断言或源码，同一原8项完整复验8/8通过，具体延迟原因未确认。五基线结束后六实例、本机进程及本批新目录核零，13历史目录保留。
