## 1. 0.10 基线与复用边界

| 现有位置 | 实际能力 | 对记录视图的约束 |
| --- | --- | --- |
| `src/renderer/components/TableTab.tsx` | 直接使用 `react-data-grid`；没有独立 `TableGrid` 组件。当前页 `rows`、元数据、筛选、排序、分页及提交都由表标签持有。 | 首批在表标签内增加当前行表单，不另建数据标签、查询会话或全页数据副本。 |
| `src/renderer/dataChanges.ts` | `DraftRow` 包含 `id`、`data`、`original`、`inserted`、`deleted`；`collectChanges` 汇总 insert/update/delete，更新保留完整 `before`。 | 网格与表单必须使用同一组 `DraftRow`。表单不能修改 `original`、自行拼 SQL 或绕过整页预览与提交。 |

| `tableColumnPreferences.ts`、`pageFindReplace.ts`、`referenceChanges.ts` | 列显隐与顺序由列名调和；页内替换和外键选择按行身份、代次及快照验证后写相同草稿。 | 表单不能改变网格列偏好，不能绕过已有替换或关联值的失效检查；这些入口也须识别尚未暂存的表单输入。 |
| `src/engine/sql.ts`、`src/engine/index.ts` | `buildChanges` 要求 InnoDB 与可靠定位键，更新/删除附完整旧值比较；`table.apply` 在事务中检查每条恰好命中一行，失败处理整批回滚，成功后界面重新读取。 | 保持现有服务器判定。新增表单不引入逐字段或逐行自动写接口，也不能在冲突后把新服务器行当作旧快照直接重试。 |
| `src/renderer/store.ts`、`App.tsx` | 数据草稿以 `dirtyTabs` 进入标签关闭及应用退出保护；活动任务阻止关闭。表数据不持久化到工作台配置。 | 新增的输入缓冲也必须参与 dirty 判断；恢复布局不等于恢复未提交记录。 |

接入前应处理两个静态可见的守卫差异，而非照搬：当前 `TableTab.editable` 只检查可靠键、页是否存在及结构过期，InnoDB 条件在服务端 `buildChanges` 才完整拒绝；现有单元格弹窗的 `text/mode` 缓冲没有单独计入 `dirtyTabs`，暂存时也未单独核对捕获的加载代次。记录表单需要统一表级/行级/字段级可编辑原因，并将单元格弹窗纳入同一输入保护规则。以上为源码现状，不声称已完成真实故障复现。

## 2. 最小增量：当前页普通记录表单

建议先只交付“记录表单”：表页工具栏显式打开当前活动行的侧面板，窄窗口可占用原内容区域，返回后恢复网格焦点。首批不增加树/JSON 切换按钮，不新增存储格式和主进程命令。没有活动行时显示“请选择当前页记录”，不自行发查询补一条记录；新建行可由既有“新增”动作创建，再以新 UUID 打开表单。

面板显示连接、库、表、当前页记录位置及状态：未修改、已有草稿、新增、待删除、只读或结构已变化。每字段显示名称、类型、可空、默认值摘要与注释，区别原值和当前草稿值。定位键可以作为摘要，但长值应有界展示；不能把显示出来的主键当作表单内部身份。

默认使用现有 `visibleKeys` 的列顺序和可见范围，提供明确的“显示隐藏字段”选项，只影响当前表单展示，不改表列偏好。隐藏字段仍完整留在 `data/original`，不得因为没有渲染输入就从更新条件中丢弃。同一行切回网格后，已经暂存的值立即可见，尚未暂存的输入不能被当作已生效草稿。

“上一条”“下一条”只在当前 `rows` 顺序内移动，位置文案为“本页第 X / N 条”，不表示全表总量；待删除行仍可查看删除状态，禁止继续编辑，撤销删除使用原行状态。新增行出现在本页草稿顺序中。到达本页首尾时禁用对应按钮，不隐式跨页、COUNT、扫描全表或追踪外键形成树。多行复选集合与当前表单行分开，切行不扩大删除或复制目标。

## 3. 一份记录草稿，明确的输入缓冲

`TableTab` 仍是 `DraftRow[]` 的唯一所有者，表单只接收当前行与回调。建议为当前编辑字段建立按精确列名索引的稀疏输入缓冲，保存模式、原始文本和捕获的基线；不要在每次按键时克隆全部页、整行大 BLOB 或 `original`。点击“暂存本行”先校验所有变更，再一次合并到该行 `data`；任一字段失败则不做部分合并。按钮必须明确说明“仅暂存到本页，仍需预览并提交”。

建议的共同操作边界为：目标元组 `(connectionId, database, table)`、`connectionVersion`、`loadGeneration`、`rowId`、精确 `columnKey`，以及捕获的本地行修订状态。数据库定位继续使用原 `original` 中的键，即使用户在表单中改了主键也不能把新键用作更新条件。相同显示值、相同主键文本或相同页内位置都不能替代行身份。

网格编辑、单元格弹窗、粘贴、页内替换及外键值选择统一通过表标签的草稿写入入口，提交前核对最新目标、行、列、忙碌状态及修订状态。如果表单缓冲形成后，同一行被其他本地入口改变，旧缓冲不能覆盖新值；首批采用明确拒绝暂存、展示需要重新核对的字段，保留用户输入供复制或主动放弃。不要未经设计自动合并竞争修改。

“预览并提交”保持当前页整批语义，包含从网格或表单形成的全部新增、删除、修改。存在未暂存输入时先要求处理输入，不能让预览漏掉它。预览固定本次 `changes` 和本地修订状态，最终确认再次核对；预览期间不允许表单悄悄改变将提交的数据。预览/提交入口使用同步防重入，最终只投递一次 `table.apply`，不能靠按钮下一次渲染后才禁用来防双击。

## 4. 值语义与精度

| 值或动作 | 表单显示和暂存要求 |
| --- | --- |
| 普通文本、BIGINT、DECIMAL、日期时间 | 保留载入值和原文本精度；数字和日期编辑仍使用文本输入，不经 `Number`、`parseFloat`、`Date` 或本地时区格式转换。未编辑字段不生成补丁。 |
| NULL | 独立明确选择，实际值为 `null`；非空列禁用置 NULL 并解释原因，不能与空框合并。 |
| 空字符串与文字 `NULL` | 都属于文本；空字符串暂存为 `''`，文字 `NULL` 暂存为四个字符，不猜测为空值。 |
| 新增行未填写 DEFAULT | 以“使用默认值／未填写”明确展示，暂存表示删除该列的自有键，不能存入 `undefined` 或猜测 `ColumnInfo.defaultValue` 为实际值；由最终 INSERT 省略字段。 |
| 已有行 DEFAULT | 首批不开放“重置为服务器 DEFAULT”；现有更新协议没有此动作，不能用删除字段、NULL 或默认值显示文本冒充。 |
| BLOB、BINARY、VARBINARY、BIT 等二进制包装值 | 摘要只展示有界 HEX 和实际字节数；完整编辑沿用偶数位 HEX → Base64 协议，保持 `00`、尾零及高位字节。空二进制独立于空文本、NULL。不自动按 UTF-8 解码；BIT 继续由既有类型参数与服务器规则处理。 |
| JSON 列文本 | 首批用现有语法验证后保留原字符串；含 `9007199254740993`、大指数、重复成员及原型同名成员时不能解析后 stringify 改写原文。无效 JSON 保留输入并阻止暂存，不能静默回退为其他模式。 |
| 生成列 | 显示当前值及只读原因，不提供赋值或 DEFAULT 切换；改变其它字段不改其原快照。 |
| `__proto__`、`constructor`、`toString`、空格/Unicode/反引号列名 | 以元数据真实列名作精确键，读取用 `ownCell`，更新用安全计算属性或自有条目构造；显示名称作为文字，不用点路径、DOM 名称拼接或原型成员查找。 |

模式切换必须保留原始输入直到用户明确暂存或放弃；不能先把 JSON/BLOB 按当前文本模式重解释再进行校验。大字段默认只显示摘要，显式打开单字段编辑时才建立完整文本缓冲。新增展示/编辑预算应在实施时与现有读取、IPC 和剪贴板上限核对；超限说明无法完整编辑，不截断后当作完整值暂存，不先 stringify/复制整页再检查预算。

## 5. 切行、刷新、分页与退出

区分两种状态：“表单尚未暂存的输入”与“当前页已暂存但未提交的草稿”。全局 dirty 是二者的并集；输入即使暂时不是合法 JSON/HEX，也已经需要保护。取消本行输入只丢弃缓冲，不撤销此前已经暂存的当前行或其它行草稿。

| 用户或外部动作 | 首批行为 |
| --- | --- |
| 当前页切行、关闭表单、切回纯网格 | 有输入缓冲时给出“暂存本行后继续／放弃本行输入／留在当前编辑”选择；暂存失败则不切换。已经进入 `rows` 的草稿继续保留，绝不写库。 |
| 切换到另一工作区标签 | 保留本标签行身份、缓冲和草稿；不因隐藏而提交或丢弃。再次显示时核对目标与代次。 |
| 筛选、排序、页大小、直接跳页、刷新、放弃全部修改 | 统一经过清页守卫；合并说明将丢弃的输入和页面草稿，取消时保留原条件、页码、选择、焦点及内容。确认后才发送读取，不能先修改筛选状态再补问。 |
| 新页读取失败或旧请求迟到 | 保持错误与不可编辑状态，不能把旧页显示成新条件结果。清除失效表单目标；迟到回调按代次拒绝，不能写入新页同坐标行。 |
| 子表结构变化、可靠键变化、连接配置版本变化 | 标记当前表单只读、使输入目标和预览失效，保留未提交内容供核对；不自动映射新列或丢弃草稿。由用户明确处理后重新读取。 |
| 预览或提交执行中 | 冻结会影响输入、目标和 `changes` 的动作，所有入口共享同一忙碌状态；取消等待原请求终态。 |
| 服务器旧值冲突、权限拒绝或提交失败 | 保留原草稿及原 `original`，解释实际错误。不能替换旧值后自动再次提交；遇到无法确认提交结果先核对服务器状态，不将断线统一说成已回滚。 |
| 提交成功 | 使用既有完整刷新取得服务器值；旧 UUID 和输入缓冲失效，不能根据相同行号自动覆盖另一记录。首批可清空选择并提示重新选行，不承诺跨刷新定位。 |
| 标签关闭、原生窗口退出、应用退出 | 输入缓冲与页面草稿均进入现有关闭/退出保护；取消退出保留两者，明确放弃才关闭。不得靠输入 blur 先丢缓冲；应用退出不自动保存数据到数据库。 |

记录数据、输入缓冲、JSON 文本和 BLOB 不写入 `settings`、查询历史、任务概要或磁盘恢复库。首批仅内存保留；强制结束进程后的恢复不在范围内，正常退出必须明确提示未提交状态。

## 6. 只读原因与键盘可访问性

建议集中一份能力函数返回具体原因，供网格、表单、单元格对话框及相关按钮共用。至少区分：尚未加载或加载失败、服务器对象不是已确认基本表、非 InnoDB、缺可靠键、结构已过期、任务繁忙、待删除行、生成列，以及字段不属于当前快照。不能只显示统一“没有主键”，也不能把拥有可靠键解释为已获得 UPDATE/INSERT/DELETE 权限；实际服务器拒绝必须原样保留，前端不通过写入试探权限。

只读记录仍能逐字段查看、选择和复制。暂不可编辑的字段应在旁边显示原因，使用真实 `label`、`aria-describedby` 等关联到控件；只读文本优先使用可聚焦的 `readOnly` 展示，不能全部禁用后让键盘无法读取内容。

表单打开后聚焦记录标题或原活动字段，关闭后按 `rowId + columnKey` 恢复网格活动位置；若目标失效则聚焦表页工具栏。Tab/Shift+Tab 遵循当前可见字段顺序；上一条、下一条、暂存及取消均为有标签的按钮，不能只能靠图标或鼠标。文本域中的方向键、Home/End、Enter、Delete 和输入法组合输入保持原编辑作用，不用于换行记录或误删整行。

表单内 Ctrl/Cmd+Enter 最多触发“暂存本行”，不能直接提交数据库；有打开的字段弹窗时由该弹窗处理。Ctrl/Cmd+S 不得保存后台查询，Escape 必须经过本行输入保护，不能一键丢稿。提示错误时定位到首个无效字段并保留输入，状态变更用适度的 `aria-live` 通知。深浅主题、窄窗口及缩放后都应保留标签、状态和操作，不以颜色单独表达 NULL、默认值或修改状态。

## 7. 树与整行 JSON 的后续范围

第一阶段只实现普通记录表单。后续可在同一记录身份与草稿基础上提供只读整行树/JSON 投影，仍限当前已加载行，不展开外键递归读取数据库。建议使用有序字段条目和显式类型标签表达记录，区分字符串、实际数值、NULL、未填写 DEFAULT、二进制字节及 JSON 列原文；不能直接将普通对象 stringify 当作可无损回写格式。

JSON 列树需要保留数字词法文本、成员顺序和重复成员的解析/定位方案，并限制深度、节点数及展开规模；实现之前仅提供原文查看，不使用 `JSON.parse` 后的 Number 或去重对象生成新值。BLOB 默认不展开完整 Base64。原型同名成员必须当作普通节点，节点路径由结构化片段表示，不能按点号拆列名。

树节点编辑、整行 JSON 回写、类型化记录文件格式、跨页连续表单、关联树、记录模板、批量表单、草稿持久恢复均单独设计与验收，不纳入第一阶段，也不因此把 D04 标为完整完成。

## 8. 建议拆分与实施顺序

1. 先提取表级/字段级写入原因、当前行身份、输入缓冲与离开守卫的纯模型，统一既有表格和单元格编辑入口；补回归后再添加视觉组件。可考虑 `recordViews.ts`、`RecordFormPanel.tsx` 和独立简体中文文案模块，具体文件名在实施时确定。
2. 接入当前行表单、类型化字段输入、页内切行及焦点恢复；所有修改回调只更新 `TableTab.rows`，默认沿用现有 IPC。若现有契约不能表达某动作，应明确不支持，不能偷偷新增语义。
3. 固定页面提交快照、同步防重入和全局 dirty 汇总，补足新输入层的边界；复验旧网格、粘贴、查找替换、关联值选择、列布局及结构变化通知。
4. 按下表完成实际验证后，再决定发布普通表单；树/JSON 视图保持待做，不通过文档预先计入安装包能力。
