# 查询会话临时对象与补全

状态：已实现会话内存目录、补全覆盖层和“会话临时对象”实际结构读取入口。2053 单元、六实例 200 集成及 Windows 最终 28 项编辑器回归通过，4 项集成因版本限制跳过；安装包和 macOS 本批尚未验收。Q01 保持部分，完整边界与原始失败见[本批验收](../../tests/integration/acceptance-q01-session-objects-20261015.md)。

## 目标与约束

同一个连接配置的两个查询标签必须分别看到自己的临时对象。临时表优先于同库同名永久表，显式库名不能绕过遮蔽。覆盖普通声明、IF NOT EXISTS、LIKE、AS SELECT、字段和表改名、字段修改和删除、表删除、切库、回滚、取消、断线以及例程/动态 SQL 变化。缓存须有实际补全入口、失效和刷新路径，而不是只支持识别一个 CREATE 语句。

MySQL 的临时表仅当前会话可见，关闭会话后消失；同名临时表遮蔽永久表。[MySQL 临时表说明](https://dev.mysql.com/doc/refman/8.4/en/temporary-table-problems.html) `SHOW TABLES` 和 `information_schema.TABLES` 不枚举用户临时表，不能把独立连接返回的永久目录当成完整会话目录。[MySQL TABLES 文档](https://dev.mysql.com/doc/refman/8.4/en/information-schema-tables-table.html)

自动触发补全继续只读缓存和独立永久目录，不在用户查询会话中附加探测命令。用户明确读取会话结构是独立操作，须提供具体入口、忙碌互斥、任务、取消与诊断变化说明，不自动执行编辑器正文。

## 协议研究与已排除的捷径

2026-10-15，在先核对身份的 200 专用 MySQL 8.4.11:13384 上，用随机 `dbark_colperm_*` 库和同名永久/临时 `subject` 做单实例研究。只有两个临时字段，未创建用户或扩大权限，完成后精确删库并按线程编号核无残留。原件在 `.cache/o16-sql-completion/run89-temporary-metadata-protocol.json`；该实验不外推其它版本。

| 操作 | UPDATE 后影响行数 | 已有 1292 警告 | 取到的字段 |
| --- | --- | --- | --- |
| 无附加命令 | 1 | 保留 | 未读取 |
| COM_FIELD_LIST | 变为 -1 | 另增加 1287 弃用警告 | 正确临时字段 |
| COM_STMT_PREPARE，不执行 SELECT | 保留 1 | 被清空 | 正确临时字段 |

研究使用的预处理每次带不同合成注释，排除命中客户端准备缓存的假保持。两个协议都确实读到了临时字段，但均不符合自动补全保持诊断状态的要求，因此不直接接入自动补全。官方还明确标记 `COM_FIELD_LIST` 自 5.7.11 起弃用，且只针对当前数据库，不能依赖它覆盖跨库对象。[MySQL 协议文档](https://dev.mysql.com/doc/dev/mysql-server/8.4.10/page_protocol_com_field_list.html)

## 实现方向

1. 每个实际会话持有有界对象目录和修订号，生命周期绑定其物理连接。默认库、SQL 模式和名称大小写规则来自已有初始化及协议缓存；状态未知时不从初始库补回。
2. 观察实际执行成功的 DDL 和结果协议，记录临时对象名称、确认过的列及可靠性。只在真实服务器终态后提交变更，不能在 SQL 发送前或仅客户端解析成功时当作对象已建立。失败、部分完成、取消和不透明调用必须标明受影响目录待核对，不能继续提供同名永久字段。
3. 自动声明缓存须解析完整引用、列列表、约束、嵌套表达式和引号模式，处理 IF NOT EXISTS 保留原结构、LIKE/AS SELECT 附加列、ALTER 字段次序和改名、DROP 多对象及跨库名称。不能把索引或约束名误当字段，不能凭 CREATE 文本推断服务器实际生成的完整列。
4. 增加“读取会话临时对象结构”的真实入口，在原会话、固定引用 SQL 和互斥下读取实际定义/字段。读取可更新会话诊断信息，须在入口说明；它与自动触发补全分开。支持已知名称刷新及显式输入例程创建的对象，结果有实际字段展示和错误状态。
5. 补全先查询当前会话目录，再合并独立永久目录。遮蔽按库/名称与服务器大小写规则处理，未知、失效和预算淘汰不得悄悄变成“没有临时表”。派生星号和不可见字段也须区分，缓存修订变化立即撤销旧候选。
6. 显式读取应复用统一任务和取消链路，保留原连接、事务和临时表；不持久化原始元数据或绑定值，不在关闭后复活目录。自动缓存读取不写 SQLite 任务、历史或查询记录。

## 必须验收

- 六个既定隔离实例：两个标签各自创建同名临时表；同名永久表具有不同字段，含显式跨库、别名、大小写与引用字符，补全必须取正确会话来源。
- 普通 CREATE、IF NOT EXISTS 不覆盖已存在定义、LIKE、AS SELECT 和附加字段、ALTER 增删改名/次序、表改名、多对象 DROP、模式及库切换的完整流程。
- 过程、函数、动态执行、可执行注释、失败和取消后的状态；读回真实结构后恢复候选，不能靠永久目录掩盖待核对项。
- 自动补全前后 `ROW_COUNT()` 与 `SHOW WARNINGS`、事务、CONNECTION_ID、原临时表数据及外部观察连接的未提交可见性保持；显式读取的诊断变化与界面说明一致。
- 没有 CREATE TEMPORARY TABLES 权限时创建失败，永久字段不能被虚构临时定义遮蔽。使用既有授权范围，不为测试扩大临时用户的数据库级权限。
- 超大定义、目录预算、长读取取消、销毁及重连、迟到结果不复活旧模型；跨标签不复用缓存。Windows 实际编辑器和安装包、两种 macOS 的原生源码/安装分别验收，未验矩阵继续标注。

该页保留完整目标。分阶段实现时，未实现的语法、刷新入口和异常边界须继续列为缺项，不能凭缓存原型就标记本工作包完成。

## 当前实现边界

成功终态观察普通临时表声明、IF NOT EXISTS、基础 ALTER 与改名、DROP；LIKE/CTAS 的完整实际字段通过显式读取补齐。未实现的条件 ALTER 清空旧字段，保留名称待核对。过程、函数、动态执行、可执行注释，以及不能确认是否包含视图或触发器的来源，会保守使目录待核对；字段请求不会改用同名永久字段。入口支持手输例程创建的名称、字段前缀和可见性，明确区分刷新缓存列表与实际读取。

自动补全只调用两个内存接口，不增加用户会话 SQL。明确读取使用原物理会话的有界 SHOW CREATE TABLE 和 SHOW FULL COLUMNS，沿用任务互斥、取消和控制连接释放；不会执行正文、覆盖已有查询结果或持久化默认值/原始定义。行结果 EOF 与无行结果终态均附带实际语句，修复只观察前者时遗漏存储函数的问题。

这里的自动字段是声明摘要，基础类型不等于服务器完整规格；复杂变换和兼容模式仍需读回。MySQL 无显式主键的声明保留字段摘要并标部分，避免遗漏服务器自动隐形主键；实际读回的不可见字段不会进入派生星号。目录未确认时，先查看需要保留的诊断，再在入口按名称读取。实际元数据读取可更新诊断，不能把这一步称为无副作用补全。完整语法、超大定义实际读取、服务器端长元数据等待的界面取消、断线和安装/平台矩阵继续验收。
