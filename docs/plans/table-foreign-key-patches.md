# 外键差异编辑实施记录

本工作属于 O01 的后续高频能力，尚未发布。字段、索引和主键的已有版本保持独立；纯解析、原生数据库探针、产品 IPC、真实界面及安装包分别验收，不能互相替代。

## 首批受控行为

读取完整 SHOW CREATE TABLE，保留外键的原始片段与范围，以 RC/KCU 逐个约束、逐有序字段交叉核对。子表和父表沿用真实列、索引、引擎、行格式、页大小、模式和身份能力。额外父表由用户显式选择，最多16个；既有父表从服务器原定义展开，父子合计最多32个，不递归加载整个关系图。自引用复用同一子表快照和列引用。

新增、删除及替换形成结构化差异，先展示引擎生成的 SQL。只允许已有完整子表 BTREE 支持索引、父表精确完整主键或唯一键；新增索引、数据修复及名称选择都需要独立显式操作。首批新名称为64字符以内 ASCII。五个实际版本均拒绝同条 ALTER 同名 DROP+ADD，替换必须由用户明确指定不同名称，不做自动改名或失败后降级。

支持复合有序元组、跨库、自引用及 RESTRICT、NO ACTION、CASCADE、SET NULL。SET NULL 必须能证明子字段可空，字段类型、符号、字符集、排序规则与完整键字节均须对应。非唯一父键、隐式补键、未知表达式、前缀、不可见/隐藏/生成属性、MATCH 和 SET DEFAULT 保持受保护范围。MariaDB 不可靠默认值和旧二进制默认值继续沿用既有保护。

## 命名空间与资源

新增和改名必须读取完整全局 InnoDB 原生头/字段目录及逻辑 RC/KCU，并形成双向闭合。不能用目标表过滤、目录空集或 JavaScript lowerCase 宣布名称可用。MySQL 8 在目标 schema 采用服务器 utf8mb3_general_ci 比较；MySQL 5.7 和本轮 MariaDB 的完整 schema/FK ID 采用 latin1_swedish_ci 比较。未知平台、版本、编码、权限、未解释目录、截断或读取错误均保留 partial。

全局目录每批128行，最多1000个头、32000个有序映射，四目录共享4MiB。每类必须读到 EOF，核对协议字段、原生 TYPE/POS、身份、动作及所有元组；前后再读服务器规则。候选名称按固定字符集与排序规则生成只读常量 SQL，严格核对每个批次回包。多次只读查询不构成原子目录快照，预览和执行前仍要重新核对，并明确外部 DDL 窗口。

与字段/索引复用独立短会话、任务编号、取消状态机和真实关闭终态。父子执行目标原子占用，直到原连接及取消控制连接实际关闭才释放；不是数据库级跨客户端锁。共享120秒、32快照/32预览、16MiB总缓存以及主进程128令牌总额。连接修订、过期、释放或一次性消费使旧令牌失效，取消和断线不自动重放 DDL。

执行前再次比较所有原父表、子表、模式、真实目录及命名空间，并重新计划。执行后分开记录已投递、收到成功包和完整定义核验；保留未改列、索引、CHECK、表尾、外部入向关系及新旧父表。缺父快照不能报告完整核验。服务器隐式新增或删除索引也必须被发现。DDL 常隐式提交，失败或取消不能承诺回滚。

## 已有原生证据与未验边界

run01/run02 在五个隔离基线共执行125个自主结构变体，保存原始响应及 SHOW CREATE 字节，并精确清理自有资源。47份自主结构夹具及白名单元数据已提取供纯解析测试；跨库标识符替换单列原/公开摘要，不发布业务数据、认证信息或第三方反编译产物。

run04 仅只读空目录与服务器名称比较；run05 仅审查既有原件和固定官方源码公式，两者不冒称采过非空 TYPE。随后 run06 实际创建并清理10个随机隔离库、50张空表和40个复合外键：五版四套目录均完整闭合；20项断言、50个名称判定通过。MySQL 8 实测默认 TYPE=48、POS从1开始；MySQL 5.7/MariaDB 默认 TYPE=0、POS从0开始，双CASCADE=5、双SET NULL=10、双RESTRICT=0、双NO ACTION=48。记录的库、线程、研究连接和本机研究进程均核零。

上述研究本身不代表产品 API、UI 或安装通过。后续产品链路已完成五基线及 SSH/严格 TLS 各25项、五版 Windows 新增界面各7项，实际父子互斥、锁等待取消、普通会话保留、草稿保护和迟到令牌释放分别断言。最小权限、完整回归、实际安装和公开阶段继续独立记录，见[产品验收](../../tests/integration/acceptance-o01-foreign-keys-20261014.md)。分页/字节预算与特殊编码等纯模块边界不能当作对应实库极限通过；macOS私网及发行签名/公证继续未验。
