## 实际入口和数据流

后继新增[命名窗口的帧关键字继承](../development/q01-window-frame-inheritance-20261021.md)，沿用本地Worker和零目录路径。首两轮RANGE解析失败保留；准确81f3a42修正后Linux592文件11458项、类型和构建通过、10平台跳过，Python另21项通过。Windows／实库及安装仍待验，不以此前075或338通过外推。

查询标签的 Monaco 接入有界词法扫描、本地 MySQL 语法 Worker、按目标惰性读取的目录缓存。已删除打开查询时预取前 20 张表字段的旧逻辑。只读 SQL 预览不注册该补全提供器。结果和替换区间均绑定编辑器模型、文档版本、连接修订和数据库；内容变动、连接改变、查询执行和卸载会撤销旧请求。

光标前后整条当前语句参与分析，常用来源包括 SELECT、JOIN、UPDATE、DELETE、INSERT 列清单、普通关联子查询、CTE 和派生表。限定名逐段保留引用与名称；CTE 和派生表显式列在本地解析，星号按实际物理来源读取目录。相同层次的重复别名不任取一张表；内层同名别名遮蔽外层，UNION 分支分别核对。WHERE、连接条件和排序字段不能冒充派生输出。

目录 API 只接受数据库、对象类别、表名和前缀，严格拒绝正文 SQL、会话编号和未知字段。主进程注入保存配置，utility process 创建独立可取消的短连接，固定参数查询 information_schema；补全不借用用户事务会话，也不执行编辑器正文。任务编号仅在内存跟踪，目录进度不进入用户任务面板或 SQLite 历史。用户查询、结构修改和文件任务沿用原持久化流程。

## 上限与取消

| 项目 | 当前上限 |
| --- | --- |
| 编辑快照 | 262144 个 UTF-16 单元 |
| 词法 token / 括号深度 | 16384 / 64 |
| 标识符和前缀 | 64 个 BMP 字符，无 NUL 或代理字符 |
| 目录返回 | 256 项，第 257 项只表示仍有更多 |
| 单次候选触发的目录目标 | 8 个 |
| 每编辑器实际并发 / 活动与排队目标 | 2 / 16 |
| 主进程同时活动目录读 | 8 |
| 每编辑器缓存 | 64 项、4 MiB 字符串和记录开销估算、15 秒有效期 |
| 可见建议 | 256 项 |
| Worker 启动 / 解析期限 | 有效就绪前 8 秒；就绪后解析 2 秒，分别超时终止线程 |

同一精确键合并读取，库名、对象名、类别和前缀均参加键值；普通 Map 保留原型同名和含点号名称。失败不缓存、不换目标重试。最后一名消费者取消后，数据库任务仍占并发槽直到实际结束。读取命令等真实驱动回调、连接终态或取消控制失败后才释放命令登记，迟到成功不得交付旧目录。

Worker 通过本地版本化就绪握手接收快照，等待启动时不传递 SQL。重复就绪不延长解析期限；取消与替换释放待发快照和旧线程。界面分别提示启动和分析超时，三个独立编辑器的首次加载按实际入口验收，见[第四检查点](../../tests/integration/acceptance-q01-worker-startup-20261015.md)。旧 macOS x64 失败尚未稳定复现，后续同字节通过不能追认旧轮根因或替代新协议的原生验收。

未限定表达式字段插入引用后的别名和字段，INSERT 列清单仅插入字段。接受建议使用普通文本编辑，名称中的美元符号、反引号和点号不作片段表达式解释。Ctrl + 空格触发建议，Enter 接受；macOS 沿用 Monaco 的 Control + 空格，撤销使用平台的 Ctrl / Command + Z。

## 解析依据及仍需完成的边界

第七检查点接入普通查询块 ORDER/GROUP/HAVING 的输出别名、字符串别名和UNION首分支输出，按实际方言处理引用字节边界；目录冲突不确定时省略建议。2089单元、六实例54项实际插入执行及Windows32项源码回归已通过，真实安装与原生新源码单独验证。祖先输出别名、窗口/LATERAL/例程等完整作用域仍待做，见[输出别名验收](../../tests/integration/acceptance-q01-output-aliases-20261015.md)。第六检查点 e9ed54d 的原生初始化修正已通过三平台源码和真实安装，各23离线通过、121私网跳过；旧失败原件保留，不外推本次新代码。

模式未知时分别扫描 ANSI_QUOTES 与 NO_BACKSLASH_ESCAPES 的四种组合，只在当前语句和编辑范围一致时继续。字符串、注释、执行注释、无法确认的引号和超预算输入停止建议；文本仍可编辑。未闭合引用名仅在文档末尾允许替换，避免吞掉后方 SQL。跨行名称暂不生成 Monaco 替换。

第二检查点已将用户会话的协议模式和 USE 后默认库接入补全及面包屑。新连接在原有初始化读取中同时取得 DATABASE()，启用默认库名称跟踪；后续 `query.completionState` 只读内存，不建连、不增加 SQL、不改变 ROW_COUNT、警告、事务或临时表。ANSI_QUOTES/NBE 仅在缓存可靠时交给 Worker；忙碌、断开和错误状态不交付过期模式。未知模式仍保留四种组合的一致性扫描。

默认库的 null 表示已确认没有默认库，databaseKnown=false 表示缺少可信状态。跟踪关闭后的 USE、没有名称报告的 CALL/EXECUTE/删除库等操作会使旧库失效，恢复跟踪本身不会恢复真值；后续实际名称报告才能确认。未知时不退回标签初始库，仍可按显式库名补全，界面显示“默认库待确认”。两个标签按各自固定会话取模式与默认库，迟到结果仍受模型和版本约束。MySQL 与 MariaDB 的动态 USE 差异已通过协议研究和六实例实库核对。
