# O01 字段差异编辑 UI 设计

状态：本文描述首批 UI 设计与接入，真实桌面阶段已经执行并保留失败，尚未发布。后端类型与执行契约以实际共享定义为准；当前结论见 [O01 产品验收](../../tests/integration/acceptance-o01-columns-20261014.md)，不能仅凭本设计或源码接入视为功能完成，也不改变旧发布文件。

关联设计：[表字段差异修改设计](table-column-patches.md)。

## 1. 真实入口与原设计器的关系

在既有数据表工具栏提供独立入口“字段差异编辑”，侧栏数据表动作提供同名入口，两者打开同一 `ColumnPatchDialog`，固定连接、数据库和表。入口有 tooltip 与 aria-label，支持深浅主题。视图不进入本功能。没有 ALTER 权限不通过客户端猜测隐藏入口；读取和实际执行权限由服务器分别校验。

新建表、原完整表设计器以及手工 SQL 定义入口继续保留。新功能不把 `TableDesign` 全表草稿回传给旧 `schema.preview/apply`，也不把打开 SQL 标签当作成功完成字段修改。原设计器的复杂属性保护不得因新入口而放宽。用户要改表名、引擎、索引、外键、表选项或首批之外的属性时，说明该项不在字段差异编辑范围，不能自动迁移到另一条执行路径。

固定顶部上下文显示连接名称、实际目标摘要、服务器方言/版本、读取时间与维护窗口提示。表名和连接选择不做可编辑字段。界面不取得查询标签的 sessionId，不改变查询事务、结果或表页草稿。

建议文案集中于新 `src/renderer/locales/columnPatches.zh-CN.ts`，样式独立；所有具体只读原因使用后端能力描述，不在组件中另写版本语法判断。

## 2. 编辑画面与差异草稿

主画面按服务器原字段顺序显示：原字段名、类型、可空、默认值摘要、注释、位置、差异状态、可编辑操作。每个既有字段由不透明 `columnRef` 标识，新增字段由稳定 `clientKey` 标识，不能以行号或新名称作为身份；合法 `__proto__`、`constructor`、Unicode 和反引号名称正常显示。

点击字段打开属性编辑区。只修改某项时仅生成相应 changes 属性；“不修改”与“无默认值”明确不同。恢复原值后移除该属性差异，整行无变化时移除 alter patch。新增、删除与多个字段修改组成同一表的批次草稿，在最终预览前不执行 DDL。

界面同时展示“原值／本次值”和“原定义片段（只读）”。原片段包含未修改属性，不能转成可编辑原始 SQL 文本；生成表达式、列字符集/排序规则、ON UPDATE、可见性、SRID、存储属性及其他未知片段标注“本批保留／该操作只读原因”。某列的类型操作只读，不等于其所有属性或整表都不能修改；具体可开放属性由快照能力决定。

普通列旁存在复杂索引、生成列、CHECK、外键或分区时，普通字段仍能形成受支持补丁。依赖检查不完整或不能安全保留的操作显示明确原因，禁止提交该补丁；不自动删除约束、关闭 foreign_key_checks 或修补其他对象。

新增普通列使用结构化类型表单，长度、精度、scale、UNSIGNED、ENUM/SET 元素分别输入和校验，不接受整段 type SQL。首批不设置自增、索引、外键或生成表达式。数值、日期默认值保留输入字符串，不通过 Number 或 Date 转换；不静默截短名称、注释或元素。

草稿只留在本次弹窗内，不写工作区 settings 或配置库。未应用草稿关闭前确认放弃；失败后保留供核对，但不得自动重新预览或执行。

## 3. 默认值：四种类型、五个可辨结果

每个既有字段首先有“不修改默认值”选项。用户明确开始修改后，默认值种类使用四个独立选项；文字量的两个空态结果不能合并：

| 操作 | 界面输入与显示 | 补丁语义 |
| --- | --- | --- |
| 无 DEFAULT | 选择“移除 DEFAULT”，不显示值输入 | `kind: none`，不是缺省 changes |
| SQL NULL | 选择“SQL NULL”，不显示值输入 | `kind: null` |
| 文字量：空字符串 | 选择“文字量／文本”，值框保持空，摘要明确显示“空字符串” | `literal/text/value: ''` |
| 文字量：文本 NULL | 同一文本框填写 `NULL`，摘要明确显示“文本 NULL” | `literal/text/value: 'NULL'` |
| 受控时间表达式 | 选择“CURRENT_TIMESTAMP 表达式”，精度由独立控件填写 | `expression/current-timestamp/precision`，不收任意 SQL |

文字 `CURRENT_TIMESTAMP` 仍是文本文字量，不能凭内容自动切换表达式。数字文字量、布尔文字量和二进制文字量使用独立 valueType；数字保留十进制字符串，二进制使用明确十六进制输入。显示值时标注类别，不能把真假 NULL 或默认值空态都显示为空白。

现存非首批表达式与 opaque 默认值显示完整只读表达式和原因。用户不修改时保留原片段；能否主动移除或改成受控类型由能力决定，不能让表单自动清空未知默认值。服务器规范化后的 DEFAULT NULL 明确标注“服务器当前定义”，不声称知道最初是否手写 DEFAULT。选择 NOT NULL 与 DEFAULT NULL 等不兼容组合应由共享模型校验，不能偷偷纠正用户输入。

## 4. 删除、位次与多行计划

删除使用独立动作“标记删除字段”，整行保留原定义与删除标记，可撤销。明确说明“应用后该列数据可能永久丢失；事务回滚不能作为恢复方法”。删除最后一列或涉及受保护依赖时不能形成有效计划；不自动删除关联索引或外键。

位置使用“保持位置／第一列／指定字段之后／最后一列”。位置引用使用原 columnRef 或新增 clientKey，列表可显示本次重命名后的名称，但不将名称当身份。删除字段不能成为 AFTER 目标，自引用、位置环、重命名交换环和重复补丁在预览前显示定位到具体行的错误；不会以临时列名或多条 DDL 绕过。

草稿摘要显示新增、删除、修改字段数及每项具体属性。首批仅接受可合并为一条 ALTER 的组合；无法合并时整批明确拒绝，不暗中分步。删除、收缩类型、收紧 NOT NULL 与重命名的风险分别显示，并说明外部视图、触发器、例程及应用 SQL 的依赖检查不能证明完整，要求维护者核对。

## 5. 不可编辑 SQL 预览与最终确认

“生成字段差异预览”发送受控 patches，不发送 SQL。预览重新核对原快照后返回单条计划与执行令牌；界面展示固定目标、具体差异、完整原定义、完整生成 SQL、风险和检查范围。SQL 编辑器必须 readOnly，不提供“修改 SQL 后继续应用”按钮。

预览明确显示：

- “执行前会重新核对目标和原定义；外部工具仍可能在重核与 ALTER 之间修改结构。请在维护窗口执行，暂停并行结构变更。”
- “DDL 可能隐式提交。取消和事务回滚不能撤销已经完成的结构修改。”
- “本功能使用独立结构连接，不提交或回滚查询标签中的事务。”

标准模式不宣传强锁或原子 compare-and-swap，不额外要求 LOCK TABLES 权限。未实现和验证的可选强锁模式不显示为可选择功能。

风险确认按 `requiredAcknowledgements` 映射成独立勾选项，删除数据等高风险操作不能只依赖一个笼统确认。最终按钮文案“确认执行本次字段差异”。确认时同步取得入口锁，捕获当前 previewToken 与确认集合；apply 只传 token、确认和 taskId，不传 target、SQL 或 patches。

修改草稿、目标配置变化、过期、关闭再开以及第一次 apply 尝试均使旧 token 不可再执行。草稿变化先返回编辑态，再明确请求新的预览，不自动发起新 DDL。过期提示“预览已过期，请重新核对并生成预览”，前端时间只是提示，后端仍是最终校验者。

## 6. 运行、取消、失败与核验状态

任务阶段按真实结构化进度显示连接、读取、重核、执行、核验和释放。读取／预览等待期间提供取消请求；应用期间也可取消，但持续显示“已请求取消，等待服务器结果和资源释放”。窗口关闭和后台标签互斥不能早于真实 finally 收尾。

执行按钮在 busy 时保持原节点、位置与语义并禁用；取消按钮在独立位置，不能让双击确认的第二击命中取消。最终同步锁持续到 IPC 与必要收尾结束，不能只依靠 React busy 状态或按钮禁用。

失败摘要使用结构化 `ddlSubmitted/ddlCompleted/definitionVerified/outcome`，不从错误字符串或 Promise rejected 猜测未执行：

| 状态 | 用户可见结果与后续动作 |
| --- | --- |
| not-sent | “尚未投递 DDL”，保留草稿；重新读取与预览需明确操作 |
| failed | 显示服务器失败和实际阶段；不能统一保证结构完全未变化，应核对当前定义 |
| succeeded 且已核验 | 显示完成及服务器警告；提供前后定义只读对比 |
| DDL 已完成、核验失败 | 明确“结构修改已完成，结果核验失败”，不显示“未提交”或建议原样重试 |
| unknown | 明确“无法确定服务器最终状态”，保留目标、预览 SQL 与进度，提供“重新读取实际定义”用于核对，不自动重放 |
| 释放失败 | 与 DDL 结果分别显示清理错误，不能宣称资源已经释放 |

已执行成功后的晚取消不能显示为撤销。重读定义不重新执行旧 SQL；读取后由用户决定是否重新调整草稿和预览。旧令牌不会复活，也不生成反向 DDL 作为自动恢复。

## 7. 目标保护、模态与隐私

连接配置修订、实际目标、服务器能力或原定义变化时，显示“目标或结构已变化，本次预览不能应用”。保持旧草稿供查看，明确读取最新定义不会自动把旧 patch 套到新列；若后续提供手工调整／重新定位，应逐项展示映射与冲突，再由用户重新预览。

get/preview 的迟到响应按本弹窗代次忽略，不能覆盖新目标或用户新草稿。apply 一经发出禁止切目标；连接配置变更由主进程保护，不通过关闭其他标签绕过保护。任务真正结束前保留父级资源计数，关闭弹窗不会失去取消与收尾责任。

模态内 Ctrl/Cmd+Enter 和 Ctrl/Cmd+S 不执行后台 SQL、不保存后台查询。输入框 Enter 仅在明确表单规则内生效，不暗中确认最终 DDL。Escape 在空闲时执行关闭规则；busy 时不绕过任务释放。只读定义和预览编辑器不能注册执行回调。

完整 DDL、默认值、注释与补丁不写任务历史、全局 settings 或自动诊断日志。任务摘要只显示阶段、目标与结果，错误按纯文本呈现。当前弹窗可保留前后定义供核对，关闭后按令牌生命周期清理。

## 8. 组件与验收分工

未来前端文件建议：`ColumnPatchDialog.tsx` 管生命周期与固定目标；`ColumnPatchEditor.tsx` 管受控属性和四类默认值；`columnPatchDrafts.ts` 管稳定行身份、差异消除、预算及预览失效；独立中文 locale/CSS。入口只涉及 TableTab、Sidebar 和 App，原 SchemaDialog 保持既有独立路径。具体共享类型落盘后再接组件，不先以自定义 any 或任意 SQL 适配占位。

纯前端验收覆盖：默认值五个结果与“不修改”区别；原型同名列；多行差异消除；位置引用、删除与重命名冲突；只读属性原因；超预算拒绝而不截断；修改后令牌失效；最后同步锁与迟到响应保护。

真实 UI 必须通过读取数据库定义与实际省略字段 INSERT 的值验收，不只检查 SQL 字符串：普通字段在复杂表旁仍可编辑；空文本、文本 NULL、SQL NULL、移除 DEFAULT 与受控时间表达式可辨；预览零写；原未改属性与约束保留；删除确认、双击单次执行、模态快捷键隔离；并发结构或连接配置变化拒绝；取消／断线／已执行但核验失败按真实状态显示；独立结构操作不影响原查询事务与表页草稿。

五库能力与保留语义由后端独立 fixture 验证后提供给 UI。未获实库证据的属性不在界面宣称可编辑；只读 SQL 查看只是辅助核对，不能代替首批字段差异编辑完成。

## 9. 当前前端准备进度

已新增 `ColumnPatchDialog`、纯草稿 helper、中文 locale/CSS 与独立单元，并接入侧栏数据表和表页两个真实入口。适配器使用实际 schema.columns 命令、query.cancel 和 TaskEvent.columnPatch，不在客户端生成 DDL 或模拟成功；固定目标并接受调用方提供的配置代次。强制卸载的取消／释放错误通过必须提供的 `onCleanupError` 回调交回工作台。重读、关闭、卸载和迟到响应同时释放对应 snapshot 与 preview，失败不会把已失效令牌恢复为可执行。

当前组件采用后端确认的 `editableType` 初始化受控类型，未知 nullable 明确显示未确定，不作可空推断。时间精度清空实际删除可选键，遵守严格 JSON 补丁预算。ENUM/SET 元素分页面编辑，保留完整数组；预览仍按共享预算校验全部元素，不静默截断。令牌释放失败保留退休令牌供明确重试清理，旧令牌不会重新变为可执行。

字段草稿与编辑器未应用状态已参与原生退出确认；打开和最终应用前检查同目标全部表页草稿及活动任务。应用结果只通知精确目标表页，无草稿且空闲时可刷新；未知或核验失败仅标过期，不能自动放弃草稿或重放 DDL。表页加载计数覆盖两路元数据／数据读取实际收尾，迟到代次不能误清另一项任务。

目前只完成静态类型检查和纯单元；运行源码接入尚未经构建、真实 GUI 与完整五库执行验收，不能称 O01 已实现发布。
