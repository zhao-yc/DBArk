# D04 整行 JSON 编辑

0.13已公开，源码、本机NSIS、主分支及固定标签三平台、公开归档及安装分别验收，适用范围见实际记录。本批补充当前页普通表记录的整行输入，继续共用网格草稿、完整旧值、一次性预览和提交。0.12只读整行JSON仍保持独立的显示格式，不能当作输入、导入或恢复文件。

## 输入及数据正确性

显式选择“整行编辑”后，按字段缩进显示`DBArk-record-input`、`version:1`及完整`fields`条目。普通条目包含精确`name`、`mode`、`text`；`text/json/binary/null/default`沿用原字段编辑语义。大整数、DECIMAL和微秒时间不经JavaScript Number；JSON列原文放在text字符串内，保留原文中的重复成员和数字token。未修改的实际number/boolean仍保留原类型。

生成列和超过单字段展开预算的值使用`{name,locked:true}`，不复制或截断原值。字段可以重排，但集合必须完整、精确且无重复；未知或遗漏字段、额外属性、非法模式、锁定项改写都整体拒绝。所有条目验证后才一次合并原`DraftRow.data`，不改`original`。失败保留完整原文和原页面草稿。

输入格式先由独立固定策略完成词法扫描、拒绝所有对象的重复成员，再允许JSON解码；嵌套在text字符串中的JSON列原文不会被去重。整行原文和最终转义后UTF-8均不超过2MiB，深度16、节点32768、每容器4096项，元数据名称总长度1MiB。单字段原有262144代码单元及2MiB稀疏输入预算不放宽；0.12单JSON字段解析仍保持独立262144字节/代码单元、深度64和8192节点预算。初始缩进空白也纳入最终字节计费，超限不发布部分格式。

## 控制器与界面

控制器只持有字段Map或整行原文之一，互斥variant决定dirty和暂存来源。非法原文仍是未暂存输入；切行、切模式、收起和单元格入口使用原留在/放弃/暂存三选守卫。刷新、排序和翻页保留原整页丢弃确认；隐藏标签和原生退出继续使用同一全局dirty状态。整行textarea的迟到输入事件先比捕获的draft引用，再核对当前目标、连接修订、代次、元数据、UUID、整行对象及data/original引用、删除和插入状态，不能写到后续新行。只读展示切换保留原字段Map及展开状态；删除后撤销重新捕获整行身份，不沿用旧输入。

界面只暂存本页草稿，没有新增IPC、会话、数据库写接口或持久化结构。实际写入仍明确生成SQL预览、确认一次性提交；并发旧值冲突由原引擎整批回滚，不恢复旧预览的重放机会。无可靠键、视图、非InnoDB、已删除、过期或忙碌状态维持只读。

## 验收

候选模型阶段212项离线、实际接入初版正式1620项单元通过；补多行排版后正式1621项、80文件和类型检查通过。首轮新增界面6过1失败：夹具直接读取超出既有256KiB整行预算的服务器值，页面正确拒绝且尚未进入本功能。改为从真实网格形成本地大值草稿，不放宽服务器预算，补字段到整行及原生刷新守卫后8/8通过；原始结果、失败截图及修正分别保留。多行和生命周期修正版重新构建及执行原九项矩阵，未沿用旧字节的通过记录。

覆盖完整格式校验、原型和Unicode名称、精确类型、NULL/DEFAULT/HEX、生成列、大值锁定、原值身份、零自动IPC、网格共享草稿、隐藏标签、退出、刷新、真实提交和冲突回滚。多行版八项实际通过后，新增生命周期检查实际复现切回表单丢失展开输入的问题，修正并增加删除撤销的行对象身份门，正式1622单元及类型通过；原九项在run18新构建上五基线45次通过，资源独立核零。原完整108项首轮107过1失败，修正普通字段删除时保留只读展开状态后重新构建，再通过原九项五基线45次及完整108项。修正版主分支三平台源码及实际安装各22离线通过、86私网跳过，本机NSIS原完整108项、实际卸载及独立资源核对通过；固定标签三平台及公开归档、原108项安装也已分别完成，未外推macOS私网。当前事实和未验范围见[整行编辑验收](../../tests/integration/acceptance-d04-record-input-20261014.md)。
