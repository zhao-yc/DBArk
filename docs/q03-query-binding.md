# Q03 保存查询来源绑定

## 行为与入口

查询工具栏或原生保存菜单打开“保存查询”。已绑定标签有两个明确操作：“保存到原查询”和“另存为新查询”；未绑定标签只能另存。更新允许修改名称和 SQL，原记录 ID 不变；另存由主进程生成全新 ID，原记录不变，当前标签转而关联新记录。

从保存查询分页列表和本地搜索打开时，仍创建随机的新查询标签；同一来源可以有多个独立会话。打开不执行原文，不替换已有标签、结果或事务。历史和普通新建查询保持未绑定；SQL 文件打开另建未绑定标签并继承已知库、无库或未知上下文，文件保存不修改查询库。

## 来源与冲突边界

标签 sourceBinding 仅保存源 ID、所见原始 JSON 的 SHA-256、来源连接 ID、公开路由配置摘要以及默认库类别，不保存原 SQL 副本、搜索条件或凭据。连接摘要不读取密码、私钥或证书内容；显示名称、颜色和分组不参与身份，路由及配置默认库参与身份。

更新在既有 SQLite mutate 事务内重新核对原文摘要、记录来源、来源连接当前身份和工作标签的默认库。源被删除、另一标签已修改、替代连接打开、连接删除/改目标，或默认库状态改变，均明确拒绝，允许用户另存自己的草稿。不会自动重读后覆盖，不恢复被删源记录，不重放写操作。

默认库分为显式已知库、显式无库、未知和遗留四类，类别之间不自动等价。未建立会话的遗留来源保持遗留字段；执行后协议状态变为显式上下文时，更新旧遗留记录会要求另存。这是当前保守边界，未提供隐式来源迁移或强制覆盖按钮。

## 持久化、预算与兼容性

绑定随查询标签保存到原 settings 快照，成功保存后推进摘要并等待恢复状态落盘；记录已成功而恢复状态保存失败时，明确报告该区别。重启恢复同一绑定并继续 CAS；关闭标签一起移除绑定，不另建孤立来源表。搜索选项不进入绑定结构，严格 schema 拒绝额外字段。

`queries.read` 保留既有所见摘要读取保护并返回来源绑定。新增 `queries.create` / `queries.updateSource` 经过共享类型、预加载白名单、严格校验和主进程本地存储；SQL 最多 2000 万 UTF-16 单元，记录沿用 128 MiB 原文预算，写入沿用原子文件替换及内存回退。SQL 原文作为字符串保存，数值、微秒日期、NULL 和二进制字面量不经解析转换。

旧 `queries.save` IPC 继续兼容新建，已有 ID 更新明确拒绝，防止绕过摘要保护。内部 LocalStore.saveQuery 保留给现有迁移/测试等可信调用，生产界面使用新命令。既有分页及搜索的陈旧原文夹具已改为读取当前绑定并通过 queries.updateSource 模拟另一编辑者修改。
