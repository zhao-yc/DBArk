# D06 页内查找替换与表列偏好

此为 0.6.0 开发批次，0.5.0 发布标签保持独立。接口与首批实现已接入，实际桌面、安装和公开产物结果以 [D06 验收记录](../../tests/integration/acceptance-p0-grid-preferences-20261014.md) 逐项追加，不将单元通过视为实库通过。

## 当前页和草稿

查找仅扫描当前已加载页的可见列，按行顺序和可见列顺序导航，包含尚未提交的草稿，排除待删除行。不调用服务器查询、自动翻页或扫描全库；需要跨页匹配时显式打开已有服务器筛选。

文字使用完整自有原值，支持字面匹配、大小写、整格和列范围。NULL、未填写 DEFAULT 与文字 `NULL` 分开，数字字符串不经过数值转换，二进制不借展示预览参与文字匹配。位置由当前行 ID 和真实列名重新计算，通过 DataGrid 的 `scrollToCell` 与 `setActivePosition` 到达未渲染行及远列，保留虚拟化。

Ctrl/Cmd+F/H 限于数据网格活动态，在输入框、单元格编辑器或模态内不捕获后台快捷键；明确打开查找后将焦点移到对应查找或替换控件，避免后续文字误入网格编辑。

## 替换边界

首批仅对可写 InnoDB 表、可靠非空唯一键及非生成 CHAR、VARCHAR、TEXT 字符串字段执行文字替换。JSON、数字、日期、ENUM、SET、NULL、DEFAULT 和二进制不做文字替换。替换值按字面保存，`$&` 等字符不是插值；大小写匹配使用原字符串的位置，避免折叠后偏移错误。

预览持有页面代次、元数据及可靠键签名、所有受影响行的原始值和当前草稿。最后确认先整批复核，再一次更新目标草稿；任一行、状态、类型、列范围或代次失配均拒绝全部变更。`original` 和其它字段不变，没有数据库写请求。最终 SQL 预览和集中提交仍由既有引擎执行，并用完整旧值检测数据库并发修改、冲突时整批回滚。

查找词最多 512 字符、替换词 4096 字符；扫描和替换计划使用 16 MiB UTF-8 预算、最多 50000 次匹配。预览先逐字段计量 JSON 转义、二进制和原始/当前行快照，再分配完整计划；其它未搜索的大字段也不能绕过预算。超限明确拒绝，不能静默截断后应用不同的计划。展示最多前 50 格，但确认应用已核验的完整计划。

## 列模型与持久化

列顺序、显隐和宽度构成一个共享列模型，用于网格、查找、勾选行复制和矩阵粘贴。选择列固定，至少保留一列数据；隐藏主键只改变展示，完整行、旧值和可靠键仍参与提交。隐藏列排序继续保留，活动列隐藏或重排后按身份重新定位，不能沿用数字坐标写入另一列。

布局即时生效，手动保存后才声明已持久化；未保存和保存失败持续显示，保存期间占用标签。异步加载和保存携带生命周期及修订号，旧响应不能覆盖新布局或标记新变更已保存。恢复默认仅重置精确目标的列布局，不刷新数据、不丢草稿。

表结构变化先按精确列名调和。只有当前和保存名称的大小写分组都唯一时才映射大小写变化；歧义不猜。删除列移除、新列按服务器顺序追加，不能丢失真实列或把原型同名字段作为对象继承属性。

`table.preferences.get/save/reset` 由主进程直接处理，不建立数据库连接、不保存 SQL、筛选值、行数据或凭据。配置 schema 3 新增 `table_preferences`，使用连接 ID、数据库、表三个精确字符串作为复合主键，标识符按数据绑定而非 SQL 拼接。

最多 500 个表、每表 4096 列、单条 512 KiB、总量 8 MiB，字节统计包含身份字段和 JSON；宽度为 64～2000 的整数。更新扣除原记录预算，满额仍可更新、缩小和重置。目标或账号、启用中的 SSH 目标/身份变化与连接保存同事务清理偏好；外观和认证轮换保留，新 ID 默认空偏好，删除连接同事务清理。

schema 2→3 只新增偏好表，旧配置、查询、片段、历史、任务和加密凭据保持。磁盘失败恢复内存与原文件，不能在后续保存时偷偷提交失败改动。0.3～0.5 的 schema 2 客户端拒读新版，回退使用升级前完整用户目录备份，不能强改版本号或删除新库。

## 后续保留

单处替换、用户正则、二进制搜索、其它数据类型批量替换及新驱动的列语义继续按完整目标推进。当前页工具不替代全库搜索，也不代表所有 Navicat 网格能力已完成。原生离线 IPC、真实表格 UI、完整安装及公开文件验收分别记录。
