# 完整INSERT暂存从open开始的归属保护

修复基线为 `aad0ddd22b4bfae417964386e28fe7188ccedaa2`。原实现只在 `prepare(true)` 后保存身份；在首次prepare之前取消，或sync失败时，清理按路径直接删除，可能删除已被外部替换的文件。

## 生命周期与身份

完整INSERT通过 `AtomicFile.create` 最后一个可选参数启用整段保护。取得open返回的句柄后，先绑定句柄提供的清理能力，再检查迟到取消；不把清理权推迟到prepare。

原生适配器在open后捕获原句柄的dev/ino、大小及mtime/ctime。dev/ino始终固定；只有本适配器的真实write成功回执才能推进大小和时间代次。写入前后、sync前后、close前核原句柄和目录项，观察到漂移后永久撤销删除能力。外层包装器在write等待回包期间改写文件，不会被下一次清理重新认领。

所有失败路径仍尝试关闭原句柄。归属明确时删除本任务partial；当前目录项或修改代次未知时保留路径，抛出清理未确认。不会追查或删除被移动到别处的原文件。重复abort仍抛出原清理错误，不把第二次调用伪报为资源已清零。创建或初始化与清理同时失败时保留两者及原cause。

prepare后的原完整身份、父目录、编码、样例、120秒TTL与最终确认约束不变。最后确认仍只发布同一暂存，不增加数据库执行、连接、全量文件回读或文件扫描。

## IO兼容边界

- `AtomicFileIO` 形状不变；`WritableFile` 增加可选 `protectOwnership(): Promise<() => Promise<void>>`，返回绑定原句柄及原路径的清理能力。
- 原生IO实现该能力；包装原生IO的适配器须透传此方法，例如保留 `{...file}`。完整INSERT遇到缺失能力的自定义IO会在查询开始前拒绝，关闭已取得句柄并保留未知目录项。
- 原CSV、JSON、快照SQL与其它AtomicFile调用不启用新参数，不强制旧自定义IO增加能力，也不改变原输出、预算和提交合同。
- 原生open增加一次句柄stat。只有启用保护的完整INSERT在文件写入／sync／close边界增加身份检查；检查随文件写入次数增长，不逐行全量读文件。未进行百万行性能验收，不能把定向功能验证当作吞吐证明。
- 这是等待边界上的身份保护，不声称普通lstat加路径删除具有跨进程原子CAS保证。无法证明的状态选择保留和报错。

## 验证边界

新增真实文件测试覆盖原两条P1输入、open回包迟到取消／外部替换、无能力IO、prepare前与write回包期间同inode改写、正常取消／写／sync失败、关闭持续未知、短写修改代次推进、prepare后取消／改写／替换和旧调用。

原只读审查目录、脚本及两条真实文件红例保持不变。另在本修复clone的忽略缓存复制原独审同输入，记录abort的清理未知错误：修复后原目标、外来文件和另处原句柄文件均保留，正常prepare后取消仅清理自有partial。缓存有原脚本SHA校验、原输入副本及回放证据。

未运行GUI、Electron、真实DB、SSH、Docker、端口、剪贴板、CI或旧1556范围。原生用户验收和跨平台性能验证不包含在本修复中。
