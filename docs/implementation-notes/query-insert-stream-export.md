# 完整查询结果的流式INSERT导出首片

本片从固定基线 `581cce8d3a6baec87d06ab475805a45d94eca179` 开发。Root选择的合同为：用户明确启动一次新执行，完整结果逐行暂存，展示来自同一暂存内容的真实INSERT样例与完整行数、编码、字节、准确目标，最后确认发布。执行前没有本次真实数据，不用旧结果、伪造样例或额外查询冒充预览。

## 产品入口和允许范围

工作台“新执行并完整导出”增加INSERT SQL格式。原CSV、JSON、CSV ZIP及已返回结果快照SQL导出保留各自合同。INSERT路径不提前清空原查询结果、选中固定结果或当前结果序号；新任务摘要及真实样例留在导出窗口，成功发布也不替换原查询结果。

用户必须明确填写目标库、表和按结果列位置排列的全部字段，一行一个字段。名称沿原结果SQL导出的保守规则验证：1至64个BMP字符，拒绝控制符、反斜线、尾部空白、无效Unicode；目标字段按NFC/小写检查唯一。只按位置映射，不解析SQL猜来源，不读目标结构。

首片只接受整个脚本恰好一个行结果集，且实际列数与明确映射相同。空行集也须有真实列头与结束帧。任何状态结果、第二个行结果集、字段数不符、未知类型或协议结果串流均失败并保原目标。因此状态先行的脚本、CALL最终状态包、多结果脚本不在支持范围。发现不匹配时SQL可能已经执行；停止后续语句，不自动重试、回滚或重放。

## 单次执行、真实预览和最终发布

1. 打开窗口、填写映射、选择文件不执行查询。只展示已捕获的原SQL文本，参数识别仍沿既有显式入口。
2. 用户确认这是一次新执行。原 `query.exportStream` 在同一查询会话使用原脚本扫描器、参数和协议策略执行一次；不另开导出连接，不追加预览/计数查询。
3. 复用原 `consumeQueryFrames` 背压及原子IO，逐行生成INSERT。没有将全部行聚合到Main或renderer。原工作台有界预览仍受200行/全体16MiB预算约束；INSERT真实样例单独最多20行、4MiB。
4. 全脚本结束后，暂存内容同步并关闭句柄，保留原目标锁和原会话互斥，任务进入 `awaiting-confirmation`。此时原目标不变，任务仍为运行中，不能显示最终导出完成。
5. UI展示真实样例、完整行数、实际已同步文件字节、编码、全部准确目标字段。用户输入准确的库.表名并确认发布；单独同步锁防双击。
6. 新 `query.confirmInsertExport` 只同步消费原任务的发布令牌，唤醒原写入器。该阶段不调用withSession、不建立连接、不执行SQL或重取结果。原原子替换成功后才报告 `fileCommitted: true`。

样例由同一逐行生成器在成功写入后收集，不重新序列化旧结果，也不重新读取数据库。正常小行样例为文件开头的真实行；大行超出样例预算时可跳过该行选后续真实行。非空结果若无任何能放入4MiB的完整样例，则拒绝发布，保原目标；不截断INSERT行伪造预览。

待确认最多120秒，期间继续占用原任务及查询会话，以避免其它操作改变会话、事务或取消命令代次。Main最多接受8个活动INSERT任务，超限在新SQL发送前拒绝。TTL、取消、关闭会话、断开连接、客户端正常退出、文档导航/崩溃都会唤醒原链并走精确收尾；原物理会话在暂存后断开时，最终确认也不能重连或继续发布。取消文件不会撤销此前已执行SQL。

## 归属和能力边界

Main复用 `ColumnsMainCapabilities` 的真实Electron窗口、主frame、文档代次捕获。SQL保存令牌单独标记 `query-insert-export`，不能借用普通SQL、CSV、快照SQL令牌或客户端路径；目标令牌在第一个路径等待前一次消费。最终发布令牌绑定准确任务、原文档、原会话对象、配置修订、全部目标映射及编码；错误目标、重复确认、旧文档和已过期令牌被拒绝。

路径授权等待后、样例发布前与最终确认入口同步核验原归属。导航、渲染崩溃及销毁主动取消本片尚未确认的任务；任务收尾后的迟到样例直接丢弃，不能复活终态。原配置保存先保留既有检查，失败的保存尝试不会先取消任务；成功保存后撤销本片旧修订能力。

最终确认在Main同步消费，随后投递原utility任务，没有中间异步选择/重连。该授权之后文档消失不被包装为文件回滚；仍以原子替换的真实结果为准。替换前用户取消仍会检查，替换开始后的晚取消不伪报撤销。

暂存关闭前从原句柄取得设备/文件编号、字节数和纳秒修改代次，目录项须匹配；发布前复核同一暂存身份及原目标父目录的归一化身份。暂存被改写/替换时拒绝发布，也不删除已不匹配的外来文件。正常失败和取消只清理本任务自己的暂存文件。没有声称该元数据校验能抵御具有任意本机权限的攻击者，也不提供跨utility异常退出的自动恢复。

## 精度与预算

- NULL直接写NULL；空串、文本、BIGINT/DECIMAL和时间原字符串写UTF-8十六进制；BLOB/BIT等二进制写X十六进制。文本含NUL、反斜线、引号及补充平面Unicode不会改写转义。
- 普通整数要求安全整数；LONGLONG/DECIMAL要求精确字符串，日期时间要求原始字符串。FLOAT/DOUBLE要求有限IEEE数值；严格文本模式仍沿原协议层拒绝FLOAT/DOUBLE，显式二进制模式沿原准备/诊断确认策略，不失败回退。
- 拒绝负零、非有限数、孤立代理项、非规范Base64、缺失字段、几何/未知协议类型及不匹配的值表示。未读取目标表，不能保证用户指定字段的类型转换、字符集、约束或以后导入条件可接受。
- 沿原队列最多8行/1MiB、字段8MiB、原始/生成行16MiB、文件10GiB预算；十六进制大分配前检查输出行预算。单个驱动协议行仍需先由驱动接收，不能宣称逐字节读取大字段或恒定零分配。
- 实际文件支持UTF-8、UTF-16LE和GB18030，沿原无损编码验证、短写完整消费、同步和替换模型。样例及SQL正文不写任务历史；历史仍只记录原模板和原执行归属。
