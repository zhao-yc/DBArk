# 0.19后续：完整复制源的只读补取契约（待ROOT批准）

本文件是方案，不是已实现能力。当前修正只安全支持完整已加载原行；不把INVISIBLE未加载值当DEFAULT，也不以长期禁用INVISIBLE宣称完整复制目标完成。本次不修改共享IPC、主进程、表页读取或0.18冻结输入。

## 现有接口核查

| 接口/实现 | 可复用部分 | 无法直接作为完整复制源的原因 |
| --- | --- | --- |
| `table.page`，`engine/index.ts:262`、`buildPageSql`、`readPage` | 可靠键、目录、精确驱动类型、FLOAT/DOUBLE二进制读取、行预算 | SQL为SELECT星号，没有投影参数，INVISIBLE不返回；无服务器源对象租约。加键过滤仍不能补出缺列。 |
| `table.referencePage`、`buildReferencePageSql` | 已验证的外键元组及精确值 | 目标须由实际外键解析，不是任意当前行定位；仍是SELECT星号。 |
| `search.recordRead`，`engine/dataSearchRecords.ts` | 引擎签发引用、服务器/物理表/定义身份、可靠键及TIMESTAMP精度条件、只读事务/MDL、取消和预算框架 | 只能读取先前搜索产生的引用，结果是只读展示字段，LEFT截至最多4096字符并附truncated，不能把投影文本/二进制作为可写原值，也不能拿当前表页随意造recordRef。 |
| `query.executeParameterized`、私有查询会话 | 值参数、显式列SELECT、精确整数字符串等基础能力 | 通用SQL执行接口，本身不绑定表页original、物理表身份/定义及异步草稿版本；主进程还会建立执行历史。没有完整复制源的受限契约，不能直接把展示结果转可写。 |
| 文件导出内部显式投影 | 按列目录点名读取、FLOAT/DOUBLE二进制协议、序列化基础 | 目标是文件与整表流，不是当前行定位和异步追加草稿。可抽取内部读取能力，不借导出接口绕路。 |

结论：通用接口能发起读取，但没有可直接复用、同时满足完整值/源身份/并发守卫的现成表页接口。建议新增受限只读补取能力，并复用内部精确读取与源身份框架；不要修改普通SQL结果为可写，也不无条件把所有表页SELECT星号改成全列。

## 建议输入与结果

推荐“加载时签发来源引用，显式复制时补取”。仅依赖客户端表名/DDL和键值，不能证明页面加载后服务器同名对象未被替换。

1. `table.page`可附加可选`copySource: { pageRef, rowRefs, expiresAt, unavailableReason? }`。来源必须在与页面SELECT相同的受控只读事务及MDL内核身份、读行并签发；不能在页面读完后给同名对象补签。`rowRefs`与本次返回行严格对齐，由引擎随机签发，渲染器生成本地行UUID时保存映射。拿不到证明就不发引用，不影响普通查看和已完整值的本地复制；仅缺失值补取不可用。来源存储绑定连接修订、目标、实例/物理表身份、规范DDL、已加载字段指纹、可靠原始键及必要TIMESTAMP精度。
2. 新只读命令`table.copySourceRead`输入`{ connectionId, taskId: UUID, pageRef: UUID, rowRef: UUID }`，不接收SQL、任意列名单、渲染器自造键或“已证明安全”标志。所有目标/投影/定位键只来自引擎来源租约与新鲜目录。引擎严格校验connection/page/row归属和有效期。
3. 结果建议为`{ target, sourceRef, metadataDigest, readAt, complete: true, values: DataRow }`。显式按可信列目录读取完整普通字段及定位所需字段，验证返回字段/数量，NULL用自有值表示；完整性或权限不足只能返回固定不可用分类/抛错，不返回部分值冒充complete，不使用LEFT截断或DEFAULT补洞。值保持原CellValue精度和独立二进制包装。
4. 新释放命令按`connectionId/pageRef`幂等释放本页租约。翻页、刷新、关页、连接保存/关闭和引擎退出主动失效；短TTL再作兜底，不让旧引用跨连接或新页面继续使用。

这会涉及TablePage/CommandMap/严格参数校验、主进程路由与引擎来源生命周期，须由ROOT批准共享接口后独立实现，不能仅在TableTab拼接隐藏SQL。

## 定位、身份及并发守卫

- 使用独立受控只读会话与事务；持有本次目标MDL后，新核源租约的实例身份、物理InnoDB表ID、规范DDL和会话模式，再读取。复用`prepareDataSearchRecord`/`recordDefinitionDigest`思想；拿不到足够身份证明或所需SELECT权限就明确不可用，不扩大授权，不只凭同名/DDL猜测。
- 可靠键来自加载时引擎实际解码的原始键，绝不使用已编辑的data键。原生索引谓词结合精确表示校验，LIMIT 2，必须恰好一行。FLOAT/DOUBLE用原表页二进制协议；BIT、二进制、TIMESTAMP和时区沿现有精确读取/绑定规则单独验，不把所有键转普通文本。零行、重复、键不支持、过期或身份不符均拒绝。
- 校验当前完整行中原已加载字段与加载时指纹一致，避免混合旧可见值和并发修改后的缺失值。未曾加载的INVISIBLE值以本次只读快照为准，界面明确读取时点；复制仍可叠加本页已显式暂存的修改。
- 前端在第一个await前占用单次补取门，捕获target/connectionVersion、加载代次、metadata、源UUID、original/data引用及完整草稿数组；返回时全部重核，任何编辑、选择变更、导航、连接修订、取消或输入变化都丢弃旧回包。只有同一次请求可追加一次深复制草稿，不改变当前选择/布局，不调用apply，不自动重试。
- 原可靠键本身若未加载，不能按行号、OFFSET或显示值猜测；需要先选择已加载且已证明非空唯一的替代键，或另行受控刷新显式投影以取得可靠键。不能让普通只读/无键表借此可写。

## 初始预算与验收

建议沿现有边界收紧：每次一行、最多1024列、原始行256KiB、序列化结果512KiB、可靠键8KiB、DDL 2MiB；超限明确拒绝，不截断。来源缓存最多4000行引用/32MiB、TTL 5分钟，每连接最多4页、同一来源最多1笔在途补取，总体执行15秒并支持原query.cancel。预算数字须在ROOT批准时确定，均不代表本次已新增限制。

后续必须验证：INVISIBLE非默认值/NULL/大整数/DECIMAL/微秒/二进制精确复制；SELECT权限拒绝、不可读缺列、生成/自增省略；并发更新、删除、同名表重建、连接改指向、DDL变更、超时/取消/迟到；复制与SQL预览阶段零数据库写入，最终仍走原集中预览和事务提交。当前缺失值拒绝只是安全基础，不替代上述完整能力。
