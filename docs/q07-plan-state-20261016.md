## 变更与边界

保存、另存以及 CAS 冲突处理会短暂设置查询标签的 `busy`。原结果分支同时要求 `!busy`，导致已有 `ExplainPlanView` 被卸载，局部模式、选中节点和展开状态随之丢失。

本次只移除计划分支的 `!busy` 条件。同一结果仍使用原组件类型、`task.current` key 和计划对象，保存期间保持挂载。传给查看器的 `busy` 属性继续禁用“获取文本计划”，保存函数继续只调用来源读取和保存接口，不执行 SQL、不新建会话、不替换结果。

实际新执行仍由 `runQuery` 清空 `outcome`、生成新任务号并等待新结果；流式导出也沿用原生命周期。本次没有增加结果缓存或修改这些函数。选择固定结果的既有切换行为保持原样。
