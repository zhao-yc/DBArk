# PostgreSQL 跨库数据搜索和只读记录定位

从「工具 → 全库搜索」选择 PostgreSQL 连接，再点「搜索数据」。依次读取数据库、对象和字段，勾选要扫描的范围。多个库、模式及对象可以放在同一轮。目录按当前连接角色的权限显示可访问的对象和字段。

- 普通表、分区表、普通视图和物化视图可选。视图须明确勾选允许，搜索视图可能执行其定义中的函数。临时对象和外部表没有独立搜索入口。
- 支持包含、整个值、前缀、服务器正则和 NULL。普通字段使用服务器文本表示，BYTEA 使用大写 HEX。匹配完整值，结果仅显示最多 128 字符和完整表示的字符数。NULL 与空字符串分别处理。
- 每个字段块最多 16 列，以独立只读连接执行。直接扫描表时遵守当前角色的列权限及行级安全策略。服务器游标逐段取行，前端逐批确认，每批最多 50 处命中或 128 KiB。单轮最多 1,000 处命中或 32 MiB，触及限制会显示未完成范围。[PostgreSQL 游标](https://www.postgresql.org/docs/18/sql-declare.html)
- 表命中具有可读主键及可核对的行版本时，可双击打开只读记录。详情显示当块字段和主键，并聚焦命中字段。校验包括关系身份、主键原文和实际行版本。旧命中在记录更新或移除后失效。定位引用在内存中保留最多 5 分钟。[PostgreSQL 系统列](https://www.postgresql.org/docs/18/ddl-system-columns.html)

应用先锁定搜索关系，再复核目录中的对象种类，避免把已变为视图的旧表范围当成普通表执行。取消、关闭或退出会收尾本次专用连接。正文搜索和数据搜索共用入口，数据搜索条件、匹配值及记录定位引用仅保留在内存。[PostgreSQL PREPARE](https://www.postgresql.org/docs/18/sql-prepare.html)

## 2026-11-07 验收

- Windows 测试虚拟机不可达，本轮使用 macOS arm64 源码 Electron。实库使用 Server-200 的一次性 PostgreSQL 18.6 和 MySQL 8.4.11，分别经回环转发访问。
- PostgreSQL 源码桌面专项 1 项通过。跨库返回 56 处匹配，覆盖长字段尾部、百分号和下划线原文、非 BMP 字符、实际 RLS、NULL 和 BYTEA。只读详情保留主键 `9007199254740993` 的精度并聚焦命中字段。外部更新后，旧命中被拒绝。
- 视图须明确授权。直接将视图声明为表的请求在执行前被拒绝，视图内用于探测的函数未触发。暂停在首批 50 处命中时，分别验证取消和正常退出，服务器搜索会话均归零。查询历史无新增。
- MySQL 8.4.11 数据搜索原生回归 7 项通过。列权限用例保留原断言，先校验回环转发后方的独占容器身份，再创建临时账号和库。原有内存表单回放验证临时密码仅在会话中保存。
- PostgreSQL 和 MySQL 的测试容器及回环转发均已清理。Windows、安装包、其他 PostgreSQL 版本及分区表与物化视图的桌面专项待验。
- Node.js 与 SQLite 原生运行时检查、严格类型检查和源码构建通过。最终独立全量 Vitest 通过 1,361 个文件、27,659 项，10 项按环境条件跳过。与桌面实库并行的前一轮触发 SQLite 百万行导出的原有 5 秒超时，独立复验通过，超时门槛保持原值。
