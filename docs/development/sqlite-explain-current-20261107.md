# SQLite 当前语句执行计划

在多语句草稿中把光标放到目标 SQL，选择「更多查询操作 → 执行与分析 → 查看当前语句执行计划」。结果可按树形、表格或 SQLite 原文查看。点击「定位计划原语句」，编辑器会选中本次计划对应的 SQL。改动草稿后，计划仍可阅读，旧定位停用。

主进程按完整草稿和 UTF-16 光标定位原语句，只向原 SQLite 会话发送一条 `EXPLAIN QUERY PLAN` 包装。原 SQL 和相邻语句均不执行，计划也不计入执行历史。临时表、事务和标签语句超时沿用原会话。空白、无效边界及不支持的语句在投递前拒绝。支持 SELECT、VALUES、WITH 和原计划允许的 DML，仍受连接权限约束。计划反映优化器选择。[SQLite 执行计划说明](https://sqlite.org/eqp.html)

现有「执行计划」继续使用选区或单条草稿，也支持定位原语句。原生计划错误按本次输入的原始范围定位。源码验收覆盖含 CRLF 和非 BMP 字符的脚本，定位不依赖搜索相同 SQL。

## 验收范围

- Node.js 24.17.0 的运行时检查、严格类型检查、源码构建和 170 项相关测试通过。扩大回归的 95 项通过及 72 项失败与变更前基线逐项一致。
- macOS arm64 Electron 源码验证原当前语句和执行计划两个专项。SQLite 原生链只收到当前 DML 的计划包装。独立磁盘读取核对目标及相邻语句均未写入，原历史未增加。点击定位选择准确范围且不产生数据库请求，编辑后旧定位停用。
- 专项用 Monaco API 设置合成脚本，菜单和定位按钮通过真实窗口操作。临时数据库和配置由本例独占，进程正常退出并核对清理。
- Windows 测试会话不可达，本轮使用 macOS arm64。Windows、macOS x86_64 运行和安装包待验。增量暂未正式发布。
