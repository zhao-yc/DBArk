# SQLite 已有 UNIQUE 约束：声明读取与增改删编译

后续进展：[组合计划与独立事务链](sqlite-unique-engine-20261102.md)已接入结构化 UNIQUE 预览和独立 writer，本文件保留声明编译阶段当时的边界与验收。编辑区仍继续开发。

## 本轮实现与边界

已有表索引管理中的 `origin=u` 自动索引仍然只读，不能直接 DROP 或用显式索引替代原约束。本轮先实现 UNIQUE 声明模型和准确源代码编译，后续沿原重建能力链接入独立事务和编辑区；**本轮尚无新用户入口或 UNIQUE 写权限**。主键、外键及字段的已有入口保持。

- `src/shared/sqliteTableUnique.ts`：有界结构模型，包含可选约束名、行内／表级位置、有序字段、各项排序规则和 ASC／DESC，以及五种显式冲突策略。新行内 UNIQUE 只能选择一列，继承原列排序规则，不能夹带方向或独立 COLLATE；普通字段和已有生成字段均可选择。
- `src/shared/sqliteTableRebuildPlan.ts`：`inspectSqliteTableUniques` 读取真实声明；`compileSqliteTableUniques` 接受新增、准确序号／原 SQL 绑定的替换与移除，返回新表声明和变更计数。未修改的字段、主外键、默认值、检查表达式和表选项保持原文；移除表级声明时保留边界注释。
- 按原声明跨度编号，不按约束名或自动索引编号定位。SQLite 可将相同 UNIQUE 声明合并到一个自动索引；重名、重复字段、连续命名标记及括号包围的旧字段仍按原声明独立读取。修改原重复字段设计时，新模型要求用户明确列出不重复字段，不能自动去重旧声明。
- 新约束名与本批新增名及全部保留约束名按 ASCII 大小写检查冲突；只排除明确删除的准确跨度，同批 UNIQUE 名称交换可编译。新字段必须准确匹配原目录，不靠大小写猜测。标识符独立引用，不接受函数、任意表达式、部分索引条件或 DDL 正文。
- 2MiB 总预算按序列化 UTF-8 计算；Zod 读取属性前拒绝访问器、循环、非预期原型、符号、非枚举字段及稀疏数组。最多 128 项编辑、1024 条原声明和 1024 个字段项。

SQLite 的 UNIQUE 允许多条约束，NULL 与其它 NULL 彼此不同，表级 UNIQUE 仅支持字段引用，详见 [SQLite 官方表约束说明](https://www.sqlite.org/lang_createtable.html#unique_constraints)。这些规则同时由独立 native 内存库核对，不能以编译器输出自证可提交。

## 后续接入要求

1. 在原受限重建契约中增加结构化 UNIQUE 补丁和准确计数标记；Main 与 Runtime 独立重算，源目录及原声明完整绑定。最终主键／外键／UNIQUE 名称互换应按整批移除及最终命名空间核对，不按中间声明位置重新编号。
2. 双候选完整复制及四次真实 typed 比较仍必需。`INSERT OR ABORT` 不能被声明的 IGNORE／REPLACE 绕过；遇重复行应整批回滚，不允许跳行或替换原行。
3. 自动索引可能合并及重新编号，不能用旧名字或条数证明原声明保留。核对完整最终表 SQL、native 自动索引完整键及对应候选，保留显式索引 SQL／键；非目标对象和数据保护不放宽。
4. UNIQUE 修改可能使其它表的父键失效，即使子表为空也要完整检查最终全部外键，未知或不合格时回滚；不能沿用旧违规数量放行新关系。ROWID、主键、序列、原字节和精度保持原保护。
5. 在原编辑区提供原文、增改删、局部草稿、全批 SQL 和唯一性／父键风险确认；只读、过期、忙态、来源失效及真实事务终态沿原路径处理，不增加隐藏写入口或自动重放。
