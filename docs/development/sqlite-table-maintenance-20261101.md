# SQLite 表清空与删除开发记录

本轮继续补齐常用表生命周期操作，暂不正式发布。左树／对象列表右键菜单和 SQLite 表页“更多 → 危险操作”提供清空、删除；不增加行内按钮，保持 31px 行高。打开菜单或表单不自动读取、执行 SQL 或打开查询会话。

## 用户流程

- 只支持已保存并授权文件连接的 `main` 普通表，包含 STRICT、WITHOUT ROWID；视图、虚拟表、影子表、系统表不能借此入口执行。只读连接可以检查和预览，不能提交。
- 显式读取字段、原表 SQL、全库有界对象定义和外键动作，显示精确十进制字符串行数。目录不截断；完整定义超限明确拒绝。所有触发器和外键均可核对，不将文本包含表名当作可靠依赖分析。
- 清空使用原生 `DELETE FROM`，作用于执行时的全部当前行，包含预览之后新增的数据。预览行数只是只读观察值，回执中的“执行前行数”才来自写锁内 COUNT；不把它称为精确删除量或所有级联变化量。
- 默认不主动重置自增序列，触发器仍按原定义执行。仅实际 AUTOINCREMENT 表允许明确选择重置；第二条语句只绑定准确原表名，SQL 预览旁显示只读参数，不拼接用户值。[SQLite 自增说明](https://www.sqlite.org/autoinc.html)
- 删除使用原生 `DROP TABLE`，删除原表及附属索引／触发器，不自动删除其他对象定义。目标表的删除触发器不会执行，外键动作和关联表触发器可能造成级联删改；引用视图及保留外键可能失效，必须明确接受并自行处理。[SQLite DROP TABLE](https://www.sqlite.org/lang_droptable.html)、[DELETE](https://www.sqlite.org/lang_delete.html)
- 每项风险确认默认不选，输入准确 `main.表名` 且完成本次预览要求的完整确认集合才可提交。更改重置选项会撤销预览、风险勾选和确认；不执行写入试运行。

## 执行与页面保护

新增 `sqlite.tableMaintenance.inspect/preview/apply/release`，由 Main 绑定原文档、连接修订及物理连接代次。目录和预览各限 64 份／64MiB／5 分钟，单目录最多 4096 个对象、1024 个字段、10000 条外键信息及 2MiB，超限不签发能力。在途只读预检用 pin 持有原预算；自然过期不伪造取消，显式释放能撤销准确迟到结果。

检查和预览使用独立只读 utility 的 BEGIN／ROLLBACK。提交使用独立 BEGIN IMMEDIATE，写锁内重核原文件身份、schema_version、完整定义、rootpage、字段、索引与外键目录，再观察真实当前行数。外键保护保持开启，不关闭 foreign_keys、不改 writable_schema、不借查询标签事务或 TEMP，不把全表行值载入客户端。

清空后必须为空；触发器 IGNORE／重新插入导致目标非空时整批回滚，外键违规只允许减少，不能增加。删除后必须准确移除原表及附属对象，其他定义原样保留；不以 DROP 后无法完成的全局外键检查宣称依赖有效。AUTO_VACUUM 合法移动其他根页不被误当作另一次删表。最终只有真实 COMMIT ACK 与后验通过才确认成功；原请求、取消应答、关闭协议及退出继续由原资源账本观察，未知结果不自动重放。

触发器／外键可能影响其他表，因此保护同连接 `main` 的所有表页：隐藏数据草稿、布局草稿及活动任务均不可覆盖。成功清空只自动刷新准确原表，其他同库页失效后等待明确刷新；成功删除只关闭干净的准确原表页。未知删除保留页并退役旧名称链接，未知清空不自动读取；原查询 SQL、事务及异库标签保持。

任务只持久原目标、动作、随机操作编号、语句数、真实执行前行数及 ACK。SQL、关联定义、确认内容、文件路径和预览能力不随任务恢复；收尾／本地记录警告与真实提交／回滚事实分别展示。

## 原生事务与资源独审

`native-maintenance-05-results/report.json` 新增四例单次通过：clear 31.4 秒、reset 20.6 秒、drop 19.7 秒、rollback 34.5 秒。每例仍为原 120 秒、1 worker、0 retry，trace／video／screenshot 均关闭。

- clear：真实只读连接可检查／预览，完成全部确认仍不能 apply；仅编辑本例连接转 RW 后继续。预览观察为 3 行，合成独立 writer 新增后写锁内 `actualBeforeRows=4`；最终原表为空，序列保留写前真实高水位 24（原观察时为 23），目标删除触发器和子表级联触发器按原定义执行。没有把观察行数伪装成删除量。
- reset：唯一两句为目标 DELETE 与固定 `DELETE FROM main.sqlite_sequence WHERE name=?`，原 driver 帧参数严格等于准确原表名；2／2 语句真实提交，最终序列记录消失。其他对象定义和独立 control 原值保持。
- drop：1／1 语句真实提交，原表及附属索引／触发器消失；child 级联清空并产生子表触发器审计，目标删除触发器没有执行。引用 view 与 FK 定义原样保留，view 的真实读取失败被如实记录，control 仍可打开；未宣称全库依赖有效。
- rollback：旧目录变化为 BEGIN IMMEDIATE 后零维护 SQL 的真实 ROLLBACK，尚未取得写锁后的行数就不补造该值；重新检查后的 DELETE 中途 ABORT，同样真实回滚，已观察执行前 3 行、完成语句 0。原行、64 位整数／BLOB／NULL、child、audit、序列和外部后来增加的定义均完整保留。

`root-native-audit.json` 逐项核三次 COMMIT、两次 ROLLBACK 的原请求、statementEnd 事务退出 ACK、close／closed／closeAck 与实际 worker exit；每份任务最小事实与原回执一致，SQL／确认输入／路径未被加到任务概要。仅展开 More 菜单的前后 frames／operations 完全相同，重启只增加准确只读分页任务，不重放维护或用户 SQL。

`native-*-06-results/` 六组相关回归为重命名 3、字段 2、索引 2、工作区 1、表格编辑 1、建表 1，共 10 例单次通过。与新增四例合计 14 例、零失败／跳过／重试；`root-native-all-audit.json` 核 28 次正常应用退出、14 个不同准确临时目录在本机 stat 不存在。五份既有核对脚本和重命名核对分别读取本轮原件，保留各自观察范围；未保留的逐 worker 帧不冒称已观察。系统 chooser 仅定向本例 owned 文件，不计为原生系统文件框输入；重启首读早于观察器，不补造其逐帧证据。
