# PostgreSQL 表页精确计数与跳页

在表或视图的记录页点击「精确计数」，查看当前筛选匹配的总记录数。点击「末页」则读取匹配范围的最后一页。在「跳转页码」输入正整数并回车或点击「跳页」，按当前已应用的每页行数读取指定页。记录表单也可使用这些分页按钮。 [Navicat 分页手册](https://www.navicat.com/manual/online_manual/en/navicat_18/win_manual/data_rdbms.html#use-navigation-bar)

计数与对应记录在同一只读事务中读取，沿用相同的筛选和排序。总数以数据库快照为准，按十进制原文显示在这次读取的表页。普通翻页读取记录，需要新的总数时可再次计数。若当前偏移已超出范围，精确计数会回到现有末页。零条匹配显示空首页。

已暂存的记录草稿继续绑定各自原页，未暂存的表单输入须先暂存或放弃。末页超出当前最大浏览偏移时，可缩小筛选范围。读取失败时可在原表页查看错误并重试。

## 验证记录

- macOS arm64，Node.js 24.17.0。运行时检查、严格类型检查、构建和 3 项定向单测通过。构建仍报告部分打包分块超过 500 kB。
- macOS 完整单元回归覆盖 1,331 个测试文件，27,485 项通过，10 项 Windows 专用测试按平台跳过。
- Server-200 隔离 PostgreSQL 18 实库通过 5 项集成测试，覆盖筛选和排序后的计数与末页、空结果、当前页越界回退，以及跨页草稿保留。
- macOS Electron 原生窗口通过 1 条端到端测试，共记录 75 项检查。分页检查包括精确计数、末页记录、非法页码、已应用分页大小、跳页及返回首页。截图记录第 3 页及匹配总数。两轮实库均独立复核了原表记录及零剩余客户端连接，随后清理了本轮容器。
- WIN11-TEST 不可达，本轮在 macOS 验收。Windows、安装包及其他 PostgreSQL 版本待验。
