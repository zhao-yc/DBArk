# PostgreSQL 复制当前记录

在网格中选中一条记录，或在记录表单中定位该记录，再点击「复制当前记录」。新增表单带入原记录和已暂存的字段值，包括空字符串、SQL NULL、十六进制字节和精确数值文本。取消表单保留原记录和原草稿。已标记删除的行不可复制。

生成列、标识列和目录确认依赖序列的默认列初始省略，由数据库生成或应用默认值。普通主键及唯一字段会带入，暂存前可修改。将某字段切到「使用 DEFAULT」可让数据库提供默认值。原字段不完整或超出草稿预算时，复制会给出错误。 [PostgreSQL 目录依赖说明](https://www.postgresql.org/docs/current/catalog-pg-depend.html)

点击「加入草稿」只新增一条本机草稿，可在草稿区撤销。副本和原记录草稿分别处理，最后用「预览记录修改」确认实际写入。

## 验证记录

- macOS arm64 使用 Node.js 24.17.0，运行时、严格类型检查、构建和 4 项定向单测通过。
- 完整单元回归覆盖 1,337 个测试文件，27,499 项通过，10 项 Windows 专用测试按平台跳过。
- Server-200 隔离 PostgreSQL 18 实库 5 项回归通过。复制保留暂存文本、空串、字节和精确数值，副本获得新的标识值、两个序列默认值和生成字段。确认前后分别回读，原记录保持。
- macOS Electron 复制记录专项通过 4 项检查。网格取消保留原草稿，记录表单产生独立副本，撤销原更新后确认新增，最终读回原记录与副本。截图、正常退出、零剩余连接及临时配置清理均已复核。首轮表树定位同时匹配同名序列，改为完整表名后按原门槛复验。原失败日志、配置及已停止的隔离库保留。
- macOS Electron 原工作区长回归首次在第 69 项后达到 120 秒上限。确认进程结束、零连接并停止隔离库后，使用新的隔离实例以相同的 120 秒、零重试配置复验，79 项检查通过。复核原数据、窗口退出、临时配置清理及零剩余连接，超时原件保留。
- WIN11-TEST 不可达，本轮使用 macOS。Windows、安装包及其他 PostgreSQL 版本待验。
