# PostgreSQL 函数和过程调用草稿

从对象树或「函数」列表打开目标重载的定义，选择「生成调用草稿」。应用会在原连接和数据库打开一个查询标签页。需要输入值时，使用查询工具栏的「执行位置参数」，按 `$1`、`$2` 等位置填写值。无输入值的草稿可以直接执行。生成草稿和打开参数窗口均不执行例程。

标量函数生成 `SELECT`，集合函数生成 `SELECT * FROM`，过程生成 `CALL`。过程的 `OUT` 参数使用带类型的 `NULL`，`INOUT` 参数需要填写输入值。可变参数以 `VARIADIC` 传入一个数组，按 PostgreSQL 数组文本格式填写，例如 `{1,2,3}`。执行结果显示在原查询结果区。[PostgreSQL CALL](https://www.postgresql.org/docs/18/sql-call.html)

草稿完整限定 schema、例程名和参数类型，所有输入参数均显式绑定，包括声明了默认值的参数。PostgreSQL 会按运行时目录解析调用。多态输入、需要补写列定义的匿名集合记录以及缺少执行权限时，定义窗口不生成草稿，可从查询标签自行构造调用。[PostgreSQL 函数重载解析](https://www.postgresql.org/docs/18/typeconv-func.html)

## 验证

- macOS 上 Node.js 24.17.0 运行时检查、类型检查和源码构建通过。
- macOS 完整单元回归共 1,326 个文件，27,455 项通过，10 项 Windows 系统 tar 用例跳过。
- Server-200 独占 PostgreSQL 18 实库回归 5 项通过。覆盖同名重载、带双引号的例程名、自定义类型、集合结果、数组可变参数、过程 OUT 和 INOUT、精确大整数、仅有执行权限的角色、带 SQL 符号的原文绑定和生成草稿零写入。多态输入及无列定义的匿名集合记录保持手动处理。
- macOS 原生窗口回归通过，共 60 项观察。从函数列表打开重载定义并生成草稿，确认生成前后执行历史一致，显式绑定后回读文本原值及过程 OUT。独立连接确认过程只写入一次，并核对原表数据、零剩余连接、成功轮次的测试容器和临时配置清理。
- 首轮因目录刷新时对象树菜单卸载而停止。改用函数列表入口后重跑通过，首轮日志和临时配置保留，首轮独占容器已停止并保留。
- Windows 测试虚拟机不可达，本轮切换到 macOS。Windows、两平台安装包和较早 PostgreSQL 版本待验证。
