# SQLite 已有表重命名开发记录

本轮继续按常用功能优先补齐对象管理，暂不正式发布。入口是左树／中央对象列表的右键菜单，以及 SQLite 表页“更多 → 设计与结构 → 重命名 SQLite 表”；左树仍为 31px，打开菜单不发数据库请求。

## 行为与边界

- 支持 `main` 内普通表，包括 STRICT、WITHOUT ROWID；视图、虚拟表、影子表和系统表拒绝。只读连接可以查看及预览，不能执行。
- 读取完整字段、原表 SQL 和有界完整关联目录，输入新名称后预览唯一原生 `ALTER TABLE main."原名" RENAME TO "新名"`，准确输入 `main.原名` 才提交。名称按标识符引用，不能变成第二条语句。
- 由 SQLite 原生维护索引、触发器、视图及外键引用，不用字符串替换重写定义；不能解析的依赖保留原生失败并整批回滚。仅大小写不同的改名遵循引擎原生拒绝，不伪造成功。[SQLite ALTER TABLE](https://www.sqlite.org/lang_altertable.html)
- 用户查询 SQL 不改写。准确提交且定义后验通过后关闭原／新名的干净表页，用新标签编号打开新名；同库其他表页的结构快照失效，不自动覆盖草稿。原表／新名的隐藏数据草稿、布局草稿和运行任务均保护。
- 收藏沿原协调逻辑迁移，冲突或保存失败明确提示。导航身份仅为当前连接内的有界证明：真实 COMMIT 与完整后目录确认后，允许同一表往返改名；外部结构变化、未知结果、断开连接或容量淘汰会切断推断，旧同名链接不能借新回包自动复活。

## 执行与资源归属

新增 `sqlite.tableRename.inspect/preview/apply/release`。Main 捕获原文档、连接配置修订与物理连接代次，输入合同严格校验；目录和预览分别限 64 份／64MiB／5 分钟，单目录完整依赖最多 4096 项、字段 1024 项、2MiB。超限明确失败，不用截断目录确认安全。

独立只读 utility 的 BEGIN／ROLLBACK 负责检查及预览；提交使用另一独立写连接的 BEGIN IMMEDIATE，写锁内再次比较原文件身份、schema_version、原定义、rootpage、字段、索引及全库依赖。原生改名后核对字段、表选项、对象 rootpage、索引明细、外键定义和违规集合，以及原自增水位，全部通过才发送一次 COMMIT；不加载全表行值。外键保护开启，legacy_alter_table 关闭，不借用查询标签的事务或 TEMP。

目录自然过期不假取消在途预检，显式释放能准确撤权。原任务、取消应答、close／closeAck 和进程退出均观察原承诺；COMMIT 已可能发送后不杀进程假报回滚。ACK 丢失保未知并锁原批，迟到真实 ACK 不被失败消息降级，不自动重放。

任务只保存原目标、随机操作编号、DDL 语句数及提交／回滚事实；不保存新表名、SQL、字段值、文件路径或导航身份。恢复任务不能恢复目录、预览或写入能力。
