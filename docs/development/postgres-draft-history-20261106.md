# PostgreSQL 草稿撤销与重做

在 PostgreSQL 表页暂存单格、记录表单、网格粘贴、查找替换、删除或批量操作后，使用「撤销上一步」和「重做下一步」检查各步草稿。批量填充、批量编辑、批量复制、批量删除和模板新增均按整批处理。撤销后开始新的编辑会清除原重做路径。

网格获得焦点时可使用 `Ctrl/⌘+Z`、`Ctrl/⌘+Shift+Z` 或 Windows 的 `Ctrl+Y`。输入框继续使用自己的编辑历史。打开表单或预览期间，表页草稿历史暂不可操作。

翻页优先保留当前草稿的原页，再保留附近历史步骤引用的快照。总共最多保留 16 个原页，草稿历史最多 100 步或 8 MiB。失效原页会截断相应的历史路径。重做沿用原页、原记录和当时暂存的字段值。确认提交前，引擎仍会复核原记录和表结构。

历史在当前标签内存中保存。成功提交、刷新、更换筛选或排序时会清空。数据库明确回滚且原草稿仍有效时，可继续撤销、重做或修正。若提交终态待核对，先检查数据库实际记录。

## 验证记录

- macOS arm64，Node.js 24.17.0。运行时检查、严格类型检查、构建和 45 项定向单测通过。
- 完整单元回归覆盖 1,338 个文件，27,513 项通过，10 项 Windows 专用测试按平台跳过。
- Server-200 隔离 PostgreSQL 18 的 5 项实库回归通过。历史原页可恢复并用于原行预览，其他标签的令牌及无效令牌被忽略。结构变化时，当前草稿的原页核对会阻止换页，只有历史依赖的原页会失效并允许继续浏览。验收库均核对零连接后清理。
- macOS Electron 源码窗口完成 15 项检查。测试用按钮和网格快捷键撤销两页草稿至空，在第三页重做原来两步。独立连接核对暂存、撤销、重做和 SQL 预览期间原行保持，明确确认后仅前两行更新。原生窗口正常退出并清理临时配置。
- 首轮窗口用例在刷新回包前选中了旧网格，后续按钮等待超时。保留原件，补充等待新页投影生效的条件后复验通过，原产品行为断言及超时门槛保持。首轮隔离库也在独立读回、确认零连接后清理。
- WIN11-TEST 不可达，本轮使用 macOS。Windows、安装包和其他 PostgreSQL 版本待验。
