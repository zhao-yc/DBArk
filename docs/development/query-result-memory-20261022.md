# 查询结果暂存整理

## 使用

在查询结果的筛选说明条点击“暂存整理”，保存一份完整筛选表达式和多列排序。再次执行查询后，点击“应用暂存整理”替换当前整理；可用“撤销结果整理”一次恢复应用前状态，“重做结果整理”恢复整份配置。

暂存包括嵌套 AND／OR、停用条件的原文、列表／区间／通配符，以及排序优先级、NULL 位置和忽略大小写。应用只处理已经返回的行，空匹配保持空；暂存、应用、丢弃均不发送 SQL。

每个查询标签仅保留一个内存槽，新暂存替换旧暂存。切换活动标签、新查询或切换结果不会自动应用或清除槽；关闭标签、删除或修改所属连接后清除。点击“丢弃暂存整理”可主动清除，即使后续查询失败或只返回无列状态包。条件值留在该标签内存，未持久化到 SQLite 或系统剪贴板。

## 校验与原子性

保存先通过正式筛选和排序控制器，复制其规范配置。只包含完整、有序的列键／名称／类型、可见列和整理配置；不包含 SQL、行、选择、撤销历史或执行来源声明。元数据和配置共用 128 Ki UTF-16 字符预算，超限整份拒绝，原暂存保持；副本深冻结。

应用须核对完整字段与可见列顺序，重名字段仍按唯一键区分。元数据不同禁用应用；元数据相同但新数据类型、值或工作预算不适用时，完整试算失败，原视图、暂存和撤销游标保持。筛选与排序同时成功后才发布新控制器并记录一整步，清除旧选择和行详情。原样应用保留既有重做分支。

配置复用由用户显式选择当前结果，不推断 SQL、默认库或会话相同；普通执行行为保持。该入口覆盖标签内临时复用，命名方案、跨标签共享、导入导出和跨启动持久化仍待实现。

## 验证

`query-result-memory.test.ts` 覆盖复制、容量、元数据、精确值、空匹配和失败原子性；`query-result-history.test.ts` 覆盖控制器 owner 交接；真实 React 的 `query-result-sort-ui.test.tsx` 覆盖重执行后手动应用、导出、NULL／大小写／停用条件、连接 ABA、旧回调及失败后丢弃。

`query-result-sort-case-live.ts` 在原单条真实常量 SELECT 流程内增加暂存、两列排序／NULL／大小写、清空、应用、一次撤销重做及丢弃，原 SQL 数量、精确 CSV／JSON 期待、正常退出和观察流关闭门保持。跨新查询复用单独由 React RAM 端口覆盖，不将同一结果的原生检查外推为新查询原生验收。实际运行结果另行记录，暂不发布。
