# SQLite 当前页查找与文本替换

开发源码为可写 SQLite 表格增加当前页查找与替换，使用独立、有硬性期限的浏览器 Worker。只读表页继续使用原“查找结果”，不授予替换资格。原始查询结果仍只读；本增量不新增 IPC、数据库任务或配置格式。

## 使用方式

1. 在可写表页从“更多 → 显示与导航”点击“查找当前 SQLite 页”，或使用 Ctrl/Cmd+F；Ctrl/Cmd+H 和原生“编辑 → 替换”打开替换输入。
2. 选择文字、NULL 或 DEFAULT，可限制字段、区分大小写及整格匹配。仅扫描已加载页与本地新增草稿，待删除行不参与，不补读其它页。
3. 上一处／下一处会真实滚入准确单元格并高亮当前范围；输入 Enter 导航时保留查找输入焦点。同格多处、Unicode 和零宽匹配独立定位。
4. 正则及捕获组替换必须明确启用并执行，键入后不会自动运行。可停止查找。
5. “预览替换当前匹配／全部匹配”展示前10项原文和新文，计数对应完整范围。明确暂存后只改本地草稿，一次撤销／重做；查询及替换输入保留，新草稿签发新来源重新查找。
6. 最终写库仍须原 SQL 预览、准确风险确认和集中提交。数据冲突按原整批回滚处理，未知写入不重放。

数字、二进制及生成值可以查找其准确原文表示，不转换64位整数或其它类型。只有实际 TEXT、非生成且非待删除格可替换；NULL、DEFAULT、整数、REAL、BLOB 不会被自动转成文字。暂存文字最终仍受目标列亲和性及数据库约束影响。

## 来源与资源保护

- 原页、行数组、每行与值数组身份、完整原值、元数据、选项修订及Worker代次绑定计划。公开摘要冻结、具体补丁私有，原计划一次消费；错误／迟到回包、克隆计划或选项ABA不能恢复资格。
- 原面板预览只认自己的准确DOM标记。用户取消预览后，旧暂存回调即使还在原页也不能写草稿。暂存后的旧Portal仅获一次准确退休交接授权；下一次父提交即收回。
- 定位等待父级提交票据后再调用真实RDG滚动／活动格接口；修改查询、停止或来源失效清除旧高亮，不用隐藏按钮或伪造选择。
- 单次Worker执行上限1500ms、启动8000ms，输入完整16MiB、匹配50,000处及内存128MiB，不截断成部分计划。正则在Worker中执行，停止／销毁／错误均调用准确Worker的terminate。
- 新文字单值65,536个UTF-16单位、最多500行／10,000补丁及2MiB输入，并再次核最终全部草稿差异预算。原大TEXT可查找并缩短，原文不套用新输入长度门。同值无改动不制造撤销步骤或废弃旧预览。
