# SQLite 已有字段类型与默认值编辑

开发源码已将声明编译、私有数据库连接接入 Main、IPC 和实际界面。现有普通 `main` 表可以累计修改字段声明类型与默认值，预览完整 SQL 后，以独立事务确认整批重建。R02 仍为部分完成；列重排、主外键约束设计和更多数据库能力继续开发，不生成正式 Release。

## 使用入口

从左树或对象浏览列表的表右键菜单、表页“更多”，选择“修改 SQLite 字段类型与默认值…”。原“管理 SQLite 字段”继续提供原生 ALTER 新增、改名、删除和版本支持的可空性操作。

1. 明确读取原字段、原 CREATE TABLE、准确行身份、自增高水位及完整 main 对象目录。只读连接可以设计和预览，不能提交。
2. 选择字段，分别保持原定义或修改类型／默认值；切换字段保留累计修改。空类型明确移除声明类型，不是清空输入后保持原样。
3. 默认值支持移除 DEFAULT、DEFAULT NULL、文本、64 位整数、有限实数、Hex 二进制及三个 CURRENT 时钟值。原任意表达式可以保持；本入口不接受新的任意 SQL 默认表达式，生成列不能设置 DEFAULT。
4. 预览全部执行 SQL、字段映射和风险，逐项确认并输入准确的 `main.表名` 后提交。修改默认值不回填旧行；未来写入使用原生 SQLite 默认值规则。

同一连接 main 表页的数据、布局草稿与活动任务会阻止提交。打开或恢复界面不执行 SQL，不改写现有查询正文、不借用查询事务。目录／预览五分钟有效，目标、配置或来源变化后旧能力失效；过期后须明确重新检查，不自动重放写操作。

## 数据与事务保护

公开 IPC 只有 inspect、preview、apply 和 release，接受严格类型补丁及一次性能力，不能透传文件路径、任意 SQL 或私有候选名。Main 保留有界原目录并独立重新生成计划；writer 在独立连接、写锁内核对文件身份、配置代次和完整结构，依照[SQLite 官方重建顺序](https://www.sqlite.org/lang_altertable.html#making_other_kinds_of_table_schema_changes)执行，不使用 writable_schema。

全部普通字段及真实 rowid 显式复制；生成列由 SQLite 重算并核对。候选、移除临时编号前后及最终表共四次完整逐值比较，覆盖全部列、行身份、NULL、TEXT 字节、BLOB、int64 和 REAL 精度。仅真实改类型的字段允许可证明无损的存储类型转换；不能用抽样、总行数或摘要替代原值检查。

原约束、生成表达式、索引和触发器恢复后，再核对全部原定义、其他对象根页、视图、外键及准确 sqlite_sequence 状态。WITHOUT ROWID 外键违规须保留具体子表主键身份，不能仅用 PRAGMA 的空 rowid 或违规条数判定；比较使用[父键亲和性和排序规则](https://www.sqlite.org/foreignkeys.html)。无法证明没有新增违规、值变化或结构变化时整批回滚。

COMMIT／ROLLBACK 仅以真实 ACK 确认；提交可能发送后停止不等于撤销。结果未知时锁住本批并要求核对原库，不重新提交。任务历史仅保留目标、阶段、计数和 ACK，不保存字段、默认值、SQL、私有名称或文件路径。私有连接明确恢复保护标志、关闭 ACK 并退出，资源收尾异常不抹去已确认事务事实。
