本批已完成Windows源码验证：默认新增加三种显式匹配策略，类型、14项关闭回归、560项扩展相关、完整18411通过／1平台跳过和构建通过；六端共30个复合例闭合，MariaDB 11.4因一次连接超时采用前2例加新资源后3例分批证据。严格TLS源码窗口1个复合例完成三轮，原App正常退出并独立核资源。历史失败及未知事实保留，F01仍为部分，暂不发布。

## 入口与边界

表数据页“导入”在默认只新增之外，提供跳过已有、新增或更新、仅更新已有三种策略。选择非默认策略时必须明确选择当前目标的完整可靠主键或唯一键，并完整映射键列；旧请求省略策略仍走原新增路径。SQL／Excel、导入模板和预览不携带策略。

同源重复记录按文件顺序处理，由服务器排序规则判断匹配。UPDATE只主动设置已映射的非所选匹配键列；触发器、ON UPDATE和生成列仍可能改变其它列或键。不使用REPLACE、INSERT IGNORE或任意唯一键的ON DUPLICATE KEY UPDATE；其它唯一键冲突、外键错误、告警和连接异常均拒绝当前批次。

真正跳过的记录只校验匹配键，不读取无用payload；需要写入时逐列保留原无损检查。JSON数字沿用原读取器的十进制token文本，不能因测试将合法VARCHAR文本误判为数字而修改产品语义。

## 实现

`files.importKeys`在独立任务连接读取SHOW CREATE和STATISTICS，返回目标身份、结构摘要及可靠键目录。排除前缀、可空、表达式、生成、不可见／忽略等无法确认可靠的索引。摘要不含统计基数或AUTO_INCREMENT下一值。目录不签发可绕过复核的授权令牌。

执行在原连接建立RR事务，持有目标元数据锁后重新核对结构和所选键，使用完整索引及参数化FOR UPDATE匹配，严格拒绝异常或多行匹配回包。整文件模式仅末尾提交；默认模式每500条已处理源记录（含跳过）提交，实际读到第501条才创建下一批，EOF不产生空事务。提交未知不重放。

连接前登记任务租约，覆盖connecting／running／closing；取消仅针对原编号，迟到建连不能读取文件或发送DML。严格关闭完成后才释放。目录超时撤销原读取，旧回包不恢复失效选择；换来源、映射、目标或导入配置均回到默认策略。

回执区分已确认处理与已确认提交的四类数量，以及本批回滚／提交未知状态。matchedUpdates计数是已确认命中的UPDATE命令，包含no-op；不等于实际变化行数。只有原COMMIT ACK确认后才推进已提交计数，回执缺失或不匹配不能以兼容rows冒充成功。
