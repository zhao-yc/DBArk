# SQLite 已有主键编辑

## 使用方式

在普通 SQLite `main` 表右键选择“修改 SQLite 字段、顺序与主外键…”，再明确读取目录。“SQLite 主键”区显示原主键及准确 SQL，可以新增、修改、标记移除或撤销本地主键草稿。

1. 选择行内单字段或表级复合声明；约束名留空表示匿名。逐项选择准确普通字段，可增加、移除、上移、下移；字段名中的逗号不拆分，生成字段不作为候选。
2. 表级主键可逐字段填写排序规则和选择 ASC／DESC；排序规则留空继承字段规则。行内主键无独立 COLLATE，切换位置不会静默删除输入，需手动调整为合法组合。
3. 冲突策略默认原生 ABORT，也可明确选择 ROLLBACK／FAIL／IGNORE／REPLACE。复制全部现有数据仍使用固定 INSERT OR ABORT，不能用冲突策略跳过或覆盖重复行。
4. 自增仅用于准确 INTEGER 单字段 ROWID 主键。行内 INTEGER DESC 与表级 DESC 的语义不同；新整数主键可能改变物理行号，但全部用户值必须逐项保持，NULL 自动填号会被拒绝。未改自增身份保留准确原序列；新启用或换列按当前键最大值初始化且至少为 0；停用移除目标序列，其他表序列保持。
5. 替换原主键前明确确认已核对原声明；特殊命名、重复字段及括号表达式可能按当前结构规范化。WITHOUT ROWID 不允许标记移除主键，可设计完整替换。
6. 暂存只形成结构草稿，不写数据库。主键、外键、字段类型／默认值及实际列顺序共同预览完整 SQL，核对主键变化、身份／序列及父键风险，准确输入原表名称并逐项确认后提交。只读连接可设计和预览，不能提交。

主外键未暂存输入一次只编辑一项，已暂存草稿可以共存。取消本次输入保留已有草稿；关闭或重新读取需明确放弃草稿。任何输入变化都会撤销旧预览与确认；过期、忙态、连接／原目标变化后旧输入和旧操作不能授权新对象。失败回滚保留草稿且不自动重试，结果未知仍锁定原批。

## 实现边界

界面复用[原组合计划和独立事务](sqlite-primary-key-engine-20261102.md)，不增加任意 SQL、文件路径或数据库执行通道。父窗口统一持有主键表单、局部草稿和来源身份；字段行使用稳定编号，重排和移除后迟到输入不会落到另一行。预览回包的主键变化标记必须与原草稿一致，否则立即释放原能力并禁止提交。

主键暂存允许仍待同批类型或命名修改解决的结构设计，Main 最终独立编译后才签发预览。已有主键时原 SQL 绑定准确声明；主外键名称互换、再移除其他外键均用同批计划校验，不把局部旧名称冲突当作最终结果。

主键改变后，最终全部外键必须可完整检查且没有违规；旧坏关系需先修复或同批明确修复，不能借旧错误或相同条数放行新父键。未修改主键的旧字段／外键路径维持原违规子集规则。提交仍需真实 COMMIT／ROLLBACK 回执及全部精度、定义、索引、生成值、序列和资源核对。
