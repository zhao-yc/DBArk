# PostgreSQL 对象依赖查看

从表、视图或物化视图的结构窗口，或从序列详情，点击「查看依赖」。窗口分别列出引用当前对象的对象，以及当前对象依赖的对象，并显示普通、自动、内部、扩展或分区等依赖类型。字段默认值以所属字段显示，视图的内部返回规则以视图显示。同一视图引用当前表的多个字段时，引用列表只列该视图一次。[PostgreSQL 依赖目录](https://www.postgresql.org/docs/18/catalog-pg-depend.html)

序列删除窗口也可查看依赖，返回后保留原 SQL 预览。依赖窗口只读数据库目录，不执行字段表达式或视图定义。没有 schema 使用权限时，相关对象的名称和类型会被遮蔽。列表省略当前对象自身的行类型和内部存储，并在达到显示预算时提示结果不完整。

窗口展示目录记录的直接依赖。最终删除由 PostgreSQL 实时检查，序列删除继续使用 `RESTRICT`。[PostgreSQL DROP SEQUENCE](https://www.postgresql.org/docs/18/sql-dropsequence.html)

## 验证

- macOS 上 Node.js 24.17.0 运行时检查、类型检查和源码构建通过。
- macOS 完整单元回归共 1,326 个文件，27,451 项通过，10 项 Windows 系统 tar 用例跳过。
- Server-200 独占 PostgreSQL 18 实库回归 5 项通过。验证字段默认值指向序列、表与视图双向引用、同一视图引用多个字段的去重、隐藏 schema 的视图和触发器名称遮蔽、无权访问目标时拒绝、超过 200 项时显示截断状态，以及读取后序列仍未取号。
- 首轮实库发现直接比较带引号的 schema 标识会误遮蔽可见对象，改为解析 schema OID 后复跑通过。
- macOS 原生场景通过，共 52 项观察。验证表与视图的双向入口、返回原结构标签、序列依赖刷新，以及返回序列删除窗口后保留 SQL 预览。
- 独立回读确认序列有两个普通引用，`is_called` 为 `false`。原表数据、零剩余连接、独占容器与临时配置清理均已核对。
- Windows 测试虚拟机连接不可用，本轮在 macOS 验证。Windows、两平台安装包及较早 PostgreSQL 版本待验证。
