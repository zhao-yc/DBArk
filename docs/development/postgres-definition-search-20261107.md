# PostgreSQL 跨库定义正文搜索

从「工具 → 全库搜索」选择已保存的 PostgreSQL 连接，将「搜索内容」切换为「定义正文」。逐行填写最多 32 个数据库名称。选择表、视图、函数或存储过程，再选择包含、前缀、完整正文或服务器正则。

- 表按现有关系目录生成可读的结构文本，包含字段、默认值、生成表达式、约束、索引和表／字段注释。分区表还显示目录返回的分区键或分区边界。
- 普通视图和物化视图包含 PostgreSQL 反编译的查询正文。函数和存储过程使用服务器的反编译定义，并按完整签名区分重载。[PostgreSQL 目录反编译函数](https://www.postgresql.org/docs/18/functions-info.html)
- 搜索及重新打开使用相同的目录文本。它适用于查阅和定位，完整备份另由备份工具生成。触发器、规则、授权、行级策略和序列的定义正文尚未纳入此入口。

每批使用一个数据库的独立短连接，最多检查 10 个对象。单个定义最多 2 MiB，遇到不可读或超限对象会列入失败明细。选择继续时，下一批从已处理位置向后读取。搜索阶段只传回对象身份、字符数和可核对的位置摘要。搜索只读取目录，不读取表数据或执行例程。

打开命中后会重新读取当前定义。正文摘要一致时，可在只读编辑器中用「上一处定义命中」「下一处定义命中」定位。正文变化时显示当前文本并废弃旧高亮。服务器正则以及无法证明位置对应的大小写转换保留命中和正文查看。

## 2026-11-07 验收

- Windows 测试虚拟机不可达。本轮使用 macOS arm64 源码 Electron 和 Server-200 上的一次性 PostgreSQL 18.6 实例。
- 两库范围先报告连接拒绝，获准数据库跨两批返回 16 个命中，包括表注释、普通视图、未填充物化视图、函数和过程。单个超 2 MiB 的函数被记录为失败，后续同类对象继续扫描。独立管理连接确认批次结束后无搜索会话残留。
- 从搜索结果打开表注释并核对第 5 行高亮，外部修改注释后再次打开旧命中，界面显示正文已变化，旧高亮失效。执行历史无新增。首轮测试夹具中的 PL/pgSQL 错误消息误将百分号当作格式占位符，改为设置消息后完整复验通过。
- MySQL 8.4.11 共用名称及正文搜索原生回归 7 项通过。PostgreSQL 和 MySQL 隔离容器及转发均已清理。
- 运行时检查、严格类型检查和源码构建通过。Vitest 通过 1,361 个文件及 27,659 项，10 项按环境条件跳过。Windows、安装包和其他 PostgreSQL 版本待验。
