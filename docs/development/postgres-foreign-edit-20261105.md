# PostgreSQL 普通表外键编辑

从表页或对象菜单打开「查看结构 → 约束 → 编辑外键」。在当前数据库查找被引用表，选择一组有序唯一键，再为每个引用列选择本表列。支持同表自引用和跨 schema 引用。

- 引用候选来自服务器目录。候选可以是主键、唯一约束或合格的独立唯一索引。部分、表达式和可延迟唯一键不进入候选。仅有列级 `REFERENCES` 权限时，必须覆盖完整键列才能选择该键。
- 创建支持复合键、MATCH SIMPLE／FULL、更新与删除时的引用动作，以及延迟检查。勾选「先创建外键，稍后验证已有记录」会发送 `NOT VALID`。新写入仍受外键约束，可在约束页另行执行 `VALIDATE CONSTRAINT`。[PostgreSQL CREATE TABLE](https://www.postgresql.org/docs/18/sql-createtable.html) · [PostgreSQL ALTER TABLE](https://www.postgresql.org/docs/18/sql-altertable.html)
- 同批可创建、改名、验证和删除。先查看实际 SQL，删除还需额外确认。锁定子表后复核其目录和被引用表的候选键，提交前核对实际约束、引用表和索引 OID。晚期失败会回滚整批操作。
- 编辑源表为有管理权限的普通表。候选在预算内返回，可按 schema 或名称缩小范围。时态外键和只对部分列执行 SET NULL／SET DEFAULT 仍可通过 SQL 编辑器配置。

## 验证

- Mac 类型检查、构建和 14 项定向单元测试通过。覆盖映射顺序、SQL 转义、继承外键过滤和同批验证状态。
- Mac 完整单元回归覆盖 1,323 个测试文件，27,417 项通过，10 项 Windows 系统 `tar` 检查按平台跳过。
- Server-200 独占 PostgreSQL 18 实库 5 项通过。覆盖跨 schema 复合外键、仅有列级 REFERENCES 权限的候选、NOT VALID 对新记录的约束、已有坏数据的验证回滚、实际更新级联及删除置空。
- 实库验证同名索引重建会使旧预览失效，锁等待期间被引用表被同名替换会回滚。普通表引用分区父表时，根约束可编辑，PostgreSQL 内部子约束由数据库维护。
- Mac 原生窗口用例 1 项通过，19 个观察点，单 worker、120 秒、零重试且关闭 trace。真实目录选择复合唯一键，创建自引用外键后单独验证和确认删除。原窗口正常退出，独占库及临时配置目录已清理。
- 首轮实库夹具使用了与客户端目录不同的限定名写法，改为两段带引号的名称后复验通过。首轮完整回归期间补入分区用例，旧编译器与新增断言混用导致该项失败，保留原件后以冻结定稿重新运行。
- WIN11-TEST 会话不可达，本轮未派发，按约定在 Mac 验证。Windows 原生窗口和安装包尚待验收。
