# 查询标签内切换默认数据库

## 实际入口

已连接的查询标签在默认库旁提供“切换默认数据库”。打开后读取当前连接可见的数据库目录，选择具体数据库并点击“确认切换”。打开目录、选择及取消均不发送切库命令。未连接且默认库未知时，继续使用已有的重连数据库选择流程。

切换沿用原物理会话，不新建标签、不重连，不修改 SQL 正文、编辑器、选区、Undo 栈、已有结果及已应用的结果筛选和排序。事务和临时表仍属于原会话；已显示结果仍是切换前那次执行的结果。只提供选择非空库，不能用重置会话模拟“清空默认库”。

## 执行和错误边界

- 新命令 `query.databaseSwitch` 仅接受原会话、独立任务编号、单个库名和预期默认库上下文。库名安全引用，不接受 SQL 片段或凭据；不写普通查询历史。
- 整个动作持有原会话互斥锁。可信同库选择直接返回；否则仅投递一次 `USE`。优先使用原命令的新状态包确认实际库；明确收到成功 ACK 但无库名报告时，同锁执行一次固定 `SELECT DATABASE()` 确认。错误、断线及未知 ACK 不自动补发或重连。
- 固定确认属于显式切库动作，可能更新服务器诊断区；普通补全和会话状态读取仍只读缓存。此设计依据 [MySQL USE](https://dev.mysql.com/doc/refman/8.4/en/use.html) 与 [MariaDB USE](https://mariadb.com/docs/server/reference/sql-statements/administrative-sql-statements/use-database) 的会话语义；事务及临时表保持仍需实际验收，不能仅由文档推断。
- 投递前先将恢复上下文持久化为未知，写盘失败零投递。收到真实确认后才保存新库；服务器已确认但本地保存失败时，明确报告两种事实，不重新发送。
- 弹窗绑定原标签、连接修订、会话、模型、正文和选区。来源离开后再恢复也不能复用旧回调。独立任务不会覆盖原结果的执行编号；关闭和取消等待原任务及取消连接收尾。
- 参数暂存及待提交的结果操作在切换开始时撤销。实际库与事务分别读取，未知事务状态不能补写为“已回滚”或“无事务”。
