# MySQL／MariaDB 表数据比较

从「工具 → 比较 MySQL／MariaDB 表数据」分别选择连接、数据库和表。两侧可选同一连接下的两张表，也可选择不同连接。可按同一字段的文本包含条件缩小范围，结果按相同、仅左侧、仅右侧及字段值不同分类。差异可分页并逐列核对原值。

同一连接中的两张 InnoDB 表使用一个只读可重复读快照。跨连接逐侧读取并显示快照可能处于不同时间点。读取使用原生协议保留整数、DECIMAL、浮点、微秒和字节。时间戳以 UTC 对照，NULL、空字符串和整行缺失分别显示。[MySQL 一致性读取](https://dev.mysql.com/doc/refman/8.4/en/innodb-consistent-read.html) · [MariaDB 一致性快照](https://mariadb.com/docs/server/ha-and-performance/standard-replication/enhancements-for-start-transaction-with-consistent-snapshot)

比较要求两侧为有完整主键的 InnoDB 普通表，字段名和声明类型一致，列物理顺序可不同。忽略非 ZEROFILL 整数声明的显示宽度。文本键按精确值匹配，排序规则认定等价的不同字串仍可能分别显示。每侧最多 10,000 行和 8 MiB，超限需缩小范围。当前提供只读比较。

## 验收

- WIN11-TEST 会话不可达，本轮未派发。按既有授权在 macOS arm64、Node.js 24.17.0 验证。Windows 原生窗口、两平台安装包及旧数据库版本待验。
- 严格类型检查和构建通过。全量 1,352 个测试文件、27,578 项通过、10 项跳过。MySQL／MariaDB 原生实库专项通过 1 项，共用比较界面的 PostgreSQL 18.6 原生比较与同步回归通过 1 项。
- Server-200 上使用 MySQL 8.4.11 和 MariaDB 11.4.13 专用容器，应用账号仅授予测试库 SELECT，经 SSH 回环转发。两种数据库的同连接跨库对照均为 28 行相同。跨驱动对照有仅左、仅右各 1 行及 27 行字段不同。
- 窗口核对了 BIGINT UNSIGNED 最大值、18 位小数、相邻 DOUBLE、字节和 NULL／空字符串。不同会话默认时区下，同一时间戳未出现假差异。逐列详情、差异翻页和两侧同一条件筛选通过。视图及非事务表不出现在比较列表，类型不一致和 10,001 行均不产生部分结果。
- 首轮在服务端元数据锁等待期间，连接断开后读取流仍等待。修正后，在测试锁仍持有时确认比较线程退出，窗口收到取消，解锁后可重新比较。两端独立读回保持原值，退出后测试账号连接数均为零，容器与转发均确认释放。
