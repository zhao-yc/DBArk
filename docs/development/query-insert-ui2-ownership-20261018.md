# INSERT UI2所有权准备修正

本片以员工4提交 `2ca0d762b30816e2cd77d1dd15c9ec9b8a6ce101` 为固定基线，读取员工1独审交接及三个原始反例后，只修测试准备中的F1–F4。原独审指出的是本轮验收准备缺口，不能据此声称产品存在文件替换或JSON舍入漏洞。产品、共享fixture、旧测试、依赖、版本和工作流均不修改。

## F1：文件身份来自原句柄

原目标在自有目录内用最初的 `wx+` 写句柄创建、同步并冻结dev/ino、大小和独立SHA-256；pending partial从其最初读句柄冻结同类元组。首次捕获与后续读取都核路径、规范路径、普通单链接文件和句柄身份。发布只消费原partial回执，取消只消费原目标回执，同字节异inode不能通过。

Windows测试发现，持续持有读写句柄会阻塞正常rename。因此捕获并核对原元组后，测试在发布/取消前明确关闭原句柄。后续临时只读句柄仅验证既有冻结元组，不创建新来源回执，不更新原dev/ino。发布路径只能是原partial同目录中预先登记的唯一目标。自有实际文件反例覆盖合法rename、发布后同字节替换、取消后同字节替换以及首次路径与原写句柄不一致；替换时原字节门仍真，新增门拒绝并使原scope永久停链。

## F2：先登记未连接Socket

先分配并登记未连接Socket，再把它交给mysql2，捕获原driver及promise wrapper、登记原connect回调，最后才对原Socket执行connect。Socket、driver、wrapper均只捕获一次；实际peer、thread和同一物理流在ACK时冻结。构造、包装、回调登记、connect或handshake失败都保留已取得的原引用，不分配新句柄续签。

迟到ACK须再次通过原TestInfo期限和sticky scope，超时后只保留原driver观察到的thread线索，不获得新授权。错误通知失败也不能解除墓碑。RAM端口反例验证分配顺序、五类初始化失败、迟到ACK、流/wrapper/thread/peer及关闭状态漂移，真实网络调用为0。

## F3：写前登记与DROP门

首次Socket或数据库DDL之前，原 `wx+` 日记句柄先写入nonce、caseHash、准确库名和四表计划并同步。CREATE DATABASE必须收到原观察连接的成功ACK，之后创建本例nonce标记旁表和邻表；不使用IF EXISTS认领已有库。

DROP之前，必须完成原应用正常退出及确切原PID消失证明，沿原观察流核准确200服务器UUID、版本/系统/大小写模式、唯一标记、完整四表集合及注释、最初SHOW CREATE定义、独立两行源快照、空目标、原邻表，并确认没有触发器、存储过程/函数或事件。任何缺项、额外对象或未知状态都停链，恢复旧快照也不能重新获得清理权。失败finally仅关闭本例已捕获的原文件句柄，不补SQL、不重连、不删除文件或目录。日记有32KiB/48条上限，仅存元数据，不存凭据。

## F4：两行中的JSON大整数

保持业务两行规模，将首行JSON改成原文数值 `9007199254740993`；服务器源快照用CAST保留该数字原文。独立手写SQL预期明确包含 `_utf8mb4 X'39303037313939323534373430393933'`，不经JSON.parse或产品serializer生成答案。纯RAM消费者对照证明精确原文匹配、舍入为 `9007199254740992` 的结果不匹配。

旧 `queryInsertUiLive.ts` 的abc黄金函数和原28项测试原样保留；live仅将新增精确黄金函数导入为原本地函数名。原TestInfo/120秒、sticky、正常退出/PID、两case及保存对话框一次回答边界保持。
