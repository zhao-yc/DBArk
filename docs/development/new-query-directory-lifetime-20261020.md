# 新建查询窗口：阻止关闭后的目录读取

## 实际线索与源码

977c536在WIN11-TEST通过类型和三文件49项定向回归；复用5b1产品源码及109份哈希一致构建后，新实库窗口在执行后审计失败，首次分类为“未许可命令：metadata.databases”。用例正文4104毫秒，另有45000毫秒worker收尾超时；文件未生成，原严格退出未确认。本轮没有修改允许名单，原5b1及977失败分别保留，不能将两次失败归为产品已修复。

该轮原始哈希、实际命令和限制见[审计诊断实证](query-result-audit-first-failure-20261020.md)。后续固定c5936a7仅增加修前RAM反例，已送达原VM会话，不重跑原GUI。

`src/renderer/App.tsx` 的NewQueryDialog effect先建连，回包后读取库目录；原cleanup只令alive=false，回包路径没有在读取前检查alive或连接修订，因此窗口关闭后仍可能发起目录读取。源码缺陷与捕获的命令相符；实际首次调用链仍需修后窗口验证，不能仅凭静态分析认定所有失败同源。

## 修前反例准备

在既有 `ui-query-context-preparation.test.ts` 提取真实NewQueryDialog的唯一effect，隔离状态和IPC端口、使用真实CompletionServerFacts，以可控Promise安排回包。新增七项：正常读取、关闭后迟到成功、建连期间修订变化、已发送目录的迟到结果、同修订新ticket保护、关闭后建连失败、当前目录失败。只捕获回包和状态，不复制生产判断、不启动React／Electron／数据库。

回包释放后等待一个明确Node事件循环回合，避免负向断言早于原Promise链完成；不以固定毫秒等待制造竞态。预期至少“关闭后迟到成功”“修订变化”“同修订新ticket”在原实现失败；尚未执行，不将预期当作真实红例。

修复应在目录派发前检查原effect仍活动且修订未变，cleanup结束原pending ticket，迟到项目不能写入旧界面。已有建连／目录请求继续由原引擎负责实际结束，不增加取消或自动重放；原审计和实库用例保持，不开放metadata.databases绕过问题。

## 修后候选准备
