# C03：连接概要导入的明确选择与受控替换

本切片从固定 `49d88115f3839d7ce3854f4f7c279b9c3eb4b8f4` 建立普通分支 `codex/employee2-c03-explicit-replace-20261016`。员工2原 `1f375ce` 分支保留，不使用工作树。这是0.19之后的独立候选，不修改版本号、既有封存报告或已完成的真实验收记录；ROOT独立审查及实测后才能决定纳入版本。

## 用户流程

1. 选择版本1的无秘密概要文件，默认仍是新增或跳过。同ID、名称、数据库目标只提示潜在重复，从不自动选目标或覆盖。
2. 每个替换行必须自行选择一个本机连接ID。初值为空，同批不能让两个源使用同一目标。
3. 点击“审阅本批替换”。主进程保存不可变的源→目标配对和被替换旧概要，界面展示旧→新数据库、SSH目标/指纹、TLS及文件缺项。
4. 分别确认目标、清除全部凭据、重新选择认证文件、保留ID的关联记录风险，再确认暂存。未全勾选不能执行。
5. 修改操作、重选目标（含A→B→A）、重新选文件、连接列表变化或关闭模态，都清除风险与确认。迟到审阅响应只能释放，不能重新发布旧确认。

不会自动关闭会话、连接数据库、执行SQL、取消正在运行的操作或重放失败批次。导入前先同步当前标签清单；打开/关闭导入模态同步撤销原收藏/链接导航意图，避免更早响应迟到后新建标签。

## 可信边界

- `connections.importPreview` 仍保存十分钟文件快照及本机单调修订，源文件后改不影响已显示内容。
- 新增 `connections.importReview` / `connections.importReviewRelease`。一个文件快照最多持有一个替换确认；重新审阅先撤销旧确认，不延长期限、不额外增加快照预算。
- 最终 `connections.importApply` 对逐行源ID、action、目标ID的规范序列精确比较。仅目标集合相同但跨行交换也拒绝；缺源、多源、重复源、重复目标、未知字段/风险和夹带目标的add/skip都拒绝。
- 最终尝试先消费整个预览，再检查风险、修订、活动、到期与存储。业务校验、进程检查、CAS或写盘失败都不重试；严格IPC格式校验失败不会进入业务处理器。
- `ConnectionConfigManager.replace` 在首个await前同步锁住全部目标，前后检查主进程标签、会话、准备中的长任务和修订，再调用原内部 `__connections.prepareSave` 屏障。真实Engine继续检查打开会话、尚未完成的建连、任务和连接使用登记。
- 检查不调用 `resolveConnection`，传给Engine的只有无秘密、无生效路径的新概要，并无条件设置transportChanged。即使端点相同也清除原秘密，不因旧密文不能解密而绕过或失败回用。
- 标签身份变动立即通过既有IPC登记到主进程，SQL正文仍防抖。布局校验或写盘失败会撤销“当前标签清单可信”依据，必须先成功保存当前布局。检查等待中新标签出现同样阻止提交。
- `LocalStore.importConnections` 最终检查期望修订和被替换旧概要，在同一个同步SQLite事务里完成全部新增/替换，并仅提升一次连接修订。任何目标不符或写盘失败都恢复内存数据库、原文件和会话秘密，后续保存不能夹带失败批次。

## 认证清除与稳定身份

替换保留明确选定的本机ID，删除该ID的整个持久秘密命名空间和全部会话秘密，包括未来新增槽。不会复用密码、SSH密码/口令、TLS口令、秘密存在标记或rememberPassword状态。

新概要没有任何可生效TLS/SSH文件路径。来源文件提示与旧目标已用文件合并为待重新选择项；即使来源省略旧文件，也不能静默消除认证要求。文件名不能作为本机路径。旧认证文件授权对这些目标失效，其它连接仍可使用原授权；替换后用户重新选择本机文件，才会生成新授权。遇到含NUL的目标或旧库身份会造成会话槽归属歧义时保守拒绝，不能清除另一连接的秘密。

历史、已保存查询、收藏、全局设置和表布局仍关联原目标ID，既不自动迁移到新身份，也不静默删除。确认中明确要求使用前复核。成功后沿用连接修改版本/对象与补全失效通道，主进程清除这些目标的旧结构令牌。没有新建或打开任何数据库会话。

原版本1交换格式、公开概要隐私白名单、500条、2 MiB、十分钟及四份预览预算保持。没有引入数据库配置迁移或外部SQL。
