# PostgreSQL 单元格就地编辑

在具备更新权限并有主键的普通表记录页，双击普通单元格或选中后按 `F2`，即可在原格位置编辑。也可以直接键入首字符开始替换。这个入口接入记录网格中的逐格编辑流程。 [Navicat 网格编辑手册](https://www.navicat.com/manual/online_manual/en/navicat_18/win_manual/data_rdbms.html#grid-view)

选择「输入文本」「写入 NULL」或「使用 DEFAULT」，按 `Enter` 或点「加入草稿」。文本中按 `Shift+Enter` 可插入换行，空文本按空字符串保存。`Esc` 取消本次编辑并返回原格。切到另一标签后，尚未暂存的输入保留在原标签。

同一记录的多个字段合为一条更新草稿。重新打开单元格会带入该字段的暂存值。草稿区显示已暂存的字段，表页网格继续显示读入的原记录，方便核对。通过「预览记录修改」检查 SQL，再点「确认提交整批修改」写入数据库。提交时复核首次暂存时的原行版本，外部修改会触发原有的冲突保护。

生成列、待删除的行、无可用主键的表和只读视图不进入就地编辑。BYTEA 的查看和修改仍使用原有的字节查看器与记录表单。

## 验证

- macOS 上 Node.js 24.17.0 运行时检查、类型检查和源码构建通过。
- macOS 完整单元回归共 1,327 个文件，27,472 项通过，10 项 Windows 系统 tar 用例跳过。
- Server-200 独占 PostgreSQL 18 实库回归 5 项通过。独立连接核对未提交时的原记录、确认提交后的 64 位整数和含引号及换行的文本，以及恢复后的原记录。两轮通过的实库测试均确认连接归零后清理容器。
- 定稿 macOS 原生窗口回归通过，共 70 项观察。新增检查覆盖双击、`F2`、直接输入、取消及焦点返回、切换标签保留输入、只读视图拒绝、原值未变时退出、NULL 与 DEFAULT 草稿和同一行多字段合并。已核对截图、应用正常退出及临时配置清理。
- 首轮新增编辑检查通过后，测试临时打开的视图改变了后续命名方案关闭时的邻近标签。补上测试清理，并修正截图中下拉框挤压字段名的问题。保留原断言、120 秒门槛、失败日志、工作区及已停止的隔离数据库容器。
- Windows 虚拟机不可达，本轮按约定使用 Mac。Windows 原生操作、两平台安装包和较早 PostgreSQL 版本待验。
