# SQLite 字段悬停说明

## 用户行为

SQLite 查询编辑器新增字段悬停说明。鼠标停在字段名上，或将光标放在字段内，按 Monaco 的显示悬停快捷键（Windows：先 Ctrl+K，再 Ctrl+I），可查看完整字段名、查询绑定、准确 main／temp 来源、原声明类型和生成／隐藏标记。不会改正文或自动执行 SQL。

声明类型不等于逐行存储类型；没有声明时明确显示“未声明”。当前有界目录没有提供可空、默认值、键及备注，不推断这些属性。[SQLite 类型说明](https://www.sqlite.org/datatype3.html)解释了声明、亲和性与实际存储类的区别。

CTE 和派生表输出只展示局部来源，明确类型及底层血缘未知。未限定字段从最近查询块查找，只有内层不存在时才回退外层；内层同名歧义不能借外层消歧。相同物理表的别名、显式 main／temp、ASCII 名称比较保持原 SQLite 规则。

输出别名、窗口名、类型名、函数名、注释、字符串、参数、未闭合引用及不支持的作用域不借同名物理列显示类型。目录不完整、来源歧义或查询状态未知时不显示不确定说明，不执行参照 SQL 来猜测类型。相关子查询语义另见 [SQLite 表达式说明](https://www.sqlite.org/lang_expr.html#cosub)。

## 实现与保护

- 复用原 `sqlite.completion` 有界标识符协议，无新 IPC、写接口或配置迁移；SQL 正文只进入本地分析 Worker。
- Worker 新增固定 `hover` 意图，完整解码三种引用标识符；补全仍采用原 128 单位前缀，悬停完整名最多 512 单位，目录前缀截取不切坏代理对。
- 悬停回包单独核验完整词与有界作用域层级；普通补全不能接收新增层级字段，原缺省分析输出保持。
- 两入口共用原串行占门和会话目录；键盘补全优先，悬停不抢占正在运行的补全。替换需等原读取、取消及 Worker 终态，不以取消 ACK 提前复用会话。
- 每次等待后核模型、版本、原连接／会话、目录 stamp 和对象代次；编辑、切标签、事务／DDL 状态变化、模态或卸载均撤销旧结果。
- 说明为不受信任、关闭 HTML 的纯文本代码块；数据库名称和声明类型不能激活命令链接。
