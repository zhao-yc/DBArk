# CSV／JSON导入提交方式

## 使用入口

表数据页选择“导入”，CSV与JSON显示“导入提交方式”：

- **每500行提交（默认）**：保留原行为。后续记录失败或取消时，已经提交的批次仍保留；当前批次尝试回滚，不能整文件撤销。
- **整文件一次提交**：文件仍流式读取，所有记录成功后才发送一次COMMIT。解析、无损类型校验、服务器错误或取消导致事务失败时尝试整文件回滚；未确认的提交或回滚要求人工核对，不能自动重放。

选择方式保留当前文件、预览和映射；旧选择对应的执行回调失效。运行期间不能切换。导入模板只保存文件解释与字段映射，不替用户改变本次提交策略。SQL文件继续按脚本自身事务边界执行；Excel当前仍使用既有分批路径，没有本次选项。

## 事务与失败边界

整文件模式需要目标表SELECT权限，先启动事务、持有目标元数据锁，再在同一会话重新核对InnoDB基本表和实际结构。期间持续检查实际事务状态，不以缓存、旧目录或未知事务位证明原子性；无法确认时明确失败，不退回分批提交。数值精度、NULL、二进制及原INSERT警告检查保持。

该方式可能长时间持锁，增加数据库事务日志与服务端资源占用。保证范围是目标InnoDB事务；触发器对非事务表或外部系统的副作用不能承诺回滚。提交一旦发送，不再以KILL干预该COMMIT；服务器已确认提交的事实不能被迟到取消、通知或连接收尾错误抹去。

已确认提交后发生附加收尾错误时，仍保留确认行数，并明确提示“服务器已确认导入提交”和“不要重复导入”。现有Main／界面仍可能把该附加错误显示为失败，不能把这一状态解释为数据库已经回滚。

主进程仅接受本次CSV／JSON执行的 `transactionMode: 'batch' | 'atomic'`，省略保持历史batch。SQL、Excel、预览、导出及持久模板拒绝夹带；显式undefined、未知枚举、访问器和继承策略也拒绝。文件能力仍来自本窗口明确选择，不能通过策略取得任意路径。
