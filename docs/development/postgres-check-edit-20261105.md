# PostgreSQL 普通表 CHECK 约束编辑

从表页或对象菜单打开「查看结构 → 约束 → 编辑 CHECK」。可以创建、替换表达式、重命名、验证或删除约束。替换会预填服务器返回的原表达式，保留约束名称和注释。将一项或多项操作加入草稿，先预览实际 SQL，再确认提交。替换和删除另需勾选确认。

- 表达式可引用本表列，也可用带 schema 的自定义函数或类型。编辑器限制单个表达式的长度和嵌套深度，识别 PostgreSQL 引号和注释。预览只发 Parse。表达式计算和数据检查由 PostgreSQL 在确认提交时处理。
- `NOT VALID` 允许先约束后续写入，再分开验证已有记录。PostgreSQL 18 及以上另可选择 `NOT ENFORCED`，只记录定义。两种状态在目录中分别显示。还可设置 `NO INHERIT`。[PostgreSQL ALTER TABLE](https://www.postgresql.org/docs/18/sql-altertable.html) · [PostgreSQL CHECK 语法](https://www.postgresql.org/docs/18/sql-createtable.html)
- 批次绑定原表、窗口、连接修订与约束 OID。执行期间独占锁定原表，并在提交前回读实际约束及验证状态。表达式失败、历史数据不符或并发结构变化会阻止整批提交。

编辑源为有管理权限的普通表。分区、继承表和域约束可通过 SQL 编辑器管理。

## 验证

- Mac 定稿类型检查、构建和 18 项定向单元测试通过。覆盖带引号的列、dollar-quote、转义、嵌套注释、数组和非法语句边界。
- Mac 完整单元回归覆盖 1,324 个测试文件，27,421 项通过，10 项 Windows 系统 `tar` 检查按平台跳过。
- Server-200 独占 PostgreSQL 18 实库 5 项通过。用带计数的检查函数区分预览、NOT VALID 安装及实际记录校验。验证历史坏数据和无效替换触发整批回滚，成功替换保留原约束注释，同名同定义重建使旧预览失效。
- 实库另核对 PostgreSQL 18 的 NOT ENFORCED 允许违规记录写入，以及连接默认字符串模式关闭时，CHECK 仍按统一模式读取、解析和执行。
- Mac 原生窗口用例 1 项通过，20 个观察点，单 worker、120 秒、零重试且关闭 trace。验收原表达式预填、单独验证、替换确认和目录回读。原窗口正常退出，独占库和临时配置目录已清理。
- 首轮窗口测试对预填文本框的定位失败。使用页面快照中的文本框可访问名称重新定位后复验通过，保留原失败现场。
- WIN11-TEST 会话不可达，本轮未派发，按约定在 Mac 验证。Windows 原生窗口和安装包尚待验收。
