# MySQL 和 MariaDB 从 XML 新建表

在数据库节点打开「从文件导入新表」，选择 XML。指定记录标签后，按需启用记录属性及 Base64 解码。默认标签为 `RECORD`，适用于 tabrelio 的列名标签和记录属性两种导出布局。选择 UTF-8 文件后，向导扫描完整文件取得源字段、记录数和 SHA-256。预览只展示有限样本。

输入并核对新表名称，再进入正式表设计器。向导以可空 LONGTEXT 作为初始建议，可按业务类型修改。例如，要解码源文件中的 Base64，需把对应目标字段设为 BLOB 等二进制类型。先核对并确认建表，再点击「继续配置导入」。建表和写入数据分别确认。

导入阶段沿用最初选中的文件和 XML 选项。核对字段映射并运行「校验整份文件」。只有预检通过且指纹匹配后才能开始整文件追加。正式导入重新计算文件指纹，确认未变化后才提交。预检后改写文件导致导入失败时，已建表保留，数据事务回滚。源记录中省略的已映射字段表示 NULL，空元素或空属性仍是空值。

输入仍遵循扁平 UTF-8 XML 1.0 的约定，文件上限 64 MiB，完整源字段目录最多 1,000 列。位置映射「XML 文档」回读待补齐。[现有表 XML 导入](xml-table-import-20261107.md) · [PostgreSQL 从 XML 新建表](postgres-xml-new-table-20261107.md)

## 验收

macOS arm64 使用 Node.js 24.17.0，通过严格类型检查、构建及 1,049 项相关单元测试。Electron 端到端测试分别连接 Server-200 上隔离的 MySQL 8.4.11 和 MariaDB 11.4.13，核对正式建表、完整预检、64 位无符号整数、Base64 二进制、空值、NULL 和后出现的字段。两组均验证预检后改写同长度文件会回滚导入，已建表保持为空。测试资源已清理。

Windows 虚拟机测试会话本轮无法连接，Windows 原生验收和安装包验收仍待执行。
