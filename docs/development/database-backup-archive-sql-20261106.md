# 数据库备份归档检查与 SQL 导出

在「工具」选择「打开数据库备份归档」，再选择 tabrelio 的 `.dbark-backup.zip` 文件。此入口可在没有数据库连接时使用，适用于 MySQL 和 MariaDB 的 tabrelio STORE／ZIP64 归档。

检查会核对两个规定条目、ZIP 目录和 CRC、清单的规范表示以及 SQL 的字节数和 SHA-256。窗口展示清单中的来源、对象计数、SQL 摘要和整包摘要。文件格式完整性与来源可信度分别判断，清单描述需按实际环境另行核对。

点击「导出原始 SQL」并选择新文件名。客户端重新校验同一归档，按原始字节写出脚本。SQL 暂存同步并关闭后，以同卷硬链接发布，已有目标不会被覆盖。目标文件系统须支持硬链接。这个入口不会连接数据库或执行脚本。

## 验收

2026-11-06 在 macOS arm64 使用 Node.js 24.17.0 完成类型检查、构建及 63 项定向测试。Windows 测试机连接不可用，Windows 和安装包未验。

macOS Electron 源码专项使用隔离文件路径。在零连接的工作台，从工具菜单打开归档。损坏样本因 CRC 不符被拒绝，有效样本显示清单与摘要，原始 SQL 和源归档均通过独立字节比对。另测了 MySQL 和 MariaDB 归档逐字节导出、检查后换包、跨窗口令牌、同名目标竞争和取消。

实际 SQL 由 Server-200 无网络容器内的 MariaDB 11.4.13 原生工具生成，共 3,866 字节。夹具用产品归档格式封装，清单为测试生成。导出文件交由另一全新隔离实例的同版本 MariaDB 客户端执行，读回两行和视图，保留精确无符号整数、定点小数、NULL 和原始字节。首轮源夹具误连初始化期临时服务器，待正式进程就绪后重新生成。成功的源和恢复容器均已清理。产品界面执行的是离线归档操作，实库导入在外部单独完成。[MariaDB 原生备份与恢复说明](https://mariadb.com/docs/server/clients-and-utilities/backup-restore-and-import-clients/mariadb-dump)

最终完整单测 27,568 项通过、10 项跳过。首轮菜单回归的旧断言把所有含「备份」的入口视作占位，现单独验证已实现的归档入口，其余占位约束继续保留。
