# PostgreSQL 函数和过程依赖查询

从对象树或「函数」列表打开目标重载的定义，选择「查看依赖」。窗口按「被哪些对象引用」与「依赖哪些对象」分组。引用例程的视图显示为视图，列默认值显示为实际字段。关联对象所在 schema 对当前角色不可见，或关联例程缺少执行权限且不归当前角色管理时，窗口会遮罩名称。

「删除例程」也提供「查看依赖」。返回后保留原删除预览及确认状态。实际删除仍使用 `RESTRICT`，由 PostgreSQL 重新检查当前依赖。[PostgreSQL 依赖跟踪](https://www.postgresql.org/docs/18/ddl-depend.html)

读取绑定原数据库、对象 OID 和完整重载签名。页面只显示 `pg_depend` 中记录的直接依赖，例如参数类型、视图引用和 PostgreSQL 解析并登记的 SQL 标准正文引用。字符串正文中的动态 SQL 或未登记引用不在列表内。[PostgreSQL pg_depend](https://www.postgresql.org/docs/18/catalog-pg-depend.html)

## 验证

- macOS 上 Node.js 24.17.0 运行时检查、类型检查和源码构建通过。
- macOS 完整单元回归共 1,326 个文件，27,455 项通过，10 项 Windows 系统 tar 用例跳过。
- Server-200 独占 PostgreSQL 18 实库回归 5 项通过。覆盖同名重载隔离、视图和字段默认值反向依赖、自定义参数类型、重命名后依赖保持、SQL 标准过程出向引用、原定义变化时拒绝读取旧目标、权限遮罩及受限删除。读取含写操作的过程定义和依赖时，业务表行数保持为零。
- 首轮的隐藏 schema 夹具已撤销所有者 `USAGE`，与预期角色不同。改用独立 schema 后复跑通过。首轮日志保留，独占容器已停止并保留。
- macOS 原生窗口回归通过，共 61 项观察。覆盖定义入口、按签名区分引用、删除窗口返回保留预览和 SQL 标准过程出向引用。独立连接复核实际 `pg_depend` 条目、原数据、零剩余连接、测试容器和临时配置清理。
- 首轮原生测试在已有的对象树右键步骤遇到目录刷新关闭菜单。改用同一对象行打开后复跑通过，原始失败现场和停止的容器保留。
- Windows 测试虚拟机不可达，本轮切换到 macOS。Windows、两平台安装包和较早 PostgreSQL 版本待验证。
