# PostgreSQL 函数和过程目录

在 PostgreSQL 数据库下从工具栏打开「函数」，可搜索用户 schema 中可见的函数、窗口函数和过程。对象树也列出这些对象。名称带 schema 和输入类型签名，同名重载分别显示。参数名、默认值和纯 `OUT` 参数不参与输入签名。[PostgreSQL pg_proc](https://www.postgresql.org/docs/18/catalog-pg-proc.html)

双击列表项，或从对象树选择「查看定义」，可以检查语言、所有者、参数、返回类型、执行身份、注释和服务器生成的 DDL。选择「打开定义草稿」会在原数据库打开查询标签，由用户另行决定是否执行。[PostgreSQL 目录信息函数](https://www.postgresql.org/docs/18/functions-info.html)

列表与详情使用相同的 schema 和例程权限检查。详情按规范输入签名匹配，查看及打开草稿均不调用函数或过程。当前覆盖普通函数、窗口函数及过程的定义浏览，聚合定义和图形化例程维护仍在覆盖清单中。

## 验证

- macOS 上 Node.js 24.17.0 运行时检查、类型检查和源码构建通过。
- macOS 完整单元回归共 1,326 个文件，27,455 项通过，10 项 Windows 系统 tar 用例跳过。
- Server-200 独占 PostgreSQL 18 实库回归 5 项通过。覆盖普通函数重载、过程输出参数、带点和引号的名称、自定义参数类型、注释和执行身份、隐藏 schema、执行权限筛选及定义只读。含写入副作用的函数仅返回定义，计数仍为零。
- 首轮实库发现 `to_regprocedure` 会在查询前触发隐藏 schema 权限错误。改为使用目录身份及统一权限过滤后复跑通过。
- macOS 原生场景通过，共 55 项观察。验证对象树右键和工具栏搜索分别打开同名的两个重载，列表可打开过程定义，打开草稿不产生执行历史。独立核对原表数据、零剩余连接、独占容器及临时配置清理。
- Windows 测试虚拟机连接不可用，本轮在 macOS 验证。Windows、两平台安装包、较早 PostgreSQL 版本和自定义窗口函数实测待补。
