# PostgreSQL 全库结构名称搜索

打开「工具 → 全库搜索」，选择已保存的 PostgreSQL 连接，逐行输入最多 32 个数据库名称。选择对象类别及匹配方式后点击「开始搜索」。可检索表、视图和物化视图、字段、索引、主键、外键、唯一约束、CHECK 约束、序列、函数和过程。函数重载按完整的输入类型签名分别显示。包含、前缀和完整匹配保留百分号、下划线及引号，正则表达式和大小写折叠按服务器规则执行。[PostgreSQL 字符串函数](https://www.postgresql.org/docs/18/functions-string.html) · [例程目录](https://www.postgresql.org/docs/18/catalog-pg-proc.html)

每批至多打开一个数据库的专用短连接。搜索读取系统目录，排除系统和临时架构。结果遵循结构详情的账号权限。目标库拒绝连接时记录失败，按用户选择停止或继续。每批最多返回 50 个命中，并受目录查询次数和响应字节数限制。续页以限定名称和匹配名称为排序键，5 分钟内可用一次。页间释放数据库连接。若目录变化，新建或重命名到已扫描排序范围的对象需要重新搜索。[PostgreSQL 权限查询函数](https://www.postgresql.org/docs/18/functions-info.html)

双击结果或选择「打开当前定义」会用原连接和数据库重新读取当前详情。字段、索引和约束命中会打开对应分区并突出显示同名项。搜索入口的详情为只读。正文模式另见[PostgreSQL 定义正文搜索](postgres-definition-search-20261107.md)。

## 2026-11-07 验收

- Windows 测试虚拟机不可达。本轮使用 macOS arm64 源码 Electron 和 Server-200 上的一次性 PostgreSQL 18.6 实例。
- 跨三个数据库范围的查询依次显示 50、55、55、56 个命中。中间库的连接拒绝单独列出。百分号和下划线按原文匹配，权限不可见的表未进入结果，页间管理连接确认没有残留搜索会话。
- 实库正则返回 14 个跨类别命中，两个同名函数按输入类型签名分别显示。打开字段命中时高亮当前字段，搜索入口未提供结构编辑，执行历史无新增。
- 首次全量回归暴露了共用定义搜索的原有校验文案和窗口打开参数变动。恢复原契约后重新运行专项和全量测试。另加入连接断开时拒绝迟到续页的断言。
- 最终 Vitest 通过 1,361 个文件及 27,658 项，10 项按环境条件跳过。
- MySQL 8.4.11 的名称及定义搜索原生回归 7 项通过。首轮和原 `e83f5e86` 基线均因旧定位器找不到第三个结果标签而失败，修正定位器后按原断言通过，包括跨页搜索时保留事务、结果和草稿。MySQL 隔离库、连接及转发已清理。
- 运行时检查、定稿类型检查和源码构建通过。PostgreSQL 服务器监控的原生读取、取消和会话信号回归通过，两个隔离实例及转发均已清理。Windows、安装包和其他 PostgreSQL 版本待验。
