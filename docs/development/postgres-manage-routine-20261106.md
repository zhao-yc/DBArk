# PostgreSQL 函数和过程重命名与受限删除

从 PostgreSQL 对象树或工具栏「函数」列表打开目标函数或过程的定义。有管理权限时，定义窗口提供「重命名例程」和「删除例程」。窗口显示当前 schema、名称和完整输入参数类型，可区分同名重载。仅有执行权限的角色仍可查看可见定义。

- 重命名时填写新名称，核对 SQL 预览再确认。提交后目录同步刷新并打开新名称的定义，保留例程身份、权限、注释和其他重载。
- 删除时核对 SQL 预览，勾选确认当前完整签名后提交。删除使用 `RESTRICT`，有依赖对象时 PostgreSQL 拒绝执行并回滚。

预览只读目录。应用以同所有者的 `ALTER … OWNER TO` 锁定对象，在事务内复核原签名和目录摘要，写入后再核对对象身份或删除结果。名称、签名、所有者或定义在确认前发生变化时，旧预览会失效。若应用无法确认提交结果，重新打开目录核对实际状态。[PostgreSQL ALTER ROUTINE](https://www.postgresql.org/docs/18/sql-alterroutine.html) · [PostgreSQL DROP ROUTINE](https://www.postgresql.org/docs/18/sql-droproutine.html)

## 验证

- macOS 上 Node.js 24.17.0 运行时检查、类型检查和源码构建通过。
- macOS 完整单元回归共 1,326 个文件，27,455 项通过，10 项 Windows 系统 tar 用例跳过。
- Server-200 独占 PostgreSQL 18 实库回归 5 项通过。覆盖同名重载和带引号的名称、函数及过程、OID 和 ACL 保留、依赖拒绝、修改或替换后拒绝旧预览、仅执行权限和一次性令牌。读目录与操作过程中没有调用例程正文。
- macOS 原生窗口回归通过，共 57 项观察。覆盖函数列表进入重命名、重开新定义、删除确认勾选、对象树与列表刷新。独立回读确认旧整数重载及改名后的重载均已移除，文本重载仍在。原表数据、零剩余连接、临时配置和独占容器清理均已核对。
- Windows 测试虚拟机不可达，本轮切换到 macOS。Windows、两平台安装包和较早 PostgreSQL 版本待验证。
