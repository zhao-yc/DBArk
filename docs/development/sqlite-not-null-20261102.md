# SQLite 已有字段：显式 NOT NULL 编辑

## 操作与语义

普通 `main` 表右键选择“修改 SQLite 字段、顺序与约束…”，明确读取目录、选择字段，在“显式 NOT NULL 处理”中选择保持、添加或保留、移除。切换字段保留草稿，可以与类型、默认值、实际字段顺序及约束编辑共同预览。

这里只修改显式声明。原显式声明与 SQLite `table_xinfo.notnull` 标记分别展示；移除声明不取消 STRICT／WITHOUT ROWID 主键的隐含非空规则。INTEGER PRIMARY KEY 即使声明 NOT NULL，输入 NULL 仍可能生成 ROWID。不能由 `notnull` 标记推断全部写入语义。

新加声明采用原生默认 ABORT；已有声明选择保留时，准确名称、重复声明、冲突策略及原文保持。移除时清除该字段全部显式 NOT NULL 及附属命名标记，保留显式 NULL、默认值及未选约束。不提供关闭约束检查或自动回填旧 NULL 的选项。生成字段也可编辑非空声明，表达式保持。

核对完整 SQL、独立非空风险和准确原表名称后提交；只读连接可设计预览，不能执行。修改草稿会撤销旧预览、风险及确认，关闭／重读保留原草稿保护。回滚后允许明确重新预览，不自动重试；未知状态及已确认提交仍锁定原批。

## 执行边界

沿用重建命令，不增加独立写入口。`changes[].notNull` 为严格布尔值；`false` 是明确移除，缺省是保持。Main、Runtime 和界面各自核对准确计数；目录能力、原目标及来源世代继续绑定，执行前独立重算完整计划。

先按原定义跨度修改非空声明，再组合其它约束；本批释放的约束名可供其它新声明使用。最终原生主键顺序、有效非空标记和行身份共同核验，保留主键隐含规则。

复制固定使用 `INSERT OR ABORT` 并逐值检查全部数据，不能因默认值、IGNORE 或 REPLACE 跳过／替换原 NULL。原数据或生成结果不满足新声明时，完整事务回滚。四次 worker 比较、独立候选定义核验、索引／触发器／视图／外键、原序列高水位和未选对象保护保持。
