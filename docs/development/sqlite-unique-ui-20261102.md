# SQLite 已有 UNIQUE 约束：原表重建编辑区

## 使用流程

在普通 `main` 表右键或表页结构操作中选择“修改 SQLite 字段、顺序与约束…”，明确读取原目录后进入“SQLite 唯一约束”。这里只管理原 CREATE TABLE 中的 UNIQUE 声明；显式唯一索引仍使用索引管理入口。

- 每个原声明显示序号、位置、字段和完整 SQL；重名、重复声明按原序号和准确 SQL 独立识别，不猜自动索引名称。可新增、修改、标记移除、继续编辑或撤销本地草稿。
- 字段逐项选择并排序，保留逗号等名称原文；普通及已有生成字段均可参与。表级支持各项 COLLATE、ASC／DESC 及五种冲突策略；行内只允许一个字段，继承原列排序规则。切换位置不会偷偷删除输入，非法组合须明确修正。
- 替换既有声明须核对原文并明确勾选确认。旧重复字段、连续命名或复杂字段词法不会在保留原约束时被规范化，只有明确替换才按当前结构生成。
- 主键、外键和 UNIQUE 未暂存输入互斥，已暂存队列可共存，与字段／实际顺序共同预览。暂存只核结构和原目标，名称交换等组合由完整预览统一核对；尚未解决的最终冲突不得提交。UNIQUE 草稿可先暂存，再设计名称交换的主外键，外键试编译会使用已有全部约束上下文。
- 未暂存表单及所有草稿参与关闭、重读和 dirty 保护。旧字段／表单／按钮、源连接及版本 ABA、目录过期或忙态均不能改后继输入；任意草稿变化撤销原预览、确认及风险选择。

## 预览与提交保护

沿用[独立事务能力链](sqlite-unique-engine-20261102.md)，没有新增 IPC、数据库引擎或凭据格式。只打开编辑区、输入、暂存或撤销均不发送数据库请求；读取与完整预览是明确操作。

预览发送准确 `uniqueEdits`，回包 `changedUniques` 必须与原请求数一致；缺失、额外或错数均准确释放原能力，不展示可提交授权。除原数据／依赖／空间风险外，必须单独确认 UNIQUE 唯一性、冲突策略、索引及父键影响；原表确认名须准确，原预览只消费一次。

复制固定使用 OR ABORT，不会因 IGNORE／REPLACE 跳行或覆盖。修改父唯一键后全部最终外键须可检查且零违规，即使子表为空；WR 冗余约束合并的辅助方向沿最终原生主键精确证明。只读允许设计／预览但不能执行；回滚保留草稿，未知结果锁定且不自动重试。
