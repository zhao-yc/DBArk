# SQLite 记录树及 JSON 节点编辑（2026-11-04）

## 使用

在可写 SQLite 物理表的编辑、新增或复制记录窗口中，选择“SQLite 记录树”。树按真实字段顺序显示当前窗口输入，包含网格隐藏字段、实际值类型、声明类型及生成列标记，每组最多32个字段；摘要会说明截断，不能把摘要当作完整字段写回。字段表单、整行 JSON 与记录树共享输入。

明确点击某个 TEXT 字段的“查看……的 JSON 树”后才解析原文；不会根据声明名为 JSON、字段名或文本外观自动解析。NULL、默认值、INTEGER、REAL及BLOB保持各自类型。原文无效或超过词法预算时说明原因，不显示部分结构。生成列和超过原完整编辑预算的TEXT仍可在词法预算内查看，不能通过节点编辑改写。

JSON 树按原文成员序号和数组下标显示，重复成员分别保留。可展开／收起、查看完整原始token及路径、替换节点值、成员改名／追加／移除、对象成员移动，以及数组插入／移动／移除。数组下标从0开始，对象成员序号从1开始，移动目标表示移动后的最终位置。名称及字符串值填写完整JSON字符串token；精确数字可按原文输入，不经过JavaScript Number。

“应用节点修改到当前输入”只改变当前窗口的完整TEXT候选，不直接暂存到表页或写库。节点／结构缓冲未应用或取消前，不能切换字段、输入方式、记录导航或保存整行；无效输入保留。取消节点只丢本次节点缓冲，保留其它窗口输入；取消整行窗口丢弃该窗口尚未保存的修改，数据库不变。新行沿用原新增草稿规则。

保存整行后才进入原页面草稿，一次整行保存可一步撤销／重做；最终仍须原SQL预览和明确提交。树不是独立写入通道，原关联表页的固定范围、冲突检测和生成列保护继续有效。

## 实现与边界

- 共享 JsonLexicalTreeView由原MySQL记录投影中抽取，继续复用同一词法树、480节点窗口、摘要与原始路径；普通列表和原生按钮提供可访问操作，不冒称额外实现ARIA tree方向键协议。换文档或字段会卸载旧节点选择和回调。
- SQLite 纯编译器 sqliteJsonFieldInput复用原节点替换、结构拼接及对象成员移动模型，只改变可信词法跨度。保持对象外空白、CRLF、重复成员、转义键、负零和极大数字原文，不把JSON容器解码为JavaScript对象再序列化。
- 开始和应用时同时核完整TEXT、准确原值对象及词法文档。生成列只读，原TEXT超过65536代码单元不能节点修改；完整合并后仍走原SQLite字段Schema及Unicode／长度门。词法模型保留既有256KiB双预算、深度64、8192节点和2048容器项限制，不为此功能放宽。
- 窗口父组件持有精确值数组代次及节点独占token；旧apply/change/close、卸载和取消不能修改新行或清后来节点的占用。来源失效后应用明确拒绝，但仍可取消自己的节点缓冲。树值比较直接比较typed类型及原文，不为dirty判断序列化整行大BLOB。
- 原节点／结构编辑UI改为通用最小输入接口，不伪造MySQL记录上下文供SQLite使用。结构编辑器补齐显式for/id标签关联，成员名／新值复用完整有界文本域，粘贴超限保留旧输入，不由浏览器maxLength截断。
- 纯Renderer增量，不新增IPC、数据库任务、路径、SQL历史或记录值持久化。MySQL仍使用原记录控制器及提交路径；共享组件与原模型回归单独覆盖。

本轮仅在可写记录窗口提供树及节点输入。SQLite只读表／视图的完整记录树、跨页草稿、批量表单和持久恢复仍待推进，D04／R02及完整Navicat目标继续部分覆盖，暂不正式发布。
