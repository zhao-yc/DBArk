# D07 防止原生粘贴截断 Hex

复审通过真实系统剪贴板确认：原生 `maxLength` 会先把带 0x 的 131072 字节输入截成合法的 131071 字节，后续共享解析器无法知道原文已丢失。修复移除 Hex 文本框的原生截断限制，保留现有字符、字节和最终暂存预算。

所有普通输入、粘贴、拖入文字和选择范围替换统一检查完整候选值。粘贴／替换在拼接前先核对原始字符总量，随后检查潜在字节预算；超限整次拒绝并显示已有预算错误，保持原编辑值、原草稿及原始行。输入事件兜底同样验证完整值，避免其它输入路径交付截断结果。合法的不完整 Hex 可继续编辑，但完整语法仍必须通过共享最终解析器才能暂存。

拒绝后不向记录控制器交付新输入；初始未修改记录保持暂存按钮不可用。不改变已有合法草稿，也不把失败结果替换成空二进制。图片、编码、NULL/DEFAULT 和原值冲突政策不变。中文预算文案未改动。
