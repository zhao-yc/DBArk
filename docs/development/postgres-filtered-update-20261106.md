# PostgreSQL 按筛选批量更新

在带主键的可写普通表中应用筛选，处理完当前页草稿后点「按当前筛选更新」。选择要设置的字段，按列类型填写值，或选择可用的 NULL、DEFAULT 和十六进制赋值。主键及生成列不在字段列表中。

点「读取匹配行并预览」可核对已应用条件、绑定参数、新值和匹配行数。统计覆盖其他页，使用数据库当前数据，忽略尚未应用的筛选输入。预览阶段只读。输入显示的准确行数，再点「确认提交」。需要调整赋值时，可以返回编辑并重新预览。

单次最多处理 1,000 行，零匹配或超过上限会拒绝生成预览。预览最长有效 5 分钟，也受原表页有效期约束。提交事务使用读已提交隔离级别，取得目标表的 `SHARE ROW EXCLUSIVE` 锁后重新核对匹配集合和行版本，随后执行参数化更新。数据库中的其他写入可能需要等该事务结束。若记录集合或任一版本变化，整批拒绝。约束错误或数据库确认的影响行数不符时，回滚本次更新。 [PostgreSQL 表级锁](https://www.postgresql.org/docs/18/explicit-locking.html)

## 验证记录

- macOS arm64、Node.js 24.17.0。原生运行时检查、严格类型检查和构建通过。完整单测覆盖 1,345 个文件，27,533 项通过，10 项 Windows 条件测试跳过。
- Server-200 的 PostgreSQL 18 独占实库回归通过 5 个文件、6 项测试。验证了跨页范围、错误行数确认、预览不可重放、约束失败回滚、匹配记录新增及同数量版本变化。数据库默认可重复读时，锁等待期间新增的匹配行也会使整批拒绝。默认只读事务的更新被拒绝并回滚，1,001 行的匹配集被完整拒绝。
- PostgreSQL 18 独占实库的 macOS Electron 专项通过 36 项观察。第二页可预览跨页 4 行，预览和错误行数确认前零写入。输入正确行数后独立读回 4 行更新，范围外记录仍保持原值。原生窗口正常退出，临时配置已清理。
- 初次测试夹具初始化超时后改用逐条命令。中间版本的只读回归发现显式指定读写会覆盖库默认设置，交付版只指定隔离级别。独立验证 PostgreSQL 允许只读事务取得此锁，拒绝 UPDATE 后由客户端回滚。三轮失败日志与独占容器保留。
- WIN11-TEST 连接不可用，本轮回退 macOS。Windows、安装包及其他 PostgreSQL 版本待验。
