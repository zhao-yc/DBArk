# SQLite 表格列布局（开发源码）

表／视图页打开“SQLite 列布局”，选择显示字段、前移／后移、列宽和冻结边界。调整立即反映在当前网格，点击“保存表列偏好”写入本机配置；同一连接和对象再次打开或重启后自动恢复。恢复默认布局需明确确认，取消不写配置。未保存布局纳入原标签脏状态，取消窗口中的变更只恢复布局，不放弃记录草稿。

## 显示和数据边界

- 网格使用独立的“显示位置 → 原字段编号”映射，原表页、行数组、编辑快照和查询保持原样。隐藏或重排不清空筛选、排序、行修改或原定位条件，不重新读取数据。
- 单格操作、列头排序、双击／F2及调宽仍按原字段识别；勾选复制只包含当前可见列，矩形粘贴沿可见顺序映射回原字段。生成列、类型／精度、矩形和最终差异预算继续使用原保护，一次暂存可一步撤销。
- 粘贴弹窗的目标字段、预览和暂存使用同一映射，来源列名不授予目标资格。布局改变撤销旧网格回调和粘贴映射，隐藏的起点不能继续粘贴；查找命中隐藏字段时先揭示原字段，再定位其当前显示位置。
- 字段删除时移除旧布局项，新字段追加；仅按精确名称调和，避免Unicode大小写折叠混淆字段。至少保留一列；冻结绑定准确可见字段，隐藏边界解除冻结。
- 支持SQLite的512字符名称及原Unicode校验、1024列、64～2000像素列宽。全库最多500个目标、8MiB，每项512KiB；不保存行值、SQL、密码或数据库路径。

## 本机保存与来源

新增可选schema9元数据表 `table_layouts_sqlite`，与MySQL原列偏好隔离，不改变旧查询、设置及SQLite写入协议。三个受限IPC仅负责本机读取、保存及重置，不创建查询会话或数据库任务。原Main文档、准确目标、连接配置摘要及CAS共同约束保存，发布前再次核对；来源变化不自动应用旧布局，需明确保存或重置。期限10分钟，来源最多256个；导航／销毁撤销旧令牌。

重置保留修订墓碑；删除连接清除本连接布局，启动清理旧客户端遗留的孤立记录。迁移前核对完整文档及原始字节预算，损坏或未知版本拒绝覆盖；写盘失败或提交门拒绝同时恢复内存和原文件。已落盘后的晚失效明确报告已保存事实，不自动重放。
