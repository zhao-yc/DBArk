# PostgreSQL 表页全量导出

在 PostgreSQL 表页应用所需筛选及排序后，点击「导出数据」。选择 CSV、JSON 或 XLSX，勾选输出列，使用系统保存窗口选择文件，再点击「开始导出」。导出范围是全部匹配记录，从第二页或后续页开始也会包含前面的匹配记录。

- 全量读取复用原表页的关系、筛选、排序和连接修订。数据库以独立的只读游标逐批返回当前快照。列或视图定义变化时，刷新表页后重新发起。只读视图也可导出。[PostgreSQL DECLARE](https://www.postgresql.org/docs/18/sql-declare.html)
- CSV 支持逗号、分号和 Tab。NULL 使用 `\N`，空字符串保持为空，二进制使用 `base64:`。CSV 和 JSON 可选 UTF-8、UTF-16 LE 或 GB18030。JSON 和 XLSX 将 PostgreSQL 数值原文作为文本保留，以保留大整数和高精度小数。JSON 的二进制字段保留类型和 Base64 内容。
- 文件先写同目录暂存。游标、事务和物理连接正常结束后再原子发布。发布前取消会终止本次读取并清理其暂存。格式或大小超限时整份失败，先前已有的目标文件保留。
- 一批最多读取 64 行和 64 MiB，单字段最多 8 MiB。XLSX 另受工作表、文件和单元格预算约束。SQL 数据脚本和 COPY 导出仍待接入表页。

## 验证

- Mac 类型检查、构建和 3 项定向单元测试通过。验证公开请求只接收原页和文件令牌、列选择、格式参数及建议文件名。
- Mac 完整单元回归覆盖 1,325 个测试文件，27,424 项通过，10 项 Windows 系统 `tar` 检查按平台跳过。
- Server-200 独占 PostgreSQL 18 实库 5 项通过。实测跨多个游标批次导出 130 条匹配记录，检查 CSV 分号和空值、UTF-16 LE JSON、XLSX 回读、大整数、高精度小数和 BYTEA。覆盖只读视图、原表结构与同名视图定义漂移，以及旧来源或其他文档的请求拒绝。
- 真实读取第二批时触发取消，原有目标文件保留，暂存清理。另一实库用例在第二批读取时提交并发更新，完整文件仍保留原游标快照中的记录值。
- Mac 原生窗口用例 1 项通过，21 个观察点，单 worker、120 秒、零重试且关闭 trace。固定测试保存路径后仍由正式 Main 和 Engine 完成写入，实际 JSON 包含两个匹配记录和一列。原窗口正常退出，独占库及临时配置目录已清理。
- WIN11-TEST 会话不可达，本轮未派发，按约定在 Mac 验证。Windows 原生窗口和安装包尚待验收。
