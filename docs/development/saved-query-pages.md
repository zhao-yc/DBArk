# 保存查询分页列表实现

入口为“历史与查询”中的“保存的查询”。现在只在进入保存分区时读取第一批概要，正文在用户打开时按摘要再读取。后续[执行历史分页](history-pages.md)已接入独立有界概要，共用生命周期但不共享资料源和句柄；旧历史500条接口只作兼容，本界面不再调用。

## 请求、排序与预算

`queries.page`严格接收任务编号、普通文字筛选和错误策略；`queries.pageContinue`只接收新的编号及随机句柄，不能修改原条件；`queries.pageRelease`幂等释放指定句柄。`queries.deleteChecked`要求所见记录ID与SHA256摘要，旧预览不能删除后来保存的新内容。

配置库增加兼容的`queries_updated_id`复合索引，schema版本仍为5。按更新时间和ID的BINARY降序，用二元键定位下一条，无OFFSET。每次SQL仅读一条正文及下一条存在性，SQLite语句在finally释放；不调用旧`queries.list`。单条128MiB的原始JSON、2000万UTF16单元SQL限制沿用本地搜索。

固定Worker逐条验证原文、生成摘要和最多512单元预览，在完整名称或SQL中执行普通不区分大小写的包含筛选，沿用旧列表的JavaScript `toLowerCase`后包含比较，不宣称完整Unicode折叠或服务器正则。SQL不执行，也不将其中的数字或JSON解析成业务值。每批最多检查25条、128KiB，单条线程命令设置2秒超时，实际回复还包含本地读取、序列化和线程收尾时间，页间无线程和正文缓存。概要及失败明细都按字节预算收尾，累计失败数在后续页仍保留，不能以最后一页没有错误表示前面均成功。

句柄只存筛选、复合位置和计数，5分钟到期；最多16个游标/活动页状态、2个活动页。它与全文搜索各自管理最多2个线程，这两类查询检索线程合计最多4个，不宣称跨两服务共享2个。查询或连接库成功修改使旧续页失效，失败写盘不改变数据、修订或原摘要。

## 生命周期与打开

列表是高频短读，活动编号复用补全的内存占位，不写任务/执行历史；最近编号最多256个、保留5分钟，使已完成本地请求的迟到取消仍在本地处理。活动及最近编号不能被数据库任务或元数据请求借用。取消等待真实Worker终止和整页finally；退出先关闭两类本地服务，再等待完整IPC操作，最后关闭SQLite。

界面仅保留当前批卡片，不累计此前页面。输入筛选后点击搜索或Enter生效，修改筛选/错误策略时不能继续旧条件的下一页；空命中页仍显示未检查范围。关闭或切回历史等待当前读取、打开或删除终态及句柄释放；释放失败保留句柄供重试，迟到回复不打开标签。

打开沿用`queries.read`的原文SHA256及有效目标连接校验。同来源保留指定库、无默认库、未知及遗留状态；失效或未指定来源须明确选择替代，换源后库为未知。新标签ID独立，不覆盖原草稿、结果或事务，不自动执行SQL。删除仅影响明确的本地记录，失败不重放；成功后刷新首批，旧续页失效。

内存sql.js的文件装载及旧`queries.list`、`history.list`兼容接口仍保留，不能将新界面的有界概要声称为所有本地接口或物理磁盘流式。极限规模及未验平台边界见[本批验收](../../tests/integration/acceptance-query-pages-20261015.md)。后续历史作为第三类独立服务另有最多2个线程，三类合计最多6个。
