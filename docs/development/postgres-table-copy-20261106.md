# PostgreSQL 整表复制

在普通持久表的工具栏点击「复制 PostgreSQL 表」。选同一数据库的可写 schema，输入新表名，选择「仅结构」或「结构和数据」。预览列出锁定来源、建表及可选的数据复制 SQL。勾选确认并点击「确认复制」后才执行。成功会刷新对象树并打开新表，数据模式同时显示实际复制行数。

结构按 PostgreSQL `LIKE INCLUDING ALL` 创建，额外保留表注释。范围包括字段类型、默认值、生成表达式、检查约束、索引和注释。外键、触发器、行级安全策略、授权和所有者需单独设置。分区、继承、临时表和 UNLOGGED 表暂不可复制。检测到默认值直接引用序列时拒绝，避免副本复用来源序列。启用行级安全或循环标识序列的表只开放结构复制。[PostgreSQL CREATE TABLE](https://www.postgresql.org/docs/18/sql-createtable.html)

确认时在服务器事务内取来源 `ACCESS SHARE` 锁，复核来源结构和目标名称。普通写入可以继续。数据模式通过一条 `INSERT … SELECT` 读取该语句可见的已提交行，覆盖整表，不受网格的筛选和分页限制。生成列由服务器重新计算，标识列保留已有值，新表的独立序列按副本实际值、步长和边界推进。提交前核对新表身份、字段、实际行数和来源结构。目标同名或来源结构变更须重新预览。确认后的语句超时为 120 秒，锁等待超时为 5 秒。若连接中断导致提交结果未知，应先核对目标 schema。[PostgreSQL LOCK](https://www.postgresql.org/docs/18/sql-lock.html) · [PostgreSQL 序列函数](https://www.postgresql.org/docs/18/functions-sequence.html)

## 验收

- WIN11-TEST 不可达，按授权在 macOS arm64 使用 Node.js 24.17.0。原生运行时、类型检查、构建与 4 项定向单测通过。全量单测覆盖 1,349 个文件，27,552 项通过，10 项按 Windows 条件跳过。
- Server-200 上的独占 PostgreSQL 18 实库通过 5 个文件的 8 项测试。独立客户端核对空结构副本、确认后精确复制、标识序列正反向分配、目标重名拒绝、来源 DDL 变更拒绝、旧式串联默认值和行级安全限制，以及表注释和索引。
- macOS Electron 原生窗口专项通过。独立客户端在预览时确认目标表尚未创建，提交后读取六条副本记录，核对有符号 64 位整数上下界、定点数、字节、NULL、空文本和生成列。副本新增行取得 `9007199254740999`，原表仍为六行。窗口正常退出，临时配置和本轮独占实库资源均已清理。
- 首轮实库的 zsh 包装在测试和清理结束后尝试给只读变量赋值，外层退出码为 1。定稿前调整了 SQL 预览样式，并修正了集成测试夹具的 `pg` 类型检查错误。原始结果和日志均保留。
- 跨数据库和跨引擎的整表复制及任务取消待实现。Windows、安装包及其他 PostgreSQL 版本待验。
