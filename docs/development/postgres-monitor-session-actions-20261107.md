# PostgreSQL 监控会话操作

在「工具 → 服务器监控」选择 PostgreSQL 连接，找到会话行。对于能核对进程身份的客户端会话，可选「断开会话」。运行中的查询还可选「取消查询」。确认区显示操作、PID、账号和数据库。输入目标 PID 后才能发送信号。

快照能力仅供原窗口、原连接配置使用，60 秒内可使用一次。客户端在一条固定 SQL 中核对实例、数据库、账号、PID 与后端启动时间。取消查询还核对活动状态、查询启动时间及服务器保留文本的摘要。匹配失败时该 SQL 不调用信号函数。PostgreSQL 按连接账号的实际权限处理信号。部分角色可以查看详情，发送信号仍可能被拒绝。[PostgreSQL 服务器信号函数](https://www.postgresql.org/docs/18/functions-admin.html)

取消查询可能使显式事务进入失败状态。断开会话会回滚未提交的事务。窗口分别显示信号回执和短时观测结果，然后尝试刷新快照。服务器信号函数按 PID 操作，目标可能在复核与信号到达之间发生变化。结果未知时请核对服务器状态，客户端仅发送一次信号。[PostgreSQL 监控统计](https://www.postgresql.org/docs/18/monitoring-stats.html)

## 2026-11-07 验收

- Windows 测试虚拟机不可达。本轮使用 macOS arm64 源码 Electron，连接 Server-200 上的一次性 PostgreSQL 18.6 实例。
- 同一 PID 重发完全相同的 SQL 后，旧快照被判为失效，后一条查询仍在执行。重新确认后，原连接收到 SQLSTATE `57014`，随后仍可执行新查询。
- 可查看其他角色的会话详情时，服务端仍可拒绝发送信号。为测试账号授予 `pg_signal_backend` 后，断开目标会话。独立管理连接确认目标 PID 消失、未提交行未保留，监控连接和测试容器均已清理。
- 首轮确认了信号送达，同时发现观测查询沿用了已经消费的回包预算。为每条查询单独分配预算后复验通过，加入对应回归断言。
- 原连接关闭与删除路径继续使用既有的连接代次。首次全量测试暴露了重复的失效入口，统一后保留既有 IPC 断开行为。
- 定稿类型检查、源码构建和实库 Electron 流程通过。全量 Vitest 通过 1,360 个文件及 27,649 项，10 项按环境条件跳过。Windows 原生和安装包待验。
