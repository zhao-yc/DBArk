# SQLite 连续关联浏览（2026-11-04）

## 使用与本轮范围

SQLite main物理表的准确已保存行，从“更多 → 显示 → 浏览 SQLite 关联记录”打开独立关联浏览器。可写源页已有草稿时仍可进入，但根取值使用源页读取时已保存的原值；未保存的新行不开放入口，字段表单须先暂存或取消。原单层父记录、子记录和父键选择入口继续可用。

浏览器初始为父方向。用户可以切换父／子方向，明确读取当前方向目录，选择声明后再明确读取记录。选中结果的一行，点击“继续查看选中记录的父记录”或“继续查看选中记录的子记录”，进入下一位置；可以反复沿父／子方向前进。打开、切方向、换声明和进入下一位置不自动读取业务数据。

“返回上个浏览位置”和“前进到下个浏览位置”只恢复本地已读结果、当前声明、页码及选中行，不重查数据库。每个位置分别保存父／子两个面板的最后目录和最后一页；方向切回可直接查看已读结果。返回后另走分支会替换后续历史，旧按钮或旧网格不会接管新位置。选中行有文字提示，返回后可沿其继续浏览。

历史最多20个位置、保守序列化预算32MiB，含源页、目录及两方向结果。超限拒绝这次继续或结果发布，明确提示；不静默淘汰旧位置，不截断结果，也不自动重试。返回较早位置后可另走分支。历史仅在当前窗口内存中，不持久化字段值；关闭后销毁。

缓存不是当前数据库快照。每次明确读取仍由Main在独立只读快照中复核对应源／父／子结构指纹。返回后重读父页会强绑原缓存父hash；明确刷新当前目录才重建该父结构锚点。最初源页、行、连接、标签或Editor代次变化后，整个链永久撤权，须关闭并重新选择。所有关联页只读，保留最初源行草稿及原查询事务。

本轮不是多分支常驻关系树、ER建模或子页编辑。D05／R02和完整Navicat对标继续部分，暂不正式发布。

## 实现

- 纯Renderer新增SqliteRelationNavigator，复用原SqliteReferenceReader与SqliteIncomingReader，不增加SQL、路径或写入IPC。下一位置的typed值只由准确已校验结果页和原行捕获，沿原INTEGER／TEXT／BLOB合同，不解析格式化显示；不完整或大BLOB键继续按原输入预算拒绝。
- 每个位置用独立单调编号，视图带不可复活的revision对象。所有动作同时核根来源、当前节点、方向、准确页／行及revision；返回同一位置也不复活旧回调。历史节点的原值／结构漂移同样撤权，不借恢复相同对象重获读取权。
- 离开位置或切换方向时销毁旧reader，保留只读数据；返回后创建新reader。父页方法可显式传入原缓存父hash，继续沿Main原回包门核对。子页继续使用目录中原childSchemaKey，未放宽任何Main验证。
- 读取同步占位，原工作Promise登记后才发出视图通知或调用外部租约端口；随后微任务中获取准确根标签租约并发送原读取。未发送前关闭不取得租约、不发cancel；取得租约过程中同步重入关闭也等待原操作收尾。
- 同一时刻最多一个活动读取，busy时禁止切方向、导航和返回。取消与关闭等待原读取和准确取消ACK双方终态；ACK失败明确显示，不自动重读。关闭同步撤销新动作，卸载永久撤权并由原异步链归还租约。
- 历史不保存到settings／文件，不添加SQL历史。原Main只读worker、晚发布门、任务概要隐私及独立BEGIN／ROLLBACK／准确exit账本保持。最初编辑快照未被交接到后代页，浏览器没有预览或提交入口。
