# 备份归档文件接线与失败后停链

本片将已登记的备份计划、执行状态机、私有文件授权、流式 ZIP64 和真实 `AtomicFile` 接成同一文件端口。仍未接入主进程 IPC、原生 dump 进程或产品入口，不能据此声称整库备份已经可用。

`DatabaseBackupFileTargets` 只消费主进程私有授权表的白名单字段，严格核对备份目的、输出令牌、租约、修订、可写标记和产物令牌。路径不来自 renderer 的原始参数。首个目录归一化等待前登记有界记录，文件端和普通 CSV/JSON/XLSX 共用目标占用；旧回执不能释放后来任务的目标。授权一旦失效便永久停写，恢复旧值不能复活，原资源仍可按原 owner 清理。

计划中的最大字节数覆盖完整 ZIP（包括头和清单）。提交入口守卫拒绝且 rename 尚未发生时可清理本例临时文件；开始原子提交后继续沿真实发布事实保留未知，不能删除或提前归还占用。

组合反例发现：执行器等待归档打开超时后，迟到目标预留仍导致一次新文件分配。原失败报告 `run1437-late-target-original.json` 保留，SHA256 为 `14984c9d804cdb3b137f2473303884dad6c128c8dae344c40f13e4eadc7e5e73`。修复在保存原错误后撤销尚未提交任务的执行信号，迟到回包只能留给显式恢复；不将超时误报为用户取消。

Root 验证分层如下，不跨来源累加：

- `run1438-late-target-fixed.json`：7 项真实状态机及文件端组合 RAM 检查通过，包括同字节迟到反例、发布、授权撤销、未知关闭、预算和目标重用。
- `run1439-backup-execution-abort.json`：18 项执行与恢复状态机回归通过；类型检查通过。此前执行加恢复预检的 32 项属于上一固定来源，不能当成本次 32 项。
- `run1436-backup-commit-guard.json`：仅选中提交守卫拒绝反例，1 项通过、9 项未选。
- `run1432-backup-atomic-file-actual`：此前固定 `3c4d479` 的本例真实文件归档，合成 dump 为 892928 字节；.NET ZipArchive 独立读回条目和 SHA256。未连接数据库，清单明确保留 `allObjectsFrozen:false`、`resourcesConfirmed:false` 和 `restoreVerified:false`。

早先 `run1430` 的类型检查在 UUID 测试字面失败，`run1431` 更正后通过；`run1434` 在记录初始化的类型检查失败，完整初始化后的 `run1435` 通过。原失败文件保留，不改记为首次通过。`run1438` 命令还列出了两条不存在的旧命名筛选路径，实际报告只执行上述 7 项；随后按准确文件名另行取得 `run1439` 的 18 项结果。

真实工具认证文件权限、准确服务端会话与锁连续性、实际 dump、失败清理及恢复验证仍待接线。RAM 中的锁、来源和权限证明不作为实库证据；本片没有读取凭据或操作系统剪贴板，没有 SSH、Docker 或实际数据库操作。
