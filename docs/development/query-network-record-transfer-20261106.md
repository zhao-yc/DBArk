# PostgreSQL 和 SQLite 查询结果复制到 MySQL／MariaDB

在来源查询勾选要复制的行，点「暂存勾选结果以跨库复制」。打开 MySQL 或 MariaDB 的 InnoDB 目标表，从「更多」菜单选择「从暂存查询结果复制记录」。当前目标表已锁定。读取目标结构后，核对字段映射并明确填写解释目标 TIMESTAMP 的数值时区偏移。预览会检查所有勾选行，SQL 区显示有限样本。输入完整库名和表名并勾选确认后，才开始整批追加。

每批最多 100 行，按当前可见字段和显示顺序使用已返回值。重复列名按来源位置和内部键区分。大整数和定点数沿用原始十进制文本，字节按二进制参数传递。含负零、无穷大或 NaN 的数值字段只可映射到文本列或跳过。目标的范围、精度、长度、生成列、必填项和触发器条件沿用事务写入预检。

确认提交后清除本次暂存来源并刷新仍有效的目标页。取消窗口或预览失败时保留暂存内容。提交结果未知时，应先核对目标表的实际数据。

目标字段可能在打开窗口后发生改型。特殊数值的文本目标约束在界面和引擎均会核对，预览和提交使用服务器重新读取的表定义。

## 验收

- WIN11-TEST 不可达，按授权在 macOS arm64 使用 Node.js 24.17.0。原生运行时、类型检查和构建通过。158 项定向单测通过。全量单测覆盖 1,348 个文件，27,550 项通过，10 项按 Windows 条件跳过。Windows、安装包及其他数据库版本待验。
- PostgreSQL 18 和 SQLite 分别复制到 MySQL 8.4.11 与 MariaDB 11.4.13，共四个新增方向。各方向预览后独立读回仍为空，提交后目标为两条勾选记录，并核对表页刷新。无符号 64 位最大值、20 位小数原文、二进制字节、空 BLOB、NULL 和空文本均保留。SQLite 的负零在目标文本列读回为 `-0`，数值列未出现在该字段的映射选项中。
- 同批窗口回归 MySQL 和 MariaDB 到 PostgreSQL 与 SQLite 的既有路径，独立核对源记录保持、窗口正常退出和成功轮次隔离资源清理。
- 首次全量回归发现表页直接依赖 Zustand 会破坏隔离夹具，已改为由工作台订阅并传入。先前窗口轮次保留了菜单加载、空表就绪、隔离账号授权和 SQL 样本文字断言的失败记录。最终使用专用目标表的明确触发器目录授权，并按原预览的十六进制文本核对数值原文。
- 失败轮次的 16 个独占容器已逐一核对归属并停止，容器、数据和原日志保留。
