# SQLite 表格操作栏宽度与菜单

## 证据与变化

`199c5e4d` 的 Windows 原生回执中，聚焦使用 `preventScroll` 后菜单仍关闭。已核原始 ZIP 的摘要、CRC 与事件：关闭前的滚动目标准确为 `#root`，`scrollLeft=50`；表格和索引两例均有该现象。此前聚焦修正不足以关闭菜单失败项。

SQLite 表格过去把所有操作按固定单行排列，窄窗口会横向撑开应用。现复用查询页已有的 `AdaptiveToolbar`：刷新、停止、筛选、导入、当前页导出、完整导出与列布局按完整按钮宽度依次显示，放不下的动作进入“更多”；不换行、不压缩文字、不保留隐藏副本。普通 SELECT 生成进入原“生成查询”分组，其余原分组保持。

原按钮的处理器、禁用条件与危险操作确认逐字保留，未改 IPC、数据库任务、凭据、表页草稿或事务。AST 对照本轮前后全部 42 个按钮及处理器相同。打开菜单仍不读取数据库；旧目标失效及外部真实滚动继续关闭菜单。

## 验证边界

独立 `sqlite-table-toolbar-native.spec.ts` 验证 1024×680、300／600px 侧栏和明暗主题：根容器与工具栏不横向溢出、根滚动位置为零，Home／End／Escape 可操作，实际经溢出入口打开列布局且不增加数据库请求。新用例与原完整表页分别保留 120 秒、单 worker、零重试及失败现场，不共享或延长期限。旧分页、筛选、排序、重启及资源断言完整保留，依赖常驻按钮的测试仅改为真实菜单定位。

本机相关 24 份测试、462 项断言、30 项离线门检查、严格类型及构建通过。独立原生布局用例通过并独立核原件：四组合根宽均 1011px、水平位置 0；600px 侧栏时操作栏为 408px，无横向溢出；准确进程正常退出 0，合成数据原样，原临时目录不存在。已人工检查 300px 暗色与 600px 亮色原截图。

首轮把新布局断言加进原完整表页，布局断言虽通过，整例达到原 120 秒期限；该轮失败及准确合成目录保留，PID 已确认不存在，后续批次未执行。新增布局断言现独立执行，原完整表页仍按原期限验证，增加不含数据的阶段日志。首轮移出脚本命令转义错误未执行文件修改，修正后准确迁移，未删除原业务断言。

其它原生用例与三平台 CI 继续分别留证，不因本机通过外推 Mac 或安装升级。本轮 WIN11-TEST 会话不可达，按既有授权本机接续，不重复派发。无服务器、Docker、实库、系统剪贴板或用户安装配置操作。原件在 `.cache/action-menu-layout-20261102/`，失败目录不自动清理。

后续本机原完整表页、索引两例、完整四格式导出、编辑与导入分别通过，连同独立布局共 7 个不同原生用例。成功轮正常退出及准确目录核零按原 JSON 另行检查，不累计为完整发行验收。导入第二轮达到原 120 秒、原件保留，之后仅增加静态阶段日志和准确启动归属附件的第三轮在原期限内通过；不是自动重试，没有放宽断言，也不能据此宣称已证明首轮超时根因。表页第二轮保留原断言，在原期限内约 1.6 分钟完成。

未完成的 SQLite 结果逐格存储类型准备已按文件摘要与补丁保留在忽略目录 `.cache/sqlite-result-storage-20261102/wip/`，未混入本修复提交。菜单失败仍按原回执跟进，暂不发布。
