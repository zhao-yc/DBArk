# SQLite 已有外键编辑与失败说明

## 使用入口

在左侧普通 SQLite `main` 表上右键，选择“修改 SQLite 字段、顺序与外键…”，再明确读取目录。“SQLite 外键”区展示原声明、准确原 SQL 与待修改状态。

1. 点击新增、修改或标记移除；约束名留空表示匿名。每项字段映射独立选择本表字段、填写父字段，可增加、移除或上下移动，字段名中的逗号不拆分。也可明确选择省略父字段列表，使用父表实际主键。
2. 选择删除／更新动作和延迟检查方式；父表建议来自原完整目录，父键是否可靠仍由提交时的原生检查确认。特殊旧 `MATCH`、`ON INSERT` 或命名标记须核对原文并明确确认替换；不修改的约束保留原文。
3. 点击“暂存 SQLite 外键修改”，然后与字段、默认值和实际列顺序共同预览。编辑中未暂存的输入会阻止整批预览；取消本次输入保留已有队列。撤销草稿只改本地队列，不修改原库。
4. 核对生成 SQL、外键修改数量和额外外键风险，输入准确原目标后提交。只读连接允许设计和预览，不能提交。

关闭、重新读取前保护已暂存及未暂存输入；当前输入与目录一起失效，不跨连接、目录或表单复用。预览后输入变化立即撤销旧能力及确认。回滚保留草稿，必须重新预览才能再提交；结果未知仍永久锁定原批，禁止自动重放。

## 实现与诊断

界面复用[已有 Main／独立 writer 链](sqlite-foreign-keys-engine-20261102.md)，没有新增数据库命令或任意 SQL 通道。外键以原声明顺序和准确原 SQL 定位，匿名、重复名称和重复关系不合并；输入及有序映射使用独立身份，重排或移除后迟到事件不能修改另一行。暂存先试编译完整本地外键队列，命名冲突、未知字段或预算超限不部分写入。

现有目录、期限、连接代次、草稿占用、独立事务、全量逐值比较、非目标对象、具体违规行及真实 COMMIT／ROLLBACK ACK 保护保持。仅在获得整批回滚回执后附加固定中文检查类别：计划与原生定义不符、无法检查可靠父键／完整关系，或出现新的违规行。未知结果和原非外键失败保持原事实，不从驱动错误中提取业务值、SQL、文件路径。持久任务概要仍使用原静态事实文案。

本轮另修复异常预览回包能力未立即释放，以及确认回滚后的具体说明被通用回执覆盖的问题；只有同原目标、数量和完整事务事实的合法结果可保留该说明。
