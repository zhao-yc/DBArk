# TXT 文件导入

在 MySQL、MariaDB、PostgreSQL 或 SQLite 的可写表打开「导入数据」，或者在数据库节点打开「从文件导入新表」，再选择「TXT 文本」。

1. 选 UTF-8、UTF-16 LE 或 GB18030，按原文件选择记录换行，也可自动识别。
2. 对于分隔文本，选择 Tab、逗号、分号、竖线、空格，或输入 1 至 8 个字符的自定义分隔符。可用双引号或单引号包住包含分隔符和换行的值，在字段内把同一引号写两次。若原文件不使用引号，选择「无」。
3. 对于固定宽度文本，按列顺序填写逗号分隔的宽度，例如 `8,12,20`。宽度按 Unicode 码点计数，每条记录须恰好等于宽度总和。每行最多 1,000 列，宽度总和最多 65,536。需要去除两端填充时，勾选「去除字段两端填充空格」，该选项仅移除 ASCII 空格。
4. 若首行是字段名，打开表头选项。字段名须非空且唯一。无表头时，从「第1列」开始按位置映射，首行作为数据导入。
5. 选择 `.txt` 文件，核对样本、源列、目标字段及字段类型。按界面提示预检并确认。新表流程先确认建表，之后再确认写入数据。

空字段保留为空字符串，`\N` 表示 NULL。以反斜线开头的普通文本用额外一个反斜线转义。映射到支持此语法的二进制列时，可用 `base64:` 前缀传入 Base64。预检发现编码错误或行宽不一致时会停止。已绑定源指纹的导入流程会核对原文件，避免把改动后的源数据写入目标。新表已创建而数据写入失败时，可在原表上重新配置导入。

MySQL 和 MariaDB 支持 InnoDB 的整批预检和按键处理。PostgreSQL 的普通表和分区表可直接追加，有合适的匹配键时也可按键处理。SQLite 使用现有的普通表预检与追加流程。

分隔文本与固定宽度布局参考 [Navicat 导入向导](https://www.navicat.com/manual/online_manual/en/navicat_18/win_manual/import_wizard.html)。
