## 使用与预算

SQLite可编辑表的整行或单元格表单，字段选择“二进制（十六进制）”后，可使用Hex、按编码查看文本和图片预览，或“从文件载入字节／原字节另存为”。载入只改变当前表单缓冲，取消不产生修改；“保存SQLite本地草稿”仍仅暂存，须再经过原SQL预览和明确提交。

SQLite修改合同维持每个BLOB最多32768字节，不扩大IPC或引擎预算。超限文件整次拒绝，原缓冲保留，不截断；通用文件读取入口最多131071字节，SQLite表单在交付缓冲前再次执行自己的较小预算。文件读取成功但SQLite预算拒绝，不表示数据已载入或暂存。Hex允许开头0x和空白，暂存时仅对BLOB去除这些显示字符，原大小写保持；未完成或非法Hex留在缓冲，最终由原SQLite合同拒绝保存。文本、整数和REAL不走这种规范化。

空文件明确成为零字节BLOB，不等于NULL；NULL仍须通过原类型选择。新增未勾选字段继续代表省略／数据库默认值。生成列及超过编辑预算的已有BLOB只读，不从分页片段生成草稿。完整原值最多2MiB可分页Hex、严格文本解码、受支持的静态PNG／JPEG／WebP图片预览及原字节另存；超过完整查看预算只显示错误，不误标为DEFAULT。

只读表页及视图中的实际BLOB可双击或按Enter打开原二进制查看器，再另存已加载的完整字节。此入口没有载入或数据库写入能力，不重读表页；SQLite声明类型不能把实际NULL或TEXT变成二进制原值。任意查询结果原路径保持，离线全局快照窗口的限制也没有放开。

## 接线与来源

新增 `sqliteBinaryInput.ts` 统一BLOB缓冲预算／规范化及完整原Hex编码，编码前先界定查看预算。`SqliteBinaryField` 复用现有 `BinaryCellViewer` 的Hex、文本、图片、文件、字节预算与Blob URL收尾；大值按完整原字节编码，显示分页从不作为另存或暂存数据。

表单字段绑定准确输入票据、原页／行、字段位置和原缓冲对象；真实文件动作仍检查已提交的渲染代次、原父租约和唯一模态，关闭、换字段或来源失效后旧文件回包不能污染新输入。只读表页另存绑定准确页、连接／标签、修订及结构来源，不借本模态已撤销的普通网格选择提升权限。文件操作复用原Main受限IPC及原子文件替换，没有新增IPC、数据库接口、持久化格式或依赖。

首次真实窗口发现子查看器在父layout effect提交事件票据之前计算按钮，造成入口永久禁用。共享查看器新增可选 `isAvailable` 只判断显示状态；点击及异步交付仍必经原 `isCurrent`。新增反例明确核对：即使按钮显示可用，过期事件票据仍发送零文件命令；原调用方不传新参数时行为保持。
