# 格式化入口沿用模型EOL合同

基线为 `67eec19c2d352b19f66ce378d945aabf99d67f68`。真实SQL文件观察显示，Main草稿保留LF时，Monaco模型可以使用CRLF。正文桥原有合同会把外部props的换行映射到模型EOL，并且不把这次等价同步回声为用户编辑。因此，未编辑的同一草稿在Main与模型中可以不满足原始字符串相等。

原 `QueryTab.formatQuery` 在调用格式器前直接比较这两个字符串，会拒绝这类正常草稿。固定父提交的真实正文桥与实际formatQuery函数已在RAM端口复现：CRLF模型就绪、零正文回声、零受控编辑，但格式器未进入；LF模型同一场景可进入。这是入口比较与原桥接合同不一致，不应靠测试预改正文、设置dirty或全局改变模型EOL绕过。

本片只调整格式化准入：要求模型明确声明LF或CRLF，将当前草稿的CRLF、CR、LF映射到该已声明EOL后，仍逐字比较模型全文。空格、标点、其它字符及缺失换行均不能被等价化。比较不回写任何正文；后续选区/全文格式化继续消费原模型，使用原executeEdits和两侧undo stop，既有存活owner、活动标签、忙态、版本、模态与延迟结果墓碑保持。

新增24项真实QueryTab/ReactDOM RAM回归覆盖按钮和快捷回调、LF/CRLF双向差异、默认保留及显式upper/lower、混合换行选区、真实正文差异拒绝和未知模型EOL拒绝。父版为14失败、10通过（原54项按名称过滤未运行）；修后连同原UI54项、正文桥、格式器、延迟意图和快捷键共149项通过，零跳过。原正文桥/formatter/deferred/来源文件实现字节不变，不改Undo策略或原来源引用。

本轮只运行RAM组件/单元回归和类型检查，没有GUI、Electron、Playwright含list、文件来源实际保存、端口/网络、数据库、CI或依赖安装。用户文件与原来源字节没有被本片读取或改写，不能据RAM宣称原生LF文件场景已验收。Root整合后仍需真实打开LF文件、按钮及快捷格式化、撤销/重做、来源dirty/保存/外改保护的原生复核。只创建本地中文 `[skip ci]` 提交，不推送。
