# SQLite 跨页草稿工作区（2026-11-05）

## 本批行为

SQLite可编辑表现在在同一标签内保留各页的准确Editor、原页快照、修改及撤销／重做历史。普通分页、跳页及整行表单的相邻页导航不再因已有草稿而拒绝；返回保留页直接恢复原Editor，不重新查询或用新读值覆盖旧草稿。底部“SQLite 多页草稿”显示保留页数、全部修改数及各页返回入口，当前干净页也可“预览 SQLite 修改”，统一预览全部有修改的原页，再明确确认一次提交。

整行表单有合法未暂存输入时，边界按钮明确显示“暂存并查看上一页末条／暂存并查看下一页首条”；先保存到原页草稿，再切页。非法JSON／HEX保持输入且不读取下一页。普通表分页不能绕过打开的输入或预览窗口；旧表单、菜单及迟到回调没有新页操作权。这里的暂存仅修改内存，不写数据库。

统一提交复用[上一批的多页事务底层](sqlite-multipage-edit-core-20261105.md)，不新增IPC、不改变数据库驱动架构。成功后清全部保留页并读取当前偏移；确认整批回滚时保留各页草稿，须明确重新预览。发送后结果未知锁住整个工作区，禁止换页重复提交，应先独立核对数据库。

刷新、改变页长、应用新筛选／排序及表头排序需要确认放弃全部保留页；取消保持输入。普通切换标签不重读有保护历史的原页。结构、连接配置／版本、标签身份或已应用查询漂移会撤销旧来源资格，恢复相同引用或内容也不复活。过期或失效草稿保留供核对，不能自动换新快照重试。

## 生命周期与边界

最多保留16页；只淘汰无输入、修改和撤销／重做历史的干净页。16页全部受保护时，在读取第17页之前拒绝，不静默丢历史。全部页共用500条变化、10000格、2MiB预览输入预算，超限不提交部分页。原单字段、快照期限及后端内存预算保持。

SqliteEditWorkspace以同一已应用查询对象和内容、准确offset／limit及每页元数据登记Editor。活动Editor独占当前界面，后台Editor只更新全组状态。Browser.restore只恢复自己交接且目标仍有效的原页；Editor是快照唯一释放拥有者，Browser.forget只移除展示票据。明确放弃、成功提交或卸载才清整组，运行中的取消仍等准确终态。

组合预览捕获完整成员、各页rows引用及来源元数据；第一份有修改的页作为主组，其余放additionalPages。回包须完整回显snapshotIds及原目标／结构；来源变化或迟到回包释放准确旧预览，apply前再核全组。无修改旧页过期不阻挡其它页计划，但参与页及发起页必须有效。结果unknown扩散到全组，迟到旧Editor不能锁住新工作区。

分页缓存是各次真实读取的原页，不是整个结果集的数据库快照。外部增删可能导致offset分页重叠，后端按原可靠键拒绝重复修改；不会自动合并、重基或覆盖原值。末页定位仍可能实际读取；返回同一已保留偏移时保留旧Editor。各页原row编号仅属于各自snapshot，不能拿某页row=0修改另一页。

草稿只在当前表标签RAM内。关闭／重启不恢复未提交输入，也不重放预览或写入。尚无逐页剔除、自动重新绑定／重基、其它驱动同等工作区、完整持久恢复及批量表单；D04／R02与整体Navicat对标继续部分覆盖，暂不正式发布。
