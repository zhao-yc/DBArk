# 保存查询列表直接重命名

## 操作流程

打开“历史查询”，切换到保存查询列表。在准确记录上点击“重命名查询”，填写新名称后确认。操作仅改本机保存名称，不打开数据库或执行 SQL。

名称最多 256 个 UTF-16 单元，保留有效 Unicode 和首尾空格；全空白、控制字符及孤立代理字符拒绝。不同记录可以同名，编号不会因此合并。按 Enter 确认；输入法组合期间不提交。按 Escape 先取消名称草稿，保留父列表。

成功后刷新当前筛选／分组的第一页，只移除改名记录的旧勾选，其它勾选保留。若名称已保存而列表刷新失败，界面明确显示已保存并要求手动刷新，不自动重放。

## 数据与并发边界

- `queries.renameChecked` 仅接收 `id`、完整原记录摘要和新名称，由 Main 调用本地存储；渲染器不传 SQL、连接或路径。
- 同一 SQLite 事务内重读并核对摘要，只修改 `name` 和 `updatedAt`。SQL、记录编号、来源连接、四类默认库上下文及分组成员保持。
- 更新时间严格推进，冻结或回拨时钟下的 A→B→A 改名不能恢复旧摘要。极端日期溢出拒写。
- 原子发布失败恢复内存和磁盘，查询库修订不推进。成功才使原搜索／分页游标及组织 CAS 失效。
- 已打开编辑器的正文、标题及来源绑定保持；旧来源的覆盖保存会按原摘要冲突处理。需要覆盖新来源时重新打开，或将现有草稿另存。
- 本功能不重命名磁盘 SQL 文件，也不改变文件来源绑定。
