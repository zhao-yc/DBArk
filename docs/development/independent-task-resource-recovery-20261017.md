# 独立任务关闭失败后的资源隔离

原`7a423`的独立任务在动作失败且连接关闭失败时，只保留原动作错误，动作等待者结束后删除任务并释放目标锁；主连接和取消控制连接的物理资源没有后续显式恢复入口。独立RAM原件保留，未把它作为真实服务器泄漏实证。

本批先整合员工3的`69b9b0c`资源证明端口及`48f7afc`登记时机小修。零网络分配的SSH私钥读取失败和期间取消，不再等待从未connect的Client派发close；已经开始的SSH、迟到channel和TLS换流仍分别观察真实终态。原两反例及最少正常门独立2+9项通过，交接SHA256为`62635933b454c676343528dd8e3f945e7326687a933003dbcd8734f1a126ec9b`，原69b红件保留。

Root新增有界RAM账本：独立任务在首次网络分配前预留容量，登记主物理连接及取消、停止控制连接。动作完成与资源释放分别结算，原1062等动作错误保留；资源未知时唤醒动作等待者，但保留原任务编号和整个执行目标集合，不能重新取得相关目标或修改连接认证。资源正常则一次释放，不以destroy调用、取消ACK或主流关闭代替全部资源终态。

只有用户显式断开或退出才请求有界恢复，直接触达原资源facade，不重试已经拒绝的close Promise或数据库写入。恢复并发合并，超时保留账本；控制连接分配后失败也捕获原facade。同连接断开期间拒绝新分配。账本最多64个独立任务、每项4个物理连接facade；清单扩张未知或缺少关闭失败后的物理证明不能凭超时释放锁。对未提供facade的旧内部RAM端口，仅保留其正常严格关闭合同；注入关闭失败后退出必须承认资源未知。

本地必要相关集11文件312项通过、0跳过，类型通过，报告`run1385-independent-host-related.json`的SHA256为`7af6d1b1252c0df804fc14cf66f9942d73cfb67427c8bfd212b44832d32af4e3`。新增真实host/RAM反例覆盖1062与close双失败、全部父目标锁、动作等待者独立结束、ManagedConnection返回前失败、控制连接分配失败、容量分配前拒绝及显式恢复；资源账本另覆盖永不落定端口的host预算、迟到分配和清单溢出。
