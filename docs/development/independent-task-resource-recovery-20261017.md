# 独立任务关闭失败后的资源隔离

原`7a423`的独立任务在动作失败且连接关闭失败时，只保留原动作错误，动作等待者结束后删除任务并释放目标锁；主连接和取消控制连接的物理资源没有后续显式恢复入口。独立RAM原件保留，未把它作为真实服务器泄漏实证。

## 普通退出不能丢弃隔离账本

固定`c3ca8df`的独审另复现P2：Engine正确拒绝未知资源退出，但Broker吞掉拒绝并终止执行进程。原6组RAM诊断及报告保留，SHA256为`7e4dfcb1a51d83d2e06db354453ecd73d0e272acabc2c6cc2937b3aec4307575`。本批普通退出只在真实shutdown成功ACK后终止进程，拒绝或3秒超时保留同一引擎，迟到ACK不能自动变成kill，并发退出合并。意外进程退出仍通知主进程。Engine失败时恢复显式断开入口，已关闭的查询会话不继续复用，未知账本和配置保留；不重新执行动作。

产品异常退出提示把“返回工作台”和“强制退出客户端”分开。只有用户明确选择后才调用独立强退入口，说明本地终止不能证明远端操作结束或撤销已提交操作；kill明确失败时仍返回工作台，不假报成功。没有调用本轮旧原生窗口或终止任何实际进程。
