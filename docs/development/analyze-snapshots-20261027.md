# 实际执行计划快照

## 使用流程

在查询工作区完成“实际执行分析”后，点击“保存计划快照”。通过工作台“打开计划快照”选择文件，可离线查看此前的 MySQL TREE 或 MariaDB JSON 实测计划，再“另存计划快照”。打开文件不会连接数据库或再次执行分析；估算计划与实测计划有明确标识。取消选择或文件校验失败时，保留原计划与阅读状态。

文件沿用 `.dbark-plan.json` 扩展名。实测文件使用独立的 `dbark.analyze-snapshot`、版本 1；旧 `dbark.explain-snapshot` 版本 1 的 JSON／文本估算文件仍受支持。旧版本程序不能读取新实测文件。程序按声明格式分别展示，不自动把估算文件转为实测；可编辑的文件不提供来源真实性证明。

## 数据与文件边界

文件只保存有界的服务器原文、结果容器、来源版本、格式和完整性标记，不主动写入原 SQL 字段、连接配置、凭据、会话或活动事务状态。计划条件和表达式仍可能包含业务字面值，保存或分享前须检查。原始指标保持文本精度，不把成本当作耗时，也不把不完整计划解析为完整树。

通用快照入口严格校验声明字段、对象和稠密数组、原文与单格结果的一致性。沿用 1MiB 文件预算、192KiB 原文预算与严格 UTF-8；未知版本、未知格式及超限明确拒绝，不自动裁剪后保存。离线显示按原文重新解析，另存始终使用原文件文档，新增诊断不会回写或挤占原文件预算。

IPC 仍使用受限 `explainFiles.open/save`，渲染进程不能指定路径。Main 保留原单句柄读取与前后文件身份校验、归属和共享锁、同目录独占临时文件、同步与原子替换；文件故障不自动重试或宣称成功。保存期间保留阅读位置，来源换代或 A→B→A 后不发布旧回执。
