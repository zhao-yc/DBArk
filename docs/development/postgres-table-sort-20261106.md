# PostgreSQL 表页多列排序

在 PostgreSQL 表或视图的记录标签点击「多列排序」，添加至多 20 个字段并选择升序或降序。用上下箭头调整优先级。每个字段可独立选择 NULL 置前、置后或数据库默认。按 Ctrl 或 Command 操作列头可添加或调整次级排序，列头的数字显示各列优先级。

点击「应用排序」后保留当前筛选，从首页按新顺序读取。全量导出沿用该顺序，即使导出列中未包含排序字段。点击「取消排序编辑」可保留当前页与顺序，应用空排序列表可恢复默认浏览顺序。有待提交的跨页记录草稿时，先提交或放弃草稿再改排序。

比较由 PostgreSQL 执行，包括数值精度、文本排序规则和 NULL 位置。数据库默认升序将 NULL 放在末尾，降序放在开头。[PostgreSQL ORDER BY 文档](https://www.postgresql.org/docs/18/queries-order.html)

同值时沿用原有分页键，优先补全主键列。无主键普通表沿用 `ctid`，无主键分区表沿用 `tableoid` 和 `ctid`。缺少稳定分页键的关系仍会显示提醒。每次翻页和导出各自读取数据库当时的快照，期间数据库的并发改动可能改变行的位置。旧单列请求保留原排序行为，等价新规则可继续使用已保留的原页。

## 验证

- macOS 上 Node.js 24.17.0 运行时检查、类型检查及源码构建通过。首轮类型检查发现原生测试局部变量重名，修正后重新检查和构建。
- macOS 完整单元回归共 1,326 个文件，27,455 项通过，10 项 Windows 系统 tar 用例跳过。
- Server-200 独占 PostgreSQL 18 实库回归 5 项通过。排序场景核对了引号列名、两列独立 NULL 位置、NUMERIC 末位差异、并列时的主键顺序、旧请求兼容、草稿保护、非法规则拒绝，以及只输出非排序列的 JSON 与 COPY 导出。两轮实库运行均独立核对原表与零连接，随后清理独占容器。
- macOS Electron 原生窗口回归通过，共 64 项观察。新增场景覆盖列头键盘排序、多列优先级、NULL 位置、应用后回首页、翻页、取消、清空以及暂存记录时锁定排序。已检查面板截图及临时用户目录清理结果。
- Windows 测试虚拟机不可达，本轮在 macOS 验证。Windows、两平台安装包及较早 PostgreSQL 版本待验证。
