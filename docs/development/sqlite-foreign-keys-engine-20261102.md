# SQLite 已有外键管理：Main 与独立事务

后续界面入口、草稿保护与可读失败说明见[已有外键编辑记录](sqlite-foreign-keys-ui-20261102.md)。下文保留本阶段的实际范围与原验证结果。

## 本轮实现

继[声明编译](sqlite-foreign-keys-plan-20261102.md)后，外键补丁已贯通原 Main、Runtime、能力仓库和独立 writer。现有重建预览新增严格可选的 `foreignKeyEdits`，输出明确的 `changedForeignKeys`；仍为原四命令，不接受任意 SQL、文件路径或原始配置。可仅编辑外键，也可与字段类型、默认值和实际列重排共同预览。

本轮没有新增界面编辑入口，不能算用户已可用的完整外键管理。现有字段／默认值／重排入口保持；外键界面、可读失败诊断和新 GUI 验收继续实施，主键设计另行继续，暂不发布。

Main 从原只读目录独立编译 SQL、风险和变化数量，再对照 Runtime 回包；Runtime 保留原文件、配置代次、目录及期限保护，复制保存外键补丁并计入预览内存预算。领取后修改补丁不能通过执行前完整重算，不把关系名称、SQL、路径或业务行写入持久任务概要。

## 事务与完整性

writer 仍在原独立连接的写锁内读当前完整数据，以原四次逐值比较核对普通／生成列、字节、精确值和真实行身份。实际新增／替换／删除的外键先进入编译候选；移除私有序号后，完整 native 候选 SQL 必须与确认计划相符，随后读取候选的完整原生外键目录。最终表的目标外键必须对应此目录，其他表外键、索引、触发器、视图、序列、对象原文和根页继续保留原检查。

目标表原生外键编号可因编辑或重排改变，因此按完整原生约束语义核对，并保留重复约束的多重性。完整 `foreign_key_check` 和具体 rowid／WR 主键身份必须通过：无法对应原具体违规的新错误、同数换关系／换行、重复坏约束增加、缺失或非唯一父键均整批回滚。可移除坏引用修复原不可检查关系，但最终不能留下不可确认的外键检查。

预览之后合法数据变化不自动使目录失效；提交读取写锁内全部当前行，新增孤儿数据同样拒绝。回滚保留外部在预览后写入的数据，不回放旧快照。原 COMMIT／ROLLBACK ACK、未知结果不重放、保护模式恢复和 close ACK 规则保持。

## 本轮验证

WIN11-TEST 不可达且未派发，按既有授权回退本机 Windows，只用独占合成 SQLite 文件：

- 严格类型、构建及 20 份／516 项相关回归通过，涵盖旧字段重建、实际列重排、完整比较、Main、Runtime、UI 和任务保护；未提高原超时或重试。
- 新增 14 项真实 worker 用例，其中两项实际贯通 Main → Runtime → worker，验证 WR 有效／孤儿关系提交或回滚及任务隐私。另覆盖新增、自引用与未来 CASCADE、替换、删除、原坏关系修复、原具体违规保留、同数新关系／重复坏约束拒绝、WR 复合隐式父主键与父 NOCASE、类型及重排组合、错误父唯一性、领取后补丁篡改及预览后外部新增数据。每项在外层清理之前确认全部原 worker exit 0、kill 计数 0。
- 新增两项 Main 协议与一项严格合同测试，核对纯外键预览、双重重算、篡改变化数量拒绝／准确释放、任务隐私和无额外 SQL 输入。
- 原 Windows 字段重建两整例通过：成功提交 22.5 秒、精度拒绝回滚 12.3 秒。原 spec、全部断言、120 秒、单 worker／零重试未改；两份成功及一份回滚 SQL 预览仅随机私有标识不同。17 个受观察 worker 全部 exit 0；能力分别 4／4、2／2 准确释放，原数据、完整性及真实 ACK 已审。
- 应用 PID 29228／43336／38768／48536 正常退出 0；准确目录 `dbark-e2e-Q7T7G8`／`dbark-e2e-kctUjT` 和四个准确 PID 独立核零。原生用户查询执行／会话及系统剪贴板均为 0，没有访问 Server-200 或已安装客户端配置。

首轮两个新夹具失败保留：完整视图读取需明确启用 BIGINT 精确返回；故意缺父表的坏数据需在夹具插入时明确关闭外键检查。仅修正夹具，原断言保持。失败数据库与原日志按原规则保留；最终日志、退出码、完整 JSON 与独立审计位于忽略目录 `.cache/sqlite-foreign-keys-engine-20261102/`。原 React／构建警告保留。
