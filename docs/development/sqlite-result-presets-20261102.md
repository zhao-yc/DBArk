# SQLite 查询结果命名整理方案

## 使用

查询结果的“更多结果操作 → 结果整理 → 整理方案”现支持 SQLite。使用原命名方案窗口保存、覆盖、重命名、删除及应用，方案仅存本机，包含筛选原值、完整字段、可见顺序、多列排序与冻结边界，不包含结果行或 SQL。

预览明确显示 TEXT、INTEGER、REAL、BLOB 类型及“其它非 NULL 存储类型”判断；精确整数、字节、NULL、嵌套 AND／OR 和停用原文完整保留。应用只处理当前已返回行，不重发 SQL，不恢复事务或重放写操作。

方案限同一连接，当前完整字段及可见顺序必须匹配。原已返回结果或版本 2 离线快照均沿实际逐格类型试算筛选与排序；类型未知、无效条件或超预算拒绝整次应用并保留原视图。成功只记录一整步筛选／排序历史；冻结范围仍按原方案规则在列管理中调整，不宣称整理撤销同时撤销冻结。

## 来源保护

复用原 Main 文档绑定、连接摘要、修订 CAS、容量和错误流程。SQLite 摘要包含数据库路径、只读模式及等待时间；变更后旧请求失效，旧包不能通过恢复原值复活。保存项与当前连接内容不符时不直接应用，可用当前整理明确覆盖；新读取仍须拿当前来源及修订。

打开及回读后均核对原结果、连接、模态与双视图身份；旧窗口、忙态或迟到回包不能覆盖下一份结果。筛选与排序共同试算成功后才发布，不放宽 IPC、写操作、凭据、存储格式或原 MySQL 入口。

## 本轮验证

WIN11-TEST 本轮主机不可达且未派发，按既有授权回退本机。类型检查、构建及 59 份 1719 项相关测试通过；新增真实 SQLite 配置文件重启读回、SQLite 连接三项配置变更及 CAS 拒绝，以及真实 React 预览／保存／回读应用用例。原 MySQL、筛选、排序、历史、方案和快照回归保持；原 React act 与构建警告保留。

Windows 源码原工作区整例 33.6 秒通过，真实入口保存、重命名、共同恢复筛选排序、一次撤销／重做，以及新进程从本机方案应用到原类型快照并准确删除均已验证；原事务、快照与草稿恢复断言保持。原 120 秒、单 worker、零重试未改，已检查本例类型及排序预览截图。

独立核对两个 owner 与候选版的数据库命令序列完全相同，仍为四次 SQL、worker 为 6／2，拒绝列表为空。方案操作仅新增本地 list／save／rename／read／delete；两个原进程正常退出 0，准确进程及临时目录核零，系统剪贴板操作为 0。

原日志、退出码、JSON 和审计保留于忽略目录 `.cache/sqlite-result-presets-20261102/`。不使用 Server-200、真实业务数据、系统剪贴板或已安装客户端配置，不创建 Release。当前方案增量的 macOS、安装包及系统对话框未在本轮验收，既有失败保持独立。
