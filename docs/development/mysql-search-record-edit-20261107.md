# MySQL 和 MariaDB 从搜索命中编辑原记录

在「工具 → 全库搜索 → 搜索数据」找到表记录，双击打开命中详情。有完整原行证据时，可点击「编辑命中记录」，在独立表单修改字段。预览 SQL 后勾选确认，提交结果由普通表格的事务回执记录。TIMESTAMP 按 UTC 编辑。原表格标签与草稿可以继续独立使用。

搜索时在服务器为匹配行计算完整值摘要，浮点数使用二进制协议保留精确值。进入表单和预览时复核服务器、InnoDB 表实例、表定义、可靠键和完整原值。提交时重新复核并锁定原行。UPDATE 继续使用完整原值条件，并使用搜索的精确键表达式处理大整数、时间键和二进制键。普通表格的其它操作继续使用原有预览和提交链。

编辑沿用已支持的精确定位范围，要求非分区 InnoDB 表、可读可靠键、整行读取权限和普通表格的可靠键一致。原始值合计预算为 128 KiB，完整编辑回包上限为 1 MiB。不具备完整证据时仍可搜索或只读定位。相同键值和完整列值被删除后原样写回时，现有 MySQL 和 MariaDB 接口以等值原行处理。

## 2026-11-07 验收

- Windows 测试虚拟机不可达，本轮采用 macOS arm64 源码 Electron 和 Server-200 回环隔离实库。
- MySQL 8.4.11 与 MariaDB 11.4.13 各通过一项源码桌面专项。验证原表页草稿保留、完整原值检查、预览与显式确认、事务回执和相邻大整数主键的准确更新。数据库只更新命中行。
- 搜索后改动未选的相邻浮点值会使旧命中无法打开编辑。预览后改动 BLOB 会阻止写入。错表、删除、伪造原值及用普通提交绕过搜索引用均被拒绝。
- 首轮用例修正了 SQL 预览中的标识符引用断言。随后复验发现新的完整行读取需捕获窗口身份，接入主进程捕获和凭据绑定后双引擎通过。两种引擎的隔离数据库和会话归零，容器和回环转发已清理。
- 最终类型检查和源码构建通过。MySQL 原生搜索及编辑 8 项、MariaDB 原生编辑 1 项通过，编辑用例核对了切换字段后仍保留已输入内容。全量单元测试 27,659 项通过、10 项条件跳过。Windows 和安装包仍待验收。
