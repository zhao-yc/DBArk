# 查询结果 HTML 导出

## 使用入口

- 已返回结果或勾选行选择「HTML 网页」，可导出当前快照。原结果发生截断时，网页显示提示。
- SQLite 和 PostgreSQL 可以从单个选区、全文或光标所在语句打开完整导出。数据来自独立只读连接，可将 HTML 格式保存为命名方案。
- MySQL 和 MariaDB 的「新执行并完整导出」将同次执行的各组结果和回执按序写入一个网页。点击确认后按原会话和所选协议重新执行 SQL。取消文件导出时，已执行语句的影响依其事务状态处理。

HTML 是 Navicat 导出向导支持的格式之一。[Navicat 导出向导](https://www.navicat.com/manual/online_manual/en/navicat_18/win_manual/export_wizard.html#export-data)

## 文件内容

网页固定使用 UTF-8，内置样式，保留列顺序、精确数值文本和空结果表头。NULL、空字符串和 Base64 二进制分别标识。表头和数据按文本转义，NUL 等不可见控制字符以可见的 Unicode 转义标记显示。文件声明内容安全策略并阻止外部资源加载。

完整导出按行写入同目录暂存文件，沿用原有文件授权、字节预算、取消及原子发布。HTML 按转义后的长度限制单字段 8 MiB、单行 16 MiB。超限或取消发生于发布前时，保留原目标文件。

## 验收

- macOS arm64 使用 Node.js 24.17.0。原生运行时、严格类型检查、源码构建和 434 项相关单元测试通过。
- SQLite 原生窗口验证 1,205 行完整查询及勾选快照导出，核对精确大整数、负零、NUL 和二进制。勾选快照导出期间查询历史保持原样。
- PostgreSQL 18.6 的两个原生用例验证 4,099 行、重名列、精确数值和取消时保留原文件。SQLite 与 PostgreSQL 的既有 CSV、JSON、Excel 或 INSERT 用例随各自测试运行。
- MySQL 8.4.11 与 MariaDB 11.4.13 各通过两项原生用例。每种实库都核对 HTML 的三组结果、空表、写入回执、恶意标签文本和一次执行，以及 CSV ZIP 回归。首轮定位到流式导出弹窗在收到相同选项事件后可能保留旧闭包，修复配置版本的界面更新后复测通过。
- 服务端用例使用 Server-200 的隔离回环容器，确认容器和转发已清理。Windows、macOS x64 和安装包待验，覆盖矩阵 Q05、R01、R02 仍为部分覆盖。
