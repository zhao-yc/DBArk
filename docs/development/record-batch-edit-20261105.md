# MySQL／MariaDB 勾选记录逐条批量表单（2026-11-05）

## 当前行为

接续[SQLite逐条批量表单](sqlite-record-batch-20261105.md)，MySQL／MariaDB 可写表页新增“批量编辑勾选记录…”。在当前页勾选已有记录或新增草稿，从工具栏／“更多”打开独立窗口；上一条／下一条只经过勾选记录，不自动读取新页。每条可以填写不同值，完整复用原 RecordFormPanel／useRecordViews 的字段表单、只读整行JSON、整行输入、词法树和二进制控件。

“保留本条输入”仅保存窗口RAM。切换或改变输入方式遇到尚未保留输入时，沿原三选守卫选择保留后继续、放弃本条未保留输入或留在原处；提示前置并主动聚焦，不藏在长表单末尾，不叠第二层Modal。放弃本条未保留输入会回到本窗口最近保留值；取消全部则整组窗口输入不进入原页，原已有草稿保持。

“暂存全部勾选记录”先沿原模型验证当前字段／整行／节点输入，再验证所有候选和原页来源，最后只setRows一次。整组变化形成原DraftHistory的一步undo／redo，未勾选行保留原引用，已有草稿与original定位保持。任一后行、字段、来源或预算无效时不发布前半批，输入可以修正。无差异返回原页引用，不制造撤销步骤。

暂存不调用table.preview或table.apply。最终仍经原SQL预览、取消／返回编辑以及明确确认提交，原InnoDB事务、完整旧值乐观检查和未知结果处理保持。窗口未保留文本与已保留候选均进入标签退出dirty保护；取消后重新计算真实原页dirty，不留下伪未保存状态。关闭／重启不自动恢复本窗口未暂存输入。

## 类型、来源与预算

原大数、DECIMAL尾随零、微秒日期、TEXT中的重复JSON键／指数／NUL／Unicode、空BLOB、NULL和空文本按现有协议保真。新增行可用DEFAULT省略字段；已有行不能省略。生成列只读。普通完整表单可以明确修改已有键，数据库定位继续使用原original，唯一性与权限仍由原预览和服务器裁决。

RecordBatchEditIntent捕获原全页数组顺序、真实行与data／original引用、准确勾选集合、连接修订、加载代次、完整目录与表页绑定，再生成独立冻结窗口基线；不会冻结真实网格。原地替换行、外部字段变化、选择／连接／目录ABA、忙态或外来模态均永久撤权，恢复相同ID或引用不能复活。父级只接受唯一自身marker，旧票据／保存／关闭不能接管后来窗口。窗口各render另签回调身份，返回同一行号也不复用旧change／save／node／document／file事件。

只编辑完整当前页，不补取缺列。完整目录绑定和全部旧行仍需与原页相符；复制补取租约不参与普通表单写入授权，来源因复制预算不可补取、但字段已完整载入时仍可编辑。缺列、待删除行、未知目标、视图、非InnoDB及无可靠键拒绝，不跳过非法子集。

最多1000条勾选、1024列，完整来源累计100000格／64MiB，单个原字符串或Base64最多1048576单元；原大字段只读保留，不套用新输入预算。例如30万字符原文未触碰时仍可修改同一行其它字段。新差异累计50000格／1MiB线路，每个新值沿原批量256KiB及原记录输入限制；最终变化与原草稿合计不得超过原5000条提交限制。发布前复用真实历史成本检查8MiB，保证整组可一步撤销。稠密自有data与精确字段校验拒绝getter／toJSON／坏Unicode／非法Base64、重复或外来行，不截断后暂存。
