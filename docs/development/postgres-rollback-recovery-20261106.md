# PostgreSQL 回滚后修正草稿

提交 PostgreSQL 表记录时，如果数据库确认整批回滚且原表页快照仍有效，界面会保留当前页和其他保留页的草稿。可修正触发约束的值，再点击「预览记录修改」。核对新预览后明确确认一次。引擎会重新校验原记录版本和关系结构。

每次点击确认都会消费原预览。遇到原行已变化、快照失效或提交终态待核对，界面保留可见草稿并冻结编辑。请先核对实际记录，然后处理原草稿并刷新。应用收到明确的回滚结果且原文档和连接版本仍有效时，才重新开放编辑。

PostgreSQL 协议中的空闲状态只说明当前连接没有进行中的事务。发送 COMMIT 后，应用需要原连接的命令回执来判断结果。[PostgreSQL 协议消息格式](https://www.postgresql.org/docs/current/protocol-message-formats.html)

## 验证记录

- macOS arm64 使用 Node.js 24.17.0，运行时检查、严格类型检查及构建通过。
- 完整单元回归覆盖 1,337 个文件，27,501 项通过，10 项 Windows 专用测试按平台跳过。首轮的 TLS 关闭测试因沙箱回环端口监听限制返回 `EPERM`，保留了首轮报告和退出码，允许监听后按原门槛重跑通过。
- Server-200 隔离 PostgreSQL 18 通过 5 项实库回归。独立查询确认两页中的第一条更新随第二条约束错误回滚。旧预览已失效，修正第二条并确认新预览后准确更新两条。原行冲突会撤销旧快照。延迟约束在 COMMIT 时失败的用例保留待核对状态，独立查询确认原数据保持。
- macOS Electron 专项通过 9 项检查。触发约束后可见原草稿，原数据保持。修正草稿并确认新预览后仅更新目标记录。已核对窗口退出、临时配置清理及测试库零剩余连接。
- macOS Electron 原工作区按 120 秒、零重试门槛通过 79 项检查，耗时约 114 秒。已核对原窗口退出、样例原值和测试库零剩余连接。
- WIN11-TEST 当前不可达，本轮采用 macOS 验证。Windows、安装包及其他 PostgreSQL 版本待验。
