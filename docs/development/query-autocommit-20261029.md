# 查询会话自动提交

## 实际入口与行为

查询标签工具栏的“事务设置”新增“本会话自动提交”。开启或关闭仅影响该标签的原物理会话，不写连接配置、GLOBAL 设置或 SQL 编辑器，也不替换已返回结果、筛选、排序和查询历史。

- 无活动事务时可以直接切换。关闭自动提交后，写入须显式提交或回滚。
- 自动提交原为关闭且存在活动事务时，开启会提交该事务。界面显示具体警告，必须勾选确认，再点击“开启自动提交并提交当前事务”。
- 自动提交原为开启且存在显式事务时，关闭不会提交该事务。同值请求只读取状态，不发送 SET，也不结束事务。
- 隔离级别与默认只读仍用各自原设置入口，活动事务中仍禁止修改；自动提交不与这两个默认值合并执行。

这些提交语义依据 [MySQL 官方说明](https://dev.mysql.com/doc/refman/8.4/en/implicit-commit.html) 和 [MariaDB 官方说明](https://mariadb.com/docs/server/reference/sql-statements/transactions/sql-statements-that-cause-an-implicit-commit)。官方语义不代替本项目的实库验收。

## 跨进程与提交边界

`query.autocommit.apply` 是独立的类型化 IPC，进入 preload 白名单与严格参数校验。输入包含原会话、独立任务编号、完整八字段事务快照、布尔目标及显式隐式提交许可；拒绝额外 SQL、作用域、访问器、继承字段和宽松布尔值。

Engine 在原会话互斥内固定读取 SESSION 默认属性、连接编号和数据库，并从新鲜协议状态取事务及自动提交位。全部快照匹配后，仅发送一条固定 `SET SESSION autocommit = 0` 或 `1`；过期来源不发送 SET。没有自动重连、重放或失败后补发。

SET 的原始确认包必须是单个、零影响计数、零警告且含完整协议状态的回包。切换结果快照由这个确认包和发送前完整快照组成，**不声称另做了 SET 后 SELECT 读回**。只有关闭到开启且原来有活动事务时，才标记 `implicitCommitAcknowledged`，不将普通开关误报为数据提交。

SET 投递之后不再对这个可能提交事务的命令发送 KILL。确认包在等待取消连接收尾之前记录；已确认的提交不被晚取消、收尾或最终事件异常覆盖，附加异常要求显式重新读取。没有确认包则结果未知，用户须核对原会话，不自动重试。任务开始通知也处于任务清理保护范围内。

界面同步锁覆盖刷新、默认值应用、自动提交及关闭。来源失效、选择往返、刷新和卸载撤销旧确认资格，旧闭包不能重复提交；每次打开重新读取。
