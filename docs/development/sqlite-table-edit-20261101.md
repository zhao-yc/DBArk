# SQLite 表格草稿与集中提交

## 使用方式

将 SQLite 文件连接设置为读写后打开普通表。单元格双击或 F2 打开类型编辑器，支持 TEXT、INTEGER、REAL、BLOB 十六进制及 NULL；JSON 作为 TEXT 保存。新增记录未填写的字段使用数据库默认值，生成列不能修改。底栏提供新增、删除、撤销／重做、放弃修改及修改预览；本地草稿不会立即写入文件。

预览列出目标和本批 SQL，勾选确认后才提交。取消预览不执行写入；提交成功后重新读取页面。只读连接、视图、虚拟表、系统表及没有可靠定位条件的表保持只读，任意 SQL 查询结果继续只读。

## 正确性与资源边界

- 渲染层只持有有界 typed 原值与随机快照令牌。Main 将令牌绑定原文档、连接配置及连接代次；提交只接受一次性预览令牌，不接受客户端 SQL、路径、旧行或私有执行回调。
- 独立读写连接以 `BEGIN IMMEDIATE` 执行整批修改，不借用查询标签的事务。优先使用未被遮蔽的 rowid，其次使用可靠主键或非空唯一键；写入前逐行核对完整原值。并发冲突、约束或触发器改变后继行时整批回滚。
- 目录定义、完整字段事实、schema_version 和实际文件路径／dev／ino 都参与校验；事务开始前、取得写锁后及 COMMIT 前重新核文件身份，不用 mtime 代替文件身份。原 TEXT 按源编码严格解码，不允许损坏字节被替换后写回。
- 保留有符号 64 位整数文本与原二进制。新增 REAL 必须有限；原值不经 JavaScript Number 再格式化。单批最多 500 项修改、10,000 个字段值、2MiB 输入正文，单字段上限 65,536 个 UTF-16 单位。
- 快照最多 64 份、总预算 64MiB、30 分钟有效；预览 5 分钟有效。未被编辑器接管的页和失效预览及时释放，已接管草稿在切换标签后保留。旧页面、旧编辑窗和旧预览回调不能作用于新草稿。
- COMMIT 前同步保存最小执行事实，实际 ACK 决定已提交或已回滚；不确定结果明确标记未知，不自动重放。COMMIT 已发送后的取消及关闭等待原结果。任务仅保存操作编号、目标、阶段、数量及 ACK，不保存字段值、SQL 或文件路径；事务内处理数量不等于已提交数量。
