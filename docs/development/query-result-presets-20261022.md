# 查询结果命名整理方案

## 操作与范围

查询返回数据后，点击结果区“整理方案”，输入名称并“保存为新方案”。方案按连接隔离，保存在本机 SQLite；同连接的其它查询标签和下次启动可读取。完整保存嵌套 AND／OR 筛选、停用条件原文、列表／区间端点及多列排序的优先级、NULL 位置、大小写选项。

选择后可预览完整表达式和排序，支持仅重命名、用当前整理覆盖或删除；覆盖是明确的新保存，不把失效方案静默转换。应用须用户点击，完整字段的顺序、唯一键、原名、类型及可见列全部一致才准入。只处理当前已返回行，不重发 SQL，不扩展截断结果；应用后可用整理撤销／重做恢复一整步。

方案包含筛选条件原值，不保存 SQL、结果行、文件路径或选择状态。不要将本机配置库公开。连接配置变化后的旧方案禁止直接应用；可明确用当前整理覆盖。失败后必须先刷新列表，不自动重放可能已成功的写入。请求期间按钮及关闭暂时禁用，导航、换结果或连接变化仍会撤销迟到回包。

## 实现与限制

`src/shared/queryResultPresets.ts` 是结构契约，Main 五条 `result.presets.*` IPC 仅访问 `LocalStore`，不调用数据库引擎。真实主文档令牌、十分钟单调期限、连接摘要／修订及文档 CAS 在读写与最终回包处复核；删空保留修订墓碑。渲染层另核原结果与完整筛选／排序视图，独立试算全部条件和排序成功后才一次发布。

SQLite schema 保持 9，新增可选 `query_result_presets` 表；旧 schema9 客户端忽略并保留该表，未知／损坏文档在迁移写入前拒绝。每连接 100 项，本机 500 个连接文档／1000 项／8 MiB UTF-8 内容；单项 512 KiB，值另受完整 128 Ki UTF-16 序列化预算。超限整份拒绝，不截断；这些是配置内容限额，不是 SQLite 文件或内存上限。
