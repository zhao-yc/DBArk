# PostgreSQL 表数据比较

从「工具」选择「比较 PostgreSQL 表数据」，分别选择已保存的连接、数据库和表。可在两侧同时使用同一个字段的文本包含筛选。结果按主键汇总相同、仅左侧、仅右侧及字段值不同的行，支持按差异类别翻页和查看完整原值。相同表定义允许物理列顺序不同。空值、空字符串和整行缺失分别显示。

同连接、同数据库的两张表共用一个 `REPEATABLE READ READ ONLY` 事务。跨库或跨连接逐侧读取，界面会标出两侧使用不同快照。时间以 UTC 对照，整数、小数和 JSON 沿用服务端输出原文，BYTEA 显示原始字节的 Base64。主键中的 numeric 尾零只在匹配时归一，字段对照仍保留原值。文本键按精确值匹配，不同排序规则的等价字串可能报告为两条差异。[PostgreSQL 事务隔离](https://www.postgresql.org/docs/18/transaction-iso.html)

两侧必须具有同名字段、相同声明类型和一致的主键字段。支持普通表和纯本地分区表。对当前账号隐藏行的行级安全策略会使整次比较失败。每侧最多 10,000 行、8 MiB。超过范围时可缩小筛选再比较。读取可取消，功能当前用于只读核对。

## 验收

- WIN11-TEST 会话不可达，本轮未派发，按既有授权在 macOS arm64、Node.js 24.17.0 验证。Windows 原生窗口和两平台安装包待验。
- 严格类型检查和构建通过。定向 9 项通过，定稿全量 1,352 个测试文件、27,578 项通过、10 项跳过。
- Server-200 上使用独占 PostgreSQL 18.6 容器、普通登录角色及两个测试数据库，经 SSH 回环转发。定稿原生专项 1 项通过。测试结束后容器和转发均已核对释放。
- 原生窗口实测普通表与分区表共用快照，同连接跨库和不同保存连接分别读取快照。跨库对照有仅左、仅右各 1 行，27 行字段不同。第二页核对 BIGINT 最大值、18 位小数、BYTEA 和 NULL／空字符串。两个数据库时区不同，等价时间不产生差异。文本筛选将范围缩到两侧各 1 行。
- 10,001 行、声明类型不同和会隐藏行的行级安全策略均未返回部分报告。持有排他锁后观察到独占比较后端进入锁等待，取消后等待数归零，释放锁后可重新比较。两侧数据独立读回保持原值。
- 首轮类型检查发现重构遗漏终态编号登记，已恢复。首轮窗口发现重复选择当前数据库会清空表目录，已修复。第二轮窗口通过同库与跨库比较，修正测试内相对定位后完成定稿复验。各轮原件分别保留。
