# PostgreSQL 表页 CSV 导入

在已有普通表或分区表打开「导入 CSV」。选择逗号、分号或 Tab，再选择本地含表头的 UTF-8 CSV，可带 BOM。向导展示源文件名、大小及首行列名，预填准确同名字段。逐列核对或调整目标字段，最后点击「确认追加并导入」。每个文件列对应不同的目标字段。已提交后自动刷新原表页。

- 文件使用 PostgreSQL 的 CSV 表示。未加引号的空字段写入 NULL，`""` 写入空字符串。字段含引号、分隔符或换行时按 CSV 规则引用，整个文件的记录行尾应一致。单独一行的反斜线加句点需要用双引号包围。单文件上限为 10 GiB。[PostgreSQL COPY](https://www.postgresql.org/docs/18/sql-copy.html)
- 支持有表级 INSERT 权限且当前角色未受行级安全策略限制的普通表和分区表。计算生成列由目标库计算。映射到标识列时使用文件值，序列仍按原数据库状态工作。省略的目标列使用目标表默认值，数据库照常执行触发器及检查约束。适用源格式为 PostgreSQL 原生 COPY CSV，日期和间隔等字段需要匹配数据库会话的输入设置。
- 文件选择只检查表头，数据库写入阶段才校验全文件数据。导入在独占事务中流式执行 `COPY FROM STDIN`。发送前复核原文件、目标表身份和列映射，提交前再核文件版本。收到 COMMIT 回执后显示实际导入行数；取消或连接中断后的回执如提示状态待核对，应先刷新并检查目标数据。

## 验证

- macOS 类型检查与源码构建通过。最终完整单元回归 1,325 个文件、27,424 项通过，10 项 Windows 系统 `tar` 用例按平台跳过。
- Server-200 独占 PostgreSQL 18 实库 5 项通过。逐值核对 UTF-8 BOM、换行表头、手动列序、大整数、精确小数、NULL、空字符串、BYTEA、含引号与换行的文本、计算生成列及分区路由。
- 后续记录违反约束时整批回滚。文件或表结构在确认后变化时阻止写入；同一表页令牌不能重放提交。未引用的结束标记触发回滚。触发器阻塞期间取消 COPY，回执提示状态待核对，独立连接查无本批记录。
- macOS Electron 源码窗口用例 1 项通过，22 个观察点。用文件选择测试桩指向专用 CSV，映射两个不同名字段，实际主进程及数据库进程确认追加一行，原表页随即刷新。成功轮次正常退出，隔离数据库、容器及临时配置均已清理。
- 首轮窗口测试桩使用了按钮文案作为系统文件对话框标题，导致选择未完成。首轮现场保留，独立数据库查询核对未写入测试行。修正测试桩标题后复验通过。
- 首轮完整单元回归有 20 项既有取消测试失败。将导入任务归属查询限定到 PostgreSQL 导入任务后，受影响的 15 个文件共 201 项定向复验通过。首轮结果保留。
- WIN11-TEST 会话不可达，本轮按约定在 macOS 验证。Windows 原生窗口、安装包及 CSV 导入经 SSH 和 TLS 的组合待验收。
