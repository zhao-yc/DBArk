# PostgreSQL 服务器监控

在「工具 → 服务器监控」选择已保存的 PostgreSQL 连接，点击「打开监控」。概要显示版本、服务器地址、当前数据库和本次监控进程 PID。数据库统计来自该连接实际使用的数据库，包括连接数、事务、读块与缓存命中、行操作、临时文件及死锁。累计统计会随服务器刷新和重置，窗口显示服务器返回的重置时间。

会话快照显示各数据库的进程，并略去本次监控自身及没有数据库的系统进程。可查看状态、等待事件和 SQL 摘要，或在当前快照内筛选及排序。普通角色看到其他角色的部分字段时，缺失值显示为 NULL。SQL 摘要最多 512 字符，服务器保留的原文本也可能已经截断。[PostgreSQL 累计统计与权限](https://www.postgresql.org/docs/18/monitoring-stats.html)

可手动刷新或启用每 5 秒自动刷新。读取使用独立短连接，会话列表默认最多 50 条。取消只作用于这轮读取，客户端核对本轮监控后端的 PID 和启动时间。快照仅留在监控窗口，任务列表记录通用状态。各统计段依次读取，权限不足会单独标记对应段。

监控会话列表另提供显式的取消查询和断开会话入口。[会话操作说明](postgres-monitor-session-actions-20261107.md)

## 2026-11-07 验收

- Windows 测试虚拟机不可达，本轮使用 macOS arm64 源码 Electron，连接 Server-200 上的一次性 PostgreSQL 18.6 实例。
- 通过正式菜单查看当前数据库统计。普通账号可见自身的等待事件和截断 SQL，其他角色的 SQL 显示 NULL。授予 `pg_read_all_stats` 后刷新可见该会话详情。撤销统计视图读取权限时，数据库统计单独显示不可用，会话列表继续显示。
- 使用一次性测试库的独立锁门阻塞统计视图读取。通过 PostgreSQL 锁目录确认原任务正在等待，点击取消后等待消失，两条独立用户查询仍在运行。恢复原视图后手动和自动刷新均通过。窗口关闭后独立查询确认监控会话已清理，SQL 摘要未出现在任务列表或历史。
- 前两轮校正了测试对下拉框的定位。直接锁统计视图的夹具同时阻塞了系统目录，后改为隔离库中的独立表锁，并保留原统计列。失败记录已保留，隔离容器和 SSH 转发已清理。
- 类型检查和源码构建通过。Vitest 全量 27,645 项通过，10 项按环境门槛跳过。Windows 原生和安装包待验。
