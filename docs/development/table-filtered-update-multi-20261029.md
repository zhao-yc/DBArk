# 全部筛选行的多字段统一赋值

## 使用流程

表标签打开“批量修改服务器全部筛选行”，选择字段、填写统一值，再用“添加字段”设置更多字段。每项独立使用文本、JSON、二进制或 NULL 编辑；不能重复选择字段。原页勾选、未提交草稿及页码不参与这次服务器范围。

预览读取已应用完整筛选和排序对应的全部行，显示准确行数、完整字段集合与统一值，以及最多10行、256KiB的完整 SQL 样本。样本未展示不代表只更新这些行。确认文本绑定准确库表、完整有序字段列表和全部行数，再明确提交一次。

每行只发送一条包含整组 `SET` 的 `UPDATE`，整批只在一个事务中提交。任一字段非法会阻止整组准备；任一行发生并发冲突或执行失败，则沿原事务保护尝试整批回滚。预览后新增的匹配行不在冻结快照内。修改字段、值，或添加／移除项都会撤销旧预览，改回原输入也不能复活。

## 正确性和兼容

- 保留可靠非空唯一键、InnoDB基本表、完整定义／索引依赖核对及副作用门。仍只允许普通非索引、非自增、非生成字段；不能将任意表达式、级联更新或跨表副作用当作本次回滚范围。
- 每个字段沿原无损校验和参数绑定，保留 DECIMAL／BIGINT 文本、NULL及二进制字节。全部原列与 TIMESTAMP 绝对时间继续参与并发谓词；完整快照仍走原磁盘 spool 和两遍校验。
- 后端最多1024个不同字段，每值8MiB、整组16MiB；界面二进制编辑沿原128KiB输入预算。确认文本最多512KiB，覆盖合法列名经JSON最坏转义后的完整表示。超限明确拒绝，不截断执行。
- 旧 `{column,value}` 调用、摘要和确认文本保持；新 `{assignments:[...]}` 绑定整组摘要，回执只返回完整 `columns`，不能伪装成首列或接受子集／重排。Main、Engine与表单分别复核。
- 首次发送前消费原预览令牌。COMMIT可能发送后不再取消；真实确认优先于迟到回调或收尾异常。未知结果不重试、不重放，关闭仍等待原任务、取消请求和快照释放。

本批同时修复既有释放门：Main不再丢失释放失败的原归属，而按原令牌保留当前清理承诺、错误和资源槽位。仅同文档的显式精确释放可重试，在途请求共享同一承诺；`observe`／退出等待不自动重试。真正成功后才移除待清理记录，不能因绑定不存在就把原spool当作已释放。旧引擎的迟到回调不能向新引擎释放，已确认的提交也不因清理失败被改写。表单的独立释放失败会通知父级，保留待释放令牌和原错误，不能只显示本地错误后漏报清理状态。

实现沿 [MySQL UPDATE](https://dev.mysql.com/doc/refman/8.4/en/update.html) 的多个赋值语法，输入只作为有类型的值，不能注入服务器表达式。SQL语法资料不代替实际事务和驱动验收。
