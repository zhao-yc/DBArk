# SQL 大写格式化的解析器延迟加载窄修

本片追加在 `638ef36964388f07ac0ba1c8c1df912e8dd6e7d2` 之后，保留该固定提交及原独立反例。Root 的独立审查确认原文保护安全，同时发现 MySQL/ANTLR 静态进入默认 renderer 链的 P2。此次只修加载边界和等待期间的编辑权限，不修改工作流、版本、偏好存储或角色/原文证明。

## 加载边界

`sqlFormatting.ts` 不再静态导入角色模块，预算常量移到轻量共享文件，数值仍为 32768 UTF16 单元、2048 token。模块顶层没有 import Promise、解析器实例或预热操作。

只有明确触发大写格式化后才调用 `prepareSqlFormattingRoles()`，实际 `import('./sqlFormattingRoles')` 成功才保存模块函数。模块缓存不缓存任何用户 SQL/角色结果，也不跳过后续解析：每次大写操作仍执行原正式角色证明和四模式 token 校验。未准备的同步 upper planner 继续拒绝，不能通过遗漏准备绕过证明。

默认保持原样仍同步调用原 `formatSqlEditor`，不等待或初始化解析器。偏好读取、保存为 upper 以及组件导入本身都不会触发模块加载。原同步 planner/编辑事务主体继续供保持原样使用；需要直接调用 upper 的内部调用者必须先明确准备，并在等待后重核自己的编辑权限。

## upper 等待期间的权限

一次 `DeferredUpperSqlFormatting` 只持有原编辑器、模型、版本、全文、有向选区和偏好快照。模型、正文、选区、配置或销毁事件留下永久失效标记，原值恢复不复活；工作区订阅同样使切走再切回、owner 替换、连接/会话/来源或偏好变化撤销请求。

QueryTab 在回包后重核原 tab 对象、编辑器引用、连接对象及版本、会话、活动标签、任务/关闭/文件操作状态、当前偏好及模态窗口。模态窗口打开再关闭也保留墓碑，提交前读取尚未投递的 MutationObserver 记录。卸载、关闭请求和编辑器替换都会撤销旧操作；新 owner 不接受旧回包的错误状态。

准备成功后先重核完整状态，再解绑观察、重核并同步调用原编辑事务。该同步调用还保留原模型/版本检查、单次 executeEdits 和两侧 undo stop，以及原选区映射。不产生后台 SQL、连接、会话或剪贴板调用。加载失败由原错误区反馈；加载或清理同时失败时保留两份错误。
