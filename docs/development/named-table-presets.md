# 命名筛选/排序方案首片

基于Root固定提交 `17de17620e222fdd9bc6b5a26522071b88f4b66f`，在普通本地clone与独立分支开发。不涉及批量复制、草稿历史、服务或外部依赖。

表页筛选区提供保存为新方案、明确覆盖同名方案、应用、删除和刷新。只保存当前已应用的平面过滤条件、all/any与排序；未添加的条件输入不保存。不保存SQL、页码、页大小、认证文件路径或其它执行目标，也不自动保存筛选值。正文明确提示筛选值保存在本机，连接复制和导出沿原白名单，不携带方案内容。

## 合同与来源

- `table.presets.list`：按连接ID、库、表读取本机方案，返回表级持久化修订、当前连接修订/概要摘要与Main内存来源令牌。纯本机读取，不启动worker。
- `table.presets.save`：新建必须无同名项；覆盖必须显式提供replaceId，名称必须与所见项一致。存储事务复核所见修订和连接来源，失败原子回退。
- `table.presets.delete`：只删除明确选择且CAS未变的一项。空集合保留修订墓碑；不删除其它库表或连接的方案。
- `table.presets.apply`：携带独立taskId，只返回整份已校验方案。Main使用原真实IPC捕获门，将来源绑定窗口、主frame、文档代次及准确连接/库/表；不是仅凭URL、数字ID或客户端摘要认定可信。导航、崩溃或销毁永久撤销旧文档来源。

应用通过既有utility `metadata.table` 独立任务、取消与strictRead资源结算读取当前字段。Main只注入可信profile，不直接加载驱动，不额外打开未绑定任务的连接，不发送表数据读取或写SQL。缺字段、目标错误、非法操作符、所见方案/连接修订变化均整份拒绝。NULL操作符、空字符串、空白、集合顺序及精确数值字符串原样保存。

UI在发起应用前调用原canReload丢稿/忙状态保护。回包必须属于原目标/字段/配置代次，父页再次核原页、行草稿对象、输入和忙状态后，整份恢复filters/mode/sort并通过原表页状态读取。保存回包不清名称或条件输入。取消后仍等待原请求结算，不以取消确认或迟到成功推断资源已经释放。

P2窄修补充：Main在helper恢复及严格取消结算之后复核，并把最终发布门交给实际IPC接缝。成功时取消登记保留到IPC发布检查；该接缝等待新增取消的结算，再同步核真实文档、连接修订及所见表级CAS，随后释放登记。原错误对象保留，读取与结算双失败以cause和errors保留两者。此合同限定已验证的实际路径，不声称跨任意Promise的最终发送绝对原子。

晚应用与原canReload共用无副作用忙门，复核全局dialog、布局窗口、关联窗口和活动计数，不重复确认丢稿或reset输入。布局/关联窗口变化同步推进代次；dialog只读观察者在发布前排空尚未回调的记录，打开再关闭或role变化也使旧请求失效。拒绝时保留后来窗口、输入和草稿。

## 存储与兼容

LocalStore新增独立 `table_presets` 表，SQLite配置版本升为7，文档版本为1。迁移前拒绝未来数据库版本及未知/损坏方案文档；迁移或写盘失败保留原文件并恢复内存，不猜测降级。

名称最多80字符且不可为空白/控制字符；单表最多20项，单项JSON最多64 KiB UTF-8，全库最多500项和500个目标。4 MiB是目标键及JSON方案内容的总字节预算，包含修订墓碑，不能理解成SQLite文件或堆内存硬上限。
