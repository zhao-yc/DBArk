# 外键 JOIN：HAVING 聚合后筛选

## 使用流程

“按外键生成 JOIN 查询”预览父结构、开启聚合并配置分组／指标后，可在“HAVING 聚合后筛选”中选择当前输出。支持 13 种运算符：等于、不等、四种大小比较、LIKE／NOT LIKE、IN／NOT IN、BETWEEN、IS NULL／IS NOT NULL；可逐项启停、删除、清空，以及嵌套 AND／OR 分组。

WHERE 先筛选输入行，HAVING 筛选分组／汇总结果，随后才排序及 LIMIT，不会把 HAVING 改成 WHERE。相关服务器语义见 [MySQL SELECT 与 HAVING 说明](https://dev.mysql.com/doc/refman/8.0/en/select.html)。全体汇总可使用 HAVING；空输入的 COUNT(*) 为零，条件可以保留或排除该行。只分组不加指标时也可筛选明确输出的分组键。

界面按稳定输出身份绑定条件。原指标改名或移动时条件跟随，删除后重建相同别名的指标不会接管旧条件，必须明确重选；分组字段同样处理。已有排序仍沿此前别名绑定规则，改名后若排序失效须独立修正。切换明细时隐藏并保留 HAVING，重新开启聚合后恢复；同一外键重读保持，切换外键清除旧绑定。

“组合 HAVING 条件”复用独占内联草稿，编辑期间隐藏旧 SQL 并禁用外部操作。应用只更新当前预览；取消保原条件与 SQL，焦点回到 HAVING 入口。Ctrl／⌘+Enter 应用、分组区域 Escape 取消，输入法及已消费事件保护沿原逻辑。WHERE 和 HAVING 的树、模式及根组合分别保存，不能互相覆盖。

所有修改仍只生成预览，明确打开同连接独立查询后自行执行，不提交父页数据、不自动执行、不修改全局结果上限。

## 编译、精度与预算

HAVING 只接受已声明的分组／指标输出，内部按原列或聚合表达式引用；即使指标别名与源 id 同名，也不会按未限定源列解析。原始 SQL、未输出字段、未知属性、继承选项、访问器、空洞及循环树拒绝。未开启聚合时显式传 HAVING 会报错，不能静默丢弃。

条件形状、启停、集合、组覆盖及字面量复用既有筛选编译。COUNT 用整数比较，SUM／AVG 及精确数值使用十进制校验和 CAST，不转 JavaScript 数字；文本按 UTF-8 十六进制编码，坏 Unicode 拒绝。普通十进制输入保留原文，科学计数法不悄悄改写；比较范围沿原 65 位数字、30 位小数或实际源类型声明的更高尺度。超过范围明确拒绝，不截断。浮点聚合及比较仍是服务器近似语义，不承诺精确小数。

WHERE 与 HAVING 各最多 30 条条件、16 组／8 层，每条含停用项必须出现一次；集合和值预算共用原合同，保留的两类值草稿（含隐藏输入）合计最多 1000000 字符。全停用子树被省略，不用真条件放宽 OR；全停用 HAVING 生成旧版无 HAVING 字节。完整 SELECT 仍受 256KiB 预算。

复制可选字段时使用无原型容器，不读取 Object.prototype 访问器。预览深冻结完整 HAVING 声明；打开前沿原意图重读双方元数据、重算 SQL，并核当前选择、渲染与占用。旧条目、旧分组 Apply、忙态及来源 ABA 保护保持。没有新增 IPC、配置格式或写协议，稳定界面 ID 不进入 SQL。
