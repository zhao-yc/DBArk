# PostgreSQL 图形化创建视图

在左侧导航右键点击 PostgreSQL 数据库，选择「新建 PostgreSQL 视图」。选择有使用与创建权限的 schema，输入视图名、查询和可选注释。使用带 schema 的名称引用业务对象，例如 `public.orders`。查询定义接受单条不含位置参数的 `SELECT`、`WITH`、`VALUES` 或 `TABLE`，可用列别名为计算结果命名。

1. 点击「预览视图 SQL」，核对目标数据库及将要执行的语句。预览读取目录以检查 schema 权限和同名关系，定义语法和对象引用在确认后由服务器检查。
2. 点击「确认创建视图」。客户端在同一事务内创建视图、写入注释，并回读目录核对目标、视图类别和注释。提交确认后刷新目录并打开只读记录页。
3. 如果提交回执中断，客户端保留结果未知状态。请先在原数据库目录核对视图。

此入口用于新建永久普通视图。同名关系会阻止创建。底层关系权限采用 PostgreSQL 默认的视图所有者语义。[PostgreSQL 18 CREATE VIEW 文档](https://www.postgresql.org/docs/18/sql-createview.html)

## 验证

- macOS 上 Node.js 24.17.0 类型检查与源码构建通过。完整单元回归覆盖 1,326 个文件，27,450 项通过，10 项 Windows 系统 `tar` 用例按平台跳过。
- Server-200 上独占 PostgreSQL 18 实库回归 5 项通过。用普通登录角色验证带引号名称、CTE、行尾注释、单条定义边界、预览零写入、令牌隔离与一次性消费、真实记录和注释、同名拒绝及定义错误回滚。
- macOS Electron 原生窗口 1 项通过，覆盖 35 个观察点。从数据库右键菜单填写定义、预览、确认，随后检查侧栏和视图记录页。独立数据库连接再次读到预期记录和注释，通过轮次的窗口临时配置及测试数据库已清理。
- 首轮原生测试把侧栏右键菜单误作工具栏菜单定位，修正测试入口后完整复跑通过。首轮容器已停止并保留诊断数据。
- WIN11-TEST 会话不可达，本轮 Windows 原生窗口和两平台安装包待验收。
