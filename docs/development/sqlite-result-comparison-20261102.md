# SQLite 固定结果对比

## 使用与边界

在 SQLite 查询页分别“固定结果”，从“更多结果操作 → 固定结果对比”明确选择两份快照和 1～8 个匹配键，再开始。沿用原四类计数、差异筛选、50 行分页、左右来源切换和字段明细；只读两份已返回快照，不重新查询、不执行同步，也不推断主键。至少一侧截断时显示范围提示。固定副本不受随后原查询结果的修改影响。

SQLite 按原逐格存储类型和规范原值匹配，支持 INTEGER、REAL、TEXT 和 BLOB。`INTEGER 2`、`REAL 2`、`TEXT "2"`、字节 `32` 以及 REAL 正负零分别匹配，不采用 SQL 隐式数值转换；键类型改变表现为移除和新增。NULL 或同类型同原值的重复键拒绝整份对比，不发布部分计数。复合键使用类型元组，NUL、分隔符和 JSON 文字不碰撞。

非键列同时比较原值和存储类型，原文相同但 INTEGER／TEXT 类型变化仍标记修改。明细保留 int64、真实 REAL 原文、NULL、空文本及完整 base64，并标注左右 INTEGER／REAL／TEXT／BLOB／NULL；缺少整行不伪造 NULL 或类型。静态 MySQL 类型的原键限制及比较规则保持。

完整原列、行和类型帧必须可靠且一致。缺失类型信息的旧 SQLite 快照拒绝猜测；类型对象、代码数组或代码变化也永久撤销来源，恢复旧对象不能复活。复用原扫描、取消、模态、连接变代与迟到回调保护；无新增 IPC、数据库请求、写操作或持久化结构。

保留每侧 100000 行、1024 列、合计 2000000 格／16 Mi 原文、单值 4096 字符及原分批上限；字节不解码，完整类型帧先准入，最终发布前复核，不在每批重复全表校验。
