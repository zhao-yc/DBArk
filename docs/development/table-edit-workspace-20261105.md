# MySQL／MariaDB多页草稿工作区（2026-11-05）

## 当前行为

普通数字分页、页码跳转及末页操作保留同表同查询的原页和UUID，返回缓存不调用`table.page`或`metadata.table`。各页使用自己的DraftHistory；稳定历史端口只代理活动页，撤销不会改变另一页。返回缓存还恢复原勾选、记录选择和已打开表单的输入来源代次。

记录表单在页边界显示“暂存并查看下一页首条／上一页末条”。先核当前活动页及原来源，再用原编辑器验证并暂存当前输入，然后保留整页并导航。非法输入不离页；切走标签、模态或连接变化后的旧回调不能先暂存隐藏输入。只读表／视图仍沿原无草稿详情导航。

工作区按目标、连接配置／版本、结构、页长及实际筛选／排序绑定。观察过连接或来源变化即留下失效状态，恢复旧显示值不会复活原来源；读取失败回到原页、原数组及原历史，不再隐式重读。末页读回已缓存页时使用原缓存，不覆盖已有修改。各页是分别读取的原页，不保证数据库分页快照。

全部保留页的变化沿原`table.preview`及`table.apply`链路聚合，未新增数据库写入口或更改事务引擎。干净当前页也能预览后台修改；预览取消保留整组。重复原定位会拒绝整批预览，不能把相同记录的两个来源先后重放。Main继续核同一预览的准确计划，原乐观锁与一次事务覆盖所有变化。

投递开始清除全部页历史。已确认回滚／未发送保留原草稿，可修正并重新预览；未知或已提交但刷新失败时，前批提交结果核对锁住整组，不允许通过切页、放弃某页或新预览重放。真实读取成功采用后才清除旧页组；回执不扩大为触发器或外部副作用保证。

## 预算、放弃与文件

- 最多16个保留页；只有干净且没有撤销／重做历史的页可以自动淘汰。有修改或历史的页满额时明确拒绝新页，先放弃或提交，不静默丢弃。
- 多页原值和当前值合计最多64 MiB／100000格，不序列化或深拷贝大BLOB来切页；历史各页沿原100步／8 MiB限制。初始大页仍沿原单页浏览和编辑路径，超出保留预算时拒绝继续保留第二页。
- 多页统一预览最多5000条变化、50000个新值格／1 MiB新输入；保留原BIGINT／DECIMAL／微秒／二进制／NULL／空串与JSON词法，不截断后当作完整值提交。
- “多页草稿”栏显示页数及全组修改数。逐页放弃确认绑定原页、原数组和工作区代次；后台页不读库，当前页优先返回另一个原缓存，最后一页才重读。忙态、未暂存输入及提交结果核对期间不能拆组。刷新、筛选、排序或页长变化需确认放弃全部页。
- 现有“保存表格草稿”入口聚合全部页已暂存变化，文件格式和Main只读核验协议保持。原文件1000条／8 MiB／单值256 KiB等限制保持，超限整份拒绝。恢复是独立草稿视图，仍须预览和明确提交；页布局、未暂存输入和历史不持久化。
- 当前干净页打开或取消逐条批量窗口时，退出保护仍按全组判断，不能误清后台页dirty。关闭／重启不会自动恢复内存页组。
- 离开页释放原引擎补取租约；缓存保留本地完整值，不自动重新签发租约。缺隐藏字段的补取操作不会在缓存返回时偷偷读库，需先处理整组并明确刷新。
