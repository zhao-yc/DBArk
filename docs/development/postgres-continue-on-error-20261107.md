# PostgreSQL 显式遇错继续

PostgreSQL 查询页的「遇错继续」默认关闭。启用后，执行选区、当前语句或全部 SQL 时，会记录普通数据库语句错误并处理后续语句，包括写操作。执行摘要列出尝试处理数、完整成功数、各条错误及是否到达本次范围末尾。每条已确认范围的错误都可点击定位；修改原文后旧定位失效。

只保留完整成功结果。到达末尾并不代表全部 SQL 成功或事务已提交：有错误的任务及执行历史仍记为失败。客户端不自动重试、重放、重连、建立保存点、提交或回滚。PostgreSQL 事务出错后，后续命令可能继续返回失败事务错误；需要用户脚本显式执行 `ROLLBACK` 等事务处理语句。此行为依据服务端 ReadyForQuery 和 SQLSTATE，不执行 MySQL 的状态探测。[PostgreSQL 消息流程](https://www.postgresql.org/docs/18/protocol-flow.html) [SQLSTATE](https://www.postgresql.org/docs/18/errcodes-appendix.html)

取消、连接或状态无法确认、词法解析失败，以及连接、资源、程序上限、运维干预、系统和内部错误类会停止后续处理。错误记录达到 100 项也停止，保留提前停止原因。前句改变字符串模式后，继续按实际原会话模式扫描尾部；不会预读或猜测未闭合的 SQL。

位置参数仍只接受单条语句，采用协议绑定。该模式下错误只保留通用失败提示及可确认的 SQLSTATE，参数值不进入摘要、执行历史、任务概要或设置。执行计划与实际分析不采用遇错继续。选项仅保存在当前查询标签内存中，重新打开应用或新建标签恢复默认关闭。
