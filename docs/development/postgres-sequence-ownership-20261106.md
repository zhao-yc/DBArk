# PostgreSQL 序列归属管理

从对象树或「其他 → 序列」打开详情，可分别查看所有者角色与所属字段。有管理权限时，点「管理序列归属」，选择绑定、解绑或转移角色，再核对 SQL 并确认。

绑定候选来自同一 schema、同一所有者的普通字段。搜索支持关系名或字段名。绑定后删除所属字段或关系会同时删除序列，解绑后序列独立保留。两项操作均保留字段默认表达式和其他引用。标识列序列的绑定由所属字段管理。[PostgreSQL ALTER SEQUENCE](https://www.postgresql.org/docs/18/sql-altersequence.html)

转移所有者角色适用于未绑定字段的序列。候选根据数据库角色关系和目标 schema 的创建权限筛选。确认后刷新对象树与序列列表，当前角色失去权限时该序列会从目录移除。[PostgreSQL ALTER SEQUENCE](https://www.postgresql.org/docs/18/sql-altersequence.html)

候选列表每次最多显示 100 项，可通过名称缩小范围。确认阶段按序列身份重新取锁，并复核候选角色 OID 或字段所属关系 OID 和字段序号。候选名称、权限或原序列变化时，需重新预览。提交前回读实际归属及原序列参数。

## 验证

- Server-200 独占 PostgreSQL 18 实库回归 5 项通过。覆盖字段跨 schema 筛选、带引号的标识符、字段在预览后改名、绑定与解绑、解绑后默认取号保留、删除所属表联动删除序列、标识列保护、角色权限撤销后回滚，以及成功转移后原角色失去查看权限。
- 角色转移验收使用专用接收角色 `DBARK_POSTGRES_SEQUENCE_OWNER`。测试登录角色可切换到接收角色，且默认不继承该角色的权限。
- macOS 上 Node.js 24.17.0 运行时检查、类型检查和源码构建通过。
- macOS 完整单元回归共 1,326 个文件，27,451 项通过，10 项 Windows 系统 tar 用例跳过。
- 首次原生验收发现候选下拉框缺少稳定的无障碍名称，补充显式名称后复跑通过，记录 50 项观察。确认搜索、绑定、解绑和转移的确认流程，以及失权后对象树与序列列表同步移除该对象。
- 独立回读确认解绑后的序列无字段归属依赖，转移后的序列属于目标角色、原角色不可见，序列值保持 `42` 且 `is_called` 为 `false`。原表数据、零剩余连接、独占容器与临时配置清理均已核对。
- Windows 测试虚拟机连接不可用，本轮改在 macOS 验证。Windows、两平台安装包和较早 PostgreSQL 版本待验证。
