# 查询中查看对象结构

## 使用与范围

在 MySQL／MariaDB 或 SQLite 查询正文的物理表、视图名称上，使用编辑器右键“查看对象结构”，也可从查询“更多”或原生“工具 → 查询执行与分析”进入。窗口显示完整只读 DDL、实际数据库和临时对象标识；关闭后保留原正文、撤销栈、结果及标签。F12 继续定位本文声明。

目标取自当前活动查询及其原会话，不能被左侧另一个数据库选择覆盖。MySQL 按原会话模式解析，SQLite 按自己的引用、大小写和作用域规则解析；可确认的表别名会追溯到其物理来源；CTE、派生、字段、附加库、表函数及不确定语法不猜物理对象。并非任意 SQL 的完整语义分析。

原会话中未限定的 SQLite 名称先查 TEMP 再查 main；显式 main 不受 TEMP 遮蔽。独立读取只允许 main。MySQL／MariaDB 使用固定且正确引用的 SHOW CREATE TABLE，支持实际表和视图；不执行用户正文、不自动切库，不重放写操作。

## 会话、取消与边界

- 解析在独立 Worker 中，沿用启动 8 秒／分析 2 秒预算；回包再次验证完整 token、原语句、名称及位置。
- IPC 只接收声明的连接、会话、对象及任务编号。Main 在派发、回包和发布时核对原窗口、文档、配置代次及准确会话；不暴露任意路径或 SQL 能力。
- 网络引擎及 SQLite 运行时各最多两个并行结构读取。切换、编辑、连接变化、关闭及取消使旧结果永久失效，原读取及取消确认完成后才归还占用。
- 借用会话不创建、提交或回滚事务；SQLite 取消等待原短读边界，不中断用户事务。独立只读连接完整收尾后才发布。
- MySQL 服务端 ERR 可能令原会话事务／模式状态变为“未知”。关闭窗口仅同步现有会话缓存，不附加 SQL，不伪装事务已结束；需要时由用户明确回滚或重新确认。
- 完整 DDL 限 2 MiB，超过明确拒绝、不截断。SQLite 分块读取编码原文，内部记录限 4 MiB；原业务单值 1 MiB、结果帧及重建核对限制保持。重建和私有读取显式检查，不能因结构预算增大而接受超限业务值。
- DDL 仅在当前只读窗口，不写入任务持久化消息或查询历史；错误持久化使用固定文案。
