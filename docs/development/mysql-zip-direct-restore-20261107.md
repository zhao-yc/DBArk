# MySQL／MariaDB ZIP 归档直接恢复

在「工具 → 打开数据库备份归档」选择 tabrelio 整库 ZIP，选择已保存的连接并点击「检查目标」。目标符合条件后，确认信任归档并点击「直接恢复归档」。归档支持第一版和第二版清单，直接恢复使用 UTF-8，沿用 SQL 文件执行器和 MariaDB 转储首行处理。

写入入口要求同系列同版本、事件调度器已关闭，并且有足够的目录权限证明同名库为空或不存在。确认绑定原窗口、原归档和已检查的连接配置，有效期随归档令牌。执行进程会先复核文件代次、整包摘要、ZIP 结构、SQL 字节和编码，在同一个执行会话重新查询目标状态，再从只读文件句柄流式执行经过逐块摘要比对的 SQL。

同名库检查只覆盖清单指定的数据库和检查时可见的状态。脚本按所选账号的权限运行，执行前请检查内容和外部依赖，并避免其他会话向同名库写入。取消或失败时会展示已确认完成的语句、失败位置及回滚状态。此前已经提交的语句和 DDL 可能保留。

## 2026-11-07 验收

- Windows 测试虚拟机不可达，使用 macOS arm64 源码 Electron，连接 Server-200 上的一次性 MySQL 8.4.11 和 MariaDB 11.4.13。直连和 SSH 严格 TLS 两轮均通过。严格 TLS 轮使用回环地址、匹配的证书及指纹校验。
- 通过正式菜单生成并恢复双方言整库 ZIP。MySQL 恢复至同名空库，MariaDB 由脚本创建同名库。独立连接核对恢复前后的表、视图、过程、函数、触发器、事件和数据，覆盖大整数、定点数、中文、emoji 和 256 KiB 二进制摘要。原 ZIP 字节一致，恢复时未生成导出 SQL。
- MySQL 测试在检查通过后从另一个会话创建对象。执行前复查拦截写入，原对象保留。第一版归档另验第 4 条语句失败时的行号和前序 DDL 保留，以及等待语句取消、后续写入停止和取消回执。
- 离线源码 Electron 回归通过，旧版归档原样导出，损坏归档被 CRC 校验拦截。隔离容器、数据库会话、转发和临时证书均已清理。Windows 原生、安装包和非回环 SSH 严格 TLS 待验。
- 类型检查和源码构建通过。全量 Vitest 通过 1,360 个文件及 27,640 项，10 项按环境门槛跳过。
