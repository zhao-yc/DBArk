# PostgreSQL 表页列布局

打开 PostgreSQL 表或视图，点击「列布局」。按列名搜索设置项，可显示或隐藏列、前移或后移、设置列宽，并选择一列作为左侧冻结边界。列头可直接拖动边缘调整宽度。也可按当前页内容调整单列或所有可见列，并选择紧凑、标准或宽松三档行高。

布局即时应用。点击「保存表列偏好」后，同一连接、数据库、schema 和对象重新打开时会从本机恢复。关闭设置面板可继续浏览，未保存的布局会在表页标出，并受标签关闭保护。「重新读取已保存布局」可放弃本标签的调整。「恢复默认列布局」在确认后清除本机配置并显示原列顺序。

显示列按准确名称匹配，区分大小写。新列追加到布局，已删除的列会移除。至少保留一列可见。筛选和排序可继续使用隐藏字段，记录表单和全量导出仍使用实际字段及原记录定位。并发更新同一布局时，后提交的一方需要重新读取已保存版本再保存。

本轮接入独立列布局。命名方案联动、对象树直接打开方案和跨设备同步仍待接入。[Navicat 数据视图手册](https://www.navicat.com/manual/online_manual/en/navicat_18/win_manual/data_rdbms.html#format-data-view)

## 验证

- macOS 上 Node.js 24.17.0 运行时检查、类型检查和源码构建通过。布局专项 5 个文件、42 项通过，核对准确列名、独立 schema、CAS、配置库重开、旧版迁移以及原窗口和驱动令牌隔离。
- macOS 完整单元回归共 1,326 个文件，27,459 项通过，10 项 Windows 系统 tar 用例跳过。
- Server-200 独占 PostgreSQL 18 实库回归 5 项通过。正式窗口轮次独立回读原表数据及零连接，随后清理专用容器。
- macOS Electron 原生窗口最终回归通过，共 66 项观察。新增场景覆盖移动列、隐藏仍参与排序的主键、冻结、调整行高、列头拖动、保存、重读、取消重置和确认重置。隐藏主键期间完成实际导出和跨页提交。首轮功能验证通过后，截图发现行高选项文字被裁切，调整控件宽度后复跑并核对最终截图。
- Windows 测试虚拟机不可达，本轮切换至 macOS。Windows、两平台安装包及较早 PostgreSQL 版本待验证。
