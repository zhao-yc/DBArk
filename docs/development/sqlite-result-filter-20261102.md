# SQLite 查询结果显式类型筛选

## 使用

查询结果工具栏的“筛选已返回结果”现支持 SQLite。每条非 NULL 条件明确选择 TEXT、INTEGER、REAL 或 BLOB；条件草稿、条件组、启停、复制条件及组合输入保护复用原面板。新增条件默认 TEXT，切换字段或类型不猜测数据内容；明确应用后才改变已返回视图。

支持等于／不等于、有序比较、包含端点的范围／反范围、列表／反列表；TEXT 另支持包含、首尾、通配、空文本及其否定。NULL 使用独立条件。BLOB 输入完整十六进制字节；日期文字作为 TEXT，保留微秒和原文，不创建 Date。支持嵌套 AND／OR、单条／全部启停、清除条件及整理撤销／重做。筛选先于排序，应用及清除均保留完整多列规则。

只操作当前已返回行，不重发 SQL，不改变事务；截断结果无法代表完整查询。原选择、查找和详情随视图变化撤销。原 SQL、值和类型标记保持；保存结果快照仍保存原始返回范围及顺序。

## 类型与正确性

同样显示为 `2` 的 TEXT、INTEGER、REAL 分别匹配；常规非 NULL 条件，包括否定条件，均限定所选原存储类，不执行 SQLite 亲和性转换。后续[快捷排除](sqlite-result-shortcuts-20261102.md)新增独立的“其它非 NULL 存储类型”判断，与同类型不等于组成完整排除组；需要组合不同类型时使用条件组。INTEGER 保持 int64 精度，REAL 按原 binary64 比较；本地只读条件可明确输入正负 Infinity，不放宽写入入口的有限 REAL 限制。

TEXT 有序比较使用固定 UTF-8 字节序；可选 Unicode 小写映射同时作用于上下限、列表及源文本，不去重音或规范化。BLOB 按原字节比较。类型来自实际 driver 标记，旧结果缺少标记时仅支持 NULL 判断，不从显示值补造类型。

条件与编码键共用原行数、工作量、单值及整体预算；未涉及的其它存储类不解码或转成文字。非法条件、逆序范围或超预算保留原视图。类型标记及活动值漂移撤销旧租约，恢复旧值不能复活旧回调。

共享条件结构新增可选 `sqliteType`；非 NULL 的 SQLite 条件必须提供，其它列与 NULL 条件拒绝该字段。原方案结构继续兼容；新类型条件不静默降级给旧读取器。未改配置表结构、数据库引擎、写入协议或凭据。
