# SQLite 已有普通表字段管理

本轮为开发源码中的原生 ALTER 增量，仅管理 SQLite `main` 内现存普通表的新增字段、字段重命名、删除字段及受实际版本支持的可空性修改。它不是完整表重建设计器，也不属于已发布安装包。本阶段严格类型、构建和相关单元检查已完成；新原生窗口、七组回归及最终完整单元复核均已通过；首轮旧 Worker 超时与其它夹具失败按各自原件保留。

## 入口与操作

- 左侧 SQLite `main` 普通表的对象菜单，选择“管理 SQLite 字段”。
- 对象浏览“表”分类的准确表行，在结构操作中选择“管理 SQLite 字段”。
- 已打开的 SQLite 表页“更多 → 设计与结构 → 管理 SQLite 字段”。

窗口先明确“读取 SQLite 字段”，展示完整字段目录、原表 SQL 及 `main` 全量有界的表、索引、视图、触发器关联定义，不只展示当前表名命中的片段。字段保留原 cid、声明类型、NOT NULL、默认值 SQL、主键顺序及 hidden 标记；STRICT、WITHOUT ROWID、保存连接的只读标记和原引擎实际能力分别呈现。全目录超过预算时拒绝，不截断后继续宣称完成影响检查。

每个本地动作生成一条准确引用标识符的原生 ALTER。加入草稿、关闭字段编辑和预览都不执行 DDL；“预览 SQLite 字段 SQL”显示全部语句及新增、重命名、删除、可空性修改数量，不能编辑成任意脚本。输入准确的 `main.表名` 后，“确认提交 SQLite 字段”只消费原预览一次。

| 动作 | 本轮行为与边界 |
| --- | --- |
| add | 原生 `ADD COLUMN`，字段追加到末尾；可选类型、常量默认值、NULL 规则和 BINARY／NOCASE／RTRIM。不顺便建立主键、唯一约束或外键。 |
| rename | 原生 `RENAME COLUMN`；依赖定义由原 SQLite 处理，不使用文本替换脚本。歧义或依赖拒绝时整组失败。 |
| drop | 原生 `DROP COLUMN`；会删除该字段数据，索引、触发器、视图、外键及其它约束可能阻止删除，不能遇错继续。 |
| nullable | 原生 `ALTER COLUMN … SET NOT NULL`／`DROP NOT NULL`；实际能力确认后才开放，旧版或未知版本明确禁用。 |

已有列的声明类型修改、已有默认值修改、列重排以及主键／外键等约束重建仍未完成；本轮不自动重建表，不用 `writable_schema` 绕过原生校验，也不将后续 CHECK 设计算入本次完成范围。

## 默认值、版本与原生语义

ADD 复用新建表的严格类型化默认值及列定义构造：无默认值、NULL、文本、有符号 64 位整数、有限 REAL 和完整十六进制 BLOB 常量。名称和声明类型整体引用，不能把声明类型扩展成其它约束或 SQL。整数不经 JavaScript Number，文本保留引号及非 BMP，BLOB 保留原字节；实际存储仍遵守 SQLite 亲和性、STRICT 和原表约束，不承诺任意声明类型均不转换值。

SQLite 原生 ADD 不接受 CURRENT_DATE／CURRENT_TIME／CURRENT_TIMESTAMP 或括号表达式默认值；含 NUL 文本需要表达式才能准确表示，因此本入口明确拒绝并保留用户输入，不替换字符或暗中改成 NULL。新增 NOT NULL 字段及其它约束仍须由实际原表数据验证，失败整组回滚。限制依据 [SQLite ALTER TABLE 官方说明](https://www.sqlite.org/lang_altertable.html)，不是以重建表模拟不支持的动作。

原生可空性修改自 [SQLite 3.53.0](https://www.sqlite.org/releaselog/3_53_0.html) 引入，本入口要求实际驱动版本不低于该版本且能力可确认。Root 本阶段独立 Node 原生 SQLite 为 3.53.0；上一 b8 原 Electron 帧为 3.53.4，二者是不同运行时证据，不能用一个版本号替代新窗口验收。每次动作后严格核对原生目录是否达到所请求的可空性；例如原定义重复声明多个 NOT NULL，而单次 DROP 后仍保留非空约束，就整组回滚，不能把语句成功响应当成“已允许 NULL”。

## 独立事务、能力与准确回执

目录及预览使用独立只读连接，写入在另一个独立读写连接的 `BEGIN IMMEDIATE` 内整组执行，不借用户查询会话、临时表或活动事务。只读连接可以查看、设计和预览，不能提交。只读预览做原目录、计划和能力检查，不代替实际写事务的约束验证。

写锁内重核准确数据库身份、表定义和完整依赖，执行每条原生 ALTER 并核对完整目录预期；原生 rename 对索引／视图／触发器等的调整及外键完整性也在事务内核对。全部通过才发送 COMMIT；动作或后验失败确认整批 ROLLBACK。定义未达到请求结果、外键检查失败或任一语句失败时，不以“部分成功”放行。

Main 绑定原窗口文档、连接修订及代次，只接收 `sqlite.columns.inspect`／`preview`／`apply`／`release`，并按共享编译器重建预览计划。目录和预览各有独立 5 分钟期限，分别最多 64 份／64MiB；自然过期阻止新领取，明确 release 仍撤销原只读操作及未领取预览，已领取 writer 的元数据释放不冒充事务取消。最终发布前复核来源，旧窗口或晚回不能复活能力。

COMMIT 前同步保存最小事实，真实 ACK 不因断包、迟到进度或清理告警降级。任务中心“SQLite 字段事务回执”展示原操作编号、连接／`main`／表、请求与已处理 DDL 数量及明确阶段；处理数量不是提交确认。任务概要不保存字段名、默认值、原 SQL、路径或驱动错误。未知结果锁定原批次、不自动重试，停止、关闭及退出等待原请求、取消应答和实际资源收尾；重启仅恢复最小事实，不恢复能力或重放设计。

预算另包括最多 128 个动作／语句、1,024 个字段、4,096 个关联对象，合同及 DDL 总 UTF8 预算 2MiB。新增字段及新名称复用最多 255 个有效 Unicode 字符的限制；目录中的已有字段名按现有 512 长度预算完整读取，仅按 ASCII 大小写比较，不合并不同 Unicode 名称。

## 原表页与草稿保护

入口扫描准确原目标的全部表页，包括隐藏页的 dirty 和活动作业；模态守卫及表页自身检查继续保护编辑预览与导入导出占用。字段与索引两个 SQLite 模态入口同轮互锁；旧点击闭包不能在新模态、连接修订、标签代次或来源变化后领取另一目标。提交回调只作用于原连接版本和原表，不用当前左树选择替换目标。这些边界已完成 UI／Main 独立静审及定向检查，新字段两组真实窗口已通过，原始帧与资源由 Root 独立核对。

仅已确认提交且定义核验通过、原页仍安全时，才通知原页重新读取。原筛选／排序草稿不静默重命名或删除；引用已不存在字段时，在构造 SELECT 前由准确字段白名单明确拒绝，用户需自行调整条件。脏页、核验不明或未知回执保留原内容并撤销旧快照权限，单向阻止自动读取；切走再激活及后续已知回执不解锁，只有用户明确刷新／应用条件并通过原保护检查后才恢复读取。
