# SQLite 类型参数脚本

## 使用

在查询页“更多 → 参数执行”或原生菜单打开表单，选区优先，否则使用完整草稿。使用 `:name` 表示值，参数名称为 1～64 位 ASCII 字母、数字或下划线，不能以数字开头；重复及跨语句引用共用一个值。表名、列名仍写在 SQL 中。

识别只扫描完整 SQLite 词法，不 prepare 或执行用户模板，不读取 MySQL 会话模式。注释、字符串和引用名称中的假参数不参与；不混用 `?`、`?NNN`、`@name`、`$name`。SQLite 已识别完整脚本，整组必须准确覆盖全部名称，缺少、重复、额外或无效值在首个用户 SQL 前拒绝。

| 表单类型 | 原生绑定与边界 |
| --- | --- |
| 文本 | TEXT，保留空串、NUL、引号及非 BMP 字符 |
| 整数 | 有符号 64 位 INTEGER，以 BigInt 绑定，拒绝范围外值 |
| 小数 | 保留原文 TEXT，最多 65 位有效数字、38 位小数 |
| 布尔值 | INTEGER 0／1 |
| Hex | 真实 BLOB，空 BLOB 与空 TEXT 分开 |
| NULL | 原生 NULL，不以空串替代 |
| 日期／日期时间／时长 | 校验格式后绑定原文 TEXT；公历年份 0001～9999，微秒不经 Date／时区转换，时长小时 00～838 |

表单显著提示：SQLite 没有与 MySQL 相同的 DECIMAL／日期存储类型；TEXT 参数进入数值亲和列、比较或运算时，SQLite 可能转换数值并损失精度。需要转换时由用户在 SQL 中显式处理，客户端不偷偷生成 CAST。依据 [SQLite 类型亲和性](https://www.sqlite.org/datatype3.html) 和 [Node SQLite 绑定接口](https://nodejs.org/download/release/latest-v24.x/docs/api/sqlite.html)。

## 执行、隐私与资源

- 原 SQL 模板与独立原生命名映射分别传入同一物理会话；不拼接参数字面量，不借用 MySQL 引号模式或转换表达式。Node 只接收完整前缀名称；全篇名称校验后，同一映射可跨语句使用。
- 模板最多 20MiB／1,000 条语句，最多 200 个不同名称／100,000 次引用；单值最多 64KiB，整组最多 1MiB。Main、共享表单及 worker 各自核对适用形状和预算，worker 在任何用户 prepare 之前复核全部名称及原生值。
- 名称／值校验通过不代表整份脚本语法都成功。后续原生语法或约束失败保留此前完整结果和准确模板范围；先前已自动提交的语句不会撤销。需要整体回滚时显式使用事务，取消不代替事务，不自动重连或重放写入。
- 沿原会话事务、临时表、只读 authorizer、ACK、结果上限与取消关闭协议。原位置数组绑定和完整流式导出保持原门；内部命名映射不能混入这些入口。
- 历史只保留模板，参数值不进入持久化工作区／任务记录或错误正文。结果流、用户明确保存的快照或目标数据库可能包含实际值。只有明确选择才暂存一组 RAM 值，再次打开仍须明确填入；忘记、来源或物理会话失效、关闭标签后不能继续借用旧值。
- 原表单固定连接对象／修订、原物理会话和独立票据。连接、标签、文件操作等 ABA 使其永久失效；后台正文改变只撤销旧定位／复用，用户仍可在原表单明确执行原不可变模板，不偷偷改成新正文。

公共 IPC 继续使用原 `query.parameterNames`／`query.executeParameterized`，不接收调用方指定方言或内部命名映射。值层先准入已实现驱动的严格集合，执行端仍按真实绑定会话复核；旧 MySQL UInt64 与 SQLite 早年日期不能互相绕过各自驱动限制。
