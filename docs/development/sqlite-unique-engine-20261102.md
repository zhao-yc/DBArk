# SQLite 已有 UNIQUE 约束：组合计划与独立事务

## 实现

在[声明模型与编译](sqlite-unique-plan-20261102.md)之后，UNIQUE 编辑已接入原 `sqlite.tableRebuild.preview/apply/release` 能力链。新增受限 `uniqueEdits` 与 `changedUniques`，不新增任意 SQL、文件路径或独立写入通道；编辑区仍待接入，本阶段不等于完整可用 UNIQUE 管理。

- Main 与 Runtime 用各自准确原目录和四个 Main 随机名称独立重算整份计划及警告；预览的唯一约束修改数须准确匹配请求。异常预览能力立即释放；旧编辑区拒绝未请求的 UNIQUE 修改标记。
- UNIQUE 与主键、外键、类型／默认值和实际列顺序可同批编译。先按原序号及完整 SQL 释放本批原 UNIQUE，再沿原主外键删除／替换编译路径处理，最后追加新 UNIQUE；约束名称循环互换只核最终保留集合，不误用改变后的旧序号。对象复制前检查所有可选编辑描述符，getter 不能先被调用。
- 预览及已领取能力各自复制补丁并计入预算。写事务开始前重算完整已领取计划，补丁变化即 not-sent；写锁内重新核对全目录及真实行数。预览只读，不试建表或执行写语句。
- 原独立 writer、两个候选、内部唯一序号和四次全量 typed 比较保持。复制固定使用 `INSERT OR ABORT`，重复数据在 IGNORE／REPLACE 下仍整批回滚；普通列、生成值、int64、字节、物理行身份、完整定义、原显式索引、触发器、视图及非目标序列均沿原保护核验。
- UNIQUE 可以作为其它表的父键。提交前全部最终外键必须完整可检查且零违规；空子表的父键失效也拒绝，不能复用旧违规或旧条数授权新关系。真实 COMMIT／ROLLBACK 回执、取消、未知结果和禁止自动重放保持。
- 不能按自动索引名称或条数反推声明。移除一条重复 UNIQUE 可以仍保留共用索引，移除全部则按最终声明和真实候选核对。最终自动索引完整元数据须与已验证候选相同。

## WITHOUT ROWID 的派生方向

真实 native 探针确认：`UNIQUE(note DESC,id)` 在 `PRIMARY KEY(note ASC,id)` 之前时可以被合并，实际主键及显式索引的辅助 note 键采用 DESC；移除或移动该 UNIQUE 后，native 可改为 ASC。主键 SQL 文字未改，不代表辅助键方向必须与旧目录相同。

仅对“改变 UNIQUE、未改变主键”的 WR 计划，先按原实际列重排映射原索引，再核原 PK 与最终候选 PK 除方向外的完整键事实一致，逐个辅助键按准确 cid／名称／排序规则对应最终 PK，只推导其方向。显式索引自身完整键、SQL、顺序和其余元数据仍须逐项一致，不能简单忽略所有辅助键；最终全部自动索引仍完整比较。混合主键修改继续沿原已验证 PK 计划。

上述风险进入 WR UNIQUE 预览警告，后续编辑区必须展示并单独确认唯一性／父键影响。
