# SQLite 已有 CHECK：原表重建编辑区

## 本次功能

普通 SQLite `main` 表右键选择“修改 SQLite 字段、顺序与约束…”，明确读取后在“SQLite 检查约束”区操作。复用 [既有独立事务](sqlite-check-engine-20261102.md)，不增加命令、写权限或配置格式。

- 查看准确原 SQL、全部命名标记、声明位置及行内附着字段；匿名、同名和重复声明按原序号分别展示。旧 `ON CONFLICT` 只说明兼容语义，不提供无效设置或关闭检查开关。
- 新增、修改、标记移除、撤销及继续编辑本地草稿。表级／行内切换保留表达式和原字段选择，已有生成字段可附着 CHECK，行内表达式可引用本表其它字段。
- 表达式使用多行输入，遵守既有 64KiB UTF-8、64 层括号及整批预算。未完成／无效输入保留，暂存不求值；实际函数、NULL／NUMERIC 及全部原行由 SQLite 原事务检查。
- 替换任何旧表达式先核完整原文；字段、位置、名称或表达式改变会撤销原文确认。新声明允许匿名，继续编辑匿名替换不会恢复原名。新名字及整批名称交换留完整预览统一核对。
- CHECK 与主外键／UNIQUE 输入互斥，四类已暂存补丁可与字段和实际顺序共同预览；外键本地编译也纳入本批释放的 CHECK 名字。未暂存输入、关闭和重读均有完整草稿保护。
- 所有输入／队列变化撤销旧预览及风险确认，准确释放旧能力；回包 CHECK 计数必须等于请求项数。额外确认 CHECK 表达式、NULL 和原数据风险，且目标名称准确才允许提交。只读可设计预览，不能执行。
- 表单令牌、队列对象引用、来源世代、目录过期、连接 ABA、忙态和关闭保护保持；旧按钮、连续输入和迟到回包不能修改后继草稿。回滚后保留草稿，不自动重试；未知态及 COMMIT ACK 沿原永久锁定保护。

新增中文文案集中管理。原文和列表有界滚动，长名称可换行，多行输入适应窄窗口；不增加行内树按钮，原 31px 对象树保持。
