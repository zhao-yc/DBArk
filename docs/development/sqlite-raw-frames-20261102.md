# SQLite 有界原字节批次与消费者确认（内部候选）

在[语句适配器](sqlite-raw-statement-20261102.md)上新增原生批次、跨帧单值解码、消费者确认和协作取消。仍未替换`SqliteWorkerCore`，客户端普通SQL结果的原字节保护尚未交付，不增加R02完整工作包或发行计数。

## 实现与约束

- C内部命令16每次最多200行、64～1MiB一帧，默认64KiB。帧头为版本及安全整数序号，行／单值／终态分别编码；数据可跨帧，头部不会切开。原1MiB单值和20MiB SQL材料上限保持，不能因帧头占位降低字段上限。
- 每次只保留当前帧和一个独立值副本，按原生存储类型及每格编码读取，不重新执行SQL。TEXT在原生侧先核UTF8／UTF16字节及UTF8表示预算，防止读到坏文本后继续预取后继行；JS再次严格解码，保留真实替代字符、BOM和NUL。
- `rawFrames.ts`解析后输出行开始／值／行完成／终态事件，不累计整行或全结果。坏序号、长度、列数、类型、编码和不完整成功终态明确拒绝；半行不会变成完整行，失败保持原错误。
- `consumeSqliteRawFrames`等待每帧`onFrame`确认，确认前不请求下一帧；读取前及确认后核取消，即使同步确认也让出事件循环。退出时明确放弃未完成单值；原statement由持有者显式finalize，不自动提交、回滚或重放。
- 逐行与帧模式不能混读；原生1555错误及消费者确认失败同时保留。原IPC、数据库配置及扩展加载策略不变。

## 真实验证

WIN11-TEST不可达且未派发任务，按既有授权在本机Windows x64串行执行；只操作本例合成SQLite文件，无Server-200、Docker、安装版配置、系统剪贴板或实体输入。

最终回执：`.cache/sqlite-raw-probe-evdZ7O/report.json`，记录C／解码器／语句适配器／帧模块／探针五份源码摘要。UTF-8、UTF-16LE、UTF-16BE分别通过：

- 每种编码读取递归SELECT的1,000,001行，只累计行数及精确总和500001500001；共5001帧，每帧最多200行及64KiB。该项为真实原生流读取，不是百万行实表分页、滚动或磁盘吞吐验收。
- 最大1MiB BLOB及各编码原生允许的最大TEXT跨帧往返；整行可跨多个帧，不把帧预算误用为行预算。UTF16原字节合规但UTF8表示超1MiB时拒绝，未提高原门槛。signed64两端、负零、无穷、五类值及空值保持。
- 首帧确认挂起时只有一次读取、两次准确表达式求值；确认后取消不再读取，显式收尾后原BEGIN仍保持，用户明确ROLLBACK。跨最大字段的半帧取消后可重新查询；坏TEXT只完成前一合法行，不执行后继分支。
- `RETURNING`只传一行后取消并finalize，自动事务的3行写入已由独立连接确认；显式事务仍未提交，明确ROLLBACK后独立读回恢复。首帧前取消本例INSERT为零写入。此事实符合[SQLite处理顺序与事务说明](https://www.sqlite.org/lang_returning.html#processing_order)，取消读取不代表已回滚写入。
- 原权限、参数、列元数据、长SQL、trigger边界、错误码、正常关闭和夹具精确清理断言继续通过。

61项相关边界单元包含在最终扩大SQLite相关189文件3776项通过中；采用3个worker、原5秒门和零重试，严格类型及构建通过，既有注释／分块体积提示保留。原生错误码与成功终态在消费者回调前捕获，回调修改对象也不能覆盖真实事实；同时核对四个客户端运行入口仍与原已验产物逐字节一致。原始日志在`.cache/sqlite-raw-frames-20261102/`；最初大小诊断因HEX会翻倍输出而超限的原件保留，后续改用独立TEXT与字节长度读取，没有改产品门槛。
