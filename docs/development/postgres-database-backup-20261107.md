# PostgreSQL 整库备份

1. 在「工具 → PostgreSQL 整库备份」选择已保存的连接和来源数据库。
2. 点击「选择 PostgreSQL pg_dump」，指定本机可信的 PostgreSQL 安装中的原生工具。macOS 选择 `pg_dump`，Windows 选择 `pg_dump.exe`。支持 14 或更新版本，推荐使用与来源数据库相同主版本的工具。
3. 默认保留对象所有者和授权。迁往角色配置不同的服务器时，可勾选「省略所有者和授权」。
4. 选择 `.sql` 文件并点击「确认并开始备份」。看到已保存字节数后，可在「工具 → 执行 PostgreSQL SQL 文件」中将文件[恢复到新库](postgres-restore-new-database-20261107.md)。

客户端用原连接导出只读事务快照，原生工具导入同一快照并生成 UTF-8 纯文本 SQL。整库备份覆盖单个数据库及原生工具识别的对象。角色和表空间等集群级定义需要独立备份。文件上限为 10 GiB。

选定工具和备份路径由系统文件对话框授权。连接的密码经私有临时文件提供给 libpq。该格式不支持含换行的密码。SSH 沿用原连接已验证的主机指纹，TLS 沿用连接的验证模式及证书。子进程输出直接进入同目录暂存文件，子进程、临时认证文件和连接收尾后才替换目标文件。取消或执行失败时原目标文件保留。原生工具的提示显示在本次窗口。

参考 [PostgreSQL pg_dump](https://www.postgresql.org/docs/18/app-pgdump.html)和 [libpq 密码文件](https://www.postgresql.org/docs/18/libpq-pgpass.html)。

## 2026-11-07 验收

- Windows 测试会话不可达，使用 macOS arm64 源码 Electron。测试库为 `server-200` 上的隔离 PostgreSQL 18.6，选取经官方源校验并在本机测试目录编译的 `pg_dump 18.6`。
- 在桌面窗口完成直连及 SSH 与 TLS 联用的整库备份。两份文件均为 5,963,993 字节。将直连备份通过客户端恢复至新库，确认提交 63 条语句，核对 84 行的摘要、标识序列、物化视图结果和大对象摘要。直连文件 SHA-256 为 `f6b1862d4e086a7f8999d4029e65963381876e24713cb5216972d9051fc387ab`。
- 当 TLS 加密的备份后端实际等待表锁时，通过窗口取消。在放开表锁前核对后端已退出，既有目标文件的字节保持原样。结束后 PostgreSQL 残留测试会话和新增临时认证目录均为零，隔离容器、SSH 和回环资源已清理。
- 首轮修正同步测试夹具阻塞本机 SSH 服务的问题。复测发现单独结束子进程仍会留下等待锁的后端，定稿按任务及后端身份结束并复核该会话。全量回归中发现的 Main 取消测试夹具和菜单登记兼容问题也已修正。原始失败日志保留。
- 类型检查、构建及 4 项 Electron 原生测试通过。全量 Vitest 共 1,355 个测试文件通过，27,617 项通过，10 项按环境条件跳过。
- Windows、安装包、其他 PostgreSQL 主版本、客户端证书认证及 10 GiB 边界仍待验证。
