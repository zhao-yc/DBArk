# D07 Hex 查看与实际暂存预算统一

复审发现无前缀 131072 字节 Hex 恰好占 262144 字符，查看器会拒绝，但旧暂存器可接受。修复让实际二进制暂存经由查看器的同一 `parseBinaryHex` 校验，不依赖界面错误或按钮状态。校验通过的字节再分段编码为 Base64，避免大型展开参数。

预算保持不变：原始字段 262144 UTF-16 单元、完整二进制编辑 131071 字节、整行输入 2097152 单元。0x 和空白计算在原始字符预算内；去除它们后仍独立计算实际字节预算。NULL、DEFAULT 和零字节二进制的语义不变。

相关单元覆盖有无前缀、空白、合法上限、字节多 1、原始字符多 1，以及最终暂存不能绕过、拒绝后原文／原始值保持。真实 Electron 用例验证无前缀超限在点击实际暂存后仍保留完整输入与错误、不形成草稿、不投递写库请求；合法最大值暂存后再次打开仍完整一致。
