# PostgreSQL 命名方案保存列布局

在 PostgreSQL 表或视图中应用需要的筛选和排序，再通过「列布局」调整显示列、顺序、冻结边界、宽度和行高。打开「命名方案」，保留默认勾选的「包含当前列布局」，输入名称并保存。方案捕获当前看到的列布局，可以和该关系独立保存的默认布局不同。取消勾选可只保存筛选和排序。

选中方案并点击「应用方案」。如果方案包含列布局，服务器成功返回首页后，筛选、排序和布局一起生效。查询失败时保留原页及布局。有未保存的列布局时，需先确认替换。旧方案和未包含布局的方案只恢复筛选和排序。

应用方案后，表页会标明当前显示来自命名方案。要回到独立保存的布局，在「列布局」点击「重新读取已保存布局」。也可以明确保存当前布局，将它用作此对象的默认设置。字段按准确名称匹配，已删除的布局列会移除，新列追加。筛选或排序引用已不存在的字段时，整份方案会拒绝应用。

布局与原条件文档在同一事务中保存。旧条件文档保持原格式，附加布局只和内容匹配的条目一起读取。对象树直接打开方案和跨设备同步仍待接入。[Navicat 表配置手册](https://www.navicat.com/manual/online_manual/en/navicat_18/win_manual/data_rdbms.html#save-table-profile)

## 验证

- macOS 上 Node.js 24.17.0 运行时检查、类型检查和源码构建通过。方案、布局和迁移专项共 8 个文件、86 项通过，覆盖旧格式读取、组合方案写盘及重开、旧客户端条件修改、覆盖、删除和写盘回滚。
- macOS 完整单元回归共 1,326 个文件，27,461 项通过，10 项 Windows 系统 tar 用例跳过。首轮共享方案面板在 MySQL 入口读取了 PostgreSQL 专用提示，限制提示范围后，受影响入口专项和完整回归均复跑通过。
- Server-200 独占 PostgreSQL 18 实库回归 5 项通过。实库与窗口轮次均独立核对原表数据及零连接，随后清理专用容器。
- macOS Electron 原生窗口回归通过，共 67 项观察。组合方案恢复筛选、首页和指定列宽。取消替换或 PostgreSQL 拒绝无效整数时，原页和原布局继续可用。重读后恢复独立保存的列宽，后续翻页和导出通过。
- Windows 测试虚拟机不可达，本轮在 macOS 验证。Windows、两平台安装包及较早 PostgreSQL 版本待验证。
