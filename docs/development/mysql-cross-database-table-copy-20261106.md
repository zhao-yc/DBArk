# MySQL 同连接跨库整表复制

从 MySQL 普通表页的「更多」菜单或对象菜单打开「复制表结构」或「复制表结构及数据」。在「目标数据库」选择同一连接下的现有库并输入新表名。跨库可以使用与来源相同的表名。同库保留新名称要求。预览后输入准确的 `目标库.新表名` 并勾选确认。成功回执刷新目标库对象树，来源标签和工作区草稿继续保留。

结构模式沿用 MySQL 8.0.46 和 8.4.11 的 Linux 普通 InnoDB 表能力。数据模式沿用 8.4.11 的能力。两端库名和来源表名须为非系统库的 ASCII 标识符，并通过现有权限、物理身份和依赖检查。预览及提交前会读取目标库的默认字符集、排序规则和加密选项，比较两次目录值，检查目标名未被表或视图占用。目标库的目录选项核对无法消除外部并发 DDL 的窗口。

结构使用完全限定的 `CREATE TABLE … LIKE`。数据模式随后在独立的 `READ COMMITTED` 事务执行完全限定的 `INSERT … SELECT`。自增零值、定点数和二进制直接由服务器传递。建表和数据提交是两个阶段。数据失败、取消或提交未知时可能已有目标表，界面保留阶段回执供核对。当前范围排除外键、触发器和特殊索引等依赖，数据模式也排除生成列。[MySQL CREATE TABLE LIKE](https://dev.mysql.com/doc/refman/8.4/en/create-table-like.html) · [MySQL INSERT SELECT](https://dev.mysql.com/doc/refman/8.4/en/insert-select.html)

## 验收

- WIN11-TEST 不可达，按授权在 macOS arm64 使用 Node.js 24.17.0。原生运行时、类型检查、构建和 411 项定向测试通过。全量单测覆盖 1,349 个文件，27,558 项通过，10 项按平台条件跳过。
- Server-200 上的 MySQL 8.4.11 和 8.0.46 均通过实库结构复制。核对了空表、独立自增初值、缺失目标库、同名视图占用和目标库目录变更拒绝。8.4.11 还核对了同名数据副本和三行精确值，8.0.46 的数据入口仍为只读。成功轮次核对零连接后清理隔离容器。
- macOS Electron 窗口在 MySQL 8.4.11 上分别完成跨库空表和同名数据副本。核对两次预览零写入、拒绝用来源库名称确认、目标目录刷新、三行原值和正常退出。独立连接核对自增零值、无符号大整数、30 位小数、二进制、NULL 和空值。
- 首轮实库读回的 SQL 误将转为文本的主键按字典序排序，保留了原始结果与已停止的独占容器。复验按数值主键排序。
- Windows 和安装包待验。MariaDB、网络库跨连接和跨引擎整表复制待实现。
