# PostgreSQL 表页查找与替换

在表或视图的记录页点击「查找本页」，或按 `Ctrl/⌘+F`。可按数据、字段名或 SQL NULL 查找，并限制到一列。文字查找支持区分大小写、整格匹配和高亮所有匹配。按 `F3` 或 `Shift+F3` 在匹配位置间前后移动。结果按本页行和可见列顺序定位，包括已有的更新草稿。待删除记录会跳过。 [Navicat 查找与替换手册](https://www.navicat.com/manual/online_manual/en/navicat_18/win_manual/data_rdbms.html#sort--find--replace-records)

在可更新的普通表点击「替换本页」，也可按 `Ctrl+H`（Windows）或 `⌥+⌘+F`（macOS）。查找后选择预览替换当前处或全部匹配。替换支持 PostgreSQL `text`、`character` 和 `character varying` 字段。文字按字面替换，空输入可移除匹配内容。数字、日期等匹配仍可导航。字段名、SQL NULL、生成列和字节不参与文字替换。

检查替换前后的值，确认加入草稿。已有行的其他暂存字段继续保留，替换沿用该行首次暂存的原行版本。当前页、可见列或草稿一旦变化，旧预览即失效。点击「预览记录修改」检查整批 SQL 和字段，然后明确确认提交。

## 验证

- macOS 上 Node.js 24.17.0 运行时检查、类型检查和源码构建通过。39 项定向回归覆盖 PostgreSQL 草稿、字面替换、查找线程和已有结果查找。
- macOS 完整单元回归共 1,329 个文件，27,479 项通过，10 项 Windows 系统 tar 用例跳过。
- Server-200 独占 PostgreSQL 18 实库回归 5 项通过。Mac 原生用例通过独立连接确认了暂存时的原值、提交后的字面 `$&` 和测试后的记录恢复。
- 定稿 macOS 原生窗口回归通过，共 72 项观察。查找和替换快捷键、字段定位、全部高亮开关、单处与全部替换、预览可见、取消和放弃草稿均已核验。定稿窗口正常退出，临时配置清理。实库确认原记录和零连接后清理容器。
- 首轮原生测试在「查找目标」的可访问标签定位超时，修正后按原断言和 120 秒门槛重跑。首轮原始日志、临时工作区和已停止的隔离库保留。复跑截图发现预览被挤出可视区，定稿调整了控件和预览布局。
- Windows 虚拟机不可达，本轮按约定使用 Mac。Windows 原生操作、两平台安装包和较早 PostgreSQL 版本待验。
