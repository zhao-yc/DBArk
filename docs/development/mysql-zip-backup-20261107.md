# MySQL／MariaDB 整库 ZIP 归档

在「工具 → MySQL／MariaDB 整库备份」选择来源、数据库和相应的原生转储工具。在「备份格式」选「tabrelio ZIP 归档」，选择保存位置并开始备份。原有「SQL 脚本」仍是默认选项。ZIP 和 SQL 的保存位置分别授权。

生成的 ZIP64 使用 STORE，包含原始 `dump.sql` 和 `manifest.json`。第二版清单记录数据库、实际服务器版本、可见对象、所选转储程序的 SHA-256、InnoDB 一致性读取方式、任务时间和原始 SQL 的大小与 SHA-256。目录来自源库可见对象，定义摘要与外部依赖仍需另行核对。原有第一版归档可继续打开。ZIP 上限 10 GiB，包含清单和容器开销。

写入期间保留原生转储字节。转储成功退出、源目录复核及连接收尾后，客户端写入清单并原子提交 ZIP。取消或失败时保留原有目标文件。

在「工具 → 打开数据库备份归档」选择 ZIP，可以校验归档和原始 SQL 摘要、查看对象、检查目标并导出 SQL。恢复时使用「执行 MySQL／MariaDB SQL 文件」在合适的目标连接执行导出的文件。恢复前请核对库名、脚本和权限。数据库范围和 SSH 的 TLS 条件沿用现有备份流程。[原生整库备份](mysql-native-database-backup-20261107.md) · [SSH 备份](mysql-ssh-database-backup-20261107.md)
