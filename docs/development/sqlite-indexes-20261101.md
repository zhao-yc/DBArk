# SQLite 已有表索引管理

本增量属于当前开发源码，不属于已发布安装包。支持 SQLite `main` 中现存普通表的索引查看、创建、替换和删除；阶段验证与上一提交的失败记录分别列在下文，不据此声明 macOS、安装包或正式发行已验收。

## 入口与使用

- 左侧 SQLite `main` 下右键普通表，选择“管理 SQLite 索引”。
- 对象浏览的“表”分类，在准确表行的对象操作菜单选择“管理 SQLite 索引”。
- SQLite 表页“更多 → 设计与结构 → 管理 SQLite 索引”。此入口使用当前原表页，不借左树另一个连接或数据库替换目标。

先明确读取原索引目录，再添加本地设计或选择替换、删除。支持普通／唯一索引、多个有序键、字段键与表达式键、各键 ASC／DESC、显式可选 COLLATE，以及部分索引 WHERE。排序规则来自当前连接的实际目录；省略 COLLATE 时保留 SQLite 原有的字段／表达式语义。

目录保留原 CREATE INDEX SQL 和完整 xinfo，包括表达式 `cid=-2`、rowid `cid=-1` 以及辅助键的 `key=false`。主键和 UNIQUE 表约束生成的自动索引只显示，不能在此删除或替换。只读连接可以查看、设计和预览，不能提交修改。

替换从原 SQLite DDL 恢复设计。无法可靠恢复时保留完整原 SQL，明确要求人工核对并填写完整新设计，不自动生成省略表达式、排序规则或 WHERE 的草稿。设计器不提供任意 SQL 脚本执行入口；表达式和 WHERE 在只读预览阶段仅进行有界安全词法及原目录检查，字符串／注释中的分号或问号不被误当作语句分隔符或参数，外部参数、外部分号及未闭合片段拒绝。表达式两侧保留必要换行，末尾行注释不能吞掉外层括号。只读预览不通过 EXPLAIN CREATE 提前进行原生 DDL 语义校验；SQLite 表达式语义、UNIQUE 及其它约束须在用户明确确认后的独立写事务中验证，失败整组回滚。

预览显示整组 SQL 及创建／删除数量。替换对应先 DROP 再 CREATE 两个动作；输入准确的 `main.表名` 后，只提交一次原预览。读取目录、编辑草稿和关闭预览都不执行原 DDL。

## 事务、来源与原页面

索引提交使用独立物理连接及单独的 `BEGIN IMMEDIATE` 事务，不借用用户查询会话、临时表或活动事务。在写锁内重核原数据库身份、表及索引目录和依赖，执行 DDL 时由原生 SQLite 校验表达式、排序规则和约束；事务内先后比较原表／索引定义及外键检查结果，全部通过后才发送 COMMIT。不会通过关闭外键、隐式替换或遇错继续来完成本批次。任一动作失败时整组回滚；不能确认提交／回滚时保留未知，不自动重放。

Main 绑定原窗口文档、连接修订及连接代次，仅接收固定的 `sqlite.indexes.inspect`／`preview`／`apply`／`release`。预览 SQL 必须与共享构造器根据原输入重建的计划一致，公共输入不能注入路径、连接对象、操作编号或事实持久化回调。

目录和预览各有独立的 5 分钟期限。自然到期只阻止新领取，已领取只读预检保留准确父引用直至结束；明确释放仍能撤销跨 TTL 的在途预检及未领取子预览。已领取 writer 的元数据释放不等于取消事务，停止、关闭和退出继续等待准确原请求、取消应答及实际资源收尾。最终 IPC 发布前再次核验来源，不接纳晚回重建的能力。

打开索引窗口前检查准确同表的全部表页，包括隐藏页的 dirty 和活动作业，不自动放弃原数据草稿。提交已确认且定义核验通过时，仅通知原连接／表：活动且无草稿、未决写入、字段编辑／预览或导入导出占用的原页可按原条件和页位置重新读取。遇到脏页、未知结果或核验不明时保留原页与草稿、撤销旧快照的写权限并提示明确刷新，不用后台新回包覆盖内容，不改变已有查询会话。

本轮审查还修复了未知结构回执后的自动读取漏洞：原 clean 页切走再激活，不能绕过“禁止自动刷新”；后续已知回执也不解除该原标签的单向读取锁。只有用户明确“刷新”或“应用筛选排序”，经过原草稿／作业检查和必要的放弃确认后，才可解除锁并重新读取。只读和读写表页分别增加组件回归，不将自动读取当作已确认提交的替代证明。

预算为每份设计最多 64 个索引键、整组最多 128 个动作、目录最多 128 个索引；表达式／WHERE 单值 64KiB，合同及 DDL 总预算 2MiB。目录和预览分别最多 64 份／64MiB／5 分钟。新索引名最多 255 个 Unicode 字符，名称整体引用、仅按 ASCII 大小写比较，并拒绝 `sqlite_` 保留前缀。

## 提交事实与响应中断

Main 在 COMMIT 前同步保存最小事务事实，真实 COMMIT ACK 优先于最终响应、关闭或通知异常。任务中心的“SQLite 索引事务回执”显示阶段、原操作编号、完整连接／库／表目标、请求及已处理 DDL 条数；处理条数不是提交确认。持久任务不保存表达式、WHERE、SQL、路径或驱动错误原文。重启只恢复最小事实，未决阶段转未知，不恢复预览或自动执行原设计。

本轮同时修复旧整文件导入的确认展示竞态：已验证事实按 COMMIT ACK、ROLLBACK ACK、等待提交的顺序展示，迟到进度不能覆盖已知终态。若原 apply 请求在 Main 已发布同操作、同目标、同请求数量的 ACK 后断包，组件依据该严格事实保留提交／回滚结果，并继续等待准确 release。失败响应对象夹带的字段、跨任务／跨操作／跨目标回执、错误数量或未确认进度均不能补造 ACK，未确认结果仍锁为 unknown。

同类索引窗口也保留上述边界：已知回滚不因响应中断误报“执行结果未知”，已知提交不漏掉原提交回调。停止及旧按钮闭包不能在 ACK 或 COMMIT 边界后再次取消；原请求与 release 未结束前不提前关闭或重复通知提交。

进一步覆盖原请求先断包或先返回 unknown、准确 ACK 才在 held release／cancel ACK 期间到达的顺序：原请求行数在领取时固定，响应已结束后只收束合法同操作回执；事件只更新展示，原请求、释放及取消应答全部结束后才单次通知提交。已知回执保留原清理告警和合法失败行；晚回滚解除 unknown 展示锁，但不自动预检或重放。原表页不会因漏掉通知而一直保留已提交草稿。
