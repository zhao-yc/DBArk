# PostgreSQL 多表 SQL 备份与恢复

从「工具 → PostgreSQL 多表备份」选择已保存的连接和数据库。按 schema 或表名搜索，勾选本次需要恢复的表，再选择保存位置并开始备份。一份文件最多包含 64 张普通持久表。没有主键的表也可选，备份包含其全部记录，包括重复值与 NULL。

来源读取使用同一个只读事务和一致性快照。客户端先锁住所选表的结构，再分批读取数据。全部读取成功、连接已收尾后才发布暂存文件。所属序列的状态单独读取，繁忙时可能领先于记录快照。

恢复前，在目标库准备同名 schema，以及未纳入备份的依赖对象，例如外部父表、类型、函数、排序规则和外部序列。通过目标库空闲查询标签打开 SQL，确认连接后执行整份文件。执行顺序为序列与表、列默认值、记录、主键及索引、外键、用户触发器和序列状态。先恢复全组的数据和索引，可以在事务内恢复互相引用的表。同名对象冲突或其它错误会使该事务无法提交。会话若仍处于失败事务状态，可从查询页回滚。

备份范围沿用普通表的逻辑结构，分区、继承、启用行级安全、重写规则和不完整结构仍有范围限制。对象所有者、权限、数据库级配置和其它对象依赖需单独处理。建表表达式或类型依赖外部对象时，需提前在目标库准备。超过查询编辑器执行上限的文件可由 PostgreSQL 原生客户端回放。

相关分段和快照概念见 [PostgreSQL pg_dump 文档](https://www.postgresql.org/docs/18/app-pgdump.html)。

## 2026-11-07 验收

- Windows 测试虚拟机连接不可用，本轮使用 macOS arm64 源码 Electron 和 `server-200` 上隔离的 PostgreSQL 18.6。通过普通账号和两个数据库执行测试。测试账号残留会话为零，容器和 SSH 转发均已清理。
- 在工具菜单选择三张表，备份五行数据。回放保留跨 schema 双向外键、外键依赖的独立唯一索引、对另一所选表标识序列的默认值、精确大整数和小数、字节、无主键表的重复值及 NULL。目标查询页取得 `COMMIT` 回执，独立连接核对记录和外键。未选表未导出，启用行级安全的表不列入候选。
- 目标存在同名表时，前面创建的表随事务回滚，既有表和记录保留。来源记录前后一致。原单表备份及恢复也在同一隔离实例串行回归。
- 定稿通过 `node scripts/typecheck.mjs`、`node scripts/build.mjs` 和单 worker 的两项 Electron 原生用例。全量 Vitest 通过 1,353 个文件，27,585 项通过，10 项按环境门槛跳过。
- 本轮 Windows 源码界面、安装包、其它 PostgreSQL 主版本及整库备份恢复尚待验收。
