# 查询脚本遇错继续

## 使用与执行语义

查询工具栏新增“遇错继续”，默认关闭，关闭标签后恢复默认，不写入连接或工作区配置。普通执行、选区／当前语句和类型参数查询在发送前固定本次取值；类型参数窗口打开时固定取值。执行计划、实际执行分析、流式导出及文件任务不附带该选项。

关闭时保持原首错停止行为；开启后，对原连接实际返回且允许继续的服务器语句错误，记录失败并执行下一条原语句，不重放失败语句。取消、断线、服务器中断／超时、本地解析／消费异常、会话恢复失败均停止。最多记录100项失败，达到上限后不再执行后续语句。

“遇错继续执行摘要”显示已尝试处理数、完整成功数、失败序号、是否到达脚本末尾及停止原因；有错误时任务和执行历史仍记失败，全成功也显示摘要。错误定位只选择原模板，不发SQL、不改变正文；正文、模型或连接来源改变后旧定位失效，Undo恢复同文也不复活。多个错误共用一份模型租约，不复制多份完整脚本。

成功语句的完整结果仍可查看、固定、排序、筛选和导出；失败CALL在ERR之前返回的片段整条丢弃，不充作成功结果。整项任务共用原行数／200结果／16MiB预算，失败片段已消耗的预算不退还；显示截断不省略后续用户SQL，也不虚构不存在的失败语句。

客户端不会自动提交或回滚；服务器错误（例如死锁）仍可能回滚事务，后续语句按实际会话状态执行。失败语句也可能已部分写入，此前提交不撤销。继续前会在同一物理会话读取实际SQL模式、连接ID和默认库，改变 `ROW_COUNT()`、`FOUND_ROWS()`、警告等诊断；工具栏提示明确说明此差异。

## 实现边界

两项查询IPC新增可选布尔 `continueOnError`，关闭时渲染端完全省略；仅 `=== true` 走新路径，原默认解析和执行主体保留。复用唯一调度器处理注释、字符串、DELIMITER、动态模式、类型参数及原UTF16范围；共享预算不随错误或语句重置。

只有本条原驱动 `error` 事件的同一个Error对象，在原命令 `end` 或原物理连接终态后，才能进入分类。连接／中断错误、网络、本地伪造错误码不能凭外形冒充可继续的服务器ERR。失败语句不会发布columns／batch；成功终态后引用既有有界结果分批发布。

ERR后使用固定三列诊断，清除旧协议缓存再核对原线程、实际模式、默认库、新鲜事务状态及转义模式一致性；不重连、不切库、不改自动提交。类型参数的错误、停止原因与历史只保留安全错误码，原 `message`／`sqlMessage`／展开SQL不进入错误报告。查询结果按原隐私说明仍可能显示实际参数值。

报告最多100项，单条4096个UTF16单元与4096字节，包含JSON转义预算，总JSON不超过512KiB。取消控制落定后释放任务、完成信号及原会话占用；控制连接收尾失败保留原错误，不将观察超时当作进程结束。

本轮实库还发现 mysql2 3.24.5 的EOF状态读取使用有符号16位：MariaDB开启ANSI_QUOTES后，SET的OK状态为33282，而SELECT的EOF被读成-32254，导致合法状态被拒。两个Maria实例的独立短会话均复现，实际字符串解析仍按NBE；真实Packet二进制用例修前5失败／5通过。沿原pnpm补丁机制只将 `eofStatusFlags()` 改为无符号读取，锁文件更新同版本补丁摘要，修后原10项全部通过；未放宽原0～65535状态、身份或模式一致性门槛。[MySQL EOF协议](https://dev.mysql.com/doc/dev/mysql-server/latest/page_protocol_basic_eof_packet.html)规定两字节状态，[MariaDB官方定义](https://raw.githubusercontent.com/MariaDB/server/mariadb-10.11.19/include/mysql_com.h)包含ANSI_QUOTES高位。
