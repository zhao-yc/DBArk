# SQLite 已有 CHECK：准确声明模型与编译

## 本阶段实现

后续已完成[Main／Runtime 受限预览与独立事务接入](sqlite-check-engine-20261102.md)。本页保留声明编译阶段的历史边界与原始验证；编辑区和平台验收仍按后续记录推进。

新增 `src/shared/sqliteTableChecks.ts` 与原表重建编译器中的 CHECK 声明读取、增改删及组合编译。**尚无新 CHECK 用户入口、预览契约或写权限**；Main 原 `sqlite.tableRebuild.preview` 仍拒绝额外 `checkEdits`，不能用本阶段的 SQL 字符串冒充可提交能力。

- 结构定义只有约束名、行内／表级位置、行内准确附着字段和表达式。普通及已有生成字段可承载 CHECK，声明位置不限制表达式引用其它本表字段。
- 新表达式最多 64KiB UTF-8、64 层括号；识别引号、双写引号、标识符和注释，拒绝外部参数、语句分隔符、NUL、坏 Unicode、未闭合文字及越界括号。生成 `CHECK (换行 + 原表达式 + 换行)`，防止尾行注释吞掉闭括号。不执行函数、不求值，不把词法隔离称为完整 SQLite 语义解析。
- 通过真实原 SQL 跨度和字段目录读取序号、位置、全部命名标记、准确原表达式与原 SQL；重名、匿名及相同表达式分别保留。`CHECK`、`DEFAULT` 等字符串或注释不会被误识别为其它约束。
- 修改以原序号和完整原 SQL 共同绑定，保留未改字段、默认值、主外键、UNIQUE、生成表达式及表选项；移除表级声明仍保留边界注释。新名字只与最终保留声明核对，不能按同名批量删除。
- 支持在内部声明编译中先释放原 CHECK，再沿原主键／外键／UNIQUE、类型／默认值路径处理，最后添加新 CHECK 和实际重排；四类约束名称循环交换已有独立 native 候选证明。该证明不等于所有表达式、私有重建或写协议已接入。
- 最多 128 项编辑、1024 条原声明和 2MiB 序列化输入；Zod 读取属性前拒绝访问器、循环、稀疏数组、非预期原型和超预算输入。组合分支复制选项前先核全部可选编辑描述符。

CHECK 按 SQLite 的 NUMERIC 规则判定，NULL 并不违规，不能代替 NOT NULL；旧表级 `ON CONFLICT` 兼容子句不改变声明的默认 ABORT 行为。原文仅读取为 `legacyConflict`，新模型不提供无效的冲突设置或启停 PRAGMA。参见 [SQLite 官方 CHECK 与冲突说明](https://www.sqlite.org/lang_createtable.html#check_constraints)，上述规则同时由独立 native 测试验证。

## 接入独立事务前必须解决的内容

1. 通过原受限契约加入准确 `checkEdits`／计数，Main 与 Runtime 分别重算；原完整目录、来源、预览租约、取消及真实事务事实保持。
2. 独立 writer 必须核实际 CHECK 检查开启。预览不得试执行表达式；原坏行、原函数不可用及新规则不满足均须完整 OR ABORT 复制与真实回滚，不跳行、不替换、不自动重放。
3. 保留双候选及四次 typed 比较、原 rowid／主键／序列、生成值、附属定义及其它表保护。仅 CHECK 改动不暗改主外键；混合主键／UNIQUE 沿原完整父键规则，不能扩大写权限。
4. 表达式中的本表限定引用必须安全处理，不能只把 CREATE 表头换成私有名。后续需设计并证明私有候选与最终准确目标定义、复制及后验链，或其它等效方案，不能牺牲未修改表达式及依赖保护。
5. 原编辑区须显示准确原文、增改删、局部草稿和整批 SQL，替换需明确核对表达式；所有字段、位置及风险变化撤销旧预览。只读、过期、源 ABA 和未知结果保持原保护。

## 已确认的限定引用边界

独立 native 探针确认：`child.a>0`、`main.child.a>0`、`"child"."a">0` 在准确原表合法，直接搬到名为 candidate 的表均报 `no such column: child.a`。以 candidate 自限定创建再改名，`legacy_alter_table=OFF` 会重写限定名；现有独立 writer 使用的 ON 模式则报重解析错误。

这不是可凭字符串替换或单独翻转开关宣布解决的边界，仍须同时保护原视图、触发器、外键、完整 SQL 和真实数据。本轮只读探针保留在 `probe-qualified.log`／`probe-rename.log`。后续已补充[限定引用私有定义与原名 CREATE 路线证明](sqlite-check-qualified-copy-20261102.md)，四种布局及晚期真实回滚的 native 内存原型通过；**Main／Runtime 的限定引用私有重建仍须接入**，不将原安全拒绝或内存原型计为用户入口成功写入，也不把不支持限定引用改成最终交付目标。
