# SQLite 已有主键：组合计划与独立事务

## 本轮实现

继[准确声明编译](sqlite-primary-key-plan-20261102.md)后，已有表主键增改删贯通原四条表重建命令、Main、Runtime、能力仓库与独立 writer。预览新增严格可选 `primaryKeyEdit`，输出明确 `changedPrimaryKey`；字段类型、默认值、实际列顺序、主键和外键可同批设计。Main 独立重算 SQL、风险及变化标记，Runtime 保存独立副本并计入预览内存预算，领取后再次完整重算，篡改主键补丁在 BEGIN 前拒绝。

本轮尚未新增主键编辑界面，不能算完整用户功能；下一步在原重建窗口接入原主键查看、有序复合字段、命名、行内／表级位置、排序规则、冲突和自增设计，以及草稿保护和身份／序列风险确认。暂不发布。

## 同批编译与行身份

主外键共同绑定准确原声明。编译先释放选中原主键跨度，在内部应用外键及字段补丁，最后添加新主键并应用实际列顺序；仅最终候选可以发布。内部短暂缺少 WITHOUT ROWID 主键的字符串不执行、不签发；最终仍必须有可靠主键。新约束名仅对最终保留集合检查，主外键名字互换不产生分步假冲突，未改字段、约束、注释与表选项仍保留原文。

最终计划推导主键顺序、隐含 NOT NULL、整数 ROWID 别名及自增身份，并在候选、移除私有序号之后及最终原表逐项对照原生目录。行内 INTEGER DESC 保留独立索引语义，STRICT 与 WITHOUT ROWID 的隐含可空性不通过修改列原文伪造。普通表移除整数主键显式复制原物理 ROWID；新增另一整数主键时，风险明确说明物理行号可能变化。

整数主键身份变化仅第一轮比较使用专用内部迁移标记：原生验证来源行身份及候选真实整数别名，按原准确行序／候选连续私有序号逐项比较全部用户值、字节和精度；后续三轮仍核对候选新真实行身份。NULL 被自动填号不能通过值比较，重复主键即使选择 IGNORE／REPLACE，也被固定 INSERT OR ABORT 拒绝，不允许静默少行。WR 主键换序后，验证表按新原生主键顺序重新生成序号，不能复用旧排序或条数代替完整比较。

## 序列、索引与父键

未改变自增身份时保留原目标序列的存在性、准确 rowid 和有符号水位，包括原序列缺失和负 rowid。新启用或换列以新键当前最大值初始化，不低于 0；停用移除目标序列。只有新启用自增时允许原生新增准确 `sqlite_sequence` 系统表；其他表的序列及根页、全部非目标对象继续准确核对。目标主键自动索引与 WR 附属行定位列允许按计划改变；原显式索引 SQL、实际键列、唯一性、表达式及部分索引定义保持，最终自动索引再与完整候选一致。

改变主键可能改变隐式父列映射及可靠父键，不能仅按原 PRAGMA 外键编号或同数旧错误判断安全。本批最终完整外键检查必须可执行且没有违规，既有坏关系须先修复或同批明确修复；即使子表为空也不能以零行跳过父键可靠性。未改主键的旧外键编辑及字段重建保留原具体违规子集规则，不扩大该门槛。写事务、真实 COMMIT／ROLLBACK ACK、未知不重放、取消与正常关闭握手保持；任务概要不保存主键名、业务值、路径或 SQL。
