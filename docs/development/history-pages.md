# 执行历史的有界概要列表

实际入口为“历史与查询”的“执行历史”。进入窗口只取首批概要，支持按连接或无来源、成功/失败、完整 SQL 或错误正文筛选；搜索须点击按钮或按 Enter。条件改变后不能继续旧批次，空命中批次仍可继续检查下一批。

## 数据与协议

`history.page` 严格接收 UUID 编号、普通文字、字段、来源、结果和损坏记录策略；`history.pageContinue` 仅接收新编号及随机句柄，`history.pageRelease` 幂等释放本资料源句柄。`history.read`、`history.readError` 要求标识和原文 SHA256；打开还要求明确有效的连接。

配置库保持 schema5，增加兼容的 `history_started_id`、`history_connection_started_id` 索引。以 `started_at,id` 的 BINARY 降序复合位置读取，不用 OFFSET，不调用旧500条全文接口。来源条件参数绑定，SQLite语句在finally释放。存储仍保留最近1000条，同时间按ID稳定排序；500只是旧接口的返回上限。

每批最多检查25条且返回不超过128KiB，错误和最终句柄计入预算。固定Worker逐条验证JSON、标识、索引来源和时间，再检查结果及完整文本，筛选不能隐藏损坏记录。SQL预览最多512、错误最多256个UTF16单元，代理对不拆分；完整内容仅明确打开或查看错误时读取。原始记录最多128MiB，SQL及错误各最多2000万UTF16单元，超限明确失败，不能按截断内容判断无命中。

普通包含使用JavaScript转小写比较，不执行正则、SQL或参数，不宣称完整Unicode折叠或服务器匹配。错误全文仅保留明确读取的一条，收起、翻批或关闭释放界面引用。损坏记录可选择停止或记录失败继续；累计检查、匹配和失败计数跨批保留，窗口不累积旧卡片。

## 生命周期及打开

`LocalSqlPages`共用两种概要列表的预算、线程收尾、修订、期限及取消实现；两个资料源各最多2个活动页、16个游标/活动状态、5分钟句柄及256个最近编号。原保存查询全文搜索另有2个线程，三种服务合计最多6个，不宣称共用2个全局槽位。

线程沿用固定脚本、空环境、空execArgv和256MiB老代/32MiB新生代设置。逐条处理限时2秒，超时或取消等待真实terminate和本页finally结束，页间无线程/原文缓存。活动及最近概要编号不能跨数据库、补全或另一列表复用。读列表不写任务或历史；退出关闭三类服务、等待完整本地IPC后才关闭SQLite。

成功新增历史、淘汰及连接变化使旧页失效；写盘失败按原有事务/文件回退且修订不增加。关闭、切换或打开新标签先等待读取及准确句柄释放，失败保留窗口和句柄供重试。释放等待后重核关闭状态，迟到响应不能重新启动或打开标签。

同来源保留真实执行开始时的已知库、明确无库、未知及遗留状态。来源失效不能采用当前选择或首个连接，须明确选替代，替代后默认库未知。打开只创建随机标识的新草稿，不执行SQL，不覆盖原标签、结果或事务。摘要变化或记录已淘汰时拒绝旧预览打开及读取错误。

内存sql.js文件装载和旧`history.list`兼容接口仍保留，不能把界面分页说成整个配置文件磁盘流式。保存查询关联编辑/另存、历史清理/导出及更多工作流继续；Q03及全功能目标仍未完成。实际结果、原失败和平台边界见[验收记录](../../tests/integration/acceptance-history-pages-20261015.md)。
