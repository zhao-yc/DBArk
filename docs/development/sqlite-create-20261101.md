# SQLite 新建数据库文件

## 使用

在“新建连接”选择 SQLite，点击“新建数据库文件”，通过原生另存对话框指定尚不存在的文件。已有普通文件、空文件、目录和符号链接均不能覆盖；存在同名 `-journal`、`-wal` 或 `-shm` 条目也会拒绝并保留原件。需要使用已有库时，仍用旁边的“选择数据库文件”。

创建成功后表单选中该文件并切为读写模式，连接名称、分组和等待超时保留。客户端显示“数据库文件已创建，连接尚未保存”，不会自动测试、连接、创建查询或保存配置。取消表单不会删除文件；之后可以重新选择该文件。普通文件选择保留原只读选项。

## 实现边界

- 公共 `files.createSqlite` 只接收准确连接编号，不接收路径、SQL、覆盖标志或数据库内容。Main 捕获原文档并显示原生保存对话框；返回仅为绑定该文档与连接的用途令牌和文件名，不能通过通用路径接口解出。
- 通过现有独立 utility 和原 SQLite 驱动在专属临时目录初始化空库，确认空 Schema、完整性、正常关闭及真实进程退出。仅读取不超过 64KiB 的格式有效字节；私有文件准确清理完成后才创建目标。
- 最终目标使用独占 `wx`，请求 0600 模式（Windows 权限仍由目录 ACL 决定），沿原句柄完整写入、同步、关闭；既存文件检查不能代替独占创建。Main 签发令牌前再次核对真实文件身份，Windows 的 Main 路径规范与 worker 原生路径协议分别处理。
- 创建后文档失效、目标身份变化或写入失败会明确报告连接未保存及文件可能存在；不会自动删除或覆盖该路径。遇到错误先核对所选文件，不自动重放新建。正常退出及强退均等待本轮文件操作，并收尾准确登记的私有进程及未确认关闭句柄。
- 表单来源、方言 ABA 或卸载使迟到选择失效，不把旧令牌合入后继表单。已有连接的目标变更仍走原保存保护，不自动关闭查询、提交事务或丢弃草稿。
