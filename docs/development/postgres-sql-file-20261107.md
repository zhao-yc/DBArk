# PostgreSQL SQL 文件流式执行

在「工具 → 执行 PostgreSQL SQL 文件」选择已保存的 PostgreSQL 连接、目标数据库和 UTF-8 `.sql` 文件。核对目标库和文件后点击「确认并执行文件」。单表和多表备份所需的 schema、类型、函数及其他未包含的依赖需预先在目标库准备。

执行使用独立数据库连接，按块读取文件。客户端在文件末尾复核原文件身份及修改时间，确认全部语句成功后才提交。提交和回滚都以服务端回执及事务状态为准。结果未知时，先查目标库。提交开始后，取消请求不能打断结果确认。

- 支持非空 UTF-8 文件及 UTF-8 BOM，最大 10 GiB。单条 SQL 最大 64 MiB，最多 100 万条，结果行不保留。单条超预算或文件变化会停止事务。
- 支持文件无事务外壳或使用裸 `BEGIN` 和 `COMMIT` 包住整个文件。内部事务控制、`COPY` 数据段、psql 元命令和位置参数会被拒绝。服务器可拒绝事务内不支持的语句。
- 失败回执显示已完成语句数。服务器语句出错时同时显示失败语句编号和可取得的 SQLSTATE。计数不等同于提交，错误正文只留在原窗口，SQL 和路径不写入任务历史。
- 执行来自可信来源的文件。事务外效果需要单独核对，包括修改既有序列状态或调用外部服务的函数。

参考 [PostgreSQL psql 的单事务行为](https://www.postgresql.org/docs/18/app-psql.html)和 [PostgreSQL 序列函数](https://www.postgresql.org/docs/18/functions-sequence.html)。

## 2026-11-07 验收

- Windows 测试虚拟机连接不可用，本轮使用 macOS arm64 源码 Electron 和 `server-200` 上隔离的 PostgreSQL 18.6。测试使用普通账号和两个数据库。结束后核对测试账号残留会话为零，容器和 SSH 转发均已清理。
- 从客户端导出的多表备份大小为 8,409,213 字节，经工具菜单流式恢复到另一数据库。查询核对两张表共 401 行，比较文本字节及摘要、二进制、外键和标识序列。客户端取得提交回执。
- 缺失对象导致语句失败时，已写入的数据及新表均回滚。延迟外键在提交阶段报错时，界面显示已确认回滚及 SQLSTATE 23503。取消真实后端的 `pg_sleep` 后确认回滚。选择后换包时未开始执行，原测试表及来源记录保持原样。
- 通过 `node scripts/typecheck.mjs`、`node scripts/build.mjs`、三项单 worker 的 Electron 原生测试和全量 Vitest。1,354 个文件共 27,596 项通过，10 项按环境门槛跳过。专项另验证执行中换包后回滚，以及缺少提交回执时显示未知。
- 单表和多表备份及恢复在同一隔离实例串行回归。Windows 源码界面、安装包、其它 PostgreSQL 主版本及 10 GiB 边界仍待验收。
