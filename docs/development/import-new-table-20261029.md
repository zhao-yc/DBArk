# CSV／JSON 导入为新表

## 操作流程

在数据库节点点击“从文件导入新表”，选择 CSV／JSON、编码及 CSV 分隔符／标题设置，明确选择文件并扫描。扫描读取整份文件，显示总记录数、完整联合字段目录和最多20条、256KiB完整样本；后续记录才出现的 JSON 字段也进入目录。空文件不能凭空推断字段，只有CSV标题的文件可提供字段。

填写并核对表名后进入原新表设计器。默认建议是允许NULL的LONGTEXT，不根据有限样本推断类型、主键或全文件兼容性；可明确修改字段类型、名称、NULL／默认值、索引和外键。不合法、重复或大小写冲突的源名会给出稳定字段建议，原源身份仍保留供映射。

沿原DDL预览、准确目标及风险确认创建，成功回执不会提前卸载仍持有资源的设计器。等原关闭完成后明确选择继续导入，才打开原字段映射／预检／导入界面，目标取实际创建回执。未核验定义、资源未释放、连接或父来源失效时不继续导入。

## 来源与两阶段边界

完整扫描冻结原字节SHA256和字节数，后续固定文件令牌、格式、编码及CSV设置；映射仍可人工调整，设计器改名导致目标不存在的字段必须重新映射。新流程必须整文件预检完整无问题且来源摘要一致，之后才可明确发送一次导入，不自动导入、不启用冲突更新。

正式导入强制整文件事务。读取同一条原始字节链，在迭代真正结束、唯一COMMIT之前核对完整指纹与前后普通文件身份；同长度改写、替换、解析错误或取消均不能绕过校验。错误沿原事务回滚及未知结果处理，不重放写入；旧的普通批次导入保持原行为。

建表DDL和后续数据导入是两个独立阶段。导入失败或源文件改变不能撤销已成功的建表，也不会自动删除新表；表可能为空，结果未知须核对服务器后再另行操作。父向导、子页面、连接修订及来源均有单向失效守卫，旧回调不能借相同最终值恢复资格；关闭等待原读取、取消与原子组件释放。
