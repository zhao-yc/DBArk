# SQLite 导入 XML

在可写的 SQLite 普通表页打开「导入 SQLite 表数据」，把格式设为 XML。选择 UTF-8 文件前，填写根元素下用于标识每条记录的标签。默认标签是 `RECORD`，适用于 tabrelio 的列名标签和记录属性两种导出布局。启用「将记录属性作为字段」时，记录属性和子元素共同参与字段映射。

检查文件后，在映射中为每个目标字段选择源列和类型。缺少某个已映射字段的记录使用 NULL，空属性或空子元素保留空文本。完全未映射的目标字段遵循原表的默认规则。导入二进制时，在映射里选择对应的 Base64 或十六进制类型。长整数可映射为整数，需要保留精确小数原文时可映射到 TEXT。

整文件预检完成后，核对写入语句和目标表，再输入准确的目标确认文字。正式导入重新检查文件身份及 SHA-256 和目标表结构，并在独立事务中追加。预检后换掉文件需要重新检查。表约束或实际写入失败时会停止并尝试回滚，界面分别显示提交、回滚、未发送或结果未知。

也可从 SQLite 的 `main` 数据库菜单打开「从文件导入新表」。完成来源检查后，选择字段并进入表设计器，先预览和确认建表，再显式继续原文件的字段映射、整文件预检和导入。两次提交分别确认，取消数据导入时已建成的表会保留。

输入为扁平的 UTF-8 XML 1.0，文件上限 64 MiB，SQLite 完整来源目录最多 1,000 个不同字段。样本最多 20 行和 256 KiB，映射与写入继续遵守 SQLite 现有的类型、长度及行大小限制。命名空间、DTD、嵌套子字段及 tabrelio 的位置映射「XML 文档」暂不接受。

## 验收

- macOS arm64 使用 Node.js 24.17.0。原生运行时检查、类型检查、源码构建及 1,045 项相关单元测试通过。来源合同核对记录标签、属性开关和文件能力的绑定。
- 四个 SQLite 源码原生用例通过。现有 STRICT 表的 XML 导入由独立 SQLite 连接核对两条记录的 NULL、空 BLOB、布尔值和有符号 64 位整数。预检后修改 XML 文件，确认未执行 INSERT。新表用例分别核对建表和数据提交回执，重启后核对数据且无重放。
- 同轮回归覆盖 CSV、JSON、约束错误整批回滚和来源文件变化。Windows 测试会话不可达，Windows、macOS x64 和安装包待验。
