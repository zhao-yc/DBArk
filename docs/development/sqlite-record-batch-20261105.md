# SQLite 勾选记录逐条批量表单（2026-11-05）

## 当前行为

可写 SQLite 表页勾选当前已加载的记录后，在“更多 → 数据编辑 → 批量编辑 SQLite 勾选记录…”打开独立输入窗口。上一条／下一条只经过勾选记录，显示准确位置；每条记录可填写不同值，并复用完整字段表单、整行 typed JSON、词法记录树和二进制编辑控件。其它已保留页继续保持，窗口不读取新页。

切换只保存窗口内缓冲，取消整组不改变原 Editor、已有草稿或撤销历史。“暂存全部 SQLite 勾选记录”先完整验证当前行及全部候选差异，再一次加入原页草稿，整个批次形成一个撤销／重做步骤；未勾选行保留原对象和原值。任一行／字段无效、来源过期或最终合并草稿超限时整组拒绝，输入保持，可修正后重新确认。没有差异时不制造历史或撤销既有预览。

暂存不发送预览或提交请求。用户仍须原“预览 SQLite 修改”、勾选确认并明确提交；统一预览会组合其它保留页，原完整旧行冲突检查、单次事务、回滚和 unknown 锁定继续由原工作区处理。

## 精度与预算

INTEGER 保持有符号64位原文，TEXT 不解析重复 JSON 键、指数或 NUL／CRLF，空 BLOB、SQL NULL 和空文本各自区别。原非有限 REAL、大 TEXT／BLOB 没有被触碰时不重新解析或重写。生成列只读；已有记录不能省略字段，混合已有与新增记录时只有新增记录可通过取消字段勾选保留 DEFAULT。新输入仍使用原有限 REAL、Unicode、完整 Hex 及单值65536字符预算。

只有差异形成补丁；typed 值按种类和原文比较，字段属性顺序不制造修改。行间保留也累计检查10000变化格／2MiB，超限不发布最后一行缓冲，并保留当前表单供修改；最终 Editor 将新补丁与已有草稿一起验证原500变化／10000格／2MiB限制。选择1000行但只改一条仍可用，不把勾选数误当实际变更数。

## 来源与发布

复用原 prepareSqliteFill 签发的准确来源，捕获真实 page、rows、勾选行及字段目录；全页当前行选择不代替原勾选列表。父票据显式区分统一填充与逐条批量表单，两种模式不能互相借用保存入口。唯一自身 Modal 标记、原 Editor、活动标签、作业状态及原快照均需保持；观察到失效留下永久墓碑，恢复同一引用或同 ID 不复活。

每次行切换产生新 token，旧行的 change／save／close 回调即使返回同一行号也无权操作新输入。失效后保留已捕获显示和窗口输入，仍可明确取消自己的窗口。父级拒绝或抛错不消费当前候选，用户可以修正后重试。

纯模型缓冲和 Editor 都先验证稠密自有 data 数组、精确字段、合法 typed 值、勾选成员及重复行／列；不调用 getter 或 toJSON。全部候选及最终变化预算通过后才一次 replace，不产生半批修改，没有新增 IPC、Main 白名单或数据库执行路径。
