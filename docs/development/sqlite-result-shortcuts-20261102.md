# SQLite 查询结果快捷生成条件

## 使用

在查询结果中选择当前单元格，使用“追加等值条件”或“追加排除条件”；勾选行后，可用“勾选值加入筛选”将当前列的勾选原值生成列表。入口复用原结果页，不读取系统剪贴板，不重新执行 SQL。打开后先审阅草稿，明确应用才改变视图；原筛选整体按 AND 追加，不平铺已有 OR 分组。原排序及整理撤销／重做继续保留。

SQLite 条件沿实际逐格类型生成。INTEGER、REAL、TEXT 的同显示值分别处理；BLOB 使用完整十六进制，NULL 独立判断，空文本、精确整数及 Infinity 保留原文。勾选集合按存储类型分组去重，再通过 OR 连接各类型 IN 条件与 NULL 条件；不把 TEXT `2` 合并成 INTEGER `2`。

“追加排除条件”排除与当前格同类型的相同值，同时保留其它非 NULL 类型，因此采用同类型“不等于”与“其它非 NULL 存储类型”的 OR 组。NULL 格仍生成“非 NULL”；普通非 NULL 格的排除不包含 NULL，与既有否定条件的 NULL 处理保持一致。手工“不等于”仍仅比较明确选择的类型。

## 身份与预算

只用内部字段键、原行列引用和原类型代码定位，不靠重复别名、格式化文字或隐藏列顺序。先绑定有界行列及代码索引，再读取选中格；未勾选格的值和访问器不读取。缺少原类型的旧结果只允许 NULL 判断。

行列、结果包装、类型代码、选择或原值发生可观察变化后撤销旧捕获；BLOB 内容变化也失效，恢复旧值不能复活旧回调。快捷入口沿原作用域及模态保护，再次校验后才生成草稿。

沿用 128 种成员（含 NULL）、单值 4096 字符、行列、整体原文与表达式树预算。BLOB 在解码前核完整 HEX 长度；超预算拒绝整次操作，不截断、不应用部分勾选。共享条件结构新增仅用于 SQLite 的 `notType`，不改变 IPC、引擎、写入或凭据协议。
