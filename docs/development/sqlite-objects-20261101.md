# SQLite 视图与触发器定义管理

本轮继续补齐高频对象操作，暂不正式发布，也不更新已安装客户端。SQLite `main` 库右键菜单可新建视图、触发器；对象列表对应分类有新建按钮，已有对象右键可编辑定义或删除。视图数据页“更多”也提供编辑定义和删除。保留原定义查询草稿入口，左树仍为 31px 单行。

## 操作方式

- 新建时先输入准确名称并显式读取目录，再编辑完整 `CREATE VIEW` 或 `CREATE TRIGGER`。编辑器复用 SQLite Monaco，不建立查询会话，不读取补全元数据；SQL 原文不自动改名或格式化。
- 替换、删除绑定打开窗口时的连接、用途、种类和准确名称。窗口展示完整有界 `main` 定义目录及视图附属触发器，供人工核对；不以文本包含名称冒充可靠依赖分析。已有损坏视图仍可读取定义并修复。
- 预览只读取、核对目标和生成 SQL，不试执行写入。全部风险默认未勾选，输入准确 `main.对象名` 并完成本次确认集合才可提交。只读连接可以检查、编辑和预览，不能提交。
- 创建只执行一条完整 CREATE；替换在独立事务内 DROP 原对象、CREATE 新定义；替换视图时逐条重建原附属触发器。任一步失败整批回滚，原定义保留。删除视图会一并删除附属触发器，其他保留对象定义可能失效，需要人工处理。
- 新视图通过原生 `SELECT ... LIMIT 0` 检查可准备及列定义；不读取视图数据行，也不试触发触发器。CREATE 成功不等于未来触发器写入已验证；SQLite 允许 `UPDATE OF` 中出现不存在的列，这类错误不一定在 CREATE 时报告。[SQLite CREATE TRIGGER](https://www.sqlite.org/lang_createtrigger.html)、[CREATE VIEW](https://www.sqlite.org/lang_createview.html)

## 执行边界

新增 `sqlite.objects.inspect/preview/apply/release`，Main 绑定原文档、连接修订、物理连接代次、准确对象及操作用途。目录和预览各限 64 份、64MiB、5 分钟；完整 main 最多 4096 个对象，整体 2MiB，超限拒绝而不截断。

检查、预览使用独立只读快照；提交使用独立 `BEGIN IMMEDIATE`，写锁内重核原文件、schema_version、完整定义及原根页。原生 CREATE 授权校验类型、准确名称、main 归属及触发器 ON 对象；原生解析决定触发器正文边界，显式空参数触发单语句门，在第一条 CREATE step 前拒绝尾随语句。内部授权不属于渲染 IPC，不能借其执行 TEMP、其他对象、附加库或业务 DML。保留已有只读、PRAGMA 和文件授权门。

只有真实 COMMIT ACK 和后置核验均通过才刷新或关闭准确视图。未知结果锁定原批，不重放；关闭、取消和退出仍等待原任务及资源账本。任务只记录准确目标、用途、编号、语句数和事务事实，不保存 SQL、目录、风险确认、路径或短期能力。

同连接 main 所有表页的数据草稿、布局草稿和活动任务均受保护。成功替换只自动刷新准确干净视图，其他同库页失效后等待明确刷新；成功删除只关闭准确干净视图。创建后从刷新目录明确打开对象，不替换当前查询。删除或未知变更使同类型旧名称链接在当前窗口退役，同名重建不自动恢复旧收藏身份；查询正文及事务保持原状。

## 真实编辑器发现与修复

`native-objects-14` 三例在首个菜单检查失败：前一步主动展开 main 的目录读取尚未完成，被比较进右键菜单观察区间。原件只包含目录查询，尚无对象检查、预览或写请求。新轮先等待真实目录、请求和 worker 收尾，再开始原样的前后 frames／operations 相等断言，不过滤请求、不增加超时或重试。

`native-objects-15` 进一步发现真实产品错误：把提交后才成立的事件票据用于渲染只读属性，导致编辑器始终只读，模型变化未进入表单；反例中仍提交了原有定义，而不是用户输入的非法定义。只读渲染现按忙态、来源、关闭及锁定状态决定，按钮仍保留严格票据。正文事件按固定来源及最新草稿合并，避免同一 React 提交前的连续输入丢失后半段；撤销的准确预览仅释放一次。测试外壳同步遵守只读门，不再掩盖实际行为。

两轮失败的六个准确 PID 后续均确认不存在，但正常退出未记录，不能追认正常收尾；准确原目录、报告、错误上下文和事务事实继续保留。失败帧中没有执行业务 DML；`native-15` 反例仍真实提交了原定义批次，其事实如实保留，不能改称未发送，也不补造缺少的失败后磁盘回读。

`unit-ui-16` 的 46 项通过；新增连续输入反例在 `unit-ui-18` 出现 47 绿／1 红，仅为内存 textarea 按 DOM 规则显示 LF，而原 SQL 为 CRLF。最终 `unit-ui-19` 的 48 项全部通过：显示单独核模型换行表示，编辑器 props、IPC 和只读预览继续严格核原 CRLF。`build-17` 中间轮及最终 `build-20` 的严格类型／构建均退出 0，最终 Vite 31.21 秒；后续以包含全部输入修复的冻结候选为准。
