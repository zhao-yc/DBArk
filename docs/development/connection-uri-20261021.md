# 从连接URI填入新连接

## 入口与范围

新建连接窗口选择“从连接URI填入”，输入`mysql://用户:密码@主机:端口/数据库`或`mariadb://`，点击“填入并清除URI”。用户名必须明确；端口缺省3306，数据库可省略，IPv6主机加方括号。认证及数据库逐组件百分号解码一次，`+`保留为加号，不按表单空格处理。

输入使用密码框，仅存在当前窗口内存；填入或取消后清除输入状态，不写历史、配置或任务。填入本身不连接、不保存，随后仍需审阅普通表单并明确测试或保存。密码默认仅会话，可按需勾选原“记住密码”。编辑已有连接不提供此入口；复制或迁移产生的新连接可使用，保留新编号、名称、分组和颜色，但清除旧SSH／TLS、文件要求及认证标记，不将原目标秘密带往新主机。

主机采用标准URL规则规范化（包括域名小写／IDN、IPv6及IPv4表示），最终主机和端口会展示在普通表单。路径只接受一个数据库组件，不套用URL路径归一化。多主机、JDBC、查询参数、片段、无效转义及不确定目标拒绝；尤其不静默忽略SSL／TLS选项，须在普通表单单独配置。

原URI最多16 Ki UTF-16单位，解码后主机512、用户256、数据库256、密码4096单位；拒绝NUL及孤立代理项。失败保留原表单并显示固定中文错误，不回显URI、密码或解析器原始错误。输入未结束时禁用测试和保存，并在提交处理器再次核对，Enter不会误提交旧表单。IPC、驱动、凭据保存及已有连接变更保护保持原流程。

## 验证与未验

35项解析回归及4项真实ConnectionDialog RAM测试通过，含Unicode／IPv6、一次解码、标点、空密码、长度、拒绝参数、取消和清除、原表单保持、复制目标隔离及只有显式测试才进入IPC。原连接变更16项、TLS2项及限权表单3项同次全部通过；这些是RAM范围，不代表实库或系统输入。

完整本机两worker运行611文件，11664通过／1个POSIX条件跳过，240.58秒；包含URI解析及表单四例。原默认并发与类型检查同时运行时的五项Worker构建超时保留，不降低原断言或5秒预算。最终会话2245退出0：类型25.89秒、6文件63项全部通过／2.11秒、普通构建31.49秒（Vite30.48秒），总59.50秒。随后区分URI区域与输入的可访问名称，避免真实定位重名；最终会话28812退出0，类型25.62秒、39项／1.70秒、构建30.67秒（Vite29.80秒），总57.99秒。既有注释及大包警告保留。

原表结构模板／字段悬停整例追加URI拒绝加密参数、填入并清除、审阅及明确保存，再继续原SELECT、四参数、表草稿、数据定义保持和正常退出／精确清库。准确491f81e3的[本机Windows实库整例](../../tests/integration/acceptance-connection-uri-491f81e-20261021.md)已单次通过：拒绝加密参数／只填表不保存／明确保存后继续完整模板与字段悬停，61行及定义保持、正常App退出／精确删库、三辅助连接关闭均核。安装版、macOS、MariaDB及其它版本的本能力实库与高级连接参数另验。C01／C03仍部分，暂不发布。
