# 备份运行端接线检查点

本片整合原生 dump 子进程和有界元数据读取器。它们是整库备份的基础模块，尚未接成完整产品执行入口；Windows 敏感文件的实际权限端口、服务器会话与全局锁连续性、完整 dump 和恢复仍在推进。

## 固定源码及独审

- 原生进程作者 `88bf438`，Root 整合 `1f3c46e`：16 项 RAM 专项、类型及另外四组独立组合通过。标准输出按需读取和 64KiB 分片；退出码、EOF、三个流关闭与 child close 分开记账。取消只请求原 child，不把请求当关闭事实。
- 源读取器作者 `cb2b5eb`、修复 `2a91989`，Root 整合 `c19b61f`／`9169fdc`：Root 39 项专项及类型通过。真实 mysql2 无 callback 的 Query／Execute 行事件逐行计量，限额或取消不返回部分完整结果，原查询与迟到事件保持归属。
- 原五组独审四绿一红保留：mysql2 的 `typeCast:true` 仍可继承连接级函数。修复在发送／记账前拒绝函数、getter、proxy 和配置换绑，原同字节反例及一个安全默认对照通过。不是修改全局驱动配置来隐藏问题。

这两项不能外推完整 NativeProcess dump 状态机、完整 SourceInspection、Main／IPC／UI、TLS／SSH 或其它数据库版本已验。`run1461` 只调用真实启动端口做版本探测，没有绕过严格 dump 策略后将其计作实际备份。

本地摘要 SHA256：`run1461` 为 `6505ca1aa0292fd4c6a13b33f989197c6cf284419e7cb07cdc309b6feee1e5e2`；`run1467` 为 `365bb62cf15d76a05cb5dd6a778692e97dfb2e3c6500d34911715d05a731e307`。

原 `run1465` 因 Root 预检将枚举值字符串 `"0"` 与数字 0 比较而失败，发生在新读取器登记或发送之前，产品的精度保持逻辑无需修改。原健康空闲会话按唯一验证进程、创建时间及 TCP 端点双重匹配后精确结束，服务器线程消失、原进程自然退出与原 TCP 消失分别核实；没有关闭其它连接。原失败资料保留。`run1467` 只修正该枚举比较，并对所有命令明确结束的健康原连接提供正常退出路径；未知仍保留，不增加重试。

敏感文件后续只使用 Root 提供的真实清理许可。Windows 目录／文件的物理绑定、完整 ACL、MySQL 配置读取的共享兼容性，以及 helper 进程自身退出均须实际验证。只看文档或 RAM 回执不能设置真实许可。
