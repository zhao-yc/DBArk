# 表数据嵌套筛选

表数据新增“组合筛选条件”。先在原面板添加条件，再把条件移入子组，分别设置“全部满足（AND）”或“任一满足（OR）”，例如 `(状态=A OR 状态=B) AND 时间范围`。内联面板只编辑组合草稿；点击“应用分组”才从第一页重新读取服务器，保留完整排序。取消不查询、不丢弃数据草稿。

## 使用规则

- 条件原值和启停状态在原条件编辑器维护；组合器只调整括号、组模式和所属组。已应用的结构会显示条件编号和括号，避免平铺条件标签误导。
- 新子组默认 OR，可继续嵌套；“解散”将该组的子项提升至父组。空子组可暂留在草稿中，应用前须移入条件或解散。
- 最多 30 条条件、16 组（含最外层）、8 层。每条条件包括停用条件在树中恰好出现一次；超预算整份拒绝，不截断。
- 原条件编辑、启停保留分组；删除重新编号并移除空子组，新增条件放到最外层末尾；“清空”同时清除全部条件与分组。修改最外层模式不改变子组模式。
- 有未提交数据时仍沿原丢稿确认；拒绝则保留原页、数据草稿和组合草稿。换连接、标签、页面、读取条件或出现外部模态后，旧组合器失效，应取消后重开。

## 跨进程与持久化

`table.page`、复制来源页和 `table.referencePage` 传递可选 `filterGroup`。叶为原 `filters` 数组下标，组包含 `mode` 与 `children`，最外层模式须与 `filterMode` 一致。IPC 和引擎先限制深度、组数、叶数并核自有数据描述符，再复制校验；不执行 getter，不把非法树降格为平铺。

SQL 原值继续走既有参数及精确数值占位符，嵌套按树顺序绑定；停用子组不参与组合，全停用不生成 WHERE。外键浏览的强制匹配条件始终 AND 整棵树，不能被 OR 绕过。缺省 `filterGroup` 的旧平铺 SQL 字节保持。

表命名方案完整保存和读取分组，继续使用原来源、修订、CAS 与元数据检查。旧平铺配置不补造树；旧客户端的严格方案配置会拒绝含新字段的方案，不会静默忽略括号。未变更 SQLite schema；使用新功能前仍建议按使用指南备份整个用户目录。

记录导航、分页、排序、草稿历史和复制来源的范围身份包含完整分组，改变括号也会撤销旧意图。完整表导出仍走原独立导出入口，不以表页筛选冒充全量导出配置。
