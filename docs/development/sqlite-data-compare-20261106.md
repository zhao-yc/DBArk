# SQLite 表数据比较

在「工具」选择「比较 SQLite 表数据」，为左右两侧选择保存的 SQLite 连接和表。支持同一文件中的两张表，也支持分别选择两个文件。两张普通表应有相同的字段名集合和相同的显式主键字段，列顺序和复合主键声明顺序可不同。匹配范围中出现 NULL 主键时，客户端会拒绝比较。

按实际存储类型匹配主键及比较值。文本大小写和原始字符区分，整数不转换成 JavaScript 浮点数，BLOB 按字节比较。输入同名字段及有类型的等值条件，可以在两侧同时筛选。筛选使用 SQLite 原列的比较规则。[SQLite 存储类型和比较](https://www.sqlite.org/datatype3.html)

差异可按仅左侧、仅右侧或字段值不同筛选，每页 25 条。打开差异可并排查看具体值，包括缺行、NULL、整数、实数、文本及 Base64 格式的二进制。每侧最多 10,000 行和 8 MiB，差异最多 8 MiB。超过预算时整次比较失败。

同一连接只用一个只读快照。跨文件分别固定读取快照，可能处于不同时间点。比较不写入数据库。本入口目前提供差异查看，选择增删改及同步继续单独推进。[SQLite 事务与快照](https://www.sqlite.org/lang_transaction.html)

## 验收

2026-11-06 在 macOS arm64 和 Node.js 24.17.0 通过类型检查、构建和 31 项定向测试。真实 SQLite 子进程验证复合主键、不同字段顺序、整数和实数类型差异、BLOB、NULL、过滤、超限和取消。WIN11-TEST 连接不可用，Windows 和安装包未验。

Electron 源码专项通过。使用真实已保存连接和工具菜单，同文件读回 28 行相同。跨文件每侧 28 行，得到 1 行仅左侧、1 行仅右侧和 27 行字段不同。按类别翻页并打开详情后，两侧原值进入视野。按最大有符号 64 位整数筛选仅匹配一行，独立连接复核两份源文件的 BLOB，窗口正常退出。

首轮因差异筛选控件的可访问名称未明确而超时，补齐显式标签后通过。详情滚动复验曾在定稿构建结束前启动，保留旧回包。等最终构建结束后，以相同断言和实际视野检查通过。
