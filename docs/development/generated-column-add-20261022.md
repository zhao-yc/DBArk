# 已有表新增数值生成列

## 实际入口和范围

对象树或表页的“字段差异编辑”→“新增普通字段”→新增字段类别“生成字段”。选择整数或 DECIMAL 输出、VIRTUAL／STORED 和表达式；“应用本行草稿”仅暂存。预览完整 SQL、目标和风险，确认后执行一次，结果区区分未投递、未知、已完成但未核验及已核验。

本批是完整生成列设计的新增步骤，不能计作 O01 完成。只在已有五个准确 MySQL/MariaDB 基线版本、Linux、大小写敏感、非分区 InnoDB、目录和原生表身份均可证明时开放。单独追加一列至末尾，允许 NULL、无 DEFAULT／ON UPDATE。旧生成列的编辑和删除能力不放宽；普通列原有工作流保持。

表达式支持十进制文字量、实际获准普通整数／DECIMAL 字段、一元正负号、加减乘和括号；字段名可用反引号，内部反引号写两次。最多 2048 字符、256 词元、16 层、32 次引用，单个文字量最多 65 位。数值不经过 Number，不提前计算。AST 重建全部 SQL 引用，拒绝自增／生成链、未知字段、注释、字符串、函数、除法、变量和子查询；输出的正规化表达式也受预算约束。

## 一致性和资源边界

生成能力使用独立投影，缺省关闭；界面不从只读 SQL 文本猜候选。附加目录权限或预算不足只关闭生成能力，取消／断线仍使原任务失败。普通字段的原风险提示、类型及依赖保护保持。

同一短会话夹读完整 SHOW、全列目录及原生表编号。get→preview→apply 重核原定义、配置修订、目录及原物理身份；一次令牌、编号进度、取消和实际连接关闭继续沿原任务链，失败不自动重放。DDL 后允许服务器重建物理编号，但必须证明服务器／目标不变、原列目录／未动定义不变、新列类型／NULL／备注、生成表达式 AST 和存储方式，以及 SHOW／GENERATION_EXPRESSION／EXTRA 相互一致，才能报告已核验。

结构核验不能证明全部数据计算或外部依赖无影响；专属确认说明 sql_mode、溢出、锁等待和默认算法可能重建表。服务器认可语法不等于数据保真，不能把未核验结果视作未执行并重试。
