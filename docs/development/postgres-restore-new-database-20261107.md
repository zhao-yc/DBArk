# 恢复 PostgreSQL 整库到新数据库

1. 在「工具 → 执行 PostgreSQL SQL 文件」选择已保存的 PostgreSQL 连接，勾选「恢复到新数据库」。
2. 选择能连接的维护数据库，填写新库名称。连接使用的角色需要 `CREATEDB` 权限。
3. 选择可信的 UTF-8 纯文本 SQL 文件。使用 `pg_dump` 的默认纯文本格式，省略 `--create`。如果源库所有者和授权角色与目标环境不同，可按需使用 `--no-owner --no-privileges`。未包含的角色、表空间和扩展依赖仍需在目标服务器准备。
4. 检查新库名称和备份文件，再点击「确认创建并恢复」。窗口分别显示建库回执和文件事务回执。

客户端从 `template0` 创建空库，使用模板默认的编码和区域设置。文件与维护库、目标名称绑定，建库前再次核对文件身份。确认建库回执后，客户端回查库 OID 和所有者，并在目标专用连接再次核对，随后以单独事务恢复文件。普通表、分区、序列、视图、函数和物化视图等对象按备份中的顺序恢复。pg_dump 的标准大对象块使用同一文件事务，客户端逐条核对打开、写入和关闭的回执。

- 同名库存在时，PostgreSQL 拒绝建库，文件不执行。可以换一个新名称重试。
- 建库在文件事务外提交。文件执行失败或取消时，界面分别显示建库及文件结果，并保留已建库。核对回执后可取消勾选「恢复到新数据库」，选中已创建的库并重新选择文件。
- 建库结果未知时，先从连接目录核对同名数据库再操作。带换库指令的 SQL、集群级备份和二进制归档使用 PostgreSQL 原生工具。
- 详细的文件大小、COPY 格式和事务边界见[恢复 PostgreSQL 原生纯文本备份](postgres-copy-script-restore-20261107.md)。

参考 [PostgreSQL CREATE DATABASE](https://www.postgresql.org/docs/18/sql-createdatabase.html)和 [PostgreSQL pg_dump](https://www.postgresql.org/docs/18/app-pgdump.html)。

## 2026-11-07 验收

- Windows 测试会话不可达，本轮使用 macOS arm64 源码 Electron。实库在 `server-200` 的隔离 PostgreSQL 18.6 容器。三项 Electron 用例串行通过，结束后测试角色残留会话为零，容器和 SSH 转发均已清理。
- PostgreSQL 18.6 使用 `pg_dump --no-owner --no-privileges` 生成 5,964,018 字节的整库文件。在窗口输入含空格、中文和双引号的库名，成功建库并确认提交 63 条语句。源库和恢复库比对了枚举及二进制记录、分区、外键、标识序列、使用函数的普通视图、物化视图结果，以及三个大对象的内容。其中一个大对象为空，一个跨多个数据块共 150,000 字节。备份 SHA-256 为 `ff2eaef1b77406ec3d09843db4168c527bd3c8f2e0cf2ebc23fff2c075097c04`。
- 使用同名库再次恢复时得到 SQLSTATE 42P04，原库 OID 与数据保持一致。换包后确认未创建数据库。语句失败时已建库保留，文件创建的表回滚。已有数据库模式的单表、多表、原生 COPY、取消与回滚一并回归。
- 首轮实测修正了驱动返回缩写建库标签和测试 schema 重名。第二轮补齐了原生整库的大对象事务块。原失败及隔离资源清理记录均保留。
- 类型检查、构建及 30 项文件专项单测通过。全量 Vitest 共 1,354 个文件通过，27,615 项通过、10 项按环境条件跳过。
- Windows、安装包、其他 PostgreSQL 主版本和 10 GiB 边界仍待验证。
