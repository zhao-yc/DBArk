# PostgreSQL 整行 JSON 编辑

可写表页的「记录表单」内点击「编辑整行 JSON」。新增、编辑、复制、修改新增草稿和关联页记录弹窗也可切换。整行文档包含全部目录字段和原值，`assignment` 表示本次赋值，原值和列信息用于核对。

- `{"mode":"text","value":"9007199254740993.000000000000000001"}` 按文本绑定。数字、时间和数据库 JSON 的原文作为字符串填写。
- `{"mode":"binary","value":"00ff"}` 向 BYTEA 字段写入十六进制表示的字节。
- `{"mode":"null"}` 明确写入 SQL NULL，`{"mode":"default"}` 请求数据库的 DEFAULT。
- `{"mode":"unchanged"}` 保持原值或在新增时省略该列。生成列保持此模式。

整行编辑最多 2 MiB，外层文档禁止重复成员。文本字段里的 JSON 保留原文，数据库在执行时按字段类型核验。带回字段表单后可核对并暂存。弹窗也可直接暂存。放弃 JSON 输入会返回切换前的字段输入。实际写入仍须 SQL 预览并明确确认整批提交。

## 验证记录

- macOS arm64，Node.js 24.17.0。81 项定向单测通过。全量单测运行 1,344 个文件，27,530 项通过，10 项 Windows 条件测试跳过。随后对提交提示清理及界面调整重新执行严格类型检查、构建和原生实库验收。
- PostgreSQL 18 隔离实库通过常规表页 31 项和关联页 10 项 Electron 检查，覆盖更新、新增和约束失败回滚后的草稿修正。独立客户端核对精确数值、带重复键的 JSON 原文、BYTEA、NULL、DEFAULT 和生成列。显式确认前数据库原值保持。两轮通过的独占容器核对零连接后清理。
- 常规表页首轮验收误把上一批成功提示当成新回执，第二轮对已经移除的草稿区检查文本而超时。两轮都用独立只读查询核对了已实际提交的新增记录。隔离容器 `tabrelio_pg_98469227c48f`、`tabrelio_pg_43fb942aae27` 及失败日志保留。
- WIN11-TEST 不可达，本轮使用 macOS。Windows、安装包及其他 PostgreSQL 版本待验。
