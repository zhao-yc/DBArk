# PostgreSQL 普通表主键与唯一约束

从表页或对象菜单打开「查看结构 → 约束 → 编辑主键与唯一约束」。可选择有序键列创建约束、重命名已有约束，或在额外确认后删除。替换主键时，先将旧主键删除加入草稿，再加入新主键。预览并确认后，服务器在同一事务中执行整批操作。

- 主键和唯一约束可选择立即检查、可延迟但默认立即检查，或默认事务结束时检查。PostgreSQL 15 及以上的唯一约束可选择将 NULL 视为相同。创建主键可能将键列设为非空，数据库会验证已有记录。[PostgreSQL ALTER TABLE](https://www.postgresql.org/docs/18/sql-altertable.html)
- 删除使用 `RESTRICT`。外键等依赖会阻止删除，显式复制标识所使用的约束也会排除在删除候选之外。重命名时 PostgreSQL 同步重命名关联索引。
- 预览绑定原表、窗口和连接修订。锁定后再次核对原结构和身份，提交前回读约束 OID、关联索引、有序键列、空值策略及检查时机。晚期失败会回滚批内前序修改。主键索引换成新身份后，原记录草稿须重新读取。
- 提交期间会独占锁定原表。已有唯一索引转约束、时态键、外键和 CHECK 约束仍通过 SQL 编辑器处理。

## 验证

- Mac 类型检查、构建和 11 项定向单元测试通过。覆盖复合键顺序、标识符转义、检查时机、旧版本选项与复制标识保护。
- Mac 完整单元回归覆盖 1,322 个测试文件，27,414 项通过，10 项 Windows 系统 `tar` 检查按平台跳过。
- Server-200 独占 PostgreSQL 18 实库 5 项通过。外键阻止主键删除，含 NULL 的主键替换和重复值的唯一约束创建会回滚前序 DDL。实际核对复合主键的有序列、非空状态、延迟唯一约束和 NULL 比较行为。删除唯一约束后关联索引一并移除，显式复制标识仍保留。
- 实库还验证同名同定义重建约束后旧预览失效。同名同列主键的索引身份变化后，旧记录草稿提交被拒绝，原行保留。
- Mac 原生窗口用例 1 项通过，18 个观察点，单 worker、120 秒、零重试且关闭 trace。真实确认复合主键替换及唯一约束，回读约束与关联索引。原窗口正常退出，独占库与临时配置目录已清理。
- WIN11-TEST 会话不可达，本轮未派发，按约定在 Mac 验证。Windows 原生窗口和安装包尚待验收。
