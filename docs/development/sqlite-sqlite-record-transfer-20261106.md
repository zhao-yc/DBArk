# SQLite 跨文件记录复制

在 SQLite 当前查询结果勾选记录，点「暂存勾选结果以跨库复制」。只读连接也可作为来源。打开目标文件的可写表，在「更多」菜单选择「从 SQLite 查询结果复制记录」，核对连接、表和映射。每批最多 100 行。暂存生成新增草稿，确认 SQL 预览后才写入目标。源查询使用已返回的勾选行和可见字段。

同一列里的 INTEGER、有限 REAL、TEXT、BLOB 和 NULL 按逐格存储类型处理。例如，`0007` 文本和空 BLOB 可共存于无亲和性列或 STRICT 表的 ANY 列。含负零的列会过滤可能改变符号的目标。若所选行中某列含正或负无穷大，该列可跳过，未映射目标字段沿用目标默认值。[SQLite 类型亲和性](https://www.sqlite.org/datatype3.html#type_affinity) · [STRICT 表与 ANY](https://www.sqlite.org/stricttables.html)

## 验收

- WIN11-TEST 不可达，按授权在 macOS arm64 使用 Node.js 24.17.0。运行时检查、类型检查和构建通过。100 项定向单测通过。全量覆盖 1,347 个文件，27,546 项通过，10 项按 Windows 条件跳过。Windows 和安装包待验。
- 原生窗口使用两份真实临时 SQLite 文件。只读源有三行，目标只接收两条勾选记录。暂存和 SQL 预览阶段独立读回均为零行。确认后核对整数上下界、负零和正零、有限 REAL、前导零文本、空 BLOB、NULL、空字符串，以及跳过无穷大字段后目标默认值生效。
- 目标网格刷新为两行且草稿归零。窗口正常退出，所属进程和成功轮次临时目录清理已确认。首轮退出超时，后两次提交后的单元格定位未命中。最终用例等待刷新后的网格行数，并核对退出阶段未出现保存或收尾失败对话框。前三轮日志和临时数据保留。
- PostgreSQL 18 与 SQLite 双向记录复制用同一构建完成原生回归。Server-200 上的专用 PostgreSQL 隔离资源已核对并清理。
