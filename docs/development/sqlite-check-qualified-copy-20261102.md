# SQLite 限定 CHECK 的私有定义与原名重建证明

## 解决的问题和当前边界

接续 [CHECK 声明编译](sqlite-checks-plan-20261102.md)。原表合法的 `child.a`、`main.child.a` 等 CHECK 引用不能直接搬进随机私有表，且现有 `legacy_alter_table=ON` 下不能靠重新限定再改名解决。

本轮新增 `compileSqliteTableRebuildCheckedCopyDefinition`，分开生成私有复制定义与最终原名定义，并以 native 内存原型证明“原名 CREATE 后显式复制”路线。**Main／Runtime 事务尚未接入此路线，未增加 IPC、预览输入、CHECK 写权限或用户入口**。不能将 SQL 字符串、内存原型或既有窗口回归当成新功能验收。

## 编译与语义隔离

- 先沿原组合编译处理准确原 SQL 绑定、字段默认值／类型、实际重排及主外键／UNIQUE／CHECK 编辑，再处理最终保留的 CHECK。原修改描述符在任何复制前核验，访问器不会因展开对象而执行。
- 仅在真实 CHECK 声明的表达式 token 跨度内识别本表 `表.字段` 或 `main.表.字段`。字段必须与真实目录相符，使用 SQLite 的 ASCII 名称折叠；支持单／双引号、反引号、方括号、中文及含点／引号的名称。
- 私有声明只把上述字段变成双引号引用的准确字段名。每个前缀 token 单独换为空白，保留中间注释和换行；末段单引号字段也转换成准确标识符，不能退化为字符串常量。字符串、JSON 路径、默认值、约束名和生成表达式不参与改写。
- 未知表／模式、未知字段、超过三段的路径或带函数调用的限定形式保持原文，留 native 语义校验拒绝；不能“修复”为另一种合法表达式。仍受原 2MiB SQL、token、字段、括号和编辑预算约束，最终定义和带序号候选也单独核预算。
- 返回 `finalSql`、移除序号后的 `privateSql`、带原私有序号及索引的完整复制定义和限定引用计数。最终定义保留原 CHECK 表达式及本表限定引用；这些输出没有数据库访问或执行能力。未限定的原完整复制 SQL 已逐字核对保持。

## native 路线证明

原型只使用 `node:sqlite` 进程内独立内存库，不调用产品写协议：

1. 开始前核实际 CHECK 检查开启，沿现有 foreign keys OFF、legacy alter ON 的独立事务布局建立候选和验证表；显式普通列、真实行号及 `INSERT OR ABORT` 复制，生成列由 native 计算。
2. 在原表→候选、候选→验证、移除私有序号后分别核对完整存储类型与实际值。按准确原名 CREATE 最终表，再显式复制候选数据，第四次核对最终表→验证。
3. 最终复制完成后才恢复准确显式索引和触发器，避免审计触发器在复制时重复执行；删除两个私有表，准确恢复目标序列的原存在性、rowid 和水位，其他表序列保持。
4. 最终定义逐字核对、入／出外键及完整性检查通过才 COMMIT。以受控合成函数让最终 CHECK 在原表已删除后真实拒绝写入，四种布局均通过真实 ROLLBACK 恢复原完整 schema、rootpage、数据、审计和序列；不关闭 CHECK 或采用忽略／替换复制。

普通 rowid、自增、WITHOUT ROWID、STRICT 均覆盖正向和晚期失败；样本包含 64 位边界行号、超安全整数主键、长精度文本、BLOB、REAL、虚拟／存储生成列、依赖及嵌套视图、入／出外键和触发器。另验证四类约束名称循环交换及实际重排，空自增表区分“序列不存在”和“序列存在”。该原型尚不替代原独立 worker 的全量比较、取消、回执和资源协议。

## 本轮验证

WIN11-TEST 不可达，确认未派发本轮任务，按既有授权在本机 Windows 验证，仅用独占合成 SQLite 内存库及原窗口用例的 owned 临时文件和配置，不访问 Server-200、Docker、剪贴板或已安装配置。

- 新专项最终 **31 项通过**；相关 **27 份／858 项通过**，之后补充约束交换和空序列三例并单独复验最终 31 项。包含严格类型检查的普通构建成功，原 Rollup 注释和大包警告保留。
- 首轮发现表级 CHECK 跨度没有行内 token 字段，改为对准确原声明进行有界取词，保留原断言。原型测试首轮还误将 Node `setReadBigInts` 的 void 返回值串联，改为先配置再读取；原失败日志保留，整数仍使用 BigInt 保真。
- 原字段／外键／主键／UNIQUE 八个 Windows 窗口整例单轮全部通过：21.8／12.7／16.6／17.4／15.8／12.9／37.0／13.5 秒。原 120 秒、单 worker、零重试、业务断言及资源门不变，不修改测试入口或自动重跑。
- 九份旧 SQL 预览与 `866cc34a` 轮仅随机私有标识不同，一对一规范化后逐字一致。62 个受观察 worker 全部 exit 0，18 个目录／预览能力都有对应释放回执，16 次应用正常退出；16 个准确 PID、八个准确目录独立核零。两份源码与 117 份实际构建产物指纹保留并再次核对。

日志、原始报告、逐例事务／资源事实、SQL 对照、指纹和退出码在忽略目录 `.cache/sqlite-check-qualified-copy-20261102/`。旧失败轮次、旧保留目录及 CI 取消记录不追认为通过；Mac 两架构、安装和新 CHECK 窗口未验，不增加完整功能或发行计数，暂不发布。

## 下一步接入

将原名 CREATE、最终显式复制及候选删除纳入 Main／Runtime 各自重算的固定步骤；核对私有与最终完整定义，保持四次独立 worker 比较、行身份／序列、完整父键、目录租约、取消、提交未知态和资源保护。受限预览增加准确补丁及计数，独立 writer 核 CHECK 实际开启后，继续完成编辑区原文确认、局部草稿和整批预览。不能直接改名私有表、切换 legacy 开关或提前开放任意 SQL 写口。
