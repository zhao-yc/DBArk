# SQLite 已有 CHECK：受限预览与独立事务

## 本阶段实现

接续 [声明编译](sqlite-checks-plan-20261102.md) 与 [限定引用原名重建证明](sqlite-check-qualified-copy-20261102.md)，将 CHECK 增改删接入原 `sqlite.tableRebuild.preview`／`apply` 能力链。**编辑界面尚未接入**，本页记录后端事务能力，不能代替新 CHECK 窗口、Mac 或安装验收。

- 原预览只新增有界结构化 `checkEdits` 和准确 `changedChecks` 计数；原序号、完整 SQL、表达式及整批输入仍按既有预算校验，未知 SQL／路径／关闭检查选项拒绝。没有新增任意 SQL 写口。
- Main 和 Runtime 分别生成完整固定计划；Main 独立核对 SQL、警告及计数，异常预览能力立即释放。Runtime 存储独立解析副本并计 RAM 预算；领取后、BEGIN 前再次重算，修改补丁、最终／私有定义或计数均为 not-sent。
- 只读源可预览但不能提交。原连接、文档、代次、TTL、明确释放、确认目标和任务编号保护保持；预览只读元数据，不创建候选、不试执行 CHECK。任务只存原最小计数与真实 ACK，不保存表达式、约束名、路径或行值。

## 原名重建与完整核验

明确编辑 CHECK，或其它结构编辑保留了本表限定 CHECK 时，计划生成最终原名 CREATE、显式最终复制和候选删除步骤。原未限定且未编辑 CHECK 的路径保持旧 SQL；保留原 CHECK 但只改默认值时不伪造 `changedChecks`。

1. 双候选仍完整复制普通字段和真实行身份，生成列由 native 计算，全部复制固定 `INSERT OR ABORT`。限定字段仅在私有 CHECK 内按真实目录迁移；原约束表达式在最终定义保持原文。
2. 原表→候选、候选→验证、移除序号后候选→验证均通过完整 worker 类型／值比较，且候选完整 SQL、字段和索引已核对，才允许删除原表。
3. 按准确原名 CREATE 最终表，在复制前读回并核对其完整定义和字段；不能将私有表直接改名或将最终 CHECK 弱化。最终显式复制完成后才恢复原显式索引、触发器，第四次比较最终表→验证。
4. 删除两座私有表，保持原行号、主键、严格／WR 选项、生成值、自增序列存在性／rowid／水位、其它表 rootpage、入／出及自引用外键和视图。混合主键／UNIQUE 沿原完整可靠父键及零最终违规规则，不借旧违规放行新父键。
5. 独立 writer 打开、Main 事务内检查和关闭还原 ACK 均核实际 `ignore_check_constraints=0`。仅允许读状态，普通 RO／RW 及私有 writer 的赋值、括号、EXPLAIN setter 都仍零 statement 拒绝；不添加忽略检查权限或切换 legacy 模式的捷径。

原坏行遇保留的 CHECK 必须回滚；明确移除对应旧 CHECK 可保留原行。NULL／NUMERIC 及未知函数、子查询等语义由 native 判定，词法通过不等于语义有效。原表删除后若最终 CHECK 才拒绝复制，仍由真实 ROLLBACK 恢复全部原定义、数据及依赖；取消、提交未知态、不可自动重放和资源保护保持。
