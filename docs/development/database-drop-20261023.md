# 删除数据库专用流程

本轮补充 O01 的独立删除库入口，暂不发布。完整 O01 仍未完成，不能以本子功能增加完整工作包或发行计数。

## 使用方式与边界

连接树的数据库行提供“删除数据库”。先读取实际库属性和六类对象目录，再预览服务端生成的只读 `DROP DATABASE`，逐字输入原库名并确认四项风险后执行。系统库禁止删除，任意 SQL 结果不会借此获得写权限。

读取、预览和执行前重核包括数据库属性、对象完整定义、可获取的 InnoDB 表身份、服务器身份及目录可见权限。未知权限、未识别对象、超出预算、目录漂移或入向跨库外键均拒绝执行；目录未完整证明时不展示零计数冒充空库。首批限定已经验证的五个版本系列，正常 Unicode 和反引号名称按原名编码。

数据库没有可依赖的独立物理 OID，空库、非 InnoDB、分区及内部名称编码的物理替换不能完全检测。重核也不能消除外部 DDL 并发窗口，维护前须暂停相关操作并自行核对可恢复备份。该窗口不执行备份、撤权、外部引用修复或其它会话临时表清理。

## 进程与工作区保护

Renderer 只提交专用类型化请求；Main 绑定真实文档、原连接修订和原父能力；Engine 在独立短连接执行一次原生删除。确认失败也消费父快照及兄弟预览，旧请求和同名重建不能复用原授权。清理凭证只允许原文档精确释放，不恢复执行权限。

库级结构租约与所属表及跨库关联父表的结构执行互斥，只有真实资源收尾后释放。同连接查询任务、事务、未知上下文和同库数据／布局草稿阻止提交。执行结束只关闭原先捕获且仍无草稿的表页，查询原文和结果保留；结果未知或新建页面保留现场。旧库各类工作台链接在当前窗口退役，不自动迁移到同名新库。

DDL 可能部分完成且无法事务回滚。成功响应后的核验或清理失败保持已执行事实；取消、断线和失败不会自动重放删除。

## 验证入口

- 单元：`database-drop*.test.ts`、`ui-database-drop.test.tsx` 和 `structure-execution-locks.test.ts`。
- 实库：`tests/integration/database-drop.test.ts`，显式双门 `DBARK_INTEGRATION_ENABLED=1`、`DBARK_DATABASE_DROP_TEST=1`，逐端口核实际服务器。
- 正式源码窗口：`tests/e2e/database-drop.spec.ts`，额外开启 `DBARK_DATABASE_DROP_UI=1`，使用独占输出目录和 13384 隔离资源。

实库和窗口专项默认关闭，不从聊天或仓库读取凭据。失败保留原日志、进程、线程及随机资源计划，确认原任务结束和资源归属后才单独清理。实际通过范围与原始失败由本轮验收记录补充；源码、安装包、平台和真实故障组合分别记账。
