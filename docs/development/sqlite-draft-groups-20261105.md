# SQLite多页草稿按原页分组保存与恢复（2026-11-05）

基线为 `3d2ea01d11cb802396d01170199f8e625c2cf10c`。上一批补齐MySQL／MariaDB文件分组，本批接续SQLite：显式保存有修改的原页归属、原页长与活动分组；关闭应用并正常重启后，独立只读核验全部原行，为每组签发新编辑能力，恢复为可继续操作的分组。第一版单列表兼容、Electron／React／TypeScript架构和Windows／macOS目标保持，版本仍0.28.0，不正式发布。

## 使用与边界

- 原多页表格暂存修改后，“保存 SQLite 草稿文件”收集全部有变化的原页。先确认文件未加密及含完整原行，再选择位置。保存不会提交或清除未提交状态。
- 第二版保存各组原offset、limit和变化数量，以及活动组offset；顺序按原offset递增。活动原页无修改时恢复打开第一个有修改的组。原页归属由Main私有快照提供，界面不能给文件指定其它原行、旧值或数据库定位。
- 正常重启后，显式选择原文件、核对统计并确认只读核验。文件身份／schema_version／表结构／完整原行／隐藏rowid或复合定位不符，任一后组失败都整份拒绝；不部分采用、不发送DML。
- 恢复后各组独享新snapshot和从零开始的原行编号，普通服务器分页禁用。点击原页分组只返回本地准确缓存，不发送 `sqlite.tablePage`。各组可继续编辑、独立撤销／重做及明确放弃；当前组放弃有其它组时仅返回另一组，不补读服务器。
- 再次保存保留剩余有修改的原页分组，只有一组也维持原页号与第二版。统一预览所有有修改的组，再明确一次提交，任一原值冲突整批回滚；未知结果整组锁定，不能从另一组重复提交。
- 第一版仍恢复为单一列表，原兼容路径继续覆盖；不借第一版伪装第二版分组。恢复操作在每组形成一步可撤销暂存，之后的新编辑继续使用本组历史。

文件仍限制8MiB、500条变化、200000格、原节点及深度预算，Main快照仍受64份／64MiB及原过期门约束，分组最多16页。typed INTEGER／REAL／TEXT／BLOB／NULL、int64原文、原REAL无穷／负零、空BLOB及DEFAULT省略保持原合同，新输入不会因文件格式扩大。

文件未加密，只保存已暂存变化及完整原行、必要定位摘要；不保存干净页、筛选排序表单、旧snapshot、旧选择、未暂存输入或保存前撤销历史。恢复页号表示保存时的变更归属，不代表当前服务器分页。没有自动崩溃恢复、跨表完整会话恢复或自动重放。

## 实现

- `src/shared/sqliteTableDraft.ts`：第二版与有无workspace严格对应；有界普通自有data复制先于解析，最多16组、递增唯一offset、同页长、活动组存在，组计数完整覆盖全文件；每组原行数不能超过保存的页长。
- `src/main/sqliteTableEdit.ts`：普通读取时在Main私有snapshot记录原offset／limit；捕获文件沿原整组预览验证和重复定位门，按私有归属排序。恢复在同一独立只读事务中检查各组定位、结构及全部旧行，结束核验后签独立能力；后续任何分组构造或预算失败都会撤销前面已签能力。
- Runtime准确driver关闭和进程退出之后才交付；取消／清理失败释放全组，不能只释放当前页。`SqliteTableEditOwners` 全部验证后一次登记；Main文档／连接失效和迟到回包撤销全部准确分组，不触及其它旧来源。
- `sqliteDraftRestored.ts` 在Renderer逐组复核新快照、完整原行、结构、原页号／页长、变化映射及活动组，缺组／重复能力／错原值整次拒绝。对话框取消、失效或拒绝回包时等每个新能力的释放结束，再归还父busy占用；取消ACK不代表原核验结束。
- 原表页和恢复页共用实际Editor端口；Browser与工作区先完整检查再采用，原输入、准确渲染、活动标签／连接修订及unknown保护保持。各组仍沿原preview／apply多快照一次事务链，不新建写SQL旁路。
