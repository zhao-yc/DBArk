# SQLite 查询会话合同适配

## 已实现

`src/main/sqliteQuerySession.ts` 将 Main 已持有的准确原生 driver 适配到现有 `query.execute` 输入、`TaskEvent` 和 `QueryOutcome`。复用原查询页消费的数据形状，没有新增 SQL 编辑器或渲染 IPC，也没有开放 SQLite 用户入口。

- 结果按内部位置键保留同名列。INTEGER、REAL 使用精确文本，保留 64 位整数、负零、无穷、NULL 和二进制；列标为 `SQLITE`，不把列声明亲和性当作每行的真实存储类型。
- 单次脚本共享返回行预算和 16 MiB 行数据预算。截断返回不停止 `RETURNING` 的实际写入；最多发布 200 个结果，超过时停止后继语句，保留原生确认完成的前序结果。
- 首错只返回完整前序结果及失败序号，失败语句已经流出的部分行不冒充完整结果。driver 错误新增冻结的 `completedResults` 事实，包含行数、截断和变更量，不能靠完成语句数猜测它们。
- 结果耗时目前按整次执行累计报告，分语句耗时留待工作区接入时补齐，不作为逐语句性能分析证据。
- BEGIN、COMMIT、ROLLBACK 走同一物理会话。延迟外键导致 COMMIT 失败时保留真实事务，不自动回滚。执行中事务状态标为待确认；连接失效后标为 broken／未知，不自动重连。
- 取消只消费原会话当前准确任务编号；旧任务不能取消后继执行。普通关闭等待消费者终态及原生关闭握手；正常关闭未提交事务与强取消的未知结果分开表述。
- 终态通知失败只标记通知通道失效，原 Promise 仍交付真实成功、完整前序失败或原 driver 取消结论。禁止新 SQL／BEGIN／COMMIT，但仍允许用户明确回滚可用原会话；不会把已提交写入改称失败或自动重放。头和批次通知异常仍走原消费者取消机制。
- 目前不支持的当前语句定位、遇错继续、MySQL 警告采集在首条 SQL 投递前明确拒绝。连接恢复和补全状态真实回报 SQLite／main，不伪造 MySQL sql_mode。

## 单文件权限边界

所有原生连接均先由 authorizer 拒绝 ATTACH／DETACH；VACUUM INTO 同样无法另取磁盘文件。读写模式也不能绕过未来 Main 文件选择权限。原始主库、事务及外键保持；只读模式和只读 PRAGMA 白名单继续独立生效。多文件附加及相关维护操作留待显式文件授权流程。
