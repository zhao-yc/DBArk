# PostgreSQL 表页网格粘贴

覆盖已有记录时，在可更新的普通表选中目标区域左上角的单元格，按 `Ctrl+V` 或 `⌘+V`。表格按当前可见列顺序和本页行顺序填入草稿。粘贴新增记录时，点击「粘贴新增记录」，选起始列，在输入框粘贴数据，再点击「加入草稿」。每行新增一条记录，未填列使用数据库默认值。 [Navicat 网格粘贴手册](https://www.navicat.com/manual/online_manual/en/navicat_18/win_manual/data_rdbms.html#paste-data-into-grid-view)

支持制表符分列和引号内换行。从 tabrelio 复制的类型化数据可保留 SQL NULL、DEFAULT 和字节，字节只可进入 BYTEA 字段。纯文本的 `NULL`、`DEFAULT` 和空字符串按字面传入。隐藏列不计入列位置。粘贴越界、行宽不一致、命中生成列或待删除行时，整批保留原草稿。

覆盖会合并同一行的其他暂存字段，沿用首次暂存时的原行版本。每次最多粘贴 100 行，已存在的草稿仍占整批预算。在草稿区核对变更后，点击「预览记录修改」，再确认整批写入。表页在确认提交前继续显示原记录。

## 验证

- macOS 上 Node.js 24.17.0 运行时检查、类型检查及源码构建通过。27 项剪贴板定向回归通过，覆盖可见列顺序、原草稿合并、字节、DEFAULT、空串及越界和非法字段拒绝。
- macOS 完整单元回归共 1,328 个文件，27,476 项通过，10 项 Windows 系统 tar 用例跳过。
- Server-200 独占 PostgreSQL 18 实库回归 5 项通过。原生窗口内的独立连接回读确认了暂存期间原值、追加后的 SQL NULL、覆盖后的字面 NULL 和精确 64 位整数及多行文本。
- macOS 原生窗口回归通过，共 71 项观察，已核对粘贴截图、越界整批拒绝、窗口正常退出及临时配置清理。两次实库测试均确认原记录和零连接后清理容器。
- Windows 虚拟机不可达，本轮按约定使用 Mac。原生用例通过窗口内的剪贴板事件投递验证，系统剪贴板快捷键、Windows 原生操作、两平台安装包和较早 PostgreSQL 版本待验。
