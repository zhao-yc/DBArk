# SQLite 跨文件整表复制

打开来源的普通表，点击「复制 SQLite 表」。在「目标 SQLite 连接」中选另一个已保存的可写连接，填写新表名，再选「仅结构」或「结构和数据」。预览后输入准确的 `main.新表名`，点击确认复制。切换目标会清除当前名称和预览。可在另一个文件中使用原表名，目标已存在的对象会阻止创建。

预览与提交都使用独立任务进程。该进程启动时将来源文件以 `mode=ro` 附加到固定的 `dbark_copy_source` schema，并核对来源和目标的真实文件身份。预览全程只读，提交只修改目标文件。普通查询和复制任务的执行阶段均拒绝额外附加或分离文件。任务记录不保存来源路径、DDL 和数据。[SQLite 附加数据库](https://sqlite.org/lang_attach.html) · [SQLite URI 模式](https://sqlite.org/uri.html)

确认后复核两端身份、目录版本、来源表结构和目标名称，再在目标事务中建表和复制。数据由 SQLite 原生 `INSERT … SELECT` 传递，保留普通列的存储类型、主键和可访问的隐式 rowid。生成列重新计算，自引用外键指向副本，显式索引使用新名称，触发器需单独配置。指向其他表的外键暂不跨文件复制，以免绑定到目标文件中的同名对象。两端文件需采用相同的数据库编码。同一物理文件的连接别名需走本文件复制。

提交前核对目标定义及实际复制行数。取消或关闭任一端连接会等待原任务收尾，进入 COMMIT 后以实际提交回执为准。成功后应用刷新目标目录并打开新表。

## 验收

- WIN11-TEST 不可达，按授权在 macOS arm64 使用 Node.js 24.17.0。原生运行时、类型检查、构建和 132 项定向测试通过。全量单测覆盖 1,349 个文件，27,558 项通过，10 项按平台条件跳过。
- 独立 SQLite 文件和原生驱动验证结构副本、同名跨文件建表、原文件字节保持、来源目录或文件变化拒绝、同物理文件别名拒绝、外部外键拒绝及关闭来源后的目标回滚。
- macOS Electron 窗口从只读连接选择另一个文件作为目标，确认预览阶段目标表尚未创建。提交后独立读回三行，核对隐式 rowid、64 位整数上下界、负零、无穷大、BLOB、NULL 和空文本。目标标签已打开，来源文件原记录仍在。同文件整表复制和勾选记录传输同轮回归通过。
- 首轮窗口专项完成读回后未在时限内收到退出事件。核对原进程和文件句柄已消失后保留首轮日志及工作区。单独运行通过正常退出及临时工作区清理检查。
- Windows 和安装包待验。不同文件编码之间的数据迁移和外键依赖批次待实现。
