# 新建表 CHECK 设计（2026-10-28）

## 实际入口

侧栏“新建表”的原设计窗口新增“CHECK 约束”页签。每项明确填写名称、完整表达式和生效意图，支持新增、删除及相邻重排；表达式原文不修剪或重写，修改字段名不会自动改写检查条件。输入时保留行身份及焦点，最后删除一项会真正移除可选 `checks`，不会传空数组或 `undefined` 绕回旧建表流程。已有表通用设计入口拒绝这个新表字段。

原确认阶段读取实际版本、SQL 模式和 CHECK 能力。缺少完整能力或不支持所选生效状态时阻止预览，不静默删除条件或将 NOT ENFORCED 改成启用。固定只读 SQL、准确目标、单次令牌及原两项建表确认保持；增加 CHECK 语义确认，与生成列并存时共四项。检查约束不等于 NOT NULL，NULL 可能符合条件；最终表达式可用性由服务器裁决。

## CREATE 与完整核验

继续原普通、前缀索引、字段编码、生成列四条生成路线，只在基础输入中剥离 `checks`，按完整解析器证明的表体边界插入命名表级约束，最终仍只有一条 CREATE。其它字段、主键、索引和外键不降级或重建；原前缀新表不支持外键的限制保持。

显式请求的 CHECK 事实绑定快照；预览、提交及末尾核验均重读版本和模式。独立结构会话明确保持外键、唯一检查及 MariaDB CHECK 开关开启，不修改查询标签或全局变量。MySQL 5.7 等可能忽略检查的版本拒绝含 CHECK 设计；MySQL 8.0.16 以上的 8.0／8.4 和 MariaDB 10.11／11.4 按能力分流，MariaDB 不伪装逐条 NOT ENFORCED。

CREATE 后先交叉完整 SHOW、TABLE_CONSTRAINTS 和 CHECK_CONSTRAINTS，再仅将已证明的准确 CHECK 范围投影给原字段、索引与外键核验器。MariaDB JSON 的匿名列级 JSON_VALID 另与真实 LONGTEXT、utf8mb4_bin、完整 COLUMNS 及默认值／可空／生成属性交叉证明；私有 proof 绑定实际源和投影文档，不能由 renderer 布尔值授予 JSON 等价。原真实类型、源文字和范围不伪造，未知约束仍拒绝完整核验。

表达式只规范整包外括号、关键字及明确裸列的服务器补引号，不猜代数等价；TRUE 常量和同名列、函数和列引用保持区分。目录矛盾、未知服务器重排或末尾 SHOW 变化只保留 CREATE 已完成事实，不宣称完整核验。取消、断线或关闭失败均不重放，不自动删除已经创建的表。
