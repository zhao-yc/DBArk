# PostgreSQL 按筛选批量删除

在带主键且可删除记录的普通表应用筛选，处理完未提交的草稿后点「按当前筛选删除」。预览显示目标表、已应用条件、参数及准确行数。计算覆盖所有页，未应用的筛选输入和页内勾选不参与计算。

核对范围后输入预览行数，再点「确认删除全部匹配记录」。预览和取消只读。单次最多 1,000 行，零匹配或超限会拒绝生成预览。预览最长有效 5 分钟，也受原表页有效期约束。提交成功后按原筛选返回第一页。

提交时在锁内重新核对完整匹配集合和行版本，再执行单条参数化 DELETE。预览后新增匹配记录或原行版本发生变化会拒绝整批。外键限制或实际影响行数不符会回滚本次操作。行数只覆盖直接匹配的目标表记录，外键动作及触发器还可能删除或修改其他记录。 [PostgreSQL DELETE](https://www.postgresql.org/docs/18/sql-delete.html) · [外键动作](https://www.postgresql.org/docs/18/ddl-constraints.html#DDL-CONSTRAINTS-FK)

## 验证记录

- macOS arm64、Node.js 24.17.0 的原生运行时检查、类型检查和构建通过。全量单测覆盖 1,345 个文件，27,533 项通过，10 项 Windows 条件测试跳过。
- Server-200 上的 PostgreSQL 18 独占实库通过 5 个文件、7 项测试。外键限制触发后原父表与级联子表均保持原值。预览后另一个连接新增匹配行，旧预览整批拒绝。重新预览后删除 5 条匹配父记录，独立读回两条保留父记录及预期级联结果，并验证已消费预览不能重放。
- macOS Electron 实库专项通过 37 项观察。从第二页预览全部 4 行，取消后独立读回全部原值。错误行数无法确认，输入正确行数后只删除直接匹配的 4 行，并按原筛选回到第一页。截图检查后明确了删除行数的标签，并用重新构建的原生窗口复验。
- WIN11-TEST 连接不可用，本轮回退 macOS。Windows、安装包及其他 PostgreSQL 版本待验。
