# SQLite 同文件整表复制

在普通表的工具栏或「更多」菜单点击「复制 SQLite 表」。输入新表名，选择「仅结构」或「结构和数据」，点「预览 SQLite 复制 SQL」。核对来源和目标后，输入准确的 `main.新表名`，再点「确认复制 SQLite 表」。成功后可关闭回执，切到自动打开的新表。只读连接可预览。

结构以真实 `sqlite_schema` 中的定义为准，保留字段、约束、生成表达式、STRICT、WITHOUT ROWID，以及显式表达式索引和部分索引。显式索引使用独立的新名称。外键仍指向原外部表，自引用外键指向副本。触发器需单独配置。虚拟表、影子表和视图不在复制范围内。单表最多 32 个显式索引，结构原文上限 2 MiB。[SQLite CREATE TABLE](https://www.sqlite.org/lang_createtable.html)

预览只读取独立只读快照。确认后在 `BEGIN IMMEDIATE` 下重核原文件、目录代次、来源定义和新名称，再于同一事务建表、建索引和复制整表数据。插入在 SQLite 内完成，保留原存储类型、主键和可读取的隐式 rowid。全部三个 rowid 别名都被普通字段覆盖时，只开放结构模式。生成列由 SQLite 重新计算，AUTOINCREMENT 使用副本现存行建立新的高水位。来源删除过的高水位不转移。[SQLite 生成列](https://www.sqlite.org/gencol.html) · [SQLite AUTOINCREMENT](https://www.sqlite.org/autoinc.html)

提交前会核对实际定义、来源与副本的行数以及写入回执。名称冲突、目录变化或约束失败会拒绝本次复制。提交前停止可回滚整批，进入 COMMIT 后等待真实回执。若结果未知，先核对原文件里的目标表。

## 验收

- WIN11-TEST 不可达，按授权在 macOS arm64 使用 Node.js 24.17.0。原生运行时、类型检查和构建通过。完整单测覆盖 1,349 个文件，27,555 项通过，10 项按平台条件跳过。另有 135 项定向测试通过。
- 独立 SQLite 文件和原生驱动验证仅结构、完整复制、复合主键、显式表达式和部分索引、自引用外键、独立 AUTOINCREMENT、隐式 rowid、负零、整数精度、空 BLOB 和生成列。约束错误、目标名称竞争和提交前取消均核对了回滚结果。
- macOS Electron 原生窗口验证预览阶段目标表尚未创建，确认后独立读回两行，并核对 64 位整数上下界、负零、空 BLOB、NULL 和空文本。应用打开了副本标签，原表保持两行。既有 SQLite 跨文件勾选记录路径同轮通过。窗口正常退出并清理临时工作区。
- 首轮原生窗口在副本标签加载期间触发退出提示。保留该轮日志，最终专项等待副本表格和在途任务收尾，验证退出时没有弹窗。
- 跨文件及跨引擎整表传输、批次管理待实现。Windows 和安装包待验。
