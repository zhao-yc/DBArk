# JSON字段创建与识别

## 操作入口

“字段差异编辑”新增普通字段时，可在类型类别选择JSON，明确可空性、无默认值或SQL NULL及备注，再暂存并预览SQL。暂存及预览均不执行DDL；原维护窗口、隐式提交、一次性令牌和关闭保护保持。JSON不接收长度、UNSIGNED或任意类型SQL；文字量／时间表达式默认值仍拒绝，NOT NULL不能设置DEFAULT NULL。

MySQL使用原生JSON；MariaDB使用LONGTEXT／utf8mb4_bin及JSON_VALID校验表示，依据[MariaDB官方JSON说明](https://mariadb.com/docs/server/reference/data-types/string-data-types/json)。界面保留实际`typeSql`，编辑器额外提供结构化JSON模型，不将MariaDB称为MySQL二进制JSON。

MariaDB必须同时证明实际编码、二进制排序规则及完整本列`CHECK(json_valid(字段))`。其他字段、额外OR表达式、缺校验和目录冲突不作JSON证明；SHOW CREATE省略继承编码时，只接受同次真实列目录，不能借表默认值。原表达式、索引和约束依赖保护保持，不自动重构引用。MySQL5.7.8之前的JSON写计划拒绝。

## 执行与核验

原结构化类型合同、纯计划器、前端类型控件及引擎读取／后核验接通同一JSON判别项。只有明确新增JSON且实际类型／编码／校验均匹配，才允许MariaDB自动展开的charset、collation、check属性通过后核验；其他字段与类型不豁免。原片段保留、未知结果不重放、取消和真实连接释放保持。

此批验收聚焦新增、默认值限制、重新读取和服务器JSON校验。现有JSON字段的类型转换、CHECK改写、表达式默认值、任意JSON路径索引及跨类型迁移另验，不将DDL入口当完整结构编辑包。
