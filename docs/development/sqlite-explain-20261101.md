# SQLite 执行计划

## 使用与语义

在 SQLite 查询标签的“更多 → 执行计划”或原生“工具”菜单调用，选区优先；没有选区时使用完整草稿。仅接受一条完整 SELECT、VALUES、WITH、INSERT、UPDATE、DELETE 或 REPLACE。多个语句、PRAGMA、DDL、事务控制、ATTACH／DETACH 和已经带 EXPLAIN 的输入在驱动之前拒绝，不执行前面的语句来准备环境。

后端只向原物理会话提交 `EXPLAIN QUERY PLAN` 包装，用原生单语句校验阻止追加执行。可读取本会话临时表和事务中可见的数据；不另开连接、不重连或重放。只读连接继续遵守原 authorizer，写目标的 DML 计划可能被原生权限检查拒绝，不为计划绕过写权限。执行计划不写入普通 SQL 执行历史。

树、原始表格和原始输出都来自本次返回，切换视图及折叠不发送 SQL。保留 SQLite 原始 id、parent、notused、detail；不从说明文字推算成本、扫描行数或实际耗时。本入口提供优化器计划，实际执行分析和计划快照文件另行接入。

SQLite 官方指出[四列计划输出及格式会随版本变化](https://www.sqlite.org/eqp.html)，并说明[部分 PRAGMA 在 prepare 阶段生效](https://www.sqlite.org/lang_explain.html)。因此本入口明确排除 PRAGMA，不依赖“加 EXPLAIN 就一定没有编译期副作用”的假设。

## 预算与失败保护

- 原输入和包装后的 SQL 均受 20MiB 上限约束，原会话互斥、ACK、任务编号、取消和正常关闭协议保持。
- 返回行数受用户结果上限和 1,000 行共同约束，原生结果预算仍为 16MiB。原生成功但结果截断时显示不完整表格警告，不生成半棵树。
- 树最多 300 个节点、64 层；重复编号、孤儿、自环、循环、未知列结构及超长说明均降级到原始表格，绝不补造父节点或假装完整。
- 原始输出最多 192KiB，按 UTF-8 完整字符保留前缀并明确标记截断；原结果不被改写。节点整数保留精确文本，不经过浮点数转换。
- 不使用 MySQL 计划 JSON、指标或快照格式冒充 SQLite；计划结果不进入普通数据编辑、写入目标表和结果整理入口。
