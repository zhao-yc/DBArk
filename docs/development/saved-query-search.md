# 本地保存查询搜索实现

本功能属于W03的开发中检查点，实际入口与验收见[使用说明](../database-search.md)及[验收记录](../../tests/integration/acceptance-w03-saved-query-search-20261015.md)。不会执行用户保存的SQL，也不借用数据库查询会话。

## 请求与执行

`search.savedQueries`接收严格校验后的任务编号、来源连接/默认库上下文、字段、匹配参数、上限和错误策略。`search.savedQueriesContinue`仅接收新任务号和随机句柄，不能修改范围；`search.savedQueriesRelease`仅释放该句柄。主进程沿用统一任务编号、事件、取消及退出守卫，本地取消不发给数据库工具进程，数据库工具进程退出也不误结束独立本地任务。

`LocalStore.querySearchNext`按BINARY主键位置读取一条JSON原文及下一条存在性，语句无论成功失败都释放。它不调用旧`queries.list`，也不在主线程解析或匹配所有SQL。每页检查最多25条，单页128KiB，总命中1000。查询保存/删除或连接配置修改在成功落盘后增加修订，页内等待及续页重新核对；失败写盘保持原修订、数据和摘要。

`savedQuerySearchWorker.cjs`是单独构建的固定入口，只接收初始化条件及一条本地记录；不继承主进程凭据环境或调试启动参数，不接受外来代码或文件路径。它在256MiB旧生代/32MiB新生代预算内解析JSON并运行JavaScript Unicode正则。普通文字全部转义，完整匹配额外核实际匹配跨度，不能忽略末尾换行；行列按UTF16计量，CRLF计一行，预览边界不拆代理对。正文、精确数值和SQL中的JSON均保持字符串，不解析SQL内容。

每条匹配命令预算2秒，初始化预算5秒；超时、取消及退出会等待实际线程terminate结束，实际回复还包含启动、序列化和收尾耗时，预算不作为整个页面的墙钟耗时保证。继续策略在确认失败线程结束后为下一条建立新线程，不重放失败记录。每页结束即停止线程；最多2个活动页、16个续页状态，句柄仅含条件、主键位置和计数，无SQL全文或活动线程。

## 打开与隐私

结果仅携带原查询概要、原文SHA256摘要、每字段首处位置及有界预览。`queries.read`要求明确的查询ID、原摘要和目标连接，当前记录修改/删除或目标连接失效时拒绝；只有用户明确打开才读取完整正文。来源不变时保留已知库、无默认库、未知及遗留信息，显式更换来源后只生成默认库未知的查询。实际打开生成新标签ID，不覆盖已有SQL、执行结果或事务，光标导航只在内存保存并在标签关闭后清理。

原文、名称、搜索值和原错误不进入任务概要；搜索条件不进入工作台设置。已有查询本身仍由用户保存在本地SQLite，本功能不会改写其内容。保存查询浏览界面已接入[独立概要分页](saved-query-pages.md)，旧历史列表及兼容接口仍保留；内存SQLite自身的文件装载和显式打开大SQL的编辑器内存也不属于本批流式保证。

真实验证分别覆盖SQLite/线程及Electron源码、安装、私网流程。底层线程终态核原生threadId为-1；退出仍核真实进程，不以清除JavaScript引用或关闭窗口代替释放。最大预算边界、未验平台/规模与原失败必须保留在验收记录，不能把纯逻辑或离线结果写成数据库驱动验收。
