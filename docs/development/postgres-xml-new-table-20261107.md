# PostgreSQL 从 XML 新建表

在 PostgreSQL 数据库节点或对象浏览器的表分类打开「从文件导入新表」。选择 UTF-8 XML，按需填写记录标签、启用记录属性字段和 Base64 解码。向导完整扫描文件，列出源字段并集、记录数及原文件 SHA-256。样本最多显示 20 行。

填写并核对新表名，进入正式 PostgreSQL 表设计器。选择有建表权限的 schema，按业务调整字段类型、约束和默认值。建议字段为可空 `text`。使用 Base64 解码的目标字段需设为 `bytea`。预览 SQL 并确认建表后，新表会出现在原数据库目录。

点击「继续配置导入」。向导沿用已选文件，重新比对原字节指纹，并从实际创建的表读取列目录。字段映射可修改或跳过。核对映射并确认追加后，PostgreSQL 在一个 COPY 事务中校验目标类型和约束。已映射但在某条记录中缺省的字段写入 NULL，空字符串保留。目标列完全未映射时使用 PostgreSQL 的默认规则。

确认建表与确认导入分开。文件在配置导入前变化会阻止签发导入能力，在映射完成后变化则使写入回滚。退出或导入失败时保留已创建的表。

当前使用扁平 XML 1.0 格式，文件上限 64 MiB，新表设计器接受 1 到 128 个源字段。位置映射「XML 文档」回读和按键更新仍待补齐。[向已有 PostgreSQL 表导入](postgres-xml-import-20261107.md) · [从 CSV 和 JSON 新建表](postgres-csv-json-new-table-20261107.md)

## 验收

macOS arm64 使用 Node.js 24.17.0，通过运行时检查、严格类型检查、构建及 31 项定向单元测试。Electron 连接 Server-200 的隔离 PostgreSQL 18.6，两项端到端测试均通过。新表用例确认了中文 schema 下的建表与写入分离、64 位整数与 `bytea` 保真、空字符串和 NULL，以及源文件在两阶段改写时均保留空表。另一用例回归现有表的 XML 映射及事务回滚。隔离容器和回环转发均已清理。

Windows 虚拟机测试会话本轮不可达，Windows 原生与安装包验收待执行。

全量单测与 `7e7cfdcd` 源码基线在同一 macOS 环境分别执行。两边均通过 27,616 项，跳过 10 项，并复现同一批 256 项失败，新增失败 0 项。
