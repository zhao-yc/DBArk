# Q03 无活动事务查询的保存后关闭

## 交付范围

本切片基于 Root `c16510c7ad35549c4d01dd5cd8b1f34de67ffc64`，独立普通克隆、任务分支 `codex/employee2-q03-save-close-20261016`。没有 worktree、Git alternates、共享对象、main/shared/IPC/依赖/版本或 Root 目录修改，不改冻结 C03/D08。

非空 SQL 查询标签在没有活动作业、事务/dirty 标记时，关闭入口新增“保存后关闭／直接关闭／取消”。后台标签的确认用 portal 显示，不切换或误关另一个活动标签。空查询、表、活动作业、事务确认、整个窗口退出保持原路径。本切片不代表整个 Q03 完成。

“保存后关闭”复用真实 QueryBindingDialog 与 QueryTab.saveQuery：已关联标签明确选择更新原查询或另存；未关联标签只能另存。主进程 CAS、删除保护、连接路由与四类库上下文、原子写入和精度预算完全沿用原接口。保存不执行正文、不建立新会话、不改变原结果/计划或自动提交事务。

## 保存与关闭是不同结果

- 记录写入失败或 CAS 拒绝：标签、草稿、名称及旧来源保留；弹窗显示错误，用户可明确另存。没有隐式刷新摘要、覆盖或重发。
- 查询记录已保存，但随后 flushSettings 失败：保留已成功的来源绑定和标签，显示原“查询已保存，但标签来源恢复状态保存失败”通知；终止自动关闭。不会再发一次 create/update。
- 记录和恢复信息成功：仍须一次性意图有效、无新作业/dirty 标记，才能结束本次目标标签。保存期间产生新编辑、模型替换、连接修订、会话或库状态变化、外部工作区新草稿时，保留最新草稿并提示，不自动关闭。
- 取消或卸载不能撤回已发出的本地记录写入；迟到成功不关闭新目标、不复活已删除标签、不向同 ID 新视图绑定旧结果或清除新作业。主进程原接口没有新增幂等协议，本切片只保证不自动重发，不把“响应未知”宣传成“确定未保存”。
- 最后关闭标签的布局持久化继续使用既有 store.closeTab 防抖；没有把查询记录与标签移除伪装成同一跨对象原子事务。没有新增窗口退出或批量关闭流程。

## 生命周期和并发保护

`QueryCloseRequests` 以请求对象身份互斥并消费完成结果，旧返回不能释放新请求。`QuerySaveCloseIntent` 在保存点击时捕获真实编辑器模型、版本、正文和工作区草稿、连接 ID/修订与概要实例、会话及库类别，订阅模型/编辑器和 store 变化。任何失效都永久撤销自动关闭权限，撤销回相同正文/上下文也不复活。

保存自身 rememberDatabase 产生的已核对上下文更新通过显式 adoptContext 接纳；除此之外不能把新默认库填回旧快照。模型未就绪时拒绝保存后关闭并保留标签。租约和全文只在当前视图内存，所有终态释放订阅。

QueryTab 保存函数现在返回恢复信息是否保存成功，普通工具栏/菜单保存仍通过薄包装忽略这个返回值，保持既有行为。保存后关闭在该函数 finally 解除自身 busy 后检查租约；App 最后再次读取 activeJobs、dirtyTabs 和目标存在性，没有新增 force 绕过守卫。store为setBusy记录仅驻内存的递增归属，保存后关闭持有WorkspaceBusyLease。新作业接替后旧finally不清除新标记，也不据此关闭；其它标签作业不影响该归属。旧视图卸载只释放自身作业，迟到finally不清除新视图标记。同标签新作业反例在未补归属的候选上真实组件运行红、修正后绿，原始JSON保留。

没有新增秘密字段或额外持久化内容：查询正文仍按既有用户明确操作保存；用户主动输入的 SQL 可能含敏感字面量，不能承诺正文天然无秘密。关闭请求、模型句柄、完整点击快照不进入 settings、日志、附件或遥测；未读取数据库/SSH 密码、证书或私钥内容，也未生成需备份的密钥文件。
