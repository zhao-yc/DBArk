# SQLite 查询结果本地多列排序

## 使用与范围

SQLite 查询结果现可点击列头循环升序、降序和移除；Ctrl／Cmd 追加优先级。“多列排序”打开独立草稿，可调整字段、方向、优先级、NULL 位置及忽略大小写，明确应用才生效。支持撤销／重做整理及恢复原返回顺序，不执行 SQL，不借用或修改查询事务。

仅作用于当前已返回行；截断结果不代表完整数据。原选择、查找和行详情随排序变化撤销，后续操作复用同一结果投影。保存结果快照仍保存原始返回顺序，不能把排序后的展示误写为原查询结果。

## 比较合同

排序依赖实际 driver 的 `sqliteStorage`，同样显示为 `2` 的 INTEGER、REAL、TEXT 具有不同存储类型。升序依次为 NULL、数值、TEXT、BLOB；INTEGER 使用 BigInt，REAL 使用原 binary64，二者按数学值比较，不先把整数转成 Number。数值相等交给后续优先级，最终按原返回位置稳定排列。

TEXT 明确使用固定 UTF-8 字节序，BLOB 使用原字节序。可选忽略大小写只对 TEXT 做无区域设置的 Unicode 小写映射；不转换其它存储类，不模拟数据库自定义 COLLATE，也不把文本日期猜成日期对象。该合同参照 [SQLite 存储类排序](https://www.sqlite.org/datatype3.html#sorting_grouping_and_compound_selects)和 [ECMAScript 数值比较](https://tc39.es/ecma262/multipage/abstract-operations.html#sec-islessthan)，MySQL 原比较器保持原合同。

旧 SQLite 结果或版本 1 快照缺少存储类型时，排序明确拒绝，不根据原文猜测。版本 2 快照与投影保留对应类型行。原类型对象、代码或活动二进制值变化使旧租约失效；还原原值不能复活旧租约。

保持原 100000 行、1024 列、2000000 单元格、单值 4096 UTF-16 单元及 8 Mi 单元预算；SQLite 的 Base64 原文与编码后的 TEXT／BLOB 比较键也计费。拒绝排序保留原视图。
