# SQLite 字段重建验收补齐本机布局读取

## 原因与修正

已读取并校验准确提交 `22b7ee9e83553b4a6d1b61bbafc838862bd3ece9` 的 [Mac arm64 原 CI 附件](https://github.com/zhao-yc/DBArk/actions/runs/41375742977/job/125055470983)。成功与回滚两例均停在“原数据页真实读取以核重启恢复”，拒绝数组准确记录 `非白名单命令：sqlite.tableLayout.get`，当时待办请求为 0。

原脚本已对布局 get 限定三个参数字段、所属连接、`main` 库与本例准确表名，SQLite 子命令列表也含 get，但总白名单漏掉了该项。正常打开数据页时读本机列布局被拒绝，随后原检查因拒绝记录统一报告“观察器失效”。

本轮只为总白名单补齐 `sqlite.tableLayout.get`。现有字段、目标、主文档、worker、cap、退出及事务限制保持；布局 save／delete／reset、其它连接或对象仍不放行。不改产品、数据库业务、IPC、凭据或写操作，也不通过清空拒绝数组、重装观察器或忽略异常继续测试。

## 验证

WIN11-TEST 本轮不可达且未派发，按既有授权回退本机，复用 `88ee1be6` 已验产品构建：

- 类型检查、14 份 381 项重建相关测试通过，覆盖真实 SQLite 驱动、完整比较、计划、Main、任务事实和界面。另核原 CI 门；新增 17 项用例执行实际 spec 的 Main 观察器，验证准确读取透传、不启动数据库 worker，以及额外字段、其它连接／库／表、布局写入、其它命令和主文档失配均拒绝，拒绝后旧链不复活。
- 首轮新 RAM 用例误把观察器包装后的 fork 当原 spy；保留失败日志，改为记录原始 fork 引用后维持断言复验。未修改原生门槛。
- 对照原脚本全文，仅规范化行尾并反向移除这一个白名单原子后，全部源文本相同；原 293 个 `expect` 调用、120 秒、单 worker、零重试、失败保留与精确清理保持。
- Windows 两条完整原生路径通过：成功提交 23.430 秒、主动回滚 13.045 秒。已实际走过列布局读取，继续验证原数据页、任务事实／ACK、事务、原行不变、默认值、索引、触发器、外键、序列、独立磁盘核验及正常重启；回执分别为 `committed`、`rolled-back`。
- 独立原件审计：观察到的 worker 分别 10／7 个且均退出 0；签发与释放的 cap 分别 4／4、2／2；布局读取为 2／1 次。四个准确 owner 正常退出 0，两准确目录及进程独立核零。原行、外键与完整性检查符合原预期，用户查询 SQL、查询会话及系统剪贴板操作均为 0。

原日志、退出码、原归档与摘要、完整 JSON、源文本及资源审计保留在忽略目录 `.cache/sqlite-rebuild-observer-20261102/`。未运行或清理旧 CI 资源，没有访问 Server-200、真实数据或已安装客户端配置；本轮只改测试，未重新构建产品或打包，不创建 Release。
