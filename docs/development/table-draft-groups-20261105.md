# MySQL／MariaDB多页草稿文件分组恢复（2026-11-05）

本批接续 `7de41fadefbd38434ea6119f935f0d4eca6fd808`。原功能可以保存全部保留页的修改，恢复却只显示扁平列表。新版保存有修改的原页号、页长及活动分组；独立核验全部原行后，恢复为可继续编辑的多页草稿分组。关闭原表标签会销毁旧内存工作区，新表页必须显式选择文件并重新核验；不会自动提交或重放写入。Electron／React／TypeScript架构和Windows／macOS目标保持，版本仍为0.28.0，不打标签、不正式发布。

## 操作与范围

1. 在同一表多页暂存修改，点“保存表格草稿”，先确认文件未加密且包含原始数据，再选择位置。保存不会清除原表未提交状态。
2. 新版只保存有修改的原页分组，变化顺序按原页号递增；原活动页无修改时，恢复打开第一个有修改的组。原页长一并保存。
3. 关闭表页后，在原连接的同一表点“恢复表格草稿”，选择文件、核对统计，再明确“核验并恢复草稿”。端点、结构或任一旧行不符时整份拒绝，不部分恢复。
4. 通过后仅显示保存的变更记录。“多页草稿”中的原页号表示变更归属，不是当前服务器分页。切换这些组不请求 `table.page` 或 `metadata.table`，普通服务器翻页保持禁用。
5. 各组可继续编辑、独立撤销新操作、按原UUID保留本次会话选择，以及明确放弃。再次保存保留剩余有变化的组；只剩一组也保留原页号。任意当前组均可统一预览全部变化，最终仍需明确一次提交。
6. 存在未暂存输入或活动单元格编辑器时不能切组；连接／目录／条件变化后旧组保持但失效，切走标签的旧回调不能改变隐藏页。提交结果未知或已提交待核对时沿原整组保护，不能拆组或重复提交。

第一版文件原样兼容，仍恢复为单一独立列表。第二版文件没有供旧客户端识别的回退伪装，旧客户端应拒绝未知版本。内存保留页与文件预算不同：文件继续限制1000条、8 MiB、单值256 KiB、结构2 MiB和200000格，恢复后的内存仍受16页／64 MiB／100000格预算限制。超限整次拒绝，原页保持。

文件不包含干净缓存页、筛选／排序配置、原UUID、原选择、保存前撤销历史或未暂存输入。恢复后的独立撤销只覆盖恢复之后的新操作。没有自动崩溃恢复、跨表会话恢复或自动应用冷启动恢复；应用冷重启、Windows及安装包本批未验。SQLite原文件功能保持，其分组持久恢复另行推进。D04及完整Navicat对标目标继续为部分完成。

## 实现与边界

- `src/shared/tableDraft.ts` 扩展版本2，`workspace` 仅含 `pageSize`、`activePage` 和递增的 `{index,changes}` 数组。精确字段、普通自有数据描述符、无空洞数组、最多16组及变更数恰好覆盖全部记录均在IPC／文件边界统一检查。版本与有无分组必须严格对应，不能第一版夹带分组或第二版缺少分组。
- 数字标签、负零、精度文本、JSON词法、BLOB、NULL、空串和DEFAULT省略保持原无损编解码；分组元数据计入精确文件字节预算，不扩容、不截断。文件不携带连接地址或密码；Main继续绑定并复核原端点摘要。
- 原 `table.draftVerify` 一次核验全组变更，分组不参与SQL生成、不放宽原值验证。文件选择经正式Main有界IO处理，恢复仍是本地草稿而非写库授权。
- `TableEditWorkspace.restoreDraft` 在完整解析、行结构／编号／复制键检查及内存预算通过后才原子替换旧干净缓存。生成新的行UUID、分组历史及本地来源，不签发原引擎补取令牌。
- `TableTab` 复用原多页草稿、集中预览和事务链。恢复后的本地切组固定原活动标签、连接版本、原渲染、输入及提交锁；页号／页长引起的React加载只消费准确一次本地采用票据。同页同页长恢复不遗留票据，避免吞掉下一次显式读取。
