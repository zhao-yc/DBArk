# SQLite 已有主键管理：声明与后续事务要求

后续主键组合计划、Main／Runtime 和独立事务已推进，见[主键事务记录](sqlite-primary-key-engine-20261102.md)。下文保留声明阶段原范围和验收要求；界面仍待接入。

## 当前实现

在已有外键编辑之后，继续实现已有表主键管理。本阶段新增有界的主键结构模型、准确原声明读取和新增／替换／移除编译。它们尚未连入 Main／Runtime 的写能力或界面，不能视为用户已可用的主键编辑，也不增加完整 R02 或发行计数。

主键只有一个准确原目标：已有声明以完整原 SQL 绑定，新增要求原表确实没有主键。读取区分行内／表级、命名标记、复合字段顺序、逐字段排序规则及 ASC／DESC、显式冲突策略和自增；保留原声明中的括号、连续排序规则、重复字段与特殊命名。新设计用准确普通字段、有效名称和枚举构建，禁止生成字段、重复新字段和任意表达式。

原字段、非目标约束、生成列、注释、表选项和外键片段继续保留。移除只删准确主键跨度，替换不从简化列模型重建整表。WITHOUT ROWID 表禁止单独移除主键，仍可设计完整替换。新名称不能与保留的其他命名约束冲突。

## 必须保留的原生语义

- 行内 `INTEGER PRIMARY KEY DESC` 不具备 ROWID 别名语义，表级 `PRIMARY KEY(a DESC)` 可具备；读取与生成不得把两种位置自动互换。[SQLite CREATE TABLE](https://www.sqlite.org/lang_createtable.html#rowids_and_the_integer_primary_key)
- 普通复合主键允许 NULL，STRICT／WITHOUT ROWID 主键有不同规则；不得以统一补写 NOT NULL 的方式偷偷改变列定义。[SQLite PRIMARY KEY](https://www.sqlite.org/lang_createtable.html#the_primary_key)
- 自增只用于准确 INTEGER 单列 ROWID 主键；表级兼容写法将 AUTOINCREMENT 放在字段列表末尾、右括号之前，已由实际 SQLite 验证。主键顺序、排序规则和显式冲突动作以独立原生目录／事务核对。新增自增会影响未来不复用行号，不等于从列名猜测自增。[SQLite AUTOINCREMENT](https://www.sqlite.org/autoinc.html)

当前模型不推断或签发 ROWID 身份，不读取文件、不试写原表。新主键即使声明 ON CONFLICT IGNORE／REPLACE，后续复制仍须用固定 INSERT OR ABORT，并完整比较全部数据，不能因冲突策略静默少行。

## 接入完整功能前的验收要求

1. Main 与 Runtime 独立编译并校验原目标、精确 SQL、风险和变化数量；能力仓库复制主键补丁并计入预算，领取后再次重算。保留原文档、配置代次、期限和来源失效保护，不能使用伪造字段修改打开写入入口。
2. 新原生主键顺序、可空性、自动索引、生成列和其他约束按最终候选逐项检查。允许计划内主键索引变化，其他索引、触发器、视图及对象仍保持原检查。主键与字段类型、默认值、实际顺序及外键须可同批设计，原声明同时绑定，不因应用顺序误认目标或误报最终名称冲突。
3. 显式处理普通主键、整数 ROWID 别名与 WITHOUT ROWID 主键之间的身份变化。复制前后仍逐行证明全部用户字段、精确值和真实行对应；NULL 不得因提升为整数主键而被自动填号后静默提交。物理 ROWID 的计划变化必须明确展示并额外确认，不能借用户改主键跳过值比较。
4. PK 顺序改变后，验证表按新准确全序重新映射；保留原四次比较和移除私有序号前后的完整证明。三种 ROWID 别名全遮蔽、重复／NULL 主键、复合排序规则和非法候选不能借无可靠身份继续执行。
5. 自增启停、换列、序列表原不存在、目标行原不存在、正负水位及有符号整数边界分别规定并验证。未改自增保留准确原水位和原 rowid；新启用或换列展示新行为。其他表序列不能被新内部候选或验证表污染。
6. 显式／隐式入向关系均须按最终真实父键重新检查。旧违规不能因父主键改列或重排、排序规则改变而借原 PRAGMA 外键编号或同数错误放行；即使子表为空，也须验证父键可靠。不能自动改写其他表外键来凑通过。
7. 同连接的数据、结构草稿及任务占用继续保护。COMMIT／ROLLBACK 只认真实回执，结果未知不重放；取消及关闭等待原任务、保护恢复和资源真实退出。
8. 在原表重建窗口提供原主键查看、新增／编辑／删除、本地草稿和完整 SQL／身份／自增风险预览；关闭、重读、忙态、过期与旧输入保持原保护。仅设计不执行请求，只读可以预览而不能提交。
9. Windows 实际窗口验证成功、冲突整批回滚、NULL／唯一性、精度、父外键、重启不重放和资源清理；Mac 两架构独立验收，不能用编译器测试替代界面、事务或安装结果。
