# 删除服务器全部筛选行

## 操作范围

表数据页新增“删除服务器全部筛选行”。读取当前已经应用的完整筛选树、停用条件及多列排序，不受当前页、勾选行或结果上限限制；没有启用筛选时明确提示范围可能是整张表。存在未提交行、字段编辑或其它表任务时不能打开。

先只读扫描完整旧值快照，显示准确总行数、原会话时区和最多十条完整 DELETE 样本。只有原文输入 `数据库.表 / 删除 / 行数` 并明确确认后才发送删除；预览、关闭预览及输入确认文字都不会删除。SQL 样本在自身容器滚动，最终提交／回滚／未知提示位于固定底部区域。

这不是 TRUNCATE：保留结构和自增计数，每行按原可靠键及全部旧值校验，在一个事务中提交。任一并发冲突或实际 RESTRICT 约束失败均回滚本批；预览后新增的匹配行不混入旧快照。

## 引擎及数据保护

- 删除使用独立 `table.filteredDelete.preview/apply/release`、独立一次性令牌及主文档能力，不能拿填充令牌确认删除。原连接修订、断开代次、主文档与完整范围摘要共同约束发布和提交；来源发生 ABA 变化也不会复活旧预览。
- 只支持可证明完整定义与可靠非空整列唯一键的 InnoDB 基本表。完整旧值流式写入私有文件，最多两份删除预览，删除用途合计 10 GiB；单字段 8 MiB、单行 16 MiB，有效期从扫描完成起十分钟，超限整份拒绝。
- 当前仅开放已核验的 MySQL 8.0.46、8.4.11，允许版本后的发行后缀。预览和执行各自根据实际独立连接版本检查；MySQL 5.7、MariaDB 及其它未验版本在配置、事务、快照和 DML 之前明确拒绝，不回退到无保护删除。当前页编辑和 SQL 工作区仍可用。
- BIGINT、DECIMAL、NULL、二进制和日期时间保持原类型与精度。TIMESTAMP 额外冻结和比较绝对 epoch，不用墙钟字符串替代精确定位；原筛选继续使用原会话时区。
- 专用会话显式启用并读回 `foreign_key_checks=1`，不修改父查询会话或 GLOBAL 设置。必须有可证明跨库目录完整的直接全局 SELECT，并有目标触发器目录可见性；隐藏目录不能视为空。引用的字面星号不当成全局授权通配符。
- 拒绝目标触发器、无法证明无外部副作用的定义，以及反向 CASCADE、SET NULL、未知删除规则；RESTRICT／NO ACTION 由真实服务器约束处理。限制反向目录最多 4096 项，超限拒绝，不截断后继续。
- 明确确认后，事务先执行常量零行 `DELETE ... WHERE 0`，取得目标写 MDL，再核完整定义、反向依赖、实际服务器及快照身份。它不计入删除行数，但保守记录“DML 可能已发送”。每次实际行删除要求 affectedRows=1、零警告及原 IN_TRANS 位；提交前再次核依赖和时区。
- 真实 COMMIT ACK 优先于晚取消、导航和收尾异常；已可能发送 COMMIT 后不发 KILL。取消等待原请求、实际取消及文件收尾；原结果未知不自动重连、重试或重放。

MySQL 8.0 的父子表 DDL／DML 隔离依据见 [WL#6049](https://dev.mysql.com/worklog/task/?id=6049)及 [MySQL 外键与元数据锁](https://dev.mysql.com/doc/refman/8.0/en/create-table-foreign-keys.html)。通用元数据锁说明不能证明旧版同样保护外键父表；不要求用户启用 performance_schema 作为产品准入条件。

## 本轮交叉修正

独立审查发现删除释放误投旧填充命令，已修为专用删除 release；Main 边界测试提取真实能力初始化并核准确 broker 命令，避免手写镜像掩盖接线问题。

删除新增的全局 SELECT 判定，以及复用的触发器授权判定，均补上引用星号反例。仅符号 `*.*` 是全局通配符，字面名为 `*` 的库表仍须准确作用域比较。

删除及既有填充的 Main／renderer 进度合并同时修正：DML 可能发送后曾失去事务保护，该失败事实保持；晚旧进度不能恢复为 true，单独 ROLLBACK ACK 不能声称完整回滚。真实完整 COMMIT ACK 仍优先，不能被降级成可重放失败。

## 验证入口及当前记录

单元入口为 `tests/unit/*table-filtered-delete*.test.ts(x)` 和 `table-range-mutation-progress.test.ts`。实库专项 `tests/integration/table-filtered-delete.test.ts` 需明确双门 `DBARK_INTEGRATION_ENABLED=1`、`DBARK_TABLE_FILTERED_DELETE_TEST=1`；源码窗口另需 `DBARK_TABLE_FILTERED_DELETE_UI_TEST=1` 及受控资源、完整输入摘要。默认及 list 不读取认证或启动引擎／桌面。

实库计划覆盖六个专用端点：开放版本运行主场景、真实 DML 锁等待取消、外部关闭外键检查后的 ADD FK 等待；保护不足的版本运行真实拒绝整例，核零产品写入、完整原数据和资源收尾，不使用 skip 代替验证。窗口使用两张独立的 81 行表：第一张取消预览零写后确认删除 61 行；第二张在第 31 排序行发生准确 CAS 并发修改，验证前 30 行删除完整回滚。已删表不通过重新补种来伪造后续验证。

WIN11-TEST 本轮健康请求曾成功发送，但随后只读重查多次返回主机不可用。本功能尚未向虚拟机派发任何产品测试，使用用户已授权的 Windows 本机备用环境，分别保留原进程、日志、退出码和输入摘要；不重复运行旧虚拟机任务。

初轮类型检查通过，60 文件的 988 项相关测试为 987 通过／1 失败。失败是 React 夹具检查了未注入的旧 release spy；改为实际注入、持有原 Promise 的 spy，保持原调用次数、释放失败不可提交及原错误断言。修正后新类型检查和 988 项全部通过，原失败保留。最终完整检查、实库及窗口结果待本轮实际结束后登记，不把这些静态计划计为通过。

首个完整冻结候选完成八阶段：类型、988 项相关、完整 17312 项通过／1 条件跳过、构建与四个默认／列表门，八个原进程均退出 0。随后 MySQL 5.7 的主整例通过，实际 61 行删除提交、并发及 RESTRICT 各 30 行前序删除后整批回滚、CASCADE 拒绝、预览后新增行保留，22 个原产品连接及 5 份快照收尾，隔离库精确清理。

同一原实库进程的下一 MDL 整例在观察层停链，取消整例被原保留门阻止启动。仅常量零行 DELETE 已发送，尚未建立 DDL／控制连接。原因是原 Engine RPC 占唯一前台 owner 时，子观察又调用前台 `step`；现已改为沿原 RPC 的 owner／期限观察。首因未被原日志保存，不事后补造；独立核原行和资源后精确清理，旧失败仍保留。

第二个完整候选同样通过八阶段及 17312 项完整测试；但 MySQL 5.7 的真实外部 ADD CASCADE 成功，原 MDL 整例超时，证明原产品保护不足，不能把单元测试通过当成实库安全。全部 81 行及子表原行独立读回无变；核完整定义、唯一计划内新增外键、原线程／事务消失后精确清理。恢复脚本曾因可选元数据锁仪表缺失和沙箱 CIM 权限停止；分别保留失败，记录仪表不可用而不冒称锁目录完整，在实际用户权限核进程后完成清理。

后续小型隔离研究验证：MySQL 5.7 的显式 `LOCK TABLES WRITE` 配合 `autocommit=0` 仍不能阻止其它会话在 `foreign_key_checks=0` 下新增级联外键；MariaDB 10.11、11.4 的普通写 MDL 同样不足。MySQL 8.0.46、8.4.11 的原写 MDL 在外部检查开／关两种情况下都观察到原 DDL 锁等待并返回真实超时，事务回滚、全行未变和探测库精确清理均完成。探测脚本的查询别名、定时器参数和 MariaDB 布尔表示错误及其恢复记录独立保留；这些研究不计作产品整例通过。TLS 专用端点的普通连接探测握手被拒，未创建数据库，不能冒充 TLS 验收。

版本准入已同时覆盖预览和执行入口；首批 103 项定向测试通过，随后新增的版本契约反例和最终全量、实库、窗口结果待新候选验证后追加。MDL 观察现在保存原 DDL 首次终态及首因，在主请求结束前等待真实连接严格收尾，意外 DDL 成功仍判失败，不延长原整例时限。

新版本准入候选的类型及 1029 项相关测试通过；沙箱内完整测试为 17343 通过、10 失败、1 条件跳过，十项均为两个原有文件的目录联接创建报 `EPERM`。保留原进程退出 1；同源同断言在正常用户权限下复验这两个文件，58 项全部通过。未修改 ACL、未加 skip；正常用户权限下的新完整验证仍需单独登记，不把定向复验替代全量结果。

正常用户权限的下一轮类型及 1029 项相关再次通过，但全量 fork 池在 39.54 秒出现 `ERR_IPC_CHANNEL_CLOSED` 并退出 1，没有完整用例汇总。核对原父进程及直接子进程已消失，同时间无对应 Windows 应用崩溃事件；具体原因仍未确认，不能称为产品通过。后续改用 Vitest 线程池及详细 reporter 跑同一全量、原断言和其它前置阶段，保留该 fork 中断记录。

线程池候选的八阶段原进程随后全部退出 0：类型、1029 项相关、完整 17353 通过／1 条件跳过、构建及四个默认／列表门。此轮六实例专项中，5.7 三个真实拒绝整例、8.0 三个完整功能整例通过；8.4 的主功能和外键并发通过，取消后事务消失检查超时，后续端点未启动。原 KILL 回执及 data/control 同 socket 关闭已确认，但夹具的另一个纯读会话仍持有行锁，观察到 PROCESSLIST 已空而 INNODB_TRX 仍是 LOCK WAIT；不能把物理关闭直接称为事务消失。进程结束后独立核原线程／事务消失、81 行原值及完整定义，再精确清理该失败库，原超时保持失败。

纯测试修正现先核原任务、唯一 DELETE／准确 KILL、原回调与严格物理关闭、零 COMMIT，再对同一夹具纯读 locker 执行一次 ROLLBACK 并严格关闭，随后仍须原线程与事务真实消失、81 行完整读回及精确清理。释放夹具阻塞源不等于产品回滚成功；取消仍报告 unknown。仅 integration、release helper 及对应单元测试三文件变化，产品、配置、其它原测试和原构建逐字保持；新类型、全部相关及默认门独立复验，明确复用原 17353 项和构建原证据，不把新增断言追加为已运行的全量计数。六实例及窗口需重新独立闭合，服务器事务清理证明的范围明确包含夹具锁已释放这一条件。

该顺序修正后，类型、1039 项相关及四个默认门通过；中途一处测试回执的 TypeScript 收窄错误也单独保留了原退出 2，运行时关闭门没有削弱。新实库 8.0 的取消整例虽通过却耗时 98.7 秒，8.4 在纯读 locker 已真实回滚及关闭后，仍读到 2729 次旧 LOCK WAIT 并超时。因此，不能把夹具锁的循环依赖当成已验证的完整根因；后续独立诊断显示原线程、事务和目标活动均空、81 行原值保持。

更强的源码依据来自 [MySQL 8.4.11 的事务目录缓存](https://raw.githubusercontent.com/mysql/mysql-server/mysql-8.4.11/storage/innobase/trx/trx0i_s.cc)及 [5.7 官方手册](https://docs.oracle.com/cd/E17952_01/mysql-5.7-en/innodb-information-schema-internal-data.html)：缓存需要距上次读取超过 100ms 才刷新，每次读取都会更新这个时间。原测试每 20ms 查询会持续推迟刷新，可能一直看到旧快照，且 PROCESSLIST 与 INNODB_TRX 不属于同一快照。这解释了观察超时的机制；不能从旧目录行直接断言真实事务仍未释放。测试仅将两个事务目录循环的读取间隔改为 200ms，仍沿原 owner／120 秒期限并要求最终真实空集，不延长期限或忽略非空；MDL 的 PROCESSLIST 观察保持原方式。新夹具用独立缓存模型验证空→锁等待及锁等待→空两种变化，产品代码保持原字节。

缓存修正后的 1045 项相关及类型／默认门通过，快速真实 KILL 又暴露原测试错误要求 DELETE 回调必达：实际原连接已严格关闭，但原 callback 和 Query end 都未到，产品原协议本已允许这种物理终态并报告 unknown。修正仅限测试分类：driver-end 必须 callback 与 end 均真、pending0；physical-close 保留两个原布尔及 pending1，不伪造回调，仍须准确 KILL、原 RPC、其它命令完整、最终原线程／事务空和 81 行实际读回。增加真实缺回调边界及缺物理证据反例；正常无专用证明路径的严格门保持不变。该原拒绝及独立核验／精确清理记录保留。

最终这一组源码的六端点 18 整例全部通过：9 个已开放版本的完整功能、9 个旧版本零 DML 拒绝；147 原产品连接、21 快照、6 次确认 COMMIT、6 次确认整批回滚、6 次产品取消，资源残留为零。真实命令收尾分为 15 个 driver-end 与 3 个 physical-close；本轮三个物理取消原 callback 均到达、Query end 缺失，未将此前缺 callback 的失败重写为新通过。

首次 Windows 源码窗口已确认取消预览零写及 61 行提交，但第三预览的 Root CAS 握手超过原 5 秒 ACK 观察门，冲突提交未执行。Root 私有协调器在关键路径重复扫描全部源码、构建及原证据，ACK 晚于 GUI 失败到达，不能算窗口通过；原错误、晚单次 CAS、两张表 20／81 行及窗口退出未证实边界均保留。后续只优化私有协调器的关键路径并保留启动前／退出后的完整冻结核验，公共产品、测试、构建及原 5 秒／120 秒期限均不变。
