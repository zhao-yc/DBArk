# SQLite 只读表页原TEXT字节保护（开发源码）

核对原生驱动时发现：只读表／视图页的普通TEXT结果可能把无效源字节替换为U+FFFD（`�`），与数据库中真实保存的替代字符混淆。已在UTF-8、UTF-16LE、UTF-16BE三个实际SQLite文件中复现，原失败和临时文件保留。

## 实现与范围

- 原分页构造器在没有编辑投影时也使用Main私有的完整TEXT校验。先按实际存储类型判断，TEXT由已有driver函数逐字节核对源编码和原文，其它类型原样返回。
- 坏编码明确拒绝整页，仍回滚本次独立只读快照并确认原进程关闭，不将替换或部分结果交给网格。用户可明确缩小筛选到有效记录重新读取，不自动缩页或重试。
- 有效的NUL、BOM、辅助平面Unicode及真实U+FFFD保持；INTEGER的64位字符串、REAL原文、NULL和BLOB字节不转换。原列名、唯一内部键及每格存储类型编码保持。
- 分页与不同值候选共用同一Main TEXT投影函数；不增加IPC、文件能力、用户查询历史或配置格式，不修改用户查询、数据文件或写入协议。
- 原LIMIT+1／OFFSET、typed绑定、16MiB结果、单值及取消门保持。只有原生SQL的安全投影和字段限定发生变化，测试的SELECT观察点改按准确目标绑定，原数据、排序、取消及资源断言不变。

本次范围是表／视图独立分页及原不同值候选，不能据此宣称任意SQL查询的所有TEXT结果已经具备同级原字节保护。查询编辑器结果的相同边界作为紧接的准确性事项继续处理，R02不增加完整工作包或发行计数。

## 验证

WIN11-TEST本轮不可达且未派发任务，按既有授权在本机Windows串行验证；仅独占合成SQLite文件，不访问Server-200、已安装客户端配置或系统剪贴板。

三编码原缺陷各一例实证失败后，原断言修复通过；拒绝后明确读取有效记录、源原始类型及Hex字节保持、表与视图的六行五类存储、NUL／BOM／真实U+FFFD均通过真实worker验证。实际非确定性视图另验通过，表浏览34项通过；其中包含原分组、分页、排序、并发快照、预算和真实取消。扩大SQLite相关185文件3711项通过，严格类型及构建通过；仍有既有Zod注释／分块体积提示。

Windows原生回归串行通过：`node scripts/sqlite-workspace-ci.mjs table`（`native-table01`，96.566秒）与 `node scripts/sqlite-workspace-ci.mjs edit`（`native-edit01`，45.069秒）。两轮沿用每例120秒、单worker、零重试，未改断言或门槛；验收前后2770个源码、脚本、测试及构建文件摘要一致。读写页的分页、筛选、排序、不同值候选、布局、草稿与提交、并发冲突回滚及恢复保持正常；这属于有效数据原生回归，坏编码拒绝的专项证据来自上述真实worker测试。

最终原始报告核对4次进程退出码均为0，准确进程均已不存在，两座成功临时目录已清理，系统剪贴板访问为0。原缺陷复现记录保留原退出码1，未用后续通过覆盖。

原始日志保留在本机忽略目录 `.cache/sqlite-page-text-20261102/`。不打包、安装或创建Release；macOS两架构、安装版、实体系统输入和全仓验收另验，原失败不追记为首轮通过。
