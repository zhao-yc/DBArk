# PostgreSQL 会话搜索路径

从查询工具栏打开「会话搜索路径」。窗口显示实际数据库、当前角色和物理 PID。配置路径是 PostgreSQL 当前保存的文本，实际查找顺序则由服务器解析，包含隐式系统 schema，并略去不存在或当前角色无法查找的 schema。未写 schema 的对象名会按路径顺序解析。[PostgreSQL 搜索路径](https://www.postgresql.org/docs/18/runtime-config-client.html#GUC-SEARCH-PATH) · [PostgreSQL 会话信息函数](https://www.postgresql.org/docs/18/functions-info.html)

在候选列表选中 schema 可用正确引号追加到末尾。也可直接调整顺序，然后点「应用本会话路径」。点「恢复会话默认路径」会恢复服务器为该会话提供的默认值。最多列出 200 个可用 schema，其余名称可手动输入。配置文本最多 4,096 个 UTF-16 代码单元。[PostgreSQL 配置函数](https://www.postgresql.org/docs/18/functions-admin.html#FUNCTIONS-ADMIN-SET)

读取和修改都在原空闲会话中执行。活动或失败事务须先由用户明确处理。应用前复核原物理身份、角色、旧配置及有效路径。新值通过固定 SQL 的参数绑定传入，发送后再读回。回执不完整时须重新读取。结果、执行历史和连接配置保持原值，设置作用于原查询标签的物理会话。
