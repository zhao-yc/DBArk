# PostgreSQL 跨页草稿文件

在普通 PostgreSQL 表页暂存一项或多项修改后，点击「保存 PostgreSQL 草稿」，选择位置保存 `.pg-draft` 文件。文件保存新增、更新和删除草稿的原页及操作顺序，以及活动页、页长、已应用的筛选和排序。保存后可在当前标签继续编辑。

在原连接、数据库和表的干净表页点击「恢复 PostgreSQL 草稿」，选择文件并核验。程序在同一只读事务中核对表结构、权限及全部待改或待删原行。任何一项不符时，当前表页保持。成功后可继续翻页和编辑，在原界面预览全部 SQL 后明确提交。

文件未加密，包含已暂存的字段值、浏览条件和原行定位及校验信息。选择受保护的位置保存。文件保存已暂存内容，关闭原标签前仍需处理正在输入的字段。恢复建立新的原页能力和本地撤销历史。每个文件最大 8 MiB，恢复继续受 16 个原页、100 项变更和 1 MiB 草稿预算约束。

## 验证记录

- macOS arm64，Node.js 24.17.0。运行时检查、严格类型检查、构建和 273 项草稿相关单元通过。
- 完整单元回归覆盖 1,339 个文件，27,516 项通过，10 项 Windows 专用测试按平台跳过。
- Server-200 独占 PostgreSQL 18 的 5 项实库回归通过。实库覆盖保存并恢复跨页混合增删改、再次保存、原连接和原页绑定、结构及原行冲突、失败后继续用原页、翻页保留恢复草稿以及单次确认写入。
- Electron 窗口专项通过 18 项检查。文件选择使用测试适配，落盘和读取经过正式 Main 实现。关闭原表标签并从对象树重开后，恢复两页草稿和活动页。独立查库确认写入只发生在明确确认后，目标两行更新，第三行保持。再次打开原文件时，原行已变更，界面整份拒绝。原生正常退出，专用库零连接后清理。
- 首轮窗口测试的关页确认无法由 Playwright 对话框事件可靠应答。保留原件后，测试改用只应答本次准确确认的一次性适配，产品路径和断言保持。
- WIN11-TEST 不可达，本轮使用 macOS。应用冷重启、Windows、安装包及其他 PostgreSQL 版本待验。
