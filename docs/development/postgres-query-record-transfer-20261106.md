# PostgreSQL 查询结果跨库复制

在 PostgreSQL 查询页运行查询，切到需要的当前结果集，勾选行后点击「暂存勾选结果以跨库复制」。暂存采用该结果集当前显示的行顺序和可见列，可包含 JOIN、表达式和别名。每批最多 100 行、200 个可见字段和 1 MiB。已截断的结果仅复制勾选且已经返回的行，目标映射窗口会提示范围。

打开可写 PostgreSQL 目标表，点击「从查询结果复制记录」。窗口显示来源连接、数据库、查询标签、结果集序号以及目标表。唯一同名同类型的字段自动匹配。重复列名须按当前可见列序号手动选择，带类型修饰的目标列也可手动映射，由目标数据库校验。

加入草稿仅生成目标表新增记录，预览并确认后才执行写入。复制使用当前窗口内存，保留 NULL、空字符串、BYTEA 和数值原文。暂存期间不重跑查询，也不会提交源事务。此入口用于当前查询结果，固定结果及文件快照沿用各自的查看和导出入口。

## 验证记录

- macOS arm64、Node.js 24.17.0 的运行时检查、严格类型检查和构建通过。8 项定向测试覆盖重复列名、可见列位置、截断标记和原类型保留，以及原有表页跨库复制和粘贴。
- 全量单测覆盖 1,346 个文件，27,537 项通过，10 项 Windows 条件测试跳过。PostgreSQL 实库回归覆盖 5 个文件、7 项测试，全部通过。
- macOS Electron 使用 Server-200 上同一连接的两个 PostgreSQL 18 独占数据库，通过 5 项观察。保留原有表页复制回归。在查询结果逆序勾选两行，重复别名要求显式选列。预览时目标表仍只有原两行，确认后独立读回恰好新增两条，保留高精度小数、字节、SQL NULL 和空字符串。源序列仍停在 3，验证暂存、预览及提交没有重跑源 SQL。窗口正常退出，源库与目标库核对零连接后清理。
- WIN11-TEST 连接不可用，本轮回退 macOS。不同连接组合、Windows、安装包及其他 PostgreSQL 版本待验。
