# PostgreSQL 表页命名方案

在 PostgreSQL 表或视图记录页先应用快速筛选或高级筛选，也可配置多列排序。打开「命名方案」，输入名称，点击「保存为新方案」。方案记录当前已应用的条件和排序，包含条件组合、启停状态、排序优先级及各列的 NULL 位置。筛选值会保存在本机配置中，复制和导出连接时不会携带。仅在筛选输入框或面板中编辑、尚未应用的内容不会保存。

重新打开同一个表页，在「命名方案」中选中一项并点击「应用方案」。服务器验证列名后，从第一页按恢复的条件读取，保留当前页长。列已删除、连接目标变更或读取失败时，当前页与已应用条件会保留。有未提交的记录草稿时，先提交或放弃草稿再打开方案。

输入已有方案名后，可明确确认「覆盖同名方案」。选择方案后也可确认删除，删除只移除本机配置。其他标签已更改方案时，先点击「刷新方案」核对最新版本。方案按连接、数据库、schema 和表或视图隔离，PostgreSQL 方案在配置库中与其他驱动分开保存。

本轮覆盖表配置中的筛选与排序。列布局、对象树直接打开及跨设备同步仍待接入。[Navicat 表配置手册](https://www.navicat.com/manual/online_manual/en/navicat_18/win_manual/data_rdbms.html)

## 验证

- macOS 上 Node.js 24.17.0 运行时检查、类型检查和源码构建通过。方案专项 4 个文件、48 项测试通过，覆盖本机配置重开、连接和 schema 隔离、原始子串及精确数值、条件组、覆盖、删除、修订冲突及跨驱动令牌拒绝。
- macOS 完整单元回归共 1,326 个文件，27,457 项通过，10 项 Windows 系统 tar 用例跳过。首轮旧库夹具意外保留了新增表。修正夹具后，原 11 表逐表比对通过，并验证升级后新表为空。
- Server-200 独占 PostgreSQL 18 实库 5 项通过。应用方案读取时，服务器拒绝引用已不存在的字段，包括停用规则。成功轮次均独立核对原表数据及零连接，随后清理独占容器。
- macOS Electron 原生窗口复跑通过，共 65 项观察。方案场景覆盖保存已应用条件、保留未应用输入、恢复首页和排序、取消删除、确认覆盖与删除、翻页和后续全量导出。首轮 Electron 的确认弹窗触发协议错误，改为窗口内确认后复跑。保留首轮日志及已停止的独占容器，最终轮正常退出并清理临时配置。
- Windows 测试虚拟机不可达，本轮切换至 macOS。Windows、两平台安装包及较早 PostgreSQL 版本待验证。
