# PostgreSQL 重命名和受限删除视图

从永久普通视图的右键菜单或记录页打开「查看结构」，点击「管理视图」。此入口面向拥有视图且对目标 schema 有使用与创建权限的角色。预览读取原视图和目标目录，确认时会锁定原视图并重新核对身份、定义和属性。若预览后原视图发生变化，请刷新结构后重新操作。

- 选择「重命名视图」，填写同一 schema 内的新名称。预览会检查重名。确认后，原视图及依赖保留，客户端刷新目录并用新名称打开记录页。[PostgreSQL ALTER VIEW](https://www.postgresql.org/docs/18/sql-alterview.html)
- 选择「删除视图」，核对 `DROP VIEW … RESTRICT` 后勾选确认项。存在阻止删除的依赖时，服务器拒绝并回滚。提交确认后，客户端移除目录项并关闭对应的干净记录页。[PostgreSQL DROP VIEW](https://www.postgresql.org/docs/18/sql-dropview.html)

查询正文和收藏沿用原引用名称。重命名或删除后，旧视图链接在当前窗口停止解析。回执中断时请在原数据库核对结果。

## 验证

- macOS 上 Node.js 24.17.0 运行时检查、类型检查和源码构建通过。完整单元回归覆盖 1,326 个文件，27,451 项通过，10 项 Windows 系统 `tar` 用例按平台跳过。新增用例验证旧链接退役后，另一大小写的 PostgreSQL 视图仍能打开。
- Server-200 独占 PostgreSQL 18 实库回归 5 项通过。用带引号和点号的名称验证改名后 OID、所有者、授权、注释、选项、依赖查询及记录保留。另核对目标重名拒绝、预览零写入、令牌隔离及重放拒绝、有依赖时删除回滚、原注释变化使预览失效，以及删除后底表记录仍可读取。
- macOS Electron 原生窗口 1 项通过，覆盖 38 个观察点。实际验证改名后对象树和记录页切换、删除确认勾选门槛及提交后关闭记录页。独立连接复核两个名称均已不存在、底表原行保持。通过轮次的窗口临时配置和数据库已清理。
- WIN11-TEST 会话不可达，本轮 Windows 原生窗口和两平台安装包待验收。
