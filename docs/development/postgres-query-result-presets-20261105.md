# PostgreSQL 查询结果整理方案

在结果区点「整理方案」，输入名称并点「保存为新方案」。窗口内可预览、改名、用当前整理覆盖或删除所选方案。方案保存在本机，内容包括筛选原值、排序配置、冻结边界和字段身份。

- 同一连接重新查询后，可打开窗口选择并应用已保存的方案。应用要求完整字段与当前可见列的键、名称、类型和顺序一致。连接配置或字段身份变化时，窗口会提示，现有结果保持。
- 筛选、排序和冻结边界在完整校验后一起应用。冻结基于当前可见列，方案中的空边界会解除冻结。显隐、列宽和行高仍由当前结果布局决定。
- 应用方案后的筛选和排序可用「撤销结果整理」恢复。冻结边界通过「管理结果列」调整。预览展示保存的配置，应用只处理当前已返回的数据。

## 验证

- macOS 类型检查、源码构建和 143 项方案契约、存储、令牌及界面定向单元测试通过。Server-200 独占 PostgreSQL 18 实库回归 5 项通过。
- 完整单元复跑覆盖 1,326 个文件，27,444 项通过，10 项 Windows 系统 `tar` 用例按平台跳过。首轮 SQLite 百万行流式用例在 5 秒附近退出，清理时查询仍在执行。保留首轮结果，同一命令在其它测试结束后完整复跑，该用例约 1.1 秒通过。
- macOS Electron 源码窗口 1 项通过，覆盖 31 个观察点。通过真实本机 IPC 保存和改名，遇到字段名变化时拒绝应用，重新查询后恢复 `NaN` 筛选、升序和冻结。撤销恢复筛选和排序，再覆盖及删除方案，执行历史经过复核。
- 通过轮次正常退出，专用配置、数据库及容器已清理。WIN11-TEST 会话不可达，Windows 原生窗口和安装包待验收。
