# 从当前筛选生成 SELECT

## 使用方式

在 MySQL／MariaDB 表或视图数据页完成筛选和排序，点击工具栏的「从当前筛选生成 SELECT」。窗口展示已应用条件、停用状态和排序，支持字段勾选、搜索、50项分页与调整投影顺序。预览确认后点击「打开新查询」，再由用户明确执行。

- 使用完整已应用条件树及多列排序；筛选面板尚未添加的输入不参与生成。
- 从匹配范围的第一页开始，使用设置中的结果上限 `LIMIT`（1～100000），不带父页 `OFFSET`。需要全量文件时使用原表页的「导出全部筛选行」。
- 表页待提交值不进入 SQL。取消、打开查询和返回父页保留原页码及已暂存草稿。
- 新草稿使用相同连接和明确数据库，首次执行时建立独立会话，不继承原事务、临时表或保存文件绑定。打开草稿不会自动执行数据库查询；工作区仍按既有方式保存标签布局。

## 实现与约束

`src/shared/tableReadSql.ts` 共用原表页的筛选叶、嵌套分组及排序编译。补可靠定位键作为并列顺序；无可靠键时不伪造稳定顺序。新 SELECT 显式列出所选字段，标识符独立引用，列名中的问号、反引号不作为值占位符处理。

文字量使用与实际表页相同的 `_utf8mb4 X'…'`，数值筛选保留原始十进制字符串与显式 CAST，避免 BIGINT／DECIMAL 降为 JavaScript Number。拒绝孤立 Unicode 代理项、未知／重复字段、重复排序和超预算输入，不截断 SQL 或条件。范围为4096个投影字段、20条显式排序、完整 SQL 2MiB，原筛选30条／1000集合值／字符预算保持。

`TableFilteredSelectIntent` 绑定实际已完成读取的页、结构、完整条件、连接修订、标签及结果上限；变化后永久失效。父组件在打开前按同一字段顺序重新编译、逐字核验，单次消费并执行100标签上限。预览及编译不调用数据库、导入导出或剪贴板接口。

## 原失败及未验范围
