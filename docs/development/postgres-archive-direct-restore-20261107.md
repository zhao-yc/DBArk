# 直接恢复 PostgreSQL 自定义归档

1. 打开「工具 → PostgreSQL 自定义归档」，选择 PGDMP 文件和本机兼容的 `pg_restore`。
2. 选择「结构和数据」「仅结构」或「仅数据」。跨角色迁移可勾选「省略所有者和授权」。
3. 点「恢复 PostgreSQL 自定义归档」。核对归档名称、处理范围、连接和目标数据库，再确认恢复。
4. 恢复全部内容或仅结构时，可从维护数据库新建目标库，也可选已有库。仅数据需要先准备匹配的目标表结构，该模式只提供现有数据库。

客户端先用原生工具离线生成并核验私有暂存 SQL。准备成功后才连接目标或创建新数据库，随后沿用现有文件事务执行。归档截断、选中后被替换或准备阶段取消时，数据库执行未开始。恢复结果分别显示建库和文件事务的回执。已建库在文件事务失败后保留。

退出时沿用当前恢复任务的取消和收尾机制。转换阶段的取消会结束原生子进程，执行阶段的取消会请求原 PostgreSQL 后端停止并等待回滚回执。提交已经开始时，界面等待原任务结算。结束后清理本次创建的私有暂存文件。仅数据与仅结构的内容遵循 `pg_restore` 各自的输出范围。

若要审阅脚本或另行保存 SQL，仍可从[自定义归档窗口导出](postgres-custom-archive-20261107.md)。

暂存 SQL 使用本机临时目录，可用空间需容纳展开后的 SQL。格式和大小边界沿用归档 SQL 导出及文件执行工具。

## 2026-11-07 验收

- Windows 测试会话不可达，使用 macOS arm64 源码 Electron。数据库为 `server-200` 上的隔离 PostgreSQL 18.6，使用本机官方源码构建的 `pg_dump` 和 `pg_restore` 18.6。
- 从归档窗口直接恢复到新库，确认创建数据库并提交 63 条语句。比对 84 行记录的摘要、标识序列、物化视图和大对象。关闭恢复窗口可回到原归档选择和目录。
- 仅结构恢复到空库后核对表为空。再选择仅数据恢复到已有库，在真实 COPY 等待期间取消并确认回滚，记录仍为零。解除等待条件后重试，数据摘要、序列及大对象与源库相符。
- 截断归档在离线准备时报错，数据库执行未开始，目标数据库未创建。独立导出 SQL 后恢复、SSH 与 TLS 整库备份及纯文本备份路径一并回归。
- 用可控子进程夹具保持转换准备阶段，点击取消后确认该子进程退出，目标库未创建。
- 类型检查、构建、33 项定向单测和 4 项 Electron 实库测试通过。测试结束后确认残留数据库会话、临时认证目录及恢复 SQL 目录为零，隔离容器和回环转发已清理。
- 定稿全量 Vitest 共 1,356 个测试文件通过，27,620 项通过，10 项按环境条件跳过。
- Windows、安装包、其他 PostgreSQL 主版本及 10 GiB 边界仍待验证。
