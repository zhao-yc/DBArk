# SQLite 查询结果临时整理

## 使用

SQLite 查询结果的“更多结果操作 → 结果整理”现支持“暂存整理”“应用暂存整理”和“丢弃暂存整理”。每个查询标签只保留一份内存配置，包含完整筛选、多列排序、冻结边界和字段身份，不保存结果行、SQL 或原逐格类型代码。

暂存不改变当前视图、历史或勾选。重新查询后保持新原结果，明确点击“应用暂存整理”才在新行上试算筛选和排序；两者均成功后一次发布，并记一整步撤销／重做。原选择随视图变更撤销，不复活旧勾选。冻结范围沿原列管理规则调整，不宣称整理撤销同时撤销冻结。

完整字段、类型和可见顺序不匹配时禁用应用。SQLite 条件保留显式存储类型，沿新结果的实际逐格代码匹配，不从显示文字猜测；精确整数、BLOB 与 NULL 保持。未知类型、无效新值或超预算拒绝整次试算，保留新原视图及原暂存；空匹配保持空集。

后续执行失败或无列结果时仍可主动丢弃暂存。修改连接配置或关闭标签清除内存配置，原回调不能修改新代次。只在当前标签操作已返回行，不重发 SQL、不修改事务、不落本机配置；需要跨重启保存可使用命名“整理方案”。复用原业务处理器与保护，没有新增 IPC、驱动或存储结构。

## 验证

WIN11-TEST 本轮不可达且未派发，按既有授权回退本机：

- 类型、构建及 60 份 1728 项相关测试通过，原 MySQL 结果页、类型筛选、排序、历史、方案与快照回归保持。新增 5 个核心用例覆盖配置独立冻结、字段重排、新行与类型代码、精确整数、字节、REAL 空匹配及坏／缺失类型拒绝。
- 新增 4 个真实 React QueryTab RAM 用例使用 SQLite 连接分支，验证重新查询后不自动应用、新行排序与引用、类型条件审阅、整步撤销／重做、失败／无列结果丢弃、字段变化与连接变代。RAM 执行响应与系统／数据库调用边界保持明确；原 MySQL 用例默认入口不变。原 React act 及构建警告保留。
- Windows 原工作区整例 38.3 秒通过，实际菜单暂存真实 TEXT 条件与 BLOB 排序，明确应用和整步撤销／重做；执行原事务 INSERT 的无列结果后，应用暂存禁用而丢弃仍可操作，事务回滚和后续快照／重启断言继续通过。原生没有额外发送第五次 SQL；“重新查询后新原行”的专项覆盖见上述 RAM 用例。
- 与命名方案版原始回执独立对照，两个 owner 的数据库命令序列完全相同，仍为四次 SQL、worker 为 6／2，拒绝数组为空。两个准确 owner 正常退出 0，进程与本例临时目录独立核零，系统剪贴板操作为 0。

原日志、退出码、完整 JSON 和审计保留于忽略目录 `.cache/sqlite-result-memory-20261102/`。原 120 秒、单 worker、零重试、失败保留及资源保护保持；不使用 Server-200、真实数据或已安装客户端配置，不创建 Release。
