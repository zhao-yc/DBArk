# SQLite 当前单元格区域粘贴

开发源码新增从准确当前单元格开始的矩形覆盖。只改本地草稿，一次暂存对应一步撤销／重做，数据库写入仍走原集中预览及确认提交，不新增 IPC 或 SQL 执行路径。SQLite 仍部分完成，暂不发布。

## 使用方式

1. 在读写表页点击一个可写数据格，再按 Ctrl+V／Cmd+V；也可以从“更多 → 数据传输 → 覆盖当前单元格区域…”打开空输入窗口后粘贴或手工输入 TSV。
2. 核对准确起点、目标行列及前十行的原草稿值／粘贴后值。范围由输入矩形决定，按当前位置逐格覆盖；来源列名只作提示，不重排目标列。
3. 可逐来源列选择保留绑定类型或显式转换。普通文本不猜数字、NULL、日期或表头；目标 SQLite 亲和性和约束仍会影响最终存储。
4. 明确暂存后检查本地修改计数，可一次撤销／重做；再经原“预览 SQLite 修改”确认 SQL 和提交。原修改及未受影响的字段保留。

没有准确数据格、越界、待删除行、生成列、损坏格式或任何一个值无效时整批拒绝，不跳格、不换行补位、不自动新增。已有记录不接受 DEFAULT；本地新增草稿可以使用 DEFAULT 清除该字段输入，继续省略并采用数据库默认值，NULL 始终是明确值。

“粘贴为新增草稿”保留为独立菜单，在其弹窗内粘贴并映射字段。网格 Ctrl+V 现在采用区域覆盖语义；原新增功能及验收业务断言保留，测试入口改走真实新增菜单，不保留隐藏兼容入口。

## 正确性与来源保护

- 输入最多500行／10,000逻辑格／2MiB UTF-8，单值65,536个UTF-16单位；DEFAULT也占逻辑格。实际编辑器还以最终差异核原500项修改／10,000字段／2MiB输入门，覆盖回原值可减少既有修改，不能简单累加行数误拒。
- int64以准确十进制文本、BLOB以字节、TEXT以原文及NULL独立保留；新REAL只接受有限值。未触及的生成列和原非有限REAL不被重写。
- 先完整校验后一次替换有变化的行；失败保原行、撤销／重做和旧预览。完全同值粘贴不制造撤销步骤，对象属性顺序不同不算值变化。
- 起点来自真实RDG数据格，不能借行头、复选框或同ID克隆行推测。原页、整批rows、实际row对象、列及元数据参与计划绑定；变更后旧窗口和回调留失效标记，不随新焦点改写目标。
- 模态自有输入仍受退出保护；成功暂存后只关闭本窗口占用，不清除其它草稿。复制、输入、局部预览和暂存不写数据库，提交未知不自动重放。
