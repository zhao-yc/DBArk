# SQLite 原生驱动基础

后续补齐[原查询会话合同适配](sqlite-query-session-20261031.md)，并将 ATTACH／DETACH 的文件能力限制扩展到读写连接；用户界面仍未开放。下文保留最初基础轮次的证据，不与后续结果合并成客户端已支持。

## 本轮范围

新增 `src/engine/sqlite/` 原生文件驱动、Main 的准确进程账本及独立构建入口。每个物理连接使用一个 utility process，采用 Electron 内置 `node:sqlite`；用户数据库不经过配置库的 sql.js，也不整库载入内存。

本轮没有开放 SQLite 连接表单、IPC、对象树或查询页。R02 仍待接入，不能据此宣称客户端已支持 SQLite。MySQL/MariaDB 的现有执行协议及配置格式保持原样。

## 执行和数据边界

- 只接受现存绝对普通文件；真实路径与文件身份复核，URI `mode=rw/ro` 阻止缺文件时自动创建。文件选择授权、可信路径能力、创建新库及导入配置迁移留给 Main 接入阶段。
- INTEGER 使用有符号 64 位字符串；REAL、TEXT、NULL、BLOB 分开编码，重复列名按数组位置保留。原生 `sourceSQL` 分句，支持触发器体、引号及注释；带参数请求仅允许一条语句。
- 每个结果头和数据批次都等待 ACK。单语句默认最多返回 1000 行，单次执行行数据默认总预算 32 MiB，批次默认 200 行；有明确硬上限。达到传输上限后继续 drain 原语句，不能将 `RETURNING` 截断传输误作部分写入成功。
- 首错停止，已完成语句数量保留；事务位来自原生连接，不自动回滚、不重连或重放。变更量采用 `total_changes()` 差值，含触发器，不等同于主表匹配行数。
- 所有连接在原生 authorizer 中仅放行明确只读 PRAGMA。部分 PRAGMA 会在 `prepare()` 阶段生效，不能等参数多句校验或消费者 ACK 后才控制副作用；写入 PRAGMA 暂不支持。[SQLite 官方说明](https://www.sqlite.org/pragma.html)
- 只读模式另拒绝 TEMP 写入和 ATTACH，防止通过其它文件绕过边界。扩展加载关闭，外键开启。错误保留原生整数码，对外不回传可能包含 SQL、路径和参数的原始正文。

## 取消与进程回收

分批迭代时协作取消，保留实际事务状态；同步原生长调用不响应时，250 ms 后终止 Main 持有的准确进程对象，并等待真实 exit。此时明确报告会话关闭、事务／写入结果未知，后续须独立核对文件，不能伪造 ROLLBACK 成功。

取消的原生终态与消费者回调分开等待，避免回调内部取消的等待环。新任务和普通关闭仍须等待原消费者结束。正常关闭使用 `closed → closeAck → exit` 握手。退出未确认时保留句柄并报错，不能返回资源已释放；Main 账本也仅在真实 exit 后移除记录。

WIN11-TEST 不可达且本轮未派发新任务，按既有授权回退本机 Windows。最新相关单元 10 文件 106 项通过，其中 SQLite 21 项：真实磁盘／Node 子进程 13 项，以及父端生命周期 5 项、账本 3 项。覆盖 DELETE/WAL 中断恢复、WAL 锁等待及读者隔离、外键／PRAGMA 前置保护、精度、分批背压、事务、只读和缺文件。

最终 `pnpm build`（含完整严格类型检查）退出 0，保留原有大包及依赖注释告警。真实 Electron 44.7.0／Node 24.21.0／SQLite 3.53.4 的 Windows x64 utility 探针退出 0；分别在 DELETE 和 WAL 文件验证精度、PRAGMA 拒绝后外键仍开启、正常关闭握手、阻塞聚合的准确进程取消、独立重开零未提交行及完整性 `ok`。四个准确 utility 句柄均取得 exit，账本为 0；通过实际窗口创建事件计数确认未创建业务窗口。

最终 worker SHA-256：`bb85cbd1aeca28af7a18a52a5d72132153d51508db46fb6464bff8e76230eec6`。注意 Electron 被准确 kill 的进程也可能给出退出码 0，因此依据取消路径和真实 exit 证明回收，不能据该码宣称正常关闭或回滚成功。

尚未验证 macOS、安装包、网络文件系统、加密 SQLite、百万行工作台、用户文件选择或现有查询 UI。Main 退出流程、连接配置、方言能力、元数据与表格编辑接入仍未完成；脚本错误后的前序完整结果展示也需随适配补齐。暂不发布。
