# SQLite 文本首尾与排除筛选（开发源码）

表／视图的“筛选与排序”新增“不包含文本、开头是、开头不是、结尾是、结尾不是”，与原“包含文本”组成六种原文匹配。条件自动使用TEXT类型；修改、启停和载入方案都只改表单，明确“应用”后才从第一页读取。读写连接的筛选继续沿原只读独立页，不提交或丢弃记录草稿。

## 匹配边界

- 区分大小写，不做Unicode规范化；`%`、`_`、引号及反斜杠均是原文。TEXT以外的INTEGER、REAL、BLOB及NULL不参与，排除条件也不会将它们纳入。
- 空文本匹配所有TEXT，三个排除条件不匹配记录；首尾匹配保留空格、换行、NUL、中文和辅助平面字符。不使用SQLite遇NUL会截断的TEXT长度计算后缀。
- 后缀沿同一物理连接的数据库编码比较完整字节；显式恢复空BLOB子串的空字节语义。原生实证覆盖UTF-8、UTF-16LE与UTF-16BE，并与独立JS原文谓词逐行比对。
- 分页、完整流式导出和生成SELECT使用同一读取构造器，值仍用typed绑定；字面查询保留原文本转义。后缀的两次值绑定计入原1024参数门，不提高行、值或结果预算。
- 命名方案保留运算符、原文和停用标记，沿原文档版本和CAS保存；旧条件继续兼容。没有新增IPC、数据库写入协议或凭据配置。
