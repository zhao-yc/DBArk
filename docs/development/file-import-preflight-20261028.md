# CSV／JSON整文件导入预检

导入窗口在原前20条映射预览之外提供“校验整份文件”。选择CSV或JSON文件、确认编码和字段映射后显式启动；预检不导入数据，通过后仍需单独点击“开始导入”。当前报告有错误或未完成扫描时，导入入口拒绝执行；修改文件、解释方式、映射、连接或提交方式后旧报告失效。冲突键目录回包仅更新匹配选项，不撤销同一文件与映射的类型预检。

## 检查范围

- 流式扫描全部数据记录，使用正式导入的无损类型及参数校验；记录号从1开始，不含CSV标题，带换行的引号字段仍属一条记录。
- 汇总已检查、有效和异常记录以及错误总数；继续扫描超过预算的错误，只保留前200条明细，每页20条。
- 解析失败只标记已完成范围，不能可靠确认的失败记录不伪造编号。
- 同一字节读取链计算完整SHA256，比较前后文件身份与字段定义。文件或字段变化使结果失效；此指纹不是执行令牌，也不提供跨服务器对象的原子快照保证。
- 仅检查已映射字段。未映射字段、默认值、唯一键、外键、CHECK、触发器、匹配策略和服务器实时约束仍在正式导入时核验。

## 任务与报告

`files.preflight`通过严格IPC参数和导入用途、格式一致的文件令牌进入独立utility任务。仅读取目录及文件，不读取目标记录，不建立事务，不执行DML，不借用查询标签会话。取消、连接关闭及退出保留原任务占用，等文件和连接真实收尾后释放。

“导出预检报告JSON”复用现有文件保存及结果导出通道。数组首项为汇总，其后为最多200条错误明细；包含检查范围、完整性、截断状态及指纹。原字段值、源文件路径、令牌及SQL不进入报告，任务持久概要只使用固定文案。用户明确保存的报告包含所选目标及映射字段名。

## 验证边界

新增核心真实文件、Engine调度、Main生产分支、控制器和真实React表单测试。RAM端口替身只证明相应生命周期和调度行为，不代替真实数据库或系统文件框验收。当前由WIN11-TEST执行冻结快照的类型、定向测试及构建；最终结果另记。暂不发布。

首轮源码快照类型、56项定向及构建通过。审查后补入来源变化的取消和同步修订保护；第二轮类型通过，但6项表单回归失败，发现控制器持有首次挂载的活动回调，使选文件后的正常预检被旧修订号拒绝。原失败和未启动的后续门单独保留。第三轮改为获取使用最新守卫、释放配对原获取方，并新增真实React生命周期回归；不改旧断言或原超时。

第三轮类型和60项定向通过，完整回归19,608通过、4失败、1平台跳过；后续门未启动。已补旧退出RAM夹具遗漏的真实生产取消函数；另外三项原件仅给出`STACK_TRACE_ERROR`，耗时分别8,653／5,121／5,063毫秒，成因不能仅据此认定。第四轮保持产品源码，复验原六文件及三个失败文件，使用单worker与可读／JSON双报告，原超时不变；后继门和最终完整回归另记。

第四至六轮定向均在原排序套件的两条用例触发原5秒期限；内存DOM与同步`act`试验未解决，已撤回。第七轮保留产品静态选项渲染修复，恢复原测试助手与断言：类型检查通过，定向87项通过；排序套件的10秒初始化hook失败，其233项未执行，整体320项未通过。不能据此判断选项渲染修复已生效，也不能以零用例失败代替套件通过。Root已回读原日志、退出码、完整报告、ZIP及2844文件身份。

整文件预检的独立引擎验证使用同一第七轮源码；其入口只复用已核实的60项预检测试及类型结果，不追认上述320项或完整回归通过。当前功能候选未提交发布，后续分层结果见下文。

六个既有隔离实例的真实Engine专项现已18项通过、无跳过；Root已独立核原报告、日志、退出码和资源收尾，18个owner库、84个登记线程及36条文件流闭合。严格TLS实例保持证书与主机名校验。同一Source07首次完整回归19612项通过、1项POSIX平台跳过、0失败，正式窗口仍待验，详见[分层验收记录](../testing/file-import-preflight-20261028.md)。

[正式窗口复合用例](../../tests/e2e/file-import-preflight.spec.ts)已在WIN11-TEST／13384单次通过：从表页打开导入，检查第22条之后的错误、坏报告阻止导入、真实JSON文件独立解析、换源撤销旧报告，以及重新明确预检后的两条精确原子导入。默认双门关闭，列表不读实库凭据；文件框使用准确一次API回答，不代表系统键鼠输入已验。预检短连接的逐物理线程账仍单独引用Engine专项，窗口用例不冒称完整线程登记。Source14类型、列表及默认关闭门先通过，随后正式窗口1项通过并核资源清零，详见[分层验收](../testing/file-import-preflight-20261028.md)。

正式执行前补强测试失败路径：主流程失败后不再尝试正常退出、清库或删除文件；保留原窗口与资源记录，只结束本例独立观察连接以释放自身锁，不重放导入、不强停。成功路径仍须完成原owner核验及精确清理。该调整只修改测试用例，不改变产品。
