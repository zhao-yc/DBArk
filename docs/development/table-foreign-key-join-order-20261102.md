# 外键 JOIN：双侧多列排序与查询上限

## 使用方式

MySQL／MariaDB 普通表的“按外键生成 JOIN 查询”仍按一条真实出向外键、完整复合映射生成 LEFT／INNER 查询。明确预览父表结构后，可添加双方字段的多列排序，调整方向、优先级及 NULL 在前／在后／数据库默认位置；同名字段按“子表 c／父表 p”区分，未输出字段也能排序。

每侧同一字段只能出现一次，最多 20 项。清空排序后不追加主键或猜测稳定顺序；同值之间的顺序仍由数据库决定。切换外键明确清空排序，同一关系重读保持本地选择和优先级。

“JOIN 结果行数上限”接受 1～100000 的完整十进制整数。未完成输入保持原文并撤销可打开预览，不默认为 0、不截断或转换科学计数法。恢复原上限和空排序时，生成旧版 SQL 字节。只改变新查询草稿，不写入全局偏好；实际执行仍受工作区结果上限约束。

本窗口不继承原表页的筛选、排序、分页或未提交数据。仍先完整预览，再明确打开同连接独立查询，不自动执行 SQL。WHERE、分组／聚合及任意多表构建继续开发，不把本增量记为完整 O04。

## 来源和编译保护

排序仅接受结构化的双方身份、真实列名、方向及 NULL 位置。标识符逐段引用，NULL 位置生成独立分桶表达式，不把 BIGINT／DECIMAL 或二进制列转成 JavaScript 数字或文本。

元数据、20 项排序、输出字段及 256KiB SQL 预算继续生效；未知属性、重复、空洞、访问器及不可枚举数据拒绝，不在克隆时丢失显式选项。预览冻结排序和上限，打开前串行重读双方目录可见的相关结构，再按全部选项重算同一条 SQL，原意图只能消费一次。这不是 DDL／数据快照或排序规则锁；SQL 执行时使用服务器当前列规则。忙态、关闭、来源变化、连接 ABA 和旧条目回调沿原保护；不增加 IPC、数据库写入或配置格式。
