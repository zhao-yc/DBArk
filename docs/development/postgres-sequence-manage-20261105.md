# PostgreSQL 序列编辑、重命名与删除

从对象树或「其他 → 序列」打开详情。拥有序列管理权限的角色可以编辑参数、在原 schema 内重命名，或受限删除。操作先展示完整 SQL，再等待确认。提交成功后，对象树和序列列表会刷新。重命名后自动打开新名称的详情。

「编辑序列参数」预填当前整数类型、起始值、增量、上下限、缓存、循环和注释。数字按精确的 64 位整数处理。更改起始值只更新未来默认重启用的参数。填写「下次取号值」会在本次事务中重启序列，须额外确认，可能重新发出已有编号。[PostgreSQL ALTER SEQUENCE](https://www.postgresql.org/docs/18/sql-altersequence.html)

「删除序列」需要单独确认。PostgreSQL 以 `DROP SEQUENCE … RESTRICT` 检查依赖。标识列序列的删除通过所属字段管理。[PostgreSQL DROP SEQUENCE](https://www.postgresql.org/docs/18/sql-dropsequence.html)

预览阶段只读目录。SQL 首行以当前所有者取得序列排他锁，然后核对 OID、目录版本、权限、所属字段和参数。业务正常取号不会使配置预览失效。确认前若序列被同名替换或其配置改变，事务回滚，需刷新详情后重新预览。提交结果未知时，关闭窗口后在原数据库核对结果。

## 验证

- macOS 上 Node.js 24.17.0 运行时检查、类型检查及源码构建通过。
- macOS 完整单元回归共 1,326 个文件，27,451 项通过，10 项 Windows 系统 tar 用例跳过。
- Server-200 独占 PostgreSQL 18 实库回归 5 项通过。核对参数编辑保留已分配值、精确重启后实际取号、注释清除、同名冲突、标识列保留所属字段及其删除保护、普通依赖拒绝删除、授权检查、外部修改与同名替换后回滚、令牌禁止重放。
- 首轮遇到新增测试变量重名，已修正。首次运行管理 SQL 时，服务器拒绝不带选项的 `ALTER SEQUENCE`。改用同所有者语句后，直接核对普通序列与标识列序列的目录版本均保持原值，并确认持有 `AccessExclusiveLock`。
- 首次原生测试发现预填注释框缺少稳定的无障碍名称。补充显式标签后，macOS 原生场景复跑通过，共 48 项观察。核对重启和删除的额外确认，以及重命名后详情、对象树和序列列表的刷新。
- 独立回读确认记录起始值为 `9223372036854775803`，下次取号值为 `9223372036854775804`，`is_called` 为 `false`。原名称及已删除序列均已从目录移除。原表数据、零剩余连接、临时配置与独占容器清理均已核对。
- Windows 虚拟机连接不可用，本轮改在 macOS 验证。Windows、两平台安装包和较早 PostgreSQL 版本待验证。
