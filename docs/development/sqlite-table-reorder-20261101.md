# SQLite 实际列顺序调整

开发源码在现有字段重建窗口增加实际列重排。列上移／下移会形成数据库结构修改草稿；只有完整 SQL 预览、风险确认及准确表名确认后，才在独立事务中重建原表。它不会更改原查询标签的 SQL，也不会自动重放未知写入。

## 使用方式

1. 在普通 main 表的右键菜单或表页“设计与结构”打开“修改 SQLite 字段类型与默认值…”，明确读取重建目录。
2. 在“SQLite 实际字段顺序”移动字段，可包含生成列；支持恢复原顺序，并保留同时编辑的类型及默认值草稿。
3. 核对原／目标字段位置和完整重建 SQL。仅顺序变化也可单独预览；恢复原序且没有其它修改时不发送空设计。
4. 除原数据、依赖及空间三项确认外，重排还需单独确认 `SELECT *` 和未列字段名 `INSERT` 的位置依赖；输入完整 `main.表名` 后提交。

## 数据和结构保护

- 完整准确列名排列包含生成列；重复、少列、多列、大小写猜测和原序请求不能获得重排能力。
- 移动原声明的完整跨度，保留注释、表达式、默认值及表级约束；复制始终显式列名，不按旧物理位置猜新位置。
- Main 与独立运行时重算同一计划；实际候选列顺序必须等于获准排列，全部原值、字节、生成列和真实行身份继续逐值核对。
- 字段位置变化会改变列号、索引列号和部分外键编号；仅对本次授权重排按真实列名／完整约束语义核对，原无重排路径保旧门槛。序列、索引、触发器、外键及其它对象仍需后核。
- 重排会改变 `SELECT *` 结果列次序和未列字段名的 `INSERT` 值位置。外部应用、视图及触发器须核对这些依赖，不能将“定义原文保持”理解为所有位置语义不变。
- 失败整批回滚；确认事实、取消收尾、过期能力、连接变更、模态、草稿保护和未知结果沿用原流程。
