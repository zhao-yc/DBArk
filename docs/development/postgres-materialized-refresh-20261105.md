# PostgreSQL 物化视图刷新

右键点击物化视图或从记录页打开「查看结构」。结构页显示当前填充状态。有刷新权限时，可选择「刷新物化视图」，核对 SQL 后确认。

- 普通刷新执行定义查询并填充数据，可用于首次填充。刷新期间，其他会话的读取可能等待。
- 并发刷新允许其他会话继续读取。此模式要求物化视图已填充，且具有有效、非部分、基于普通列的唯一索引。
- 清除填充数据使用 `WITH NO DATA`，需另行勾选确认。清除后，记录页提示先刷新再查询。

PostgreSQL 17 及以上支持委派 `MAINTAIN` 权限，旧版本沿用视图所有者的权限规则。客户端在确认时仅解析一条目标查询以保留共享锁，核对原视图身份和刷新资格，再执行事务内的原生刷新。刷新语句使用 120 秒上限，锁等待使用 5 秒上限。确认提交后刷新结构和对应记录页。[PostgreSQL 18 刷新说明](https://www.postgresql.org/docs/18/sql-refreshmaterializedview.html) · [PostgreSQL 16 刷新说明](https://www.postgresql.org/docs/16/sql-refreshmaterializedview.html)

## 验证

- macOS 上 Node.js 24.17.0 运行时检查、类型检查和源码构建通过。完整单元回归覆盖 1,326 个文件，27,451 项通过，10 项 Windows 系统 `tar` 用例按平台跳过。
- Server-200 独占 PostgreSQL 18 实库回归 5 项通过。覆盖无数据视图首次填充、拒绝表达式与部分唯一索引、三种刷新方式、保持 OID、预览零写入及令牌隔离和重放拒绝。
- 独立事务核对普通刷新申请排他锁前已持有目标共享锁；另一读取会话仍持共享锁时，并发刷新成功且读到新数据。委派角色仅获 schema 使用和物化视图 `MAINTAIN`，实际完成刷新，撤回权限后结构读取被拒绝。原视图被替换后，预览令牌拒绝执行，替换对象的定义序列未推进。
- macOS Electron 原生窗口 1 项通过，覆盖 39 个观察点。首轮 Playwright 对下拉选项的通用禁用断言误判，改为检查选项原生属性后完整复跑通过。复验三种刷新方式、清除前额外勾选及已打开记录页联动。独立连接确认最终未填充且底表原记录可读，通过轮次的窗口临时配置与数据库已清理，失败轮次的独占容器已停止并保留诊断数据。
- WIN11-TEST 会话不可达。本轮 Windows 原生窗口、两平台安装包及 PostgreSQL 旧版本实库待验收。
