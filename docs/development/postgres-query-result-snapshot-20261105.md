# PostgreSQL 查询结果快照文件

在 PostgreSQL 查询页点击「保存结果快照」，选择文件位置。可以保存本次结果或正在查看的固定结果。第三版快照保留完整已返回行列、命令标签、来源 SQL 和截断标记，筛选、排序与列显示属于当前视图。

- 在 PostgreSQL 查询页点「打开结果快照」，选择第三版文件，系统会将其加入固定列表并切换到新快照。可继续筛选、排序、查看来源 SQL、导出及对比。
- 全局快照查看器可打开第三版及现有第一、二版文件。PostgreSQL 标签只接纳第三版，其他查询标签使用其原有格式。文件内容由客户端本地校验与加载，打开操作无需连接数据库。
- 文件未加密，包含原数据与 SQL。文件上限为 16 MiB，打开后还受当前标签最多五份、合计 16 MiB 的固定结果预算限制。若撤销文件回包，客户端仍会等待原文件操作收尾。

## 验证

- macOS 类型检查和源码构建通过。111 项快照格式、文件、主进程及查看器定向单元测试通过。Server-200 独占 PostgreSQL 18 实库回归 5 项通过。
- 完整单元回归覆盖 1,326 个文件，27,450 项通过，10 项 Windows 系统 `tar` 用例按平台跳过。
- macOS Electron 原生窗口最终通过 1 项，覆盖 34 个观察点。应用实际保存第三版文件，独立回读核对 `SELECT` 命令标签、影响行数、精确 NUMERIC 和 BYTEA。窗口拒绝第一版文件后打开已保存结果，并将其与另一份 PostgreSQL 快照对比。原事务和执行历史经过复核。
- 首轮原生回归发现独立工具栏占用计划视口，按钮并入现有查询工具栏后，原计划视口断言通过。后续将测试预期由单一 `SELECT 3` 修正为应用实际返回的 `SELECT` 和行数 `3`，完整复验通过。失败容器已停止并保留诊断，通过轮次正常退出并清理独占资源。
- 文件选择器使用测试桩提供专用路径，实际读写走应用主进程。WIN11-TEST 会话不可达，Windows 原生窗口和安装包待验收。
