# 按列位置导入 XML 文档

在 MySQL、MariaDB、PostgreSQL 或 SQLite 的现有表导入窗口，或「从文件导入新表」向导，选择 XML。将「XML 布局」设为「XML 文档（按列位置）」，填写要导入的行结果序号。序号从 1 开始，按 `result` 元素出现顺序计算。执行回执不占序号，空结果仍占一个序号。若原导出已截断，只能读回文件实际保存的行。

导入使用 UTF-8 的 tabrelio v1 XML 文档，列按文件中的位置与单元格对应。有效的唯一列名保留原样。重名列附加位置标识，空名、超长或无法直接映射的列名使用位置名称。若位置名称与原列名冲突，向导会生成不同的名称。核对字段映射后再确认写入。导入新表仍须分别确认建表和数据写入。

显式 NULL 和空文本分开。二进制值使用文档记录的类型，目标列须是对应的二进制类型。SQLite 映射请选择 Base64 二进制。大整数和小数文本保持原样，目标数据库按所选字段类型处理。可恢复 UTF-16LE Base64 表达的控制字符，实际写入须满足目标数据库的文本约束。孤立代理码元会被拒绝，避免替换字符入库。

全文件结构检查覆盖其它结果和汇总。找不到所选结果、列数不符、单元格类型或 Base64 无效、汇总记录数不符时停止导入。沿用原有 XML 导入的文件大小上限和整文件事务。导出文档契约见 [XML 数据导出](data-xml-export-20261107.md)。

## 验收

macOS arm64 使用 Node.js 24.17.0，通过运行时检查、严格类型检查、构建及 399 项定向单测。最终构建共通过 10 项 Electron 用例和 1 项 PostgreSQL 实库集成用例。SQLite 现有表核对了第二组结果、64 位整数、BLOB 和 NUL 文本。PostgreSQL 18.6 现有表核对了重名列独立映射、精确小数及二进制。MySQL 8.4.11 和 MariaDB 11.4.13 分别从第二组结果建表，核对无符号 64 位整数、BLOB、空文本和 NULL。原有记录布局、CSV／JSON 导入及事务回滚随相关用例复验。

Server-200 隔离容器和回环转发已清理。Windows 虚拟机测试会话本轮不可达，Windows 原生和安装包验收待执行。
