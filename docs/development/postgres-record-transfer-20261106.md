# PostgreSQL 跨库复制记录

先处理源页已有草稿。在 PostgreSQL 表或视图的网格勾选当前页记录，点击「暂存勾选记录以跨库复制」。暂存使用已读到的可见字段原值。窗口内保留一批暂存，重新暂存会替换旧批次，也可主动清除。上限为 100 行、200 个可见源字段和 1 MiB。

打开另一张 PostgreSQL 可写表，可以切换数据库或连接。点「从另一张表复制记录」后，核对来源和目标的连接、数据库与表名。同名同类型字段自动匹配，可删除映射并为不同名字段手动选择来源。BYTEA 只与 BYTEA 映射。生成列由数据库计算，带序列默认值的字段默认留空，未映射列使用目标表默认值。必填且无默认值的目标字段须显式映射。

「加入草稿」只生成目标表新增草稿并消费暂存。取消映射保留暂存供再次打开。暂存仅在当前窗口内存，不经过系统剪贴板。草稿仍需使用目标表的记录修改预览，再确认提交。数值以协议原文传递，保留 SQL NULL、空字符串和原字节。目标数据库校验类型及约束。

## 验证记录

- macOS arm64、Node.js 24.17.0 的原生运行时检查、类型检查和构建通过。定向单测 7 项通过。完整单测覆盖 1,346 个文件，27,536 项通过，10 项 Windows 条件测试跳过。
- Server-200 上的 PostgreSQL 18 隔离回归通过 5 个文件、7 项测试。Electron 专项另用同一连接下的两个独占数据库。只读源视图有 3 行，勾选其中 2 行。取消、加入草稿及预览时独立读回目标仍为空，确认后准确写入两条，源视图仍有 3 行。
- 读回核对了手动字段映射、超出 JavaScript 安全整数范围的目标序列、高精度小数、BYTEA 原字节、零字节、SQL NULL、空字符串及生成字段。窗口正常退出，两个库均核对零连接后清理。
- 首轮窗口测试的视图定位超时，第二轮发现映射下拉框的可访问名称不明确。修正后复跑通过，两轮失败现场保留。一次 Vite 重建在 2 GiB 堆预算下耗尽，使用 4 GiB 临时预算后构建通过。
- WIN11-TEST 连接不可用，本轮回退 macOS。不同连接组合、Windows、安装包及其他 PostgreSQL 版本待验。
