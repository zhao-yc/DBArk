# SQLite 本机筛选／排序方案（开发源码）

表或视图的“筛选与排序”中打开“SQLite 筛选方案”，填写名称后保存当前条件。选择已保存项，点击“载入”回填条件、AND／OR、多列排序及每页条数；检查后点击原“应用”才重新读取。载入不更改已应用条件、网格原页、选择或未提交的增改删草稿，原放弃修改确认继续生效。

## 范围与约束

- 按原连接、`main` 和准确对象名隔离；不依赖左树当前选择。同名保存拒绝，覆盖和删除须选中准确方案并确认；不支持隐式覆盖、重命名或跨连接导入。
- 保留精确 INTEGER／REAL 原文、文本空值及换行／NUL、BLOB、NULL 条件、范围、列表、启停标记和排序优先级。不保存页偏移、数据库行、SQL、文件路径或写入令牌。
- 方案包含用户填写的筛选值，仅存本机配置库；没有单独加密筛选值，勿以此保存秘密。凭据仍走原 `safeStorage` 流程。
- 新增可选 schema9 元数据表 `table_presets_sqlite`，与 MySQL 方案隔离，保留旧配置兼容。删除最后一项仍保存修订墓碑；删除连接清理本连接方案，启动清理旧客户端留下的孤立记录。
- 每目标最多20项，全库最多500个目标、500项及8MiB，单项最多1MiB。条件沿用原32条、8列排序、每列表128项、原值总量及1024个参数门槛。损坏或未知版本在迁移写盘前拒绝，不静默重写。

## 来源与并发保护

四条受限 IPC 只操作配置库，不创建查询会话、事务、任务、utility 或目标文件授权。Main 从真实窗口／主文档捕获来源，令牌绑定准确连接及对象、连接修订和配置摘要，10分钟失效，最多256个；导航与销毁撤销旧令牌。保存和删除在原子持久化事务内核对所见修订，冲突要求刷新，失败还原内存与原文件。

连接路径、读写模式等配置改变后，旧来源不能载入；刷新后须明确重新保存或覆盖才能重新绑定。字段缺失（包括停用条件）整份拒绝。载入等待期间修改表单后又改回，旧回包仍拒绝；换页、换连接、忙态和卸载不能交付旧结果。已落盘后若发布检查失效，明确提示“已保存，请刷新核对”，不自动重试。
