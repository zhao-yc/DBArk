# PostgreSQL 文件按键导入

在有写入权限的 PostgreSQL 普通表或分区表打开「导入数据」。选择 CSV、JSON 或 XML，并核对字段映射。「冲突处理」默认只新增。若需要匹配现有数据，先选策略，再明确选择完整匹配键。

| 策略 | 匹配到记录 | 未匹配到记录 |
| --- | --- | --- |
| 跳过已有，仅新增 | 跳过 | 新增 |
| 新增或更新 | 更新已映射的可更新列 | 新增 |
| 仅更新已有 | 更新已映射的可更新列 | 跳过 |

匹配键可以是主键、唯一约束或独立唯一索引，支持复合键。只列出所有键列均为非空、使用默认比较规则且立即生效的完整唯一索引。部分索引、表达式索引、可延迟唯一约束及未列入白名单的键类型不参与。匹配键、主键、序列默认列和生成列保留原值。更换文件或映射后需重新选择策略及键。

JSON 或 XML 的单条记录缺少已映射字段时，该字段按导入规则写入 NULL。希望保留目标值的字段可跳过映射。原生 CSV 沿用完整列映射和原有 NULL 规则。

按键模式需要 `SELECT`、`INSERT`、`UPDATE` 表权限，以及数据库 `TEMP` 权限。启用用户触发器或存在更新时会级联修改引用行的外键时，界面不提供按键模式。原追加入口保持可用。

执行先在事务临时表中读取完整文件并验证非空、唯一源键。随后以目标写锁复核结构与索引，再按键执行。其它唯一约束或类型检查失败时，整批数据回滚。PostgreSQL 序列可能因回滚出现编号间隙。回执在提交确认后分别显示新增、匹配更新、跳过已有和跳过未匹配的行数。匹配更新包含值未变化的行。[PostgreSQL 表锁](https://www.postgresql.org/docs/current/explicit-locking.html)

## 验收

macOS arm64 使用 Node.js 24.17.0，通过运行时检查、严格类型检查、构建及 517 项定向单测。Electron 连接 Server-200 的隔离 PostgreSQL 18.6，五项端到端测试通过。按键用例核对 CSV、JSON、XML 三种策略，包含带附加列的独立复合唯一索引、大整数、小数和二进制、NULL 与重复源键、其它唯一键冲突回滚、索引删除，以及等待并发提交后按最新记录匹配。原 CSV、JSON、XML 导入路径随相关用例复验。

表工作区实库集成用例通过，另核对按键更新第一分区及新增到第二分区的实际路由和提交回执。隔离容器与回环转发已清理。Windows 虚拟机测试会话本轮不可达，Windows 原生及安装包待验。
