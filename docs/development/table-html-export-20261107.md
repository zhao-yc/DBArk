# 表和视图 HTML 导出

SQLite、MySQL、MariaDB 的记录页使用「导出全部筛选行」。PostgreSQL 使用「导出数据」。先应用筛选和排序，再选择「HTML 网页」、要输出的字段和保存位置。没有启用筛选时导出全部记录。当前页码不限制文件行数，未选择导出的字段仍可参与原筛选和排序。

网页固定使用 UTF-8，可离线打开。数据和标题按文本转义，NULL、空字符串及二进制分别显示，空结果保留表头。任务读取数据库中已提交的记录，沿用现有的源对象核验、流式写入、取消和原子发布流程。

本次覆盖表页和视图页的全量导出。Navicat 的向导还提供多对象选择、合并文件和导出任务方案。覆盖矩阵 F01、R01、R02 维持部分覆盖。[Navicat 导出向导](https://www.navicat.com/manual/online_manual/en/navicat_18/win_manual/export_wizard.html#export-data)

## 验收

- macOS arm64 使用 Node.js 24.17.0。原生运行时、严格类型检查、源码构建及 336 项相关单元测试通过。PostgreSQL 文件写入测试覆盖游标未确认时保留原文件。
- SQLite 原生窗口从第二页导出全部 1,353 条匹配记录，逐格核对 7 个所选字段、精确整数、NULL、空文本和二进制。CSV、JSON、INSERT SQL 和 XLSX 同轮通过。SQLite 真实文件的视图用例还验证了空匹配保留表头。
- PostgreSQL 18.6 的原生专项验证表和视图各从第二页导出 9 条匹配记录。引擎实库用例验证视图跨批导出 130 条记录。另一次广域原生回归在到达导出前卡在原有记录编辑步骤，保留了原始日志和临时工作区。
- MySQL 8.4.11 与 MariaDB 11.4.13 的原生专项各验证了表和视图导出 40 条匹配记录。排序使用未导出的字段，网页仅含所选两列，逐行核对顺序、转义和实际值。数据库记录和查询历史保持原样。
- 网络实库使用 Server-200 的隔离回环容器，已核对容器、测试库、转发与会话的清理结果。Windows、macOS x64 和安装包待验。
