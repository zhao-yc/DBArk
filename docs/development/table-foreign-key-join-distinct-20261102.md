# 外键 JOIN 完整输出去重

## 行为与使用

表页“按外键生成 JOIN 查询”的明细模式新增“去重完整输出行（DISTINCT）”。默认关闭，按全部已选输出字段的组合去重，包括重复的 NULL 组合；不会暗加主键、排序字段或改变选列顺序。

WHERE 先筛选原关联行，随后去重、排序和 LIMIT。选列中包含子侧唯一 ID 时，不同子行仍可能全部保留。数据库实际类型及排序规则决定相等性，文本不保证按字节区分，没有排序时不保证顺序。

去重时排序必须引用对应侧已选输出字段；子侧同名字段不能代替父侧字段。取消输出后仍保留原排序，但阻止生成／打开旧查询，提示重新勾选或明确修正排序。不自动删排序，不为消除错误而追加字段。保留多列优先级、NULL 位置及原上限。

此限制依据 [MySQL 对 DISTINCT 与 ORDER BY 的规则](https://dev.mysql.com/doc/refman/8.0/en/group-by-handling.html)，并在兼容性基线实测。普通明细仍允许未输出排序；WHERE／ON 不要求引用列出现在输出中。

分组聚合使用自己的 GROUP BY／COUNT DISTINCT；切换到汇总时隐藏并暂存明细去重，切回恢复。同一外键重读保留，切换外键重置。预览及打开仍只生成独立查询草稿，不自动执行或提交。

## 实现与边界

- 本地 `ForeignKeyJoinOptions.distinct?: boolean`；不改变 IPC、引擎、配置存储或写操作协议。
- 只接受自有布尔数据属性，拒绝访问器、继承声明及未知字段；关闭或未声明时保持原 SQL 字节。
- 原意图、双侧结构重读、当前渲染／忙态检查、深冻结回执和一次消费保持；旧控件不能穿透模式切换或正在核验的回执。
- 所有 SQL 仍受原 256 KiB 预算，输入及字段数量门槛保持。
- 本轮属于 O04 部分增量，任意多表、高级表达式和完整可视化查询构建继续。
