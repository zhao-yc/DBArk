# SQLite CSV／JSON 导入为新表

## 使用流程

在 SQLite `main` 数据库右键菜单或表对象列表选择“导入为新表”。选择 CSV／JSON、编码和 CSV 解释设置，明确检查完整文件，再人工选择最多 128 个来源字段和新表名称。

初始字段使用可空 TEXT 保留整数、小数、日期及 JSON 原文，不从有限样本推断类型。空键、控制字符和按 ASCII 大小写重复的名称生成安全初名；原字段对应关系仍须在导入阶段明确确认。进入正式 SQLite 设计器后可调整字段、默认值、约束、索引、STRICT 等设计，先预览 SQL，再输入准确目标确认建表。

建表与数据导入是两次独立事务。收到真实建表提交回执并核验结构后，先显示“表已创建，导入尚未开始”，用户明确继续才进入原整文件导入器。文件及解释设置锁定为原来源，重新检查真实新表，再人工映射、完整预检、确认准确 `main.表名` 并提交。后续失败、取消或原文件变化均保留已建表，不自动删表、重建或重试。未核验结构或提交未知的建表回执不能自动进入导入。

## 来源与目标约束

- 新来源能力独立于尚未存在的表，完整检查不创建查询会话或数据库 utility；只发布有界样本，不以样本代替完整文件。
- Main 绑定原文档、连接对象及修订、原生文件选择对象和解释设置；runtime 再核物理数据库、原文件身份、完整 SHA、字节数、记录数及字段目录。
- 来源能力最多 64 份／64 MiB、30 分钟。首次成功检查目标后固定准确表，只允许显式重检同表；目标检查及预览沿原独立 5 分钟期限。自然来源过期不级联撤销较新的目标预览。
- 明确释放、原文档／连接失效，以及数据提交或结果未知会撤销原来源和未领取子能力。释放元数据不能假装取消已领取写事务；取消、退出和提交边界继续等待原任务及真实 ACK，结果未知不重放。
- 任务和重启只恢复最小状态或真实事务事实，不保存路径、样本、映射、SQL 或来源能力。原查询事务和临时表保持独立。

SQLite 表页也接入原生“工具 → 数据导入”命令，使用当前活动表；左树中的另一连接或数据库不覆盖该目标。新表创建通知只刷新原库目录，不打开新标签或替换当前查询。

## 验证边界

本轮虚拟机连接不可达且未派发任务，按既有授权回退本机 Windows 串行验证，仅使用自有合成 SQLite／文件和独立临时客户端配置。环境为 Node 24.17.0／pnpm 12.11.2；不访问 Server-200、不使用剪贴板、不更新已安装客户端，不创建正式 Release。

严格类型和最终构建通过。Main／后端／导航五份专项共 122 项通过，其中新增真实文件回归在第 128 条读取时跨 TTL 并明确释放父检查或来源，拒绝晚回提交能力，原盘零 DML、准确只读进程退出；已领取 writer 的真实 ACK／未知边界保持。独审发现的该竞态同时修复 Main 和 runtime：在途只读预检保留准确强引用和原预算直到终态，自然期限与明确撤权分别处理。

新表导入两项 Windows 原生用例分别 13.603 秒和 9.274 秒单次通过，保持每例 120 秒、单 worker、零重试及关闭 trace／截图／视频。Root 独审两次 DDL COMMIT 和一次数据 COMMIT 的原始 statementEnd／close／closeAck、源字节摘要、磁盘四个 TEXT 字段及有符号 64 位原文、改源后零数据写入和空表保留。原任务完整恢复，只新增准确一条正常表页读取，不重放 DDL／导入；任务记录和本地配置无来源值、路径或 SQL。四次正常退出、两座准确临时目录已独立核不存在。
