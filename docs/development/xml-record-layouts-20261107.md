# XML 记录布局

查询结果快照、完整查询以及表和视图的全量导出可选「XML（列名标签）」或「XML（记录属性）」。文件使用 UTF-8 和 `.xml` 扩展名，根元素为 `RECORDS`，每行写为一个 `RECORD`。选列、筛选和排序沿用各入口已有配置。SQLite 和 PostgreSQL 的完整查询可将布局保存为命名方案。

- 列名标签把原列名作为子元素，例如 `<RECORD><id>1</id></RECORD>`。
- 记录属性把原列名作为属性，例如 `<RECORD id="1"></RECORD>`。

两种结构参考 Navicat 的导出示例。[Navicat 导出向导](https://www.navicat.com/manual/online_manual/en/navicat_18/win_manual/export_wizard.html#additional-options)

tabrelio 省略 NULL 字段，显式保留空文本，二进制使用 Base64。数值按客户端接收的精确文本写出。属性中的制表符、换行和回车用字符引用保存，以便解析后恢复原值。列名须符合无命名空间的 XML 命名规则且唯一。属性布局保留 `xmlns` 给 XML 解析器。列名不合法或值含 XML 1.0 禁用字符时，导出失败并保留原目标文件。查询可为列设置别名，或选用支持原值往返的「XML 文档」。[XML 1.0 规范](https://www.w3.org/TR/xml/)

两种布局各写一个行结果集。MySQL 和 MariaDB 的「新执行并完整导出」按从 1 开始的行结果集序号选取数据，语句状态不占序号。执行回执保留在工作台。若指定结果集不存在，文件保持原样，已执行的 SQL 仍可能生效。需要把多组结果和回执写进同一文件时，可选「XML 文档」。

## 验收

- macOS arm64 使用 Node.js 24.17.0。运行时、严格类型检查、构建和 445 项相关单元测试通过。独立 XML 解析器核对快照中的原列名、控制空白、NULL、空文本、精确数值及 Base64。用例验证重名和非法名称被拒绝、非法值出现时保留原文件，以及导出方案重开后恢复。
- SQLite 两个原生用例通过。从表页第二页导出时，两种记录布局均逐格核对了 1,353 条筛选记录。原有位置映射 XML、HTML、Excel、INSERT 和结果快照随相关用例复验。
- PostgreSQL 18.6 三个原生用例及一个引擎实库回归通过。表和视图的两种布局各核对 9 条记录，完整查询核对 4,099 条记录及末行精确整数和小数。
- MySQL 8.4.11、MariaDB 11.4.13 各通过四个原生用例。独立连接确认含写入的脚本按确认次数执行，文件仅包含所选行结果集。指定序号不存在时保留了目标文件。Server-200 的隔离容器、测试库、会话和本地转发均已核对清理。
- 本轮为 macOS 源码验收。Windows 测试会话不可达。macOS x64、安装包和 Navicat 客户端回读待验。
