# SQL 文件导入：下一项高频改进

本文是静态盘点及实施边界，不是已实现或实库验收记录。完整 F01 保持“部分”。

## 已定位的问题

`src/engine/index.ts` 的 `importSql` 在异常后忽略 `ROLLBACK` 失败，断线时也可能
直接跳过回滚，却固定显示“未提交事务已回滚”。每条语句成功后还刷新 SQL 模式；
该刷新或 EOF 回滚失败，会被统一 catch 标成“第 N+1 条 SQL 失败”，此时下一条可能
根本未发送。现有扫描器已有范围 API，但导入只取 SQL 文本，丢失原文件位置。

`TransferDialog` 的导入回包尚未像导出一样核对 `executionKey`，来源失效后迟到回包
可能显示在新目标上。以上均未在本轮修改产品代码；需先补失败反例，再实施修正。

## 实施边界

- 提供结构化 SQL 导入回执，分别记录解码、解析、执行、模式刷新、提交或回滚阶段。
  仅已确认的语句才能显示原范围；刷新失败不虚构未发送语句的执行失败。
- 区分服务器确认的提交、确认的回滚及未知状态，不能吞回滚错误或把断线当确认。
  保留此前已提交写入，不重连、不重放，也不承诺脚本整体原子性。
- 流式扫描记录原文件行列及稳定语句序号，覆盖 BOM、CRLF、跨块字符串／注释和
  `DELIMITER`；明确 UTF-16 字符范围与原编码字节范围的区别，不伪称相等。
- UI 只消费原任务、表单和目标修订仍有效的回执；有限文本展示、不将 SQL 文件或
  凭据写入公共日志。不扩展本次范围到 CSV 重复键策略。

## 必要验收

先验证重复 SQL 的准确位置、多种编码与块边界、成功语句后模式刷新失败、EOF 未提交
事务、回滚失败／断线／取消和迟到回包。再在 200 六个隔离实例验证提交前后及失败行
的独立读回、原连接／事务收尾；真正 ACK 丢失须有真实故障证据，模拟不可替代。
最后走正式 Windows 导入窗口；安装及 macOS 分别记证，不扩大本轮通过数或发布范围。
