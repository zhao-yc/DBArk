# PostgreSQL 整表 SQL 备份与恢复

在普通 PostgreSQL 表页打开「导出数据」，选择「整表备份（SQL）」与保存位置，然后点击「开始导出」。该格式固定保存全部记录和可写入字段，独立于表页筛选、排序和勾选列。计算生成列由目标库按定义恢复。

恢复前，在目标库准备同名 schema，以及脚本引用的类型、排序规则、访问方法、外部序列、父表和触发器函数等依赖。新开该库的空闲查询标签，选择「打开 SQL 文件」，核对后执行整个文件。脚本在一个事务内创建同名新表、写入记录、建立索引与约束，再安装用户触发器。目标同名表或所属序列已存在时，脚本会因创建冲突失败。执行报错且查询会话仍在事务中时，请用查询页的「回滚」收尾。超过查询编辑器执行上限的文件可通过[SQL 文件流式执行](postgres-sql-file-20261107.md)回放。

备份包括列类型、默认值、生成列、标识列、表及列注释、主键及其它逻辑约束、索引、用户触发器及启停状态。表拥有的 `serial` 和标识列序列保存参数与当时观察到的序列状态。备份账号需要读取整张表及所属序列。记录及结构取自同一只读事务。PostgreSQL 序列状态在事务外变动，忙碌表的序列值可能比备份里的记录更靠后。

该功能的单位是普通持久表。分区、继承表、启用行级安全的表、重写规则、未完成的索引和未验证的非空约束会被拒绝。脚本保留逻辑结构，物理存储选项、所有者、权限、复制设置、对象依赖本身及 PostgreSQL 18 中具名非空约束的名称不在此范围。

官方参考见 [PostgreSQL 单表转储及依赖](https://www.postgresql.org/docs/18/app-pgdump.html)、[PostgreSQL 目录定义读取](https://www.postgresql.org/docs/18/functions-info.html)和 [PostgreSQL 序列函数](https://www.postgresql.org/docs/18/functions-sequence.html)。

## 2026-11-07 验收

- Windows 测试虚拟机连接不可用，本轮改用 macOS arm64 源码 Electron。数据库为 `server-200` 上通过 SSH 回环连接的隔离 PostgreSQL 18.6，使用普通账号及两个数据库。通过后核验测试账号残留会话为零，容器和转发已清理。
- 源表保留筛选时导出三条完整记录。验证带引号表名、超安全整数、精确小数、带时区微秒时间、二进制、空值、枚举、计算生成列、外键、部分索引及禁用触发器。通过目标数据库查询标签打开 SQL 并执行，独立连接核对全部记录及目录对象。
- 移除触发器函数后，回放失败，事务回滚后新表和所属序列均不存在。目标依赖恢复后正常回放。已有同名表时再次回放失败且记录原样保留。后续新增记录获得预期的标识列与 `serial` 值。源表数据前后一致。
- 通过 `node scripts/typecheck.mjs`、`node scripts/build.mjs` 及单 worker 的 `postgres-table-sql-backup-native.spec.ts`。全量 Vitest 通过 1,353 个文件，27,584 项通过，10 项按环境门槛跳过。
- 本轮 Windows 源码界面、安装包、其它 PostgreSQL 主版本及整库恢复尚待验收。
