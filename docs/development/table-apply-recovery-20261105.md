# MySQL／MariaDB提交结果核对与防重复投递（2026-11-05）

## 问题与行为

原表页的同一预览只允许一次投递，但普通异常后关闭预览仍可从同一份旧草稿创建新预览。如果服务器已经提交，仅返回界面的响应丢失，新增记录可能被再次提交。本批先补齐此高频提交异常流程，作为继续扩展MySQL／MariaDB跨页草稿的前置。

投递前绑定当前目标、Renderer连接代次、task、preview、操作数量与执行计划语句数。开始投递即清除执行前撤销历史并暂停写入资格。成功响应或同批严格回执确认提交后，只能重新读取；刷新失败保留原完整草稿，继续只读。普通错误、任务failed／cancelled标签、缺失或仍运行的回执不代表回滚，也不提供重试。

异常后的本地回执必须通过既有白名单解析，并匹配task、preview、连接／库／表、三类操作数量、语句数和已观察的operation编号。Main全局connectionRevision与Renderer每连接版本含义不同，不互相比较。已经观察的COMMIT发送或ACK不能被迟到、矛盾或缺失回执撤销。同一任务在未知后收到迟到ACK只提升提交事实，旧草稿继续受保护。

已确认未发送／已回滚时，原草稿可修改并重新预览，执行前历史仍不恢复。所有未知／已提交状态均禁止旧按钮、网格修改、批量写入、撤销重做及从原草稿新建预览。保护复用记录上下文的失效资格，不修改事务引擎或把错误文字当作数据库事实。

## 用户核对及读取

表页显示“本次提交需要核对”，提供提交记录和重新读取入口。先核对提交记录及数据库，再明确确认；取消时不读取。读取授权绑定当前提交身份和目标，只消费一次。未知结果不会自动读取或自动重放；明确放弃本地草稿只会读取当前表，不重试、不回滚已投递操作。

读取成功采用新数据后才解除保护。读取失败保持原页／原行，不以空页假装恢复。旧提交、旧确认、旧读取、后继目标或连接修订的回包不能接管新页。保护只在本表标签内存保存；关闭／重启不会自动恢复旧候选，提交记录仍沿既有本地持久化流程展示。回执范围仅目标事务，不能扩大为触发器或外部副作用保证。
