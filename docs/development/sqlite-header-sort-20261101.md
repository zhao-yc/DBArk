# SQLite 表页列头服务端排序

## 使用

- 读写表格、只读连接与视图均可点击列头，按升序、降序、不排序循环；Ctrl／⌘＋点击添加或调整次级排序，最多八列。键盘聚焦列头后使用 Enter／空格沿 RDG 同一入口操作。
- 列头立即按**已应用**的筛选关系、完整筛选及每页条数，从第一页重新读取。不是仅整理当前已返回行；整数精度、NULL、二进制与动态类型顺序由 SQLite 决定。
- 尚未应用的筛选、关系、每页条数继续保留在表单中，不随列头操作执行。排序表单同步新的排序顺序，下一次明确“应用”才合并其它草稿。
- 页内增删改尚未提交时，沿原“放弃草稿并继续读取”确认；取消保留原行、排序与撤销栈，不发读取或释放。单元格、范围粘贴、替换预览、SQL 预览及导入导出窗口阻止列头重读。
- 排序只读取表数据，不调用查询标签会话或写入协议；刷新、翻页与完整筛选导出继续沿同一已应用查询。没有唯一排序键时，同值记录顺序仍可能变化。

## 实现

`sqliteTableHeaderSort.ts` 只在准确页列映射中把 RDG 键转换为数据库字段，严格验证方向、重复项、未知列及八列预算，不拼 SQL、不转换原值。箭头来自已应用查询，不从未提交排序表单推断。

读写网格和只读 `ResultsGrid` 共用父入口与原 `SqliteTableBrowser.load`。父入口复核渲染、页、编辑器与完整行数组；系统确认期间同步订阅 workspace，来源、活动、占用及结构变化留下墓碑。确认返回后再次核对才丢弃准确原草稿并读取 offset=0，旧回调不能处理后继页。没有 IPC、配置或数据库引擎变更。
