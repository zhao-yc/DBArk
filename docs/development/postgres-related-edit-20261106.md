# PostgreSQL 编辑关联记录

在独立关联页选中一行，点击「编辑所选记录」。填写字段后加入草稿，点击「预览记录修改」，核对原行号、主键、修改值和参数化 SQL 后明确确认。提交成功后沿当前关联范围、搜索和页码刷新。确认回滚后，可继续编辑原草稿并生成新预览。若显示提交结果待核对，先检查数据库中的实际记录。

编辑适用于具备主键、表级读取及更新权限并符合普通编辑条件的目标表。每次只更新用户选中的现有记录。引擎在事务中加锁并复核目标行原值，再检查原源记录和外键目录。任何核对失败都会在发送 UPDATE 前停止。关联编辑令牌不用于整表读取或传输。[PostgreSQL 行锁](https://www.postgresql.org/docs/current/explicit-locking.html#LOCKING-ROWS)

## 验证记录

- macOS arm64 使用 Node.js 24.17.0。运行时检查、严格类型检查、构建和 7 项定向单测通过。
- 完整单元回归覆盖 1,337 个文件，27,505 项通过，10 项 Windows 专用测试按平台跳过。预览调整前的单测主动停止，最终源码重新完整运行通过。
- Server-200 隔离 PostgreSQL 18 实库 5 项通过。父、子关联页都能提交选中行，其他记录保持原值。分区根表保持浏览入口。编辑令牌无法发起无关读取或删除。约束失败回滚后可以重新预览，旧预览不能重放。源行在预览后变化时事务返回未发送，独立查询确认目标保持。测试库核对零连接后清理。
- 最终构建的 macOS Electron 双向关联和编辑专项通过 10 项检查。预览显示第 42 行及原主键，约束失败后可见草稿并能重开修改。独立查询确认成功后只更新第 42 行，页码和关联范围保持。普通复制与回滚专项另通过 9 项检查，均核对原窗口退出、临时配置清理和数据库零连接。
- WIN11-TEST 不可达，本轮采用 macOS。Windows 原生操作、安装包和其他 PostgreSQL 版本待验。完整 79 项工作区整例沿用既有 120 秒超时记录，本轮覆盖关联编辑与普通复制、回滚专项。
