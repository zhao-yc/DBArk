# SQLite 已有外键管理：声明编译

## 当前范围

已有表外键管理本轮完成结构模型、原声明定位和增改删编译，尚未接入 Main、IPC、事务写入和界面，不算已可用功能。目标仍是通过完整 SQL 预览和原生重建管理已有外键；不能用本轮编译或旧重建回归代替新外键端到端验收。主键管理另外继续。

复用已有重建词法器，以声明位置和准确原文共同定位行内／表级外键；重复名称和完全相同的重复声明仍可区分。读取本地／父字段、隐式父主键、动作、延迟规则及原约束名。MATCH 和旧 ON INSERT 单独保留为原文兼容信息，不暗示 SQLite 强制执行了这些规则。

新片段只由严格名称、有序字段、五类删除／更新动作及延迟枚举生成，名称完整引用，不接受任意 SQL 或文件路径。增加、替换和删除可以累计，修改同一原声明两次、原位置／原文变化、保留约束名冲突及未知本地字段均拒绝。替换行内外键生成表级声明，以支持复合映射；其他列、默认值、CHECK／UNIQUE、生成列、原外键、表选项及未删除片段的注释保持。空父字段列表保留为原生隐式主键，不推断 rowid。

模型限制为 128 项修改、1024 项原外键／字段映射和总输入／输出 2 MiB UTF-8；深解析前检查访问器、循环、稀疏数组和预算。输出没有文件操作、数据库请求、执行能力或提交事实。

实现依据：[SQLite 表结构重建](https://www.sqlite.org/lang_altertable.html#making_other_kinds_of_table_schema_changes)、[外键支持与动作](https://www.sqlite.org/foreignkeys.html)。原 SQL 读取只提供语法与声明信息；父表候选键、排序规则、已有数据和真实约束行为仍必须由 Main／独立 writer 在完整目录及事务内确认。
