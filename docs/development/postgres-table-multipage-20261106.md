# PostgreSQL 表页跨页记录草稿

在 PostgreSQL 普通表的记录标签暂存新增、修改或删除后，可以回首页、上一页或下一页继续编辑。草稿列表保留各项操作和暂存时的行号。返回原记录重新编辑时，会更新已有草稿并继续核对首次暂存的原记录。

筛选、排序、页长、刷新和导入导出在处理草稿前保持锁定。每批可暂存最多 16 个原页、100 项操作，沿用 1 MiB 的值预算。预览会展示整批语句及参数值，核对后点击「确认提交整批修改」。

引擎为每个草稿保留原页的记录版本和摘要，旧能力与原文档、标签、连接和数据库绑定。提交时先锁定关系并复查所有原记录，再执行整批 DML。发现外部改动时整批不发送写入，约束错误时整批回滚。结果未确认时保留草稿供核对。[PostgreSQL 显式锁](https://www.postgresql.org/docs/18/explicit-locking.html)

## 验证

- macOS 上 Node.js 24.17.0 运行时检查、类型检查和源码构建通过。
- macOS 完整单元回归共 1,326 个文件，27,455 项通过，10 项 Windows 系统 tar 用例跳过。
- Server-200 独占 PostgreSQL 18 实库回归 5 项通过。覆盖跨页混合批次、跨页重复记录拒绝、其他表和文档的快照拒绝、筛选排序边界、外部改行后整批不发送、约束错误回滚和一次性预览。
- 首轮原生测试发现翻页后再次点击相同网格位置时未同步选择。网格现在按页面快照重置选择。首轮日志和临时配置保留，独占容器已停止并保留。
- macOS 原生窗口回归通过，共 62 项观察。窗口在五个原页暂存一项更新和四项删除，回首页重编同一行后仍是五项，确认后一次提交。独立连接核对最终原表记录、零剩余连接和成功轮次的资源清理。
- Windows 测试虚拟机不可达，本轮切换到 macOS。Windows、两平台安装包和较早 PostgreSQL 版本待验证。
