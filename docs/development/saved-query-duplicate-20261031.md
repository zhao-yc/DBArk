# 保存查询创建独立副本

## 行为

在“查询 → 已保存查询”的记录卡片选择“复制查询”，修改或保留默认的“原名称（副本）”，明确点击“创建副本”。副本保留完整 SQL、原来源连接、默认库状态和原分组；原记录及编辑器不被替换。不打开副本、不执行 SQL，也不创建数据库会话。

来源连接已经删除时仍允许复制本地资料；以后打开时沿用原有的明确连接选择流程。同名不同编号的查询保持独立。默认名称按 Unicode 码点缩短，包含后缀时不超过原名称的 256 个 UTF16 单元限制。

## 实现及保护

- `queries.duplicateChecked` 仅接收编号、原文 SHA256、所见组织修订及名称，不接受 SQL、连接、目标编号或文件路径。
- 主进程分配随机编号；在单个 SQLite 事务内重核原文及组织版本，并插入新记录和原分组关系。来源或分组变化时拒绝旧确认；同一确认不能再次提交。
- 原子发布失败恢复原数据库及修订；副本不继承已打开编辑器的覆盖保存权限，也不读取或解密凭据。
- 复用名称编辑器的输入法、Enter/Escape、旧事件失效和同步双击保护。复制成功后刷新失败保留成功提示，并要求刷新，不自动再次复制。
- 保持现有配置 schema、数据库引擎及写操作协议。
