# PostgreSQL 表导入 XML

在可写的 PostgreSQL 普通表或分区表打开「导入数据」，选择 XML。填写根元素下标识每条记录的标签，默认使用 `RECORD`。启用「将记录属性作为字段」后，记录属性与子元素可同时映射。源字段可以跳过，完全未映射的目标列遵循表的默认规则。

选择文件后，tabrelio 扫描完整来源，取得字段并集和 SHA-256，并显示有限样本。每条记录中省略的已映射字段写入 NULL，空属性或空子元素保留空文本。可为映射到 `bytea` 的值启用 Base64 解码。数值以文本交给 PostgreSQL 的目标类型解析。

确认追加后，客户端按映射流式转换并通过原生 COPY 写入。文件身份和完整字节指纹及服务器行数经过复核才发送提交。数据库约束、解析错误、读取变化或取消会停止当前导入并尝试回滚。若提交结果无法确认，需核对数据库后再操作。[PostgreSQL COPY](https://www.postgresql.org/docs/current/sql-copy.html)

输入为 UTF-8 XML 1.0 的普通文件，使用扁平记录，文件上限 64 MiB，源字段最多 1,000 个。XML 读取拒绝符号链接，并在打开句柄后和读取完成时复核源路径和身份。当前支持向已有表追加。位置映射「XML 文档」、PostgreSQL 从 XML 新建表及按键更新待补齐。

## 验收

- macOS arm64 使用 Node.js 24.17.0。运行时检查、类型检查、源码构建和 74 项直接相关的单元测试通过。扩大回归中 1,064 项通过，另有一条既有 PostgreSQL 执行计划断言失败，在未修改的 `d74ca275` 上复现同一失败。
- PostgreSQL 18.6 原生用例确认写入 3 行，由独立连接核对 NULL、空文本、空字节、精确数字、字段跳过及表默认值。预览后将文件改写为同长度的不同内容，事务确认回滚。另一个引擎实库用例覆盖原 CSV 与表页行为。
- SQLite 四个原生用例通过。MySQL 8.4.11 和 MariaDB 11.4.13 各通过一个 XML 原生回归。Server-200 隔离容器、测试库、会话和转发均已核对清理。
- Windows 测试会话不可达，本轮验证使用 macOS 源码版。Windows、macOS x64 和安装包待验。
