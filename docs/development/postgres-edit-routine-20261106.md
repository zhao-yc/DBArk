# PostgreSQL 已有函数和过程正文编辑

从对象树或「函数」列表打开目标重载的定义，选择「编辑例程正文」。窗口预填服务器保存的正文。修改后预览完整 SQL，再点击「确认更新正文」。成功后重新读取当前重载的定义，核对修改后的正文。

适用范围为 128 KiB 以内的 SQL 或 PL/pgSQL 字符串正文，包括有默认参数和输出参数的例程。正文中的业务对象请使用完整 schema 限定名。SQL 标准 `RETURN` 和 `BEGIN ATOMIC` 形式仍可在定义窗口查看，也可打开为查询草稿。权限沿用服务器的原例程所有权和创建权限。[PostgreSQL CREATE FUNCTION](https://www.postgresql.org/docs/18/sql-createfunction.html) · [PostgreSQL CREATE PROCEDURE](https://www.postgresql.org/docs/18/sql-createprocedure.html)

预览只读目录。确认后锁定原重载，复核目录状态，将正文作为一个 SQL 字符串传给服务器，并在同一事务内核对正文、OID、参数、权限、配置、注释和出向依赖。正文校验失败、原对象发生变化或回读不符时，回滚本次更新。

## 验证

- macOS 上 Node.js 24.17.0 运行时检查、类型检查和源码构建通过。
- macOS 完整单元回归共 1,326 个文件，27,455 项通过，10 项 Windows 系统 tar 用例跳过。
- Server-200 独占 PostgreSQL 18 实库回归 5 项通过。覆盖同名重载、带引号的名称、正文中的引号和反斜杠、默认参数、过程输出参数、定义者权限、已有视图依赖、OID 保留、无效正文和过期预览回滚。SQL 标准正文仍能查看，编辑预览拒绝替换。
- macOS 原生窗口回归通过，共 58 项观察。函数和过程均从实际目录打开，预填原正文，预览后提交并重新加载定义。独立连接回读新正文与原注释，核对原表数据、零剩余连接、成功轮次的临时配置和独占容器清理。
- 首轮原生验收的快照显示正文已预填，但自动化无法按精确标签定位。补上显式无障碍标签后通过。首轮日志和临时配置保留，首轮独占容器已停止并保留。
- Windows 测试虚拟机不可达，本轮切换到 macOS。Windows、两平台安装包和较早 PostgreSQL 版本待验证。
