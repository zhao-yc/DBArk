# 表页勾选记录复制到已有表

## 操作流程

在表格页勾选当前页记录，从“更多 → 数据传输”选择“复制勾选记录到已有表”。明确选择目标连接、数据库和基本表，读取目标结构、核对字段映射和时间解释方式，先预览，再输入完整 `库名.表名` 并确认追加。

来源是打开面板时已载入的勾选快照，只含当前可见列，保留原显示顺序。它不读取其它页、不补读隐藏字段、不使用剪贴板、不更换源页选择，也不自动提交源表草稿。空勾选、旧页 ID、恢复草稿、未提交改动或活动单元格输入都不能打开流程。

## 实现边界

- 复用 `snapshotTablePageExport`、`ResultInsertSourceIntent` 和原 `result.insertPreview/apply/release`，不新增 IPC 或引擎写入协议。BIGINT、DECIMAL、JSON 原文、NULL、空文本、二进制及日期微秒沿原 typed 契约保留。
- 复制是目标追加 INSERT；不会更新、删除或覆盖已有记录。字段映射、生成列、默认值、数据精度和结构变化沿原引擎校验；每批使用独立事务，不借用源页会话。
- 换页、勾选 ABA、源标签／连接／布局改变、实际已读条件不匹配，以及额外模态窗口会永久撤销原来源。来源 token 在构造快照前发布，开门本身零数据库请求。
- 目录、预览、提交各自持有准确工作区 busy 世代。自己的操作不会误撤销来源；其它作业覆盖同一个 `true` 时仍失效，旧释放不能清除后继作业。
- 关闭须等待原请求、取消 ACK 和预览令牌释放。保留已收到的 COMMIT／ROLLBACK 事实，失败不自动重放；提交后原页保持原样，需要用户明确刷新目标查看。

## 时间语义

表页没有记录源会话时区。因此表来源的“目标 TIMESTAMP 解释时区”初始为空，要求用户核对源时区并明确填写数值偏移。此流程保留日期时间原文和微秒；不推测 UTC，也不承诺自动保持跨时区的同一瞬间。原查询结果入口继续使用其原默认 `+00:00`，原行为不变。自动跨时区传输仍属于后续工作。

## 验证

WIN11-TEST 持续不可达，按既有授权回退本机 Windows。40 文件 621 项唯一相关用例分轮通过：功能 9 文件原 95 项，补充直接依赖组件的 31 文件最终 524 项，最终 helper 重验 9 项含新增的两个默认／列表门。覆盖真实 React 表页到目标表单的选择、目录、映射、预览及一次确认，旧勾选／标签 ABA，源草稿拒绝，自身 busy 与外来同 true 覆盖，迟到预览、取消 ACK 和准确释放，以及额外模态来源失效。

最终严格类型检查及普通构建退出 0；新增原生入口的真实 Playwright 默认 1 skip／列表 1 声明均退出 0，未启动客户端或加载认证。真实窗口与数据库证据仍须独立取得，以上统计不替代它们。

新增真实窗口专项 `tests/e2e/table-row-transfer.spec.ts` 默认及 `--list` 不加载驱动、桌面或认证。显式双开关后只消费 Root 预置的 13384 两准确随机库，计划验证取消零写入、跨库两行精确追加、第二行冲突整批回滚、源三行保持和正常退出。Server-200 的主机名及机器身份已核对。创建双隔离库的操作被自动审批以原资源授权未覆盖为由拒绝，尚未启动；待用户明确授权后才能执行。

此前错误测试文件名的预检失败、新 UI 确认控件定位错误、RAM 的 `remove()` 类型错误及三份旧 AST 夹具缺少新增空状态等原件分开保留；没有放宽业务断言、期限或资源保护。相关原始日志在忽略目录 `.cache/table-row-transfer-20261031/`。

本项仅覆盖当前页勾选和已有 MySQL/MariaDB 目标，不等于完整跨连接迁移、全筛选行传输、自动跨时区传输或完整 M04 完成。macOS、安装版、真实权限不足及自然断线组合另验；不创建正式 Release。
