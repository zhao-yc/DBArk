# PostgreSQL 函数与过程补全

在 PostgreSQL 查询标签里输入名称前缀，按 Ctrl+空格打开候选。表达式可补全普通函数、聚合函数和窗口函数，`FROM` 和 `JOIN` 可补全可作为关系调用的函数，`CALL` 提供过程候选。可以先键入 schema 限定符来查找指定 schema 中的可执行对象。[PostgreSQL pg_proc](https://www.postgresql.org/docs/18/catalog-pg-proc.html)

候选分别显示每个重载的参数、所在 schema 和返回类型。接受建议会插入正确引用的名称和调用括号，光标落在括号内。标识符后已有括号时，仅替换名称。表名和字段仍按现有规则补全并排在函数前。

未限定名称时，已连接的查询标签按其空闲原会话的角色和 `search_path` 查找候选。目录同时检查 schema 使用权限及函数或过程执行权限。补全仅读取元数据，保留原执行历史和事务状态，事务打开时暂缓目录读取。[PostgreSQL 信息函数](https://www.postgresql.org/docs/18/functions-info.html)

## 验证

- macOS 上 Node.js 24.17.0 运行时检查、类型检查及源码构建通过。补全定向单元 12 项通过。
- macOS 完整单元回归共 1,326 个文件，27,453 项通过，10 项 Windows 系统 tar 用例跳过。
- Server-200 独占 PostgreSQL 18 实库回归 5 项通过。核对普通函数、聚合函数、窗口函数、表函数和过程，同名不同签名、两个查询标签的实际搜索路径、原角色权限、隐藏 schema、字段与函数同时返回、事务内延后，以及有写入副作用的函数未被补全执行。
- 首轮混合候选断言使用的单字母前缀达到了候选预算，目标窗口函数未出现在截取结果中。改用有真实同前缀字段和函数的目录样本后复跑通过。
- macOS 原生场景通过，共 53 项观察。验证两条重载候选、schema 限定、表函数、`CALL`、括号内光标及执行历史保持。独立核对原表数据、零剩余连接、独占容器和临时配置清理。
- Windows 测试虚拟机连接不可用，本轮在 macOS 验证。Windows、两平台安装包及较早 PostgreSQL 版本待验证。
