# 从 PostgreSQL 对象树打开命名方案

在左侧连接树展开数据库，点击表或视图名称左侧的箭头，查看该对象已保存的命名方案。树节点展开时读取本机方案清单。打开的清单会随本机方案保存、覆盖或删除更新。

点击方案子项或按 Enter，进入独立的表页标签。首屏应用方案的筛选、排序和列布局。普通表页、其它方案标签和原有未提交记录保留。再次点击同一方案时聚焦已打开的标签。要从已保存设置重新开始，可关闭该方案标签再打开。

工作区只记录方案及标签编号。恢复标签时，客户端重新读取仍有效的方案。方案已删除、来源连接变更或服务器拒绝查询时，会显示错误和「重新读取方案」，并保留空页。普通表页仍可从原对象名称打开。

本轮支持从 PostgreSQL 左侧对象树打开命名方案。跨设备同步仍待接入。[Navicat 表配置手册](https://www.navicat.com/manual/online_manual/en/navicat_18/win_manual/data_rdbms.html#save-table-profile)

## 验证

- macOS 上 Node.js 24.17.0 运行时检查、类型检查及源码构建通过。方案、布局与标签专项共 5 个文件、55 项通过，覆盖不同方案与普通表页的身份隔离、拒绝错标签或旧修订，以及连接换代后释放迟到首屏。
- macOS 完整单元回归共 1,326 个文件，27,463 项通过，10 项 Windows 系统 tar 用例跳过。首轮两组侧栏测试缺少新节点的图标和错误组件测试端口，补齐夹具后保留原断言，侧栏专项 37 项和完整回归复跑通过。
- Server-200 独占 PostgreSQL 18 实库回归 5 项通过。实库与原生窗口均独立核对原表数据和零连接，随后清理专用容器。
- macOS Electron 原生窗口回归通过，共 68 项观察。新增场景覆盖折叠和展开、保存后清单刷新、Enter 打开、重复打开聚焦原标签、保留普通页未提交记录，以及无效方案报错并保持空页。已核对原生截图与临时配置清理。
- Windows 测试虚拟机不可达，本轮切换至 macOS。Windows、两平台安装包、整应用重启恢复及较早 PostgreSQL 版本待验证。
