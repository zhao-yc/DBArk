# 表浏览行复制为 INSERT SQL

统筹未发布检查点：`39e8701` 已整合到普通任务分支，完整 **6546/6546** 项单元测试、类型检查和构建通过，1484 个源码文件及 108 个构建文件摘要保持。作者定向 66 项另有独立 15 项反例，共 81 项通过；独审摘要 `e1a817900583f38d43321ff9b3d8d2b6633c324c541e74cadea9ba86bac88f95`。Root 默认关闭的入口列表检查通过。本检查点没有原生剪贴板或 GUI 实跑；真实数据库回放另行准备，不继承固定 R93 安装候选的通过数。

表浏览工具栏提供“复制当前行为 INSERT SQL”和“复制选中行为 INSERT SQL”。只使用当前已加载页的原始值，勾选行按页顺序输出，每行一条带完整库、表、列名的 INSERT；不会翻页、补取字段或执行输出 SQL。任意查询结果没有此入口。

所选行含新增、修改或删除草稿时整次拒绝；不会默默改用旧值或省略草稿。未勾选的草稿不参与复制。字段输入、加载或其他阻塞状态期间拒绝复制。无主键、非 InnoDB 表仍可复制已加载的完整原值，此操作不要求写表权限。

当前目录必须为明确的普通表，并与表页的完整元数据键、目标、连接版本和加载代次一致；原始行还须对应本页加载快照。生成列、不可见列、未知列类型/额外属性、缺失或额外字段均拒绝，不能生成看似完整的 INSERT。这里证明的是加载快照归属，不声称目录与服务器在复制瞬间仍完全一致。

整数、DECIMAL、时间微秒和 JSON 原文不通过 JavaScript Number 或 JSON 重新序列化。整数 Number 仅接受安全整数；DECIMAL 仅接受原始字符串。文本和时间复用 SQL 导出的 UTF-8 十六进制字面量，二进制复用 X 字面量，不依赖 SQL mode 的引号或反斜杠规则。标识符分别引用库、表和字段。损坏的二进制包装、未配对代理项及非有限数值拒绝复制。自增零值也拒绝，因为未知 `NO_AUTO_VALUE_ON_ZERO` 时重放可能分配新值；本功能不修改 SQL mode，也不保证生成的 INSERT 可在不同结构或已有冲突数据的目标中直接执行。

专用 `table.copyInsertSql` 命令只接收严格的结构化目标、列描述和行值，不接收任意文本或 SQL 执行参数。主进程在一次同步调用中先完成校验与全部 SQL 生成，然后只调用一次原生写入。没有剪贴板读取、文件输出、数据库请求、重试或截断。上限为 1000 行、1024 列、50000 单元格、单值 256 KiB、请求 JSON 及最终 SQL 各 1 MiB（UTF-8 字节）；任何一项超限整次拒绝。
