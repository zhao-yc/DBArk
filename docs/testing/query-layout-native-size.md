# 原生分栏的窗口尺寸完成与几何观察

R8 `39189445206`、源码 `2b26d31fdbd361606e7832678f19f4dc05a75ed4` 的 macOS arm64 源码缩进通过，随后分栏在原第147行失败：要求最大高度大于410，实际ARIA上限226，零重试、用例4985毫秒。原附件没有实际窗口尺寸或各工具条矩形，不能把226判成产品错误，也不能认定为屏幕夹窗。Windows和macOS x64的两项源码专项通过，不代表安装阶段或其他测试通过。

产品按查询区实际高度扣除非编辑区、非结果区的直接子元素高度，并给结果内容保留96像素。226可能是合法空间限制；原测试只调用`setContentSize(1400,1000)`，未证明窗口已经达到请求尺寸。

R9 `39194270038` 的新增精确尺寸门失败：arm64真实客户区与页面视口稳定为1400×645，x64为1400×942，DPR均为1；两例都在创建查询前失败，不能拿空查询区判断布局错误。R9原报告及其精确等式失败事实保留。原专项只有1400×1000／1400×480请求和真实布局/行为门；实际客户区必须精确1000是后来增加的前提。

本修正只改测试。每次原生窗口仍只发一次原尺寸请求，在原用例120秒期限内最多5秒观察同一窗口。宽度必须实得原1400，高度须为正整数且不超过本次原请求；native内容尺寸与renderer视口必须一致，并连续两个采样的尺寸、DPR及可取得的原生诊断相同。差异或变化样本中断稳定链，不以请求值替代actual。此观察只证明当前尺寸状态，不证明布局已完成；初次查询准入仍须真实最大高度大于410。原360、370、340、390、缩小恢复、模型历史、SQLite9和独立重启断言保持。645或942稳定本身不能使专项通过；缩小480和恢复仍由原实际几何、偏好及模型断言证明。

观察和附件写入均在原`run.step`内，每个await两侧核原owner和scope；不在finally或失败后补读窗口。原官方BrowserWindow handle先取得窗口id与webContents id；原application的Main回调按这两个身份复核同一存活窗口，再读真实内容尺寸。补充只读bounds、contentBounds、minimumSize、zoomFactor，以及与该窗口匹配的screen bounds、workArea、scaleFactor，均为数字，保留屏幕原点；不把物理像素、DIP和CSS视口混为一个量。身份或内容尺寸读取失败立即停链；仅补充getter失败时diagnostics为null，catch后不补读，不把未知当成显示空间已验证。附件写入失败只留通用测试注解，不隐藏原尺寸、布局或过期scope错误。

收集器不读取SQL、DOM正文、表单值、凭据或环境，不调用`setViewport`、DOM style、模型setter、偏好写入或显示环境配置。原runtime 37个await／52个guard、120秒用例、15秒窗口准备及零重试不改。托管macOS arm64是否提供足够显示模式仍未知；本修正不安装显示工具、不切换runner，也不据645或942直接归因屏幕夹窗。

纯RAM提取当前测试函数和Main只读收集器，执行原controller与合成系统端口，覆盖连续稳定、视口不一致、不稳定、无效尺寸、原410边界、缩小请求、窗口/contents身份变化、迟到scope及诊断失败。RAM的立即采样不模拟真实5秒，也不代表实际窗口或完整交互验收。原R8/R9失败原件不修改、不重跑；新原生执行由统筹独审后另行安排。
