# 原生分栏的窗口尺寸完成与几何观察

R8 `39189445206`、源码 `2b26d31fdbd361606e7832678f19f4dc05a75ed4` 的 macOS arm64 源码缩进通过，随后分栏在原第147行失败：要求最大高度大于410，实际ARIA上限226，零重试、用例4985毫秒。原附件没有实际窗口尺寸或各工具条矩形，不能把226判成产品错误，也不能认定为屏幕夹窗。Windows和macOS x64的两项源码专项通过，不代表安装阶段或其他测试通过。

产品按查询区实际高度扣除非编辑区、非结果区的直接子元素高度，并给结果内容保留96像素。226可能是合法空间限制；原测试只调用`setContentSize(1400,1000)`，未证明窗口已经达到请求尺寸。

本修正只改测试。每次原生窗口请求之后，在原用例120秒期限内以最多5秒的观察轮询读取同一窗口的`getContentSize()`，必须仍精确等于请求值；同时记录页面窗口、查询区、编辑区、分隔条和直接子元素的几何数字及类名。初次分栏准入同样最多5秒观察真实布局，但仍要求大于410。原360、370、340、390、缩小恢复、模型历史、SQLite9和独立重启断言保持。未达到尺寸或准入就失败并保留现场，不跳过、不改当前期望，不调用`setViewport`、模型setter或偏好写入来制造几何。

观察和附件写入均在原`run.step`内，每个await两侧核原owner和scope；不在finally或失败后补读窗口。附件写入失败只留通用测试注解，不隐藏原断言错误。收集器不读取SQL、DOM正文、表单值、凭据或环境。此次没有增加屏幕工作区API，仍不据附件直接归因显示器限制；后续如需屏幕信息应在已核对主窗口入口独立增加只读观察。

纯RAM执行原测试函数、原controller与合成窗口端口，覆盖延迟尺寸完成、始终不足、布局观察、严格410边界、迟到owner停链及附件失败。RAM不是实际窗口验收。原R8失败原件不修改、不重跑；新原生执行由统筹在后续整合完成后另行安排。
