# 新文件占位的首次模型

旧构建`e0fa1dd`的文件打开先登记空查询标签，再异步接收文件正文。所有隐藏查询页也会挂载，空Monaco模型可能已选择平台默认CRLF；后续LF受控正文按该模型EOL同步。编辑后的Undo恢复模型CRLF并回传Main，因此与原磁盘LF的严格摘要不同。R1900的旧构建、期待和成功证据保持，不能用新产品的首次LF模型替代它的差异覆盖。

现在只有本次新打开文件的占位延后第一次`SqlEditor`创建。`beginQueryFileOpen`在同一次store提交中登记空标签及操作专属内存阶段；Main仍按原合同先获得持久化的目标文档身份。成功时再以同一次提交写入完整原文、来源绑定、标题与活动标签并解除阶段。父props尚未追上原子提交时，该占位的首次模型继续等待；已有编辑器不受此等待影响。初次模型收到完整原文，沿Monaco原规则检测均匀LF或CRLF，不调用EOL或正文setter，不更改摘要、编码、BOM或来源权限。

阶段不进入`settings`、SQLite、IPC或重启配置。普通busy、标题、空SQL均不能创建阶段。已有编辑器、保存或另存绑定、恢复配置、隐藏/重显不会因此重建；混合EOL、裸CR仍按原模型表示及严格摘要处理，不承诺其编辑/Undo后精确恢复磁盘行尾分布。

Root另以真实组件和RAM模型端口构造“加载时不挂载目标、回包后首次挂载却收到旧占位props”的输入边界，原实现会创建空模型；尚不声称实际App调度或原生窗口已复现。现在用不持有文档的WeakSet仅记精确原占位对象，首次挂载即使错过活动阶段，也会等待父props追上当前完整标签。标题、空正文、同id副本和恢复的文档均不能冒充此标记；已有模型onReady后的路径保持。首次错误构造没有触发父容器重渲染，仅是测试端口错误，原记录保留，不作为产品反例；修正输入后的独立红例才证明上述组件边界。

租约同时观察来源标签的连接、来源修订和数据库上下文，以及精确目标对象、连接概要与连接修订。来源离开或连接变化后永久失去应用旧回包的权限；来源SQL和标题可继续编辑且保留。目标曾关闭、改动、换来源或出现事务dirty后永久失去删除权，即使后来同值恢复也不能删除。来源失效但目标一直是本操作未修改的空占位时，仍允许本操作在收尾时移除它。清理必须持有原目标busy租约；同id新owner、后来文稿或新作业不能被旧收尾清除。

取消、读取拒绝、初次flush失败只收尾本操作的未修改占位。成功原子提交后的flush失败则保留完整正文和已确认来源，沿原未知/未持久化提示处理，不回滚、不重读、不重放。后续真实任务与SQL文件I/O合同保持。

RAM覆盖真实store、hook和QueryTab接线；只有文件IPC、DOM及Monaco端口为内存实现。它验证占位零新模型、原文首次传入、严格dirty摘要、取消、来源/连接ABA、关闭重建、同id新owner和前后flush失败。RAM恢复正文不冒充真实键盘Undo。真实Windows LF首次建模、编辑/格式化/Undo/Redo、磁盘字节和独立重启需在统筹整合后另立原生验收，不能修改旧R1900期待来报绿。
