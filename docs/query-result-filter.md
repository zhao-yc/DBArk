## 操作和范围

在已完成查询或固定结果上点击“筛选已返回结果”打开内联条件面板。可以按原字段类型选择文本包含／等于／不等于，数值和时间的等于／不等于／大小比较，或任意字段的NULL／非NULL。字段显示原位置、名称和类型，内部唯一key决定身份。多条件支持AND／OR，可逐条移除、清空草稿、显式应用或取消。取消不改变已生效过滤和排序；输入法组合尚未结束时不允许应用，Enter／空格不自动提交，Escape只在组合结束后取消。

新文本候选增加：文本不包含、文本开头为／不是、文本结尾为／不是、为空文本、非空文本。功能项参考 [Navicat 17 官方手册第112–113页的筛选操作](https://www.navicat.com/manual/pdf_manual/en/navicat_17/mac_manual/navicat_mac_en.pdf#page=112)，仅作为公开功能资料，未据此宣称验证本机17.0.8行为。DBArk的本地原文比较语义如下：

| 条件 | 匹配规则 |
| --- | --- |
| 不包含、开头、结尾及其否定 | 按UTF-16原文区分大小写；`%`、`_`、反斜杠及正则符号均为普通字符；不归一化Unicode或裁剪空白 |
| 空条件的包含／开头／结尾 | 所有非NULL文本匹配；对应否定均不匹配 |
| 为空文本／非空文本 | 分别等价于文本等于／不等于空串；空格属于非空文本；两者均排除NULL |

空文本条件与NULL条件都禁用并清空“条件原值”；控制器拒绝残留的隐藏非空原值。换回等于后输入框恢复，空串仍可作为明确条件。所有新增条件仅向可靠文本类型开放，未扩大数值、时间、未知或字节类型准入。

后续[区间筛选开发候选](development/query-result-range-filter-20261020.md)为已准入的数值和日期时间增加“介于／不介于”。面板分别填写下限、上限；介于包含两端，不介于只匹配闭区间之外，两者均排除NULL。BIGINT、DECIMAL、微秒和负TIME沿用精确比较器，FLOAT／DOUBLE沿用有限number；颠倒、缺失或无效端点完整拒绝。离开区间移除旧上限，重新进入须重新填写；只有显式应用才改变结果。固定5b1c468已在WIN11-TEST通过类型／235项定向／构建及完整11005通过、1平台跳过；同提交Linux CI检查成功，桌面与发布job跳过。GUI／实库仍待验，不沿用上一提交的通过数。

界面显示原返回行数、过滤后行数和原结果截断说明。只处理已经返回的快照，不重发SQL、不修改ORDER BY、会话或事务，也不读取未返回行。应用或清除筛选会重置排序、勾选、查找和行详情，界面明确提示；随后可以对过滤结果进行已有的多列优先级排序。

文本默认按UTF-16原文区分大小写；勾选“忽略大小写”的条件先对两端使用Unicode小写映射，不做locale推断、重音去除、字符规范化或完整大小写折叠，不采用数据库collation。原文与映射共用原预算，映射扩展超限也完整拒绝。不执行用户正则或解析JSON；空串是独立值。普通比较（包括不等于）不包含NULL，必须显式用NULL／非NULL条件。没有条件时AND和OR都保留全部行。数字和时间输入按声明类型去除外围空白，文本输入保留空白。

BIGINT、DECIMAL、微秒日期时间和负TIME复用原精确比较器，不转Number／Date；负零及小数尾零按原数学值比较。只有原协议FLOAT／DOUBLE输入转为有限number，与已返回浮点表示比较。未知类型和真正二进制只支持NULL判断；BLOB元数据若实际为字符串可用文本条件，遇字节包装则整次明确拒绝，不解码或猜值。AND／OR不短路绕过坏值或总预算。

## 身份、租约和预算

独立QueryResultFilter绑定原source、原行列数组／对象引用、完整元数据、可见列和业务上下文。过滤仅创建冻结的原行引用数组、规则及sourceIndices，不修改或冻结原行、原列、SQL或源rows。清除回到准确原source对象。排序先接过滤结果；queryResultFilteredSortView把排序位置显式合成为原返回位置，并保留同一个最终QueryResult容器。选择、查找、详情、复制和导出只索引这份最终rows，空过滤结果导出为空，不回退原始全量。

面板草稿有独立单向租约和稳定条件ID，旧输入不能修改移除后占同位置的另一条条件。切标签、结果、查询、任务、连接修订、模态或卸载会撤销旧草稿。旧应用／取消／compositionend不能影响新面板。原数组、元数据或任一活动条件键漂移会撤销旧视图，包括被过滤排除的行；恢复值不能复活旧复制、导出、详情或应用动作。字节NULL条件只保存属性描述符的值身份，不调用getter或解码。

筛选上限为100000行、1024列、32个条件，所有条件合计最多2000000个行×条件比较；每个条件原值和被比较原文最多4096 UTF-16单位，全部输入及实际读取的唯一条件列共用8 Mi单位预算。全部条件另共用32 Mi字符比较工作预算，包含及不包含按最坏源长度×条件长度计费，前后缀及其否定按源长度＋条件长度计费，其他比较按键长度计费。重复条件仍计入总比较工作，重复字段的原值快照共享，避免重复扫描和存储。不按局部数据或截断键猜结果，超限完整拒绝，不部分采用。

区间候选在同一预算内按两个行比较计费；两个端点各受4096单位限制并共同计入8 Mi输入预算，两次比较都计入32 Mi工作预算。仍先拒绝超过32条条件的输入，不为统计区间额外扫描超限规则；不会扩大旧行列上限。

排序的原预算和1c6e64a的降级边界保持。筛选bind拒绝时仅禁用本功能，原能力继续按自身预算及准确原source校验。1025／4096列只保留原详情父端口合同，原网格超过1024列的既有选择租约限制未扩大；100001行／4097列的原能力限制保持。
